## 개요

Claude 3.5 계열(Claude 3.7 Sonnet, Claude 3 Opus, Claude Opus 4.7, Claude Code)은 사회언어학, 법률, 물리·양자컴퓨팅, 에이전트 인프라, 지식 검증 영역에서 **평가 대상이자 개발 도구로 동시에** 활용된다. 8편의 논문은 Claude의 위상이 모델 → 에이전트 → 추론 하네스로 확장되는 흐름을 보여준다.

## 핵심 발견

### 1. 사회언어학적 맥락 민감성
PLUM 코퍼스 연구에서 Claude 3.7 Sonnet은 영어·힌디어·스페인어 전역에서 프롬프트 정중함과 상호작용 이력에 따라 응답이 달라졌다. '보편적 예의'는 존재하지 않으며, 다국어 서비스 설계 시 문화권별 프롬프트 기준이 필요하다.

### 2. 법률 도메인: 평가 깊이에 따른 성능 격차
베트남 법륤 이중 평가에서 Claude 3 Opus는 최상위권을 기록한 반면, 경쟁법 에이전트(Maat) 연구의 일반 Claude는 도메인 전문성 부족과 공식 인용 누락을 보였다. 모순이 아닌 **평가 깊이의 차이**로, 표면 요약은 강하나 전문가급 판례 인용에는 RAG 결합이 사실상 필수다.

### 3. 과학 코딩: 자율성의 프론티어와 상한
물리학자 감독 사례 연구(N=1, 12일·57세션)에서 Claude Code는 15개 감독 이벤트 중 10개를 오라클 테스트 기반 자율 반복으로 해결했으나, 심층 도메인 지식이 필요한 3개는 최종 미해결이었다. 양자 셔틀링 컴파일러 연구는 Opus 4.7이 **명세서만으로 전체 컴파일러 코드를 생성·개선**함을 최초 입증했으나, 복잡 아키텍처에서는 인간 피드백 루프가 유지됐다.

### 4. 하네스 인프라화와 거버넌스 격차
OpenForgeRL은 Claude Code를 Codex·OpenClaw와 함께 표준 추론 하네스로 분류한다. 그러나 481개 공개 CLAUDE.md 분석은 자연어 "do not"이 빌트인 deny와 달리 실행 차단이 아닌 모델 해석에 의존함을 실증한다. 에이전트 인프라의 보안 보장 수준은 표현층에 따라 근본적으로 달라진다.

### 5. 인식론적 불안정성
의사과학 검증 연구에서 Claude를 포함한 4개 LLM 패밀리의 판정은 배포 설정(API vs 웹)과 시간 스냅샷(2025.10–2026.2)에 따라 흔들렸다. Claude가 지식 참조원으로 쓰일 경우 동일 질문의 검증 결과가 재현 불가능할 수 있어, 배포 구성의 명시적 문서화가 요구된다.

## 논문 간 관계

- **겉보기 모순**: 벤치마크 최상위(§2) vs 전문성·인용 한계(§2, §3) → 평가 깊이와 인용 요건 차이로 해소.
- **일치**: 고난도 태스크에서 자율 해결에는 상한이 있으며 인간 감독과 도메인 지식이 결정적(§3, §4).
- **보완**: §3의 능력 입증 ↔ §4·§5의 제어·일관성 문제. 성능 연구와 거버넌스 연구가 병행 진화 중.

## 트렌드 및 향후 방향

연구 초점은 모델 벤치마크(4월) → 도메인 에이전트(5월) → 하네스·학습 인프라·과학 코드 생성(7월) → 배포 거버넌스·보안(7–8월)으로 이동했다. 향후 과제는 ① 개입 수준별 자율성 상한의 정량화, ② 배포 설정 간 응답 안정성 표준 수립, ③ 자연어 규칙과 빌트인 컨트롤 간 의미론적 정합성 검증이다.
