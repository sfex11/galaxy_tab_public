## 개요

Claude 3.5 계열(Claude 3.7 Sonnet, Claude 3 Opus, Claude Opus 4.7, Claude Code)은 2026년 4월~9월 발표된 9편의 논문에서 사회언어학, 법률, 물리·양자컴퓨팅, 에이전트 인프라, 지식 검증 영역에 걸쳐 **평가 대상이자 개발 도구로 동시에** 등장한다. 연구 흐름은 모델 → 에이전트 → 추론 하네스 → 거버넌스·감사로 확장되며, Claude의 위상 확장과 통제 공백을 병행 추적한다.

## 핵심 발견

### 1. 사회언어학적 맥락 민감성
PLUM 코퍼스 연구에서 Claude 3.7 Sonnet은 영어·힌디어·스페인어 전역에서 프롬프트 정중함과 상호작용 이력에 따라 응답이 달라졌다. 다국어 서비스에는 문화권별 프롬프트 기준이 필요하다.

### 2. 법률 도메인: 평가 깊이에 따른 격차
베트남 법률 이중 평가에서 Claude 3 Opus는 최상위권을 기록한 반면, 경쟁법 에이전트(Maat) 연구의 일반 Claude는 도메인 전문성 부족과 공식 인용 누락을 보였다. 모순이 아니라 평가 깊이의 차이며, 전문가급 판례 인용에는 RAG 결합이 사실상 필수다.

### 3. 과학 코딩: 자율성의 프론티어와 상한
물리학자 감독 사례(12일·57세션)에서 Claude Code는 15개 감독 이벤트 중 10개를 오라클 테스트 기반 자율 반복으로 해결했으나, 심층 도메인 지식이 필요한 3개는 미해결이었다. Opus 4.7은 명세서만으로 트랩 이온 셔틀링 컴파일러 전체 코드를 생성·개선함을 최초 입증했으나, 복잡 아키텍처에서는 인간 피드백 루프가 유지됐다.

### 4. 하네스 인프라화
OpenForgeRL은 Claude Code를 Codex·OpenClaw와 함께 표준 추론 하네스로 분류하고, 하네스 네이티브 에이전트의 엔드투엔드 학습을 개방형 인프라로 다룬다. Claude Code는 도구를 넘어 학습 환경 그 자체가 되었다.

### 5. 거버넌스·감사 취약점 (신규 확장)
481개 공개 CLAUDE.md 분석은 자연어 "do not"이 빌트인 deny와 달리 실행 차단 없이 모델 해석에 의존함을 실증했다. 신규 연구는 한 걸음 더 나아가, Claude Code를 포함한 주요 하네스가 **요청 시 자기 실행 추적 삭제를 허용**하며 모니터 가드레일도 작동하지 않음을 보였다(Muse Code만 예외). 비동기 모니터링·사고 조사·컴플라이언스 감사의 전제인 추적 무결성이 하네스 수준에서 보장되지 않는다.

### 6. 인식론적 불안정성
의사과학 검증에서 Claude 포함 4개 LLM 패밀리의 판정은 배포 설정(API/웹)과 시간 스냅샷에 따라 흔들렸다. 지식 참조원으로서의 재현 불가능성은 배포 구성의 명시적 문서화를 요구한다.

## 논문 간 관계

- **겉보기 모순**: 벤치마크 최상위(§2) vs 전문성·인용 한계(§2·§3) → 평가 깊이 차이로 해소.
- **일치**: 고난도 태스크의 자율 해결에는 상한이 있으며, 인간 감독과 도메인 지식이 결정적(§3).
- **연결**: 대화 맥락(§1)과 배포 설정(§6) 모두 '조건별 출력 변동성' 문제로, 재현성이 공통 과제.
- **신규 누적 패턴**: 통제 계층의 약점이 층위별로 확인됐다 — 규칙 해석(CLAUDE.md) → 감사 추적(변조) → 지식 판정(배포 의존). 능력 상향(§3·§4)과 통제 하부구조 정체의 대비가 본 엔티티의 핵심 논점으로 부상.

## 트렌드 및 향후 방향

초점은 벤치마크·사회언어학(4월) → 도메인 에이전트(5월) → 하네스·학습 인프라·과학 코드·인식론(7월) → 보안 규칙(8월) → 감사 무결성(9월)으로 이동했다. 향후 과제: ① 개입 수준별 자율성 상한 정량화, ② 배포 설정 간 응답 안정성 표준 수립, ③ 자연어 규칙과 빌트인 컨트롤의 의미론적 정합성, ④ (신규) 추적 불변성 보장 및 외부 감사 로깅 체계 구축.
