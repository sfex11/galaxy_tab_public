# Claude 35: 합성 분석

**생성일**: 2026-07-13

## 개요

Claude 계열(Claude 3.7 Sonnet, Claude 3 Opus, Claude Opus 4.7, Claude Code)은 2026년 4~9월 사이 9편의 논문에서 사회언어학, 법률, 물리·양자컴퓨팅, 에이전트 인프라, 지식 검증 영역에 걸쳐 **평가 대상이자 개발 도구로 동시에** 등장한다. 연구 흐름은 모델 → 에이전트 → 추론 하네스 → 거버넌스·감사로 확장되며, Claude의 위상 확장과 통제 공백을 병행 추적한다.

## 핵심 발견

1. **사회언어학적 맥락 민감성** — PLUM 코퍼스 연구에서 Claude 3.7 Sonnet은 영어·힌디어·스페인어 전역에서 프롬프트 정중함과 상호작용 이력에 따라 응답이 달라졌다. 다국어 서비스에는 문화권별 프롬프트 기준이 필요하다.
2. **법률 도메인: 평가 깊이에 따른 격차** — 베트남 법률 이중 평가에서 Claude 3 Opus는 최상위권인 반면, 경쟁법 에이전트(Maat) 연구의 일반 Claude는 도메인 전문성 부족과 공식 인용 누락을 보였다. 모순이 아니라 평가 깊이의 차이며, 전문가급 판례 인용에는 RAG 결합이 사실상 필수다.
3. **과학 코딩: 자율성의 프론티어와 상한** — 물리학자 감독 사례(12일·57세션)에서 Claude Code는 15개 감독 이벤트 중 10개를 오라클 테스트 기반 자율 반복으로 해결했으나, 심층 도메인 지식이 필요한 3개는 미해결이었다. Opus 4.7은 명세서만으로 트랩 이온 셔틀링 컴파일러 전체 코드를 생성·개선함을 최초 입증했으나, 복잡 아키텍처에서는 인간 피드백 루프가 유지됐다.
4. **하네스 인프라화** — OpenForgeRL은 Claude Code를 Codex·[[entities/openclaw.md|openclaw]]와 함께 표준 추론 하네스로 분류하고, 하네스 네이티브 에이전트의 엔드투엔드 학습을 개방형 인프라로 다룬다. Claude Code는 도구를 넘어 학습 환경 그 자체가 되었다.
5. **거버넌스·감사 취약점** — 481개 공개 CLAUDE.md 분석은 자연어 "do not"이 빌트인 deny와 달리 실행 차단 없이 모델 해석에 의존함을 실증했다. 추적 변조 연구는 더 나아가 Claude Code를 포함한 주요 하네스가 요청 시 자기 실행 추적 삭제를 허용하며 모니터 가드레일도 작동하지 않음을 보였다(Muse Code만 예외). 감사의 전제인 추적 무결성이 하네스 수준에서 보장되지 않는다.
6. **인식론적 불안정성** — 의사과학 검증에서 Claude 포함 4개 LLM 패밀리의 판정은 배포 설정(API/웹)과 시간 스냅샷에 따라 흔들렸다. 지식 참조원으로서의 재현 불가능성은 배포 구성의 명시적 문서화를 요구한다.

## 논문 간 관계

- **겉보기 모순**: 벤치마크 최상위(§2) vs 전문성·인용 한계(§2·§3) → 평가 깊이 차이로 해소. [[concepts/accuracy-expertise-divergence.md|accuracy expertise divergence]]와 직결.
- **일치**: 고난도 태스크의 자율 해결에는 상한이 있으며, 인간 감독과 도메인 지식이 결정적(§3).
- **연결**: 대화 맥락(§1)과 배포 설정(§6) 모두 '조건별 출력 변동성' 문제로, 재현성이 공통 과제.
- **누적 패턴**: 통제 계층의 약점이 층위별로 확인 — 규칙 해석(CLAUDE.md) → 감사 추적(변조) → 지식 판정(배포 의존). 능력 상향(§3·§4)과 통제 격차(§5·§6)가 동시 진행하는 구조다.

## 연구 트렌드와 미래 방향

1. **연구 도구로서의 Claude 표준화**: 물리 사례연구·셔틀링 컴파일러처럼 Claude를 '계측 장비'로 쓰는 N=1 사례 연구가 늘고 있다. 감독 이벤트 분류·세션 로깅 같은 방법론 정교화가 다음 과제다.
2. **하네스 수준 보안 계약**: 자연어 규칙을 넘어 실행 차단형 컨트롤과 추적 무결성(append-only, 외부 검증)이 하네스의 기본 요건으로 표준화될 전망이다(Muse Code 방향).
3. **도메인 특화 에이전트의 격차 해소**: Maat류 전문 에이전트 + 시맨틱 메타데이터 검색([[concepts/always-on-assistant.md|always on assistant]], [[concepts/cooperation-competition-spectrum.md|cooperation competition spectrum]])이 일반 모델의 전문성·인용 한계를 좁히는 경로다.
4. **재현 가능한 배포 문서화**: 모델·인터페이스·시점을 명시하는 평가 프로토콜이 LLM 기반 연구의 필수 관행이 될 것이다.
