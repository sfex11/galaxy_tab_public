2025.07.11 LLM Agent Architecture

에이전트를 쪼개야 할 때:
페르소나와 실행체, 신뢰 경계가 갈라지는 순간

PES(페르소나-실행 분리)가 요구하는 아키텍처 최소 단위의 재정의와 그 파급효과를 분석한다.

PES Agentic Harness 신뢰 경계 체크포인트 의미론 Agent OS

01하나의 지갑에 두 개의 통장을 넣으면 생기는 일

비유

한 회사의 CEO가 전략을 세우고, 실무자가 그 전략을 실행한다. CEO의 메모장과 실무자의 업무 로그를 한 장의 종이에 나란히 적어 놓는다고 상상해 보라. 실무자의 로그를 감사하려 할 때 CEO가 낙서한 내용이 섞여 들어가고, CEO가 자유롭게 생각을 전개하려 할 때마다 "감사 추적이 깨진다"는 이유로 제지받는다.

이것이 현재 LLM 에이전트 아키텍처가 안고 있는 구조적 모순의 핵심이다.

지금까지 LLM 에이전트의 아키텍처는 하나의 에이전트가 하나의 신뢰 경계를 가진다는 전제 위에 설계되어 왔다. Crab 논문의 C/R 런타임, agentic-language의 자연어 계획 실행, 체크포인트-복구 메커니즘—모두 "에이전트 전체"를 하나의 단위로 취급한다.

그런데 Persona-Execution Separation (PES) 논문이 이 전제를 정면으로 해체한다. 페르소나(어조, 자기표현, 커뮤니케이션 스타일의 진화)와 실행체(상태 있는 작업, 도구 호출, 감사 추적)는 본질적으로 다른 신뢰 도메인에 속하며, 이 둘을 단일 경계 안에 두는 것은 구조적 불일치를 낳는다.

질문은 단순하다: 최소 단위를 바꿔야 하는가? 답은 명확하다. 바꾸지 않으면 아키텍처 전체가 신뢰 경계의 모순 위에 서게 된다.

02단일 신뢰 경계가 숨기고 있던 세 가지 균열

스냅샷의 함정: 체크포인트가 훔쳐가는 것

Crab 논문에서 C/R 런타임은 결함 내성, 롤백, 분기를 위해 "에이전트 전체 스냅샷"을 체크포인트로 사용한다. 이 설계는 하네스가 관리하는 상태가 단일 신뢰 경계 내에 있다는 암묵적 전제 위에 서 있다.

문제는 스냅샷이 페르소나의 진화 상태와 실행체의 감사 추적 상태를 동일한 묶음으로 영속화한다는 점이다. algorithm-system-translation-gap이 지적하듯, 에이전트의 "의미론적 의존 그래프"를 OS의 "프로세스 단위 스냅샷"으로 번역할 때 비효율이 발생하는데, PES 관점에서 이 비효율은 단순한 낭비가 아니다. 신뢰 경계를 횡단하는 상태 결합을 영속화하는 행위다.

OS는 페르소나 상태와 실행 상태의 구분을 모른다. 그래서 두 신뢰 도메인의 상태를 하나의 덩어리로 캡처하고, 이것이 롤백 시 페르소나의 진화 역사를 훼손하거나 실행체의 감사 추적을 끊어버린다. — agent-os-semantic-gap의 PES 관점 재해석

자연어 계획의 이중성

agentic-language가 설계하는 자연어 계획 실행은 RunAgent가 계획을 제약 기반으로 해석하는 구조다. 그러나 이 계획 표현의 "의도"와 "실행"이 동일한 언어 표면에 섞여 있다.

PES 관점에서 자연어 계획은 사실 두 가지 독립적 아티팩트여야 한다. 하나는 페르소나 계획—어조와 자기표현의 진화 방향이고, 다른 하나는 실행 계획—상태 있고 감사 가능한 작업의 순서다. 이들이 단일 표현으로 통합되면, 페르소나의 자유로운 진화가 실행체의 감사 추적성을 오염시키거나, 반대로 감사 제약이 페르소나 진화를 억제하는 alignment-scope-erosion이 발생한다.

의미론적 붕괴의 재해석

기존에 agent-boundary-semantic-collapse로 기술되던 현상은 "에이전트 경계가 의미론적으로 붕괴된다"는 것이었다. PES 렌즈를 끼면 이 현상의 실체가 보다 정밀하게 드러난다. 페르소나 경계와 실행 경계가 의미론적으로 구분 없이 함께 붕괴되는 것이다. 두 경계가从一开始 분리되지 않았으니 "붕괴"조차 제대로 기술할 수 없었던 셈이다.

03쪼개진 최소 단위: 무엇이 어떻게 달라지는가

기존 단위 재정의된 단위 신뢰 경계 핵심 속성
Agent Persona 진화 자유, 무감사 지시, 어조, 자기표현
(포함됨) Executor 감사 필수, 불변 추적 상태 있는 작업, 도구 호출

이 분할이 단순한 "이름 바꾸기"가 아님을 이해하려면, 각 구성요소가 기존 아키텍처에서 어떻게 동작했는지와 어떻게 달라져야 하는지를 비교해야 한다.

하네스의 재구조화

agentic-harness-engineering이 설명하는 하네스는 단일 에이전트의 라이프사이클을 관리한다. PES 이후 하네스의 책임은 변한다. 더 이상 "하나의 에이전트"를 관리하는 것이 아니라, 페르소나-실행체 간의 신뢰 경계 인터페이스를 관리해야 한다.

특히 롤백은 실행체 수준에서만 발생해야 한다. 페르소나 상태를 롤백하면 의도적 진화의 역사가 훼손된다. 반대로, 실행체 상태를 페르소나와 결합하여 롤백하면 감사 추적의 연속성이 끊어진다.

체크포인트 스펙트럼에 새로운 축 추가

checkpoint-restore-efficiency-spectrum은 기존에 "얼마나 적은 상태를 캡처하는가"를 효율의 축으로 삼았다. PES 이후에는 "어느 신뢰 도메인의 상태를 캡처하는가"라는 새로운 축이 추가되어야 한다. 효율의 측정 기준이 "크기"에서 "신뢰 도메인의 정합성"으로 확장되는 것이다.

위임 토폴로지의 재설계

authority-delegation-topology가 기술하는 "페르소나가 실행체에 작업을 위임하는 구조"는, 단일 에이전트 내부의 위임으로 모델링되어 있었다. PES에서 이 위임은 신뢰 도메인 간 위임으로 재설계되어야 한다. 내부 함수 호출이 아니라, 프로토콜을 통한 도메인 간 통신이 되어야 한다.

04숨겨진 연결들: PES가 밝혀낸 기존 개념의 진짜 의미

PES라는 렌즈를 통해 기존 Wiki 엔티티들이 새로운 관계망을 드러낸다. 이 연결들은 단순한 재해석이 아니라, 기존 아키텍처의 위협 모델 자체를 갱신하는 것이다.

  • 실행의 의미론적 불투명성(agent-execution-semantic-opacity)은 "실행이 불투명하다"를 넘어 "페르소나가 실행의 내부 상태를 투명하게 관찰할 수 있는가"라는 신뢰 경계 문제로 재구성된다. PES에서 페르소나는 실행체의 내부 상태를 직접 관찰하면 안 된다—관찰 자체가 경계 침투이기 때문이다.
  • 감사 가능 간극(auditable-gap)은 agent-reliability-auditing과 연결되어, 감사 가능한 것은 오직 실행체라는 명제로 구체화된다. 페르소나는 감사 대상이 아니다. 이 구분이 없으면 감사의 범위가 무한히 확장되거나, 반대로 축소되어 의미를 잃는다.
  • 권한 경계 침투(authority-boundary-penetration)의 방향성이 전환된다. 기존에는 "외부 → 에이전트" 침투에 초점이 있었으나, PES에서는 페르소나 ↔ 실행체 간의 내부 경계 침투가 새로운 위협 모델이 된다. 방화벽이 외부 침입만 막고 내부 부서 간의 데이터 유출을 무시하는 것과 같다.
비유

은행의 내부 통제 시스템을 생각해 보라. 외부 해커 방어(firewall)만 신경 쓰다가, 고객 응대 부서와 거래 실행 부서 사이에 정보 장벽(Chinese Wall)이 없다는 것을 뒤늦게 발견한 상황이다. PES가 밝혀낸 것은 바로 이 "내부 장벽의 부재"다.

05패러다임 전환: "에이전트"라는 단어를 버릴 때

결론을 정리하자. 현재 Wiki의 agent-os-semantic-gap, agentic-harness-engineering, algorithm-system-translation-gap, agentic-language는 모두 에이전트를 단일 신뢰 경계로 전제하고 설계되었다. PES가 이 전제를 해체한다면, 최소 단위의 재정의는 선택이 아닌 필수다.

그러나 이 재정의가 요구하는 것은 단순한 분할이 아니다. 페르소나와 실행체 사이에 어떤 인터페이스 의미론을 둘 것인가가 본질적 질문이다. 페르소나가 실행체에 어떤 형태의 지시를 전달하고, 실행체가 어떤 형태의 피드백을 반환하며, 이 교차점에서 감사 추적의 연속성을 어떻게 유지하는가—이것이 PES 이후 아키텍처 설계의 핵심 과제가 된다.

기존 패러다임: "에이전트"라는 단일 최소 단위를 중심으로 체크포인트, 롤백, 감사, 위임을 설계한다. 모든 상태가 하나의 경계 안에 있다.

전환된 패러다임: "페르소나"와 "실행체"를 독립된 최소 단위로 삼고, 두 신뢰 도메인 사이의 인터페이스 의미론을 1급 시민(first-class citizen)으로 설계한다. 체크포인트는 도메인별로 분리되고, 롤백은 실행체에만 적용되며, 감사는 실행체에만 요구되고, 위임은 도메인 간 프로토콜로 formalize된다.

"에이전트"라는 단어가 편의상의 묶음이 아니라 아키텍처의 원자로 사용되어 온 날들이 끝난다. 앞으로의 에이전트 시스템은 "에이전트"를 최소 단위로 삼는 것이 아니라, 페르소나와 실행체라는 두 원자의 결합체로 모델링되어야 한다. 그리고 그 결합의 방식—인터페이스 의미론—이야말로 진정한 설계의 대상이 된다.

최소 단위를 재정의한다는 것은 바닥을 다시 까는 것이다. 불편하지만, 잘못된 바닥 위에 지은 건물은 아무리 높아도 결국 균열이 간다.
