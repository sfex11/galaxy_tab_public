보이지 않는 실종 — 에어갭 에이전트에서 '침묵적 누락'이 기존 방어선을 무너뜨리는 구조적 이유

2025년 7월 · 심층 분석 Agent OS Semantic Gap Omission

소방서에서 화재 경보기가 울리지 않는다면, 그것은 화재가 없어서가 아닐 수 있다. 경보기 자체가 불이 났다는 사실을 감지하지 못하는 것일 수도 있다. 더 근본적인 문제는, 불이 난 적이 없다는 증거만 남아 있기 때문에 아무도 경보기가 고장 났다는 사실조차 모른다는 점이다.

에어갭(air-gapped) 환경에서 동작하는 소형 언어 모델의 에이전트 파이프라인에서 벌어지고 있는 일이 정확히 이 구조다. 기존 연구와 엔지니어링은 "잘못된 것이 생성되는" 실패 — 환각(hallucination), 오판단 — 에 집중해 왔다. 그런데 에어갭 소형 모델에서 지배적인 실패 모드는 전혀 다른 것이다. 생성되어야 할 사실이 아예 존재하지 않는 '침묵적 누락(omission)'이다.

이 글에서는 논문 "Where Facts Go Missing: A Layerwise Taxonomy and Per-Layer Attribution of Information Omission in Air-Gapped LLM Agent Pipelines"의 핵심 발견을 바탕으로, 왜 기존의 체크포인트-복구(C/R) 하네스가 이 실패를 잡아내지 못하는지, 그리고 agent-os-semantic-gap이라는 기존 개념 틀을 어떻게 재구조화해야 하는지 분석한다.

1. 기존 방어선의 설계 전제: "오염된 상태를 잡아라"

지금까지 에이전트 파이프라인의 신뢰성 문제는 하나의 암묵적 전제 위에 세워져 있었다. "실패하면 상태에 흔적이 남는다"는 것이다.

환각이 발생하면 토큰 시퀀스에 거짓 정보가 기록된다. 오판단이 일어나면 잘못된 행동 결정이 실행 로그에 남는다. 어느 쪽이든 "존재하는 것의 잘못됨"이므로, 출력 검증기가 이를 탐지하고 Crab 같은 의미론적 C/R 런타임이 이전 정상 상태로 롤백하면 된다.

Crab이 정의한 agent-os-semantic-gap의 본질은 이것이었다 — 에이전트의 의미론적 의존 그래프(어떤 상태에 의존하는가)를 OS의 체크포인트 메커니즘(전체 스냅샷)으로 번역할 때 발생하는 비효율. 해결책은 "상태가 손상되었으니 이전 정상 상태로 되돌리면 된다"는 전제에 기반했다.

이 전제는 환각과 오판단이라는 실패 모드 안에서는 매우 튼튼하게 작동했다. 마치 감기 증상이 있으면 체온계로 열을 재고, 열이 있으면 해열제를 먹는 것과 같은 논리다. 증상이 있으니 진단이 가능하고, 진단이 있으니 처방이 가능하다.

그런데 열이 나지 않는데 병이 진행되는 경우가 있다면? 체온계는 정상을 가리키고, 환자는 "아무 문제 없다"고 말하며, 의사는 퇴원시킨다. 이것이 침묵적 누락이 기존 하네스를 무력화하는 구조적 메커니즘의 핵심이다.

2. 침묵적 누락이 기존 하네스를 관통하는 이유

누락(omission)과 환각(hallucination)은 존재론적으로 완전히 다른 범주에 속한다. 이 차이를 명확히 하지 않으면 왜 기존 도구가 무용해지는지 이해할 수 없다.

차원 환각 / 오판단 (기존) 침묵적 누락 (에어갭)
실패의 존재론 잘못된 것이 생성됨 — 상태에 오염 존재 생성되어야 할 것이 없음 — 상태에 오염이 없음
C/R 트리거 출력 검증 → 오류 탐지 → 롤백 탐지 대상이 실행 흔적에 존재하지 않음
파이프라인 관점 스키마 축적 병목 등 레이턴시 이상으로 진단 가능 파이프라인이 정상 완료되므로 병목 자체가 성립하지 않음
비유 배송된 물건이 불량품 주문한 물건이 배송 자체가 안 됨

여기서 핵심을 다시 한번 강조한다. agentic-harness-engineering이 구축한 제어 계층은 "존재하는 것의 잘못됨"을 잡도록 설계되었지, "존재해야 할 것의 부재"를 잡도록 설계되지 않았다.

Crab의 의미론적 의존 그래프는 "현재 상태가 무엇에 의존하는가"를 추적한다. 하지만 "현재 상태가 무엇에 의존해야 했으나 누락되었는가"는 추적하지 않는다. 이것은 단순히 기능이 부족한 것이 아니다. 추적 대상 자체가 실행 흔적에 존재하지 않기 때문에, 기존 추적 체계의 설계 공간 밖에 있는 문제다.

마치 CCTV 카메라가 "누가 들어왔는지"는 기록하지만 "누가 들어와야 했는데 들어오지 않았는지"는 기록하지 않는 것과 같다. 카메라의 결함이 아니라, 카메라라는 매체의 근본적 한계다.

3. 간극의 제2차원: "정보적 의존 그래프" vs "실행 흔적"

논문이 제시하는 층별 귀인(layerwise attribution)은 이 문제를 정밀하게 해부한다. 어느 트랜스포머 층에서 어떤 사실 정보가 소실되는지를 보여주기 때문이다. 하지만 이 진단 결과를 기존의 agent-os-semantic-gap 프레임워크에 끼워 넣으려 하면 구조적 불일치가 발생한다.

기존 제1차원 (Crab이 다룸)

에이전트의 상태 의존 그래프 ↔ OS의 스냅샷 표현

문제: 의존 관계가 텍스트 전체 스냅샷으로 뭉개짐

해결: 의미론적 C/R으로 정밀 복원

신규 제2차원 (누락이 노출시킴)

에이전트 추론의 정보적 의존 그래프 (어떤 사실이 도출을 위해 필수적인가) ↔ 실행 흔적 (실제로 생성된 토큰 시퀀스)

문제: 정보적 의존 그래프의 노드 중 실행 흔적에 materialize되지 않은 노드가 존재하는데, OS는 '존재하지 않는 것'을 상태로 표현할 수 없음

해결: 불가 — 기존 OS 추상화에 "부재의 상태"라는 개념이 없음

비유하자면, 제1차원은 "레시피대로 요리를 했는데 중간에 맛이 변했다 — 언제 맛이 변했는지 추적해서 되돌리자"는 문제다. 반면 제2차원은 "레시피에 분명히 '소금 1티스푼'이 적혀 있었는데, 조리 과정 어디에서도 소금을 넣는 행위가 발생하지 않았다"는 문제다.

후자의 경우, 조리 기록(실행 흔적)을 아무리 뒤져도 소금이 빠졌다는 증거는 나오지 않는다. 소금에 대한 언급 자체가 없으니까. 오직 원래 레시피(정보적 의존 그래프)와 완성된 요리(최종 출력)를 대조했을 때만 "뭔가 빠졌다"는 걸 알아차릴 수 있다.

층별 귀인이 제공하는 것은 이 제2차원 간극의 진단 도구다. 어느 층에서 정보가 소실되었는지를 보여주지만, 그 소실을 OS 수준에서 어떤 '상태'로 간주해야 하는지의 문제는 남는다. X-ray 사진이 뼈 금이 간 곳을 보여주지만, 그 금이 "어떤 종류의 부상"으로 분류되어야 하는지는 의학적 분류 체계가 필요한 것과 같다.

기존 개념의 한계 확인: Wiki에 agent-os-semantic-preservation-failure라는 슬러그가 존재하지만, 이는 보존 대상이 존재할 때의 실패를 전제한다. 누락의 경우 보존할 대상 자체가 실행 흔적에 없으므로 이 엔티티의 스코프 밖이다. checkpoint-consensus-reduction이나 cache-phase-preservation도 동일한 한계를 공유한다.

4. 명시적 부재 상태: 새로운 제어 추상화의 제안

지금까지의 분석에서 하나의 결론이 도출된다. 기존 OS 추상화에서 상태는 "존재하는 것의 스냅샷"이지 "존재해야 할 것의 목록"이 아니다. 이 전제를 뒤집지 않는 한, 침묵적 누락은 영원히 제어 불가능한 블랙박스로 남는다.

제안하는 개념은 명시적 부재 상태(Explicit Absence State)다.

실행 흔적에 materialize되지 않았으나, 정보적 의존 그래프상 필수였던 노드를 OS가 "부재 상태(absence state)"로 표현하고, 이를 C/R 트리거 조건으로 삼을 수 있는가?

이를 실현하기 위해서는 세 가지 구성요소가 필요하다.

1사전 정보적 의존 그래프 (Prior Informational Dependency Graph)

에이전트가 태스크를 수행하기 전, 도메인 지식 기반으로 "이 태스크에는 이런 사실들이 필수적"이라는 그래프를 구성한다. 레시피의 재료 목록과 같다. 이것이 없으면 누락을 판별할 기준 자체가 없다.

2부재 탐지기 (Absence Detector)

실행 흔적과 사전 그래프를 비교하여 materialization failure를 탐지한다. 기존의 출력 검증기가 "생성된 것의 정확성"을 검사했다면, 부재 탐지기는 "생성되지 않은 것의 필수성"을 검사한다. 완전히 다른 검사 축이다.

3부재-기반 롤백 (Absence-Triggered Rollback)

오류가 아닌 부재를 트리거로, 층별 귀인이 가리키는 해당 층 이전으로 되돌아가 재생성을 시도한다. 기존 C/R이 "잘못된 상태 → 이전 정상 상태"로 이동했다면, 부재-기반 롤백은 "불완전한 상태 → 누락 발생 층 직전으로" 이동한다.

이 패턴은 이미 다른 영역에서 유사한 패러다임 전환의 선례가 있다. adaptive-inference가 모델이나 라우트 선택이라는 기존 제어 변수에 "추측 길이(γ) 선택"이라는 새로운 차원을 추가한 것처럼, 부재-기반 제어는 "생성되지 않은 것"이라는 더 근본적인 내부 상태에 반응하는 적응의 새 유형이다. SpecKV가 압축이라는 내부 시스템 상태에 반응하는 적응을 제시했다면, 부재-기반 제어는 그보다 한 단계 더 깊은 곳 — 존재하지 않는 상태 — 에 반응한다.

5. 패러다임 전환: '존재의 검증'에서 '부재의 표현'으로

이 분석이 가리키는 패러다임 전환은 하나의 문장으로 요약된다.

에이전트 OS의 신뢰성 패러다임은 "존재하는 것의 정확성을 검증"하는 것에서,
"존재해야 할 것의 부재를 표현·탐지·복구"하는 것으로 전환되어야 한다.

이 전환은 단순히 기존 하네스에 기능을 하나 더 추가하는 것으로는 달성되지 않는다. OS 수준의 상태 추상화 자체를 재설계해야 한다.

현재의 agent-os-semantic-gap 정의는 단일 차원이다 — 상태 의존성 그래프와 OS 스냅샷 표현 사이의 간극. 이것을 다음과 같이 2차원 구조로 재정의해야 한다.

agent-os-semantic-gap = {
  차원1: 상태 의존성 그래프 ↔ OS 스냅샷 표현
         (Crab이 다룸 — "존재하는 상태의 정밀 보존")
         실패 유형: 환각, 오판단, 상태 오염

  차원2: 정보적 의존 그래프 ↔ 실행 흔적
         (신규 — "존재해야 할 것의 부재 탐지")
         실패 유형: 침묵적 누락, materialization failure
         해결 방향: 명시적 부재 상태, 부재-기반 롤백
}

에어갭 소형 모델이라는 제약 환경은 이 문제를 극단적으로 드러낸다. 외부 지식 검색이 불가능하므로 모델 내부에 인코딩된 지식에 전적으로 의존해야 하는데, 소형 모델은 층 전파 과정에서 정보 소실이 대형 모델보다 훨씬 빈번하게 발생한다. 그 결과, 환각보다 누락이 지배적 실패 모드가 된다.

이것은 에어갭 환경만의 문제가 아니다. 모델이 작아질수록, 오프라인 환경이 늘어날수록, 에이전트 파이프라인이 길어질수록, 누락의 비중은 계속 커진다. 지금 이 순간에도 수많은 엣지 디바이스에서 동작하는 소형 에이전트들이 "정상 완료"라는 가면을 쓴 채 필수 정보를 조용히 잃어버리고 있을 것이다.

가장 위험한 실패는 소리 없는 실패다. 시스템이 정상이라고 말하고, 로그에 오류가 없고, 체크포인트가 깨끗한데 — 결과물이 불완전한 경우. 이것을 잡기 위해서는 "무엇이 없는지"를 말할 수 있는 언어가 필요하고, 그 언어를 OS가 이해할 수 있어야 한다.
