추론 엔진과 도구 호출 사이의 벽이 무너지는 순간

적응적 추론은 인프라 문제고, 도구 호출은 행동 선택 문제다. 이 두 차원이 RL로 학습된 하나의 능력으로 합쳐지면 무슨 일이 벌어지는가.

2025년 7월 · Speculate While You Reason 분석

두 개의 독립된 방이라고 믿었던 것들

LLM 에이전트 연구에서 우리는 오랫동안 두 가지 문제를 별개의 방에서 다뤘다. 하나는 적응적 추론(Adaptive Inference)의 방이고, 다른 하나는 도구 호출(Tool Calling)의 방이다.

적응적 추론의 방에서는 SpecKV 같은 시스템이 묻는다: "다음 토큰을 몇 개나 추측할까?" 이것은 KV 캐시의 압축 비율이라는 내부 시스템 상태를 보고, γ(감마) 값을 조절하는 순수한 인프라 최적화 문제다. 자동차로 치면 엔진의 연료 분사량을 조절하는 일이다.

도구 호출의 방에서는 "Tool Attention Is All You Need" 같은 연구가 묻는다: "수십 개의 서버에 흩어진 도구 중 어떤 것을 호출할까?" 이것은 MCP 배포 환경에서 스키마가 축적될 때 레이턴시 병목이 어디서 생기는지 다루는 외부 행동 선택 문제다. 자동차로 치면 목적지까지 어떤 경로로 갈지 정하는 일이다.

SpecKV는 "추측 길이를 얼마로 할까"를 결정하고, 도구 호출 시스템은 "다음에 무엇을 할까"를 결정한다. 전자는 엔진이, 후자는 운전자가 각자 알아서 한다 — 이것이 지금까지의 암묵적 합의였다.

하지만 "Speculate While You Reason"이라는 논문이 이 합의에 균열을 냈다. 에이전트가 자신의 다음 도구 호출을 RL로 학습해 미리 예측하면, 그 순간 추측은 더 이상 인프라의 일이 아니다. 그것은 학습된 추론 능력이 된다. 벽이 무너지는 순간이다.

벽이 무너지는 세 가지 축

경계 붕괴는 단일 지점에서 일어나지 않는다. Joint Agent-Speculator RL은 세 축에서 동시에 공격한다.

첫째, 추측의 단위가 토큰에서 행동으로 승격된다

SpecKV가 예측하는 것은 다음 토큰 시퀀스다. "the cat sat on the" 다음에 "mat"이 올 것 같으니 3개 토큰을 추측해보자 — 이런 식이다. 하지만 Joint RL에서 에이전트가 예측하는 것은 자신의 다음 도구 호출이다. "파일을 읽은 다음에는 아마 검색 도구를 쓸 것이다"라고 예측하는 것은, 토큰 수준의 추측과는 근본적으로 다른 계층의 일이다.

비유

피아니스트가 다음 음을 예측하는 것(SpecKV)과, 지휘자가 다음 악장의 분위기를 예측하는 것(Joint RL)의 차이다. 음은 개별 토큰이지만, 악장의 분위기는 행동 단위의 예측이다. 전자는 손가락의 반사, 후자는 음악적 이해다.

둘째, 최적화의 위치가 엔진에서 정책으로 이동한다

SpecKV의 γ 선택은 추론 엔진 내부의 휴리스틱이다. 엔진이 "지금 KV 캐시가 70% 압축되었으니 추측 길이를 줄이자"라고 스스로 결정한다. 하지만 도구 호출 추측은 RL로 학습된 에이전트 정책의 일부다. "얼마나 추측할까"와 "다음에 무엇을 할까"가 동일한 매개변수 공간에서 최적화된다.

이것이 의미하는 바는 명확하다. 추측 길이 결정이 더 이상 엔진의 사적인 결정이 아니라, 에이전트의 추론 능력 그 자체와 뒤엉킨다는 것이다.

셋째, 반응 대상이 시스템 상태에서 신념 상태로 이동한다

여기가 가장 근본적인 변화다. Wiki의 adaptive-inference 엔티티는 적응의 대상을 두 가지로 구분했다: CADENCE는 외부 환경에 반응하고, SpecKV는 내부 시스템 상태에 반응한다. 하지만 도구 호출 추측은 에이전트의 신념 상태(belief state)에 반응한다.

내부 시스템 상태(KV 캐시 압축률)는 기계의 체온이다. 신념 상태("이 태스크에서는 검색이 먼저 와야 한다")는 기계가 형성한 이해다. 전자는 하드웨어가 측정하고, 후자는 학습이 만들어낸다.

새로운 연결이 요구하는 세 가지 개념

경계가 붕괴되면, 기존 개념으로는 설명할 수 없는 현상이 나타난다. Wiki에 아직 존재하지 않는 세 가지 연결이 필요하다.

Concept 1

적응적 병목 이동 (Adaptive Bottleneck Migration)

적응의 병목이 인프라 계층에서 인지 계층으로 이동하는 현상이다. SpecKV가 고민하던 "추측 길이를 γ=4로 할까, 8로 할까"라는 병목이, Joint RL에서는 "에이전트가 다음 행동을 얼마나 잘 예측하도록 학습시킬까"라는 병목으로 전이된다.

자동차 비유를 이어가면, 연료 분사 타이밍을 최적화하던 문제가 "운전자가 코너를 얼마나 잘 읽는가"로 바뀌는 셈이다. 최적화의 대상이 기계에서 사람(에이전트)으로 넘어간다.

Concept 2

에이전트 루프 그 자체가 연산이다 (Agent Loop as Computation)

에이전트 루프 — 관찰→추론→도구 호출→관찰 — 는 그동안 '프레임워크'로만 취급되었다. 루프 바깥에서 추론이 일어나고, 루프가 도구 호출을 실행하는 구조다. 하지만 도구 호출 추측은 루프의 한 사이클 전체를 하나의 계산 단위로 펼쳐놓는다.

루프와 추론 사이의 경계가 소멸한다. "도구를 호출하는 것"이 더 이상 추론의 외부 동작이 아니라, 추론의 연장선이 되는 것이다.

Concept 3

에이전트 네이티브 서빙 (Agent-Native Serving)

만약 도구 호출 추측이 학습된 정책의 일부라면, 서빙 시스템의 역할이 근본적으로 바뀐다. 기존의 aggregate-pipeline-serving이 지적한 스키마 축적 병목은, 인프라 휴리스틱으로 스키마 로딩 지연을 숨기는 방식으로 해결하려 했다.

하지만 추측이 학습된 능력에 의존하게 되면, 서빙 시스템은 에이전트 정책의 신뢰도(confidence)에 따라 동적으로 파이프라인을 구성해야 한다. "이 에이전트는 지금 다음 행동을 92% 확신하므로 미리 스키마를 로드한다" — 이런 식의 서빙이 필요하다.

연속체 위에 놓인 적응: 더 이상 분리할 수 없는 것

핵심을 정리하자. SpecKV가 adaptive-inference의 스펙트럼을 "외부 환경 → 내부 시스템 상태"로 확장했다면, Joint RL은 이를 "내부 시스템 상태 → 학습된 인지 상태"로 한 단계 더 밀어붙인다.

외부 환경 반응 (CADENCE)
내부 시스템 상태 반응 (SpecKV)
학습된 인지 상태 반응 (Joint RL) ← 새로운 축
적응적 추론의 연속체: 세 지점이 하나의 스펙트럼에 놓임

이 연속체 위에서 적응적 추론은 더 이상 인프라의 독립 차원이 아니다. 그것은 에이전트의 추론 능력 자체와 동일한 선 위에 놓인다. γ를 선택하는 것과 다음 도구를 예측하는 것이, 근본적으로 같은 종류의 인지적 결정이라는 뜻이다.

비유

초보 요리사에게 "불 세기를 조절해라"는 엔진 조작 지시다. 하지만 숙련된 요리사에게 불 세기 조절은 요리 실력 자체의 일부다. 숙련도가 올라갈수록 기술과 도구 조작 사이의 경계는 녹아내린다. Joint RL이 에이전트에게 하는 일이 바로 이것이다 — 추론 능력이 높아질수록 인프라 최적화와 행동 선택의 경계가 소멸한다.

이 관점에서 보면, Wiki의 현재 분류 체계가 가진 문제가 명확해진다. adaptive-inference와 aggregate-pipeline-serving을 독립 엔티티로 분리하는 것은, 요리 실력과 불 조절을 별도의 항목으로 분리하는 것과 같다. 낮은 수준에서는 분리가 가능하지만, 높은 수준에서는 불가능하다.

패러다임 전환: 분리에서 통합으로

그렇다면 우리는 무엇을 바꿔야 하는가?

  1. 분류 체계의 재구성. 적응적 추론을 인프라 전용 카테고리가 아니라, 에이전트 능력 스펙트럼의 일부로 재분류해야 한다. adaptive-inference 엔티티는 agent-reasoning의 하위 스펙트럼으로 이동하는 것이 개념적으로 정확하다.
  2. 서빙 아키텍처의 재설계. 에이전트 네이티브 서빙은 단순한 파이프라인 최적화가 아니다. 서빙 시스템이 에이전트 정책의 신뢰도를 읽고 동적으로 행동해야 하는, 근본적으로 다른 패러다임이다. 스키마 로딩, 추론 병렬화, 도구 실행 스케줄링이 모두 "이 에이전트가 지금 얼마나 확신하는가"에 종속된다.
  3. 평가 지표의 통합. 적응적 추론의 효율성(토큰 당 연산량)과 도구 호출의 정확성을 따로 측정하는 것은 더 이상 의미가 없다. "에이전트가 예측한 다음 행동이 실제 행동과 일치하는 비율"이라는 단일 지표가, 동시에 추론 효율성과 행동 정확성을 포착한다.
  4. 연구 방향의 전환. "추론 엔진을 어떻게 최적화할까"에서 "에이전트가 스스로 추론-실행 파이프라인을 학습하도록 어떻게 만들까"로 질문이 바뀌어야 한다. 엔진 설계자의 문제가 RL 연구자의 문제가 되는 것이다.

SpecKV가 "외부 환경 → 내부 시스템 상태"로 스펙트럼을 확장했다면, Joint RL은 "내부 시스템 상태 → 학습된 인지 상태"로 한 단계 더 확장한다. 적응적 추론은 더 이상 인프라의 독립 차원이 아니라, 에이전트의 추론 능력 자체와 동일한 연속체 위에 놓인다.

벽이 무너진 자리에 새로운 지형이 보인다. 그 지형의 이름은 통합된 적응적 인지다. 인프라 최적화와 행동 선택이 하나의 학습 과정에서 나오는 세계 — 그것이 "Speculate While You Reason"이 열어 보인 다음 패러다임의 윤곽이다.
