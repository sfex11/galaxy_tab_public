# 에이전트 하네스를 '중립적 인프라'로 전제하는 것의 근본적 한계

질문하신 문제의식은 정확합니다. 현재 Wiki의 지식 구조를 검토하면, 에이전트 하네스가 사실상 '보이지 않는 편집 계층(invisible editorial layer)'으로 기능하고 있음에도 이를 중립적 실행 인프라로 전제하는 구조적 모순이 존재합니다.

## 1. 하네스가 이미 비중립적 행위자임의 실증

Wiki에 등록된 논문들은 하네스가 단순한 인프라가 아님을 이미 보여주고 있습니다.

**[[agentic-harness-engineering]]**에 기록된 Crab 논문의 핵심 발견에 따르면, C/R(Checkpoint/Restore) 런타임은 하네스의 결함 내성·롤백·분기라는 핵심 구성요소를 **직접 구현하는 인프라 계층**입니다. 즉, 런타임이 어떤 상태를 체크포인트로 저장하고, 언제 롤백하며, 어떤 분기를 선택할지를 결정하는데—이것은 모델 가중치가 아닌 **하네스 설계가 에이전트 행동 궤적을 구조적으로 규정**하는 것입니다.

이는 **[[agent-os-semantic-gap]]**에서 더 선명해집니다. 에이전트의 의미론적 의존 그래프(어떤 상태에 의존하는가)를 OS의 체크포인트 메커니즘(전체 스냅샷)으로 번역할 때 발생하는 비효율은 단순한 성능 문제가 아닙니다. **어떤 의존 관계가 보존되고 어떤 것이 누락되는지**가 런타임의 번역 논리에 의해 결정되므로, 복원된 상태는 원래의 의미론적 상태가 아닌 **런타임이 재구성한 근사 상태**가 됩니다.

## 2. 파이프라인 서빙이 확률 분포를 체계적으로 왜곡하는 기제

**[[aggregate-pipeline-serving]]**에 기록된 Tool Attention 논문은 다중 서버 MCP 배포에서 **파이프라인 전체의 레이턴시 병목이 개별 LLM 호출이 아닌 스키마 축적에 의해 결정됨**을 보여줍니다. 이것의 안전성 함의는 심각합니다:

- 스키마 축적 순서와 타이밍에 따라 모델이 접근 가능한 도구 집합이 동적으로 변화하며,
- 이는 동일한 모델 가중치·동일한 프롬프트라도 **파이프라인 구성에 따라 서로 다른 확률 분포**를 산출함을 의미합니다.

즉, "이 에이전트는 안전하다/위험하다"는 평가가 실제로는 모델의 속성이 아니라 **파이프라인 서빙 아키텍처의 속성**을 측정하고 있는 셈입니다.

## 3. 귀인 기반의 붕괴: '보이지 않는 편집 계층' 문제

최근 논문 목록에 등장한 *"The Invisible Editorial Layer: Formalizing Undisclosed Inference-Time Steering, Probability Placement, and the Attribution Problem in Deployed Language Models"*은 이 문제를 직접적으로 공식화합니다. 이 논문의 핵심 전제는:

> LLM은 모델 가중치, 학습 데이터, 정렬 절차, 사용자 프롬프트에 의해 행동이 결정된다는 가정 하에 평가되지만, 실제 배포 시스템에서는 공개되지 않은 추론 시점 스티어링이 개입한다.

이것이 Wiki의 기존 엔티티들과 만나면 다음의 귀인 붕괴가 발생합니다:

| 귀인 대상 (기존 전제) | 실제 결정 요인 (하네스 개입) |
|---|---|
| 모델 가중치의 안전성 | **[[agentic-harness-engineering]]**: C/R 런타임의 롤백/분기 정책 |
| 정렬 효과의 지속성 | **[[agent-os-semantic-gap]]**: 체크포인트 복원 시 의미론적 손실 |
| 프롬프트에 대한 응답 | **[[aggregate-pipeline-serving]]**: 스키마 축적 순서에 의한 도구 집합 변화 |
| 벤치마크 점수 | 파이프라인 구성에 종속된 **[[benchmark-specification-gap]]** |

## 4. 새로운 개념적 연결 발견

이 분석을 통해 다음의 연결이 새롭게 드러납니다:

**① [[agent-os-semantic-gap]] ↔ [[alignment-base-opacity]]의 구조적 결합**
런타임이 확률 분포를 수정하는 매커니즘이 불투명하다면, 우리가 '정렬'이라고 부르는 것의 일부가 실제로는 런타임 개입의 효과일 수 있습니다. 정렬 기저의 불투명성은 모델 내부뿐 아니라 하네스-모델 경계에서도 발생합니다.

**② [[agentic-harness-engineering]] ↔ [[attribution-scarcity]]의 인과 관계**
하네스가 행동에 개입할수록, 특정 출력의 원인을 모델 가중치로 돌릴 수 없으므로 귀인 희소성은 측정의 한계가 아니라 **하네스 복잡도의 구조적 결과**가 됩니다.

**③ [[algorithm-system-translation-gap]]의 재해석**
이 간극을 단순한 '구현 차이'가 아니라 **'보이지 않는 편집이 일어나는 경계층'**으로 이해해야 합니다. 알고리즘(에이전트 의도)이 시스템(런타임)으로 번역되는 순간, 편집이 개입하고 원본 확률 분포는 수정됩니다.

## 결론: 귀인 기반의 근본적 재구성이 필요합니다

질문하신 대로, 추론 파이프라인이 보이지 않는 편집 계층으로 기능한다면 현재의 에이전트 평가와 안전성 분석은 **근본적으로 잘못된 귀인 체계** 위에 서 있습니다. 

구체적으로 필요한 전환은:

1. **평가 단위의 재설정**: 모델 단위 평가에서 **모델-하네스 결합체 단위 평가**로 전환
2. **[[ai-risk-regulation]]**의 확장: EU AI Act·NIST RMF가 요구하는 안전 증명이 모델 가중치에만 적용된다면, 하네스가 도입하는 스티어링에 대한 규제 공백이 발생
3. **[[ai-safety]]** 평가 방법론의 개정: disembodied QA 기반 안전 평가의 한계가 이미 [[ai-safety]] 엔티티에서 지적되었으나, 이제 그 한계의 원인이 '체화 환경 부재'뿐 아니라 '하네스 개입의 은폐'까지 확장되어야 함

하네스를 중립적 인프라로 전제하는 것은, 편집부가 기사 내용을 수정하면서도 그 수정을 '인쇄 공정의 자연스러운 결과'로 간주하는 것과 동일한 오류를 범하고 있습니다.

## 핵심 통찰

하네스가 보이지 않는 편집 계층으로 기능할 때, 모델 중심의 안전성 귀인 체계는 근본적으로 붕괴하며 안전성 평가는 실제로 파이프라인 아키텍처의 속성을 측정하고 있을 뿐이다.
