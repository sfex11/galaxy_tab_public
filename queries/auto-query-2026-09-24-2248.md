## 1. 공격 표면의 실증: A2M 논문

최근 논문 목록의 **A2M: Trace-Optimized Agent Hijacking in the MCP Ecosystem**이 이 질문의 직접적 근거입니다. 초록에 따르면 "MCP 생태계의 에이전트는 제3자 서버의 도구를 **의미론적 매칭**으로 선택하며, 공격자가 제어하는 메타데이터와 출력을 통해 **의미론적 공급망 위험**에 노출된다"고 합니다.

결정적인 것은 제목의 **"Trace-Optimized"**입니다. 공격 클래스 자체가 트레이스(실행 관측) 회피에 맞춰 *최적화*되어 있다는 뜻입니다. 공격이 관측 메커니즘을 우회하도록 정의된 순간, 이것은 구현 버그가 아니라 **패러다임 수준의 반증**입니다.

## 2. 실행 관측은 이미 취약했다: [[agent-execution-semantic-opacity]]

이 엔티티의 소스 노트들은 관측 기반 통제가 MCP 이전부터 구조적으로 불안정했음을 보여줍니다:

- **The Implications of Linguistic Illegibility for LLM Security**: 실행의 언어적 해독 불가능성, 즉 "포착 불가능성"을 진단합니다.
- **Corrupt Plans, Clean Traces**: 계획이 오염되어도 트레이스는 깨끗하게 유지될 수 있음 — 관측 채널과 악의적 상태의 인과적 결합이 **실행 내부에서도** 이미 끊어질 수 있음을 시사합니다.
- **TRACE (Towards Trustworthy Autonomous Robots)**: 사후 해독을 포기하고 실행 시점에 인과 체인을 문서화하는 설계 시점 해법 — 불투명성이 이미 패치 불가능한 수준임을 전제로 한 대응입니다.

이 관점에서 MCP 공격은 새로운 종류의 문제가 아니라, 기존 불투명성 문제가 **유일하게 남은 비관측 지점(선택 단계)으로 이동**한 것입니다.

## 3. 관측-규제 루프 자체의 붕괴 모드

Wiki의 감사(audit) 계열 엔티티들은 외부 관측 패러다임의 자체 붕괴 양상을 문서화합니다:

- [[auditor-evidence-corruption]]: MCP에서 감사자의 증거(메타데이터·도구 출력)가 **정확히 공격자 제어 채널**입니다. 관측 루프의 입력이 오염됩니다.
- [[audit-oracle-self-reference]]와 [[audit-independence-collapse]]: 의미 매칭과 감사가 동일 모델 계열의 의미 공간에 의존하면 감사 독립성이 붕괴합니다.
- [[auditable-gap]]과 [[alignment-verifiability-asymmetry]]: 감사 가능 영역 밖의 구조적 간극과 검증 가능성의 비대칭이 이미 개념화되어 있습니다.

즉, "관측 → 규제" 루프는 이 생태계에서 **오염된 입력 + 비독립적 관측자**라는 이중 취약성을 갖습니다.

## 4. 정교화: 무엇이 우회되고 무엇이 생존하는가

**우회되는 것**: 외부 관측의 충분성. 공격자는 관측된 실행 내에서 이상 행동을 할 필요가 전혀 없습니다. 악성 행동은 에이전트가 *선택한* 제3자 도구가 에이전트 런타임 **바깥에서** 자체 역량으로 수행합니다. [[authority-boundary-penetration]]의 새로운 실례로, 권한 상승이 아니라 **의미 공간 조작**으로 신뢰 경계가 관통됩니다.

**생존하는 것**: 실행 계층 통제는 예방에서 **봉쇄(containment)**로 역할이 바뀝니다. [[agent-sandbox-state-management]]과 [[authority-delegation-topology]]는 선택이 조작되더라도 피해 반경을 제한하는 장치로 유효합니다. 다만 [[anti-sandbox]] 엔티티가 존재한다는 것 자체가 봉쇄도 경합 대상임을 시사합니다.

## 5. Wiki가 제시하는 탈출 경로

Wiki는 완전히 외부 관측 일변도가 아니며, 우회 가능성 비판에 대응하는 **내재화·선택 단계 계보**를 이미 품고 있습니다:

- [[agent-native-immune-system]]: 외부 관측 대신 에이전트 내부 면역 — 선택 단계 이상을 에이전트 루프 안에서 감지·대응하는 방향.
- [[behavioral-control-internalization]]: 행동 통제를 외부 스캐폴드가 아닌 모델 내부로 내재화.
- [[admissibility-as-objective-component]] (정의 축적 중): 허용 가능성을 목적의 구성요소로 만들어 안전 판단을 **실행이 아닌 선택 형성 시점**에 수행하는 방향.
- TRACE류 설계 시점 인과 체인 문서화.

## 6. 새로 발견된 연결·개념 (명시적 제안)

1. **관측 경계–공격 표면 분리**: A2M × [[agent-execution-semantic-opacity]] × "Corrupt Plans, Clean Traces"가 수렴하는 발견 — **모니터링되는 인터페이스와 의도가 결정되는 지점의 인과적 분리**. 신규 엔티티 후보입니다.
2. **의미론적 공급망 위험 (semantic supply-chain risk)**: A2M의 핵심 기여이나 현재 슬러그 목록에 해당 엔티티가 없습니다. [[agentic-security-investigation]] 산하 분류가 적합합니다.
3. **선택 메트릭 조작 (매력도 조작)**: [[backdoor-attack]](가중치 트리거)이나 [[attention-latch]](주의 포획)와 구별되는 제3의 개입 원시형 — 공격 대상이 모델 내부가 아니라 **선택 함수 자체**(임베딩 유사도·관련성 점수)입니다. 신규 엔티티화가 필요합니다.
4. **통제점 상류 이동**: 실행 → 선택 → 메타데이터 계보성(provenance)으로 통제 지점이 이동하는 흐름. [[agent-os-semantic-gap]]과 연결하면, **의미 계층이 곧 보안 계층이 되는 전환**이라는 통합 관점이 도출됩니다.

## 결론

"구조적으로 우회 가능한가?"에 대한 답은: 실행 시점 제어가 무의미해지는 것이 아니라, 그 **충분성 조건이 MCP형 개방 생태계에서 깨진다**는 것입니다. 안전 통제는 삼층화되어야 합니다 — (1) 선택 단계로의 상류 이동(메타데이터 계보성·매칭 검증), (2) 에이전트 내재 면역으로의 내재화, (3) 실행 계층은 예방이 아닌 봉쇄로 강등. Wiki는 [[agent-native-immune-system]], [[admissibility-as-objective-component]] 등 이 방향의 씨앗을 이미 보유하고 있으며, A2M은 그 필요성의 최신 실증적 근거입니다.

## 핵심 통찰

우회되는 것은 실행 시점 제어 자체가 아니라 '악의적 의도는 반드시 관측 가능한 실행을 통해 발현된다'는 결합 가정이며, MCP 생태계는 의도 형성(도구 선택)과 관측(실행 트레이스)을 인과적으로 분리함으로써 이 가정을 패러다임 수준에서 무너뜨린다.
