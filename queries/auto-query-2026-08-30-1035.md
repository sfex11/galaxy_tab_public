# Auto Query: 현재 Wiki에서 다중 에이전트 시스템은 복수의 독립 에이전트를 오케스트레이션(토론·프롬프트 정렬·병렬 실행)하고 통신(자연어·KV 캐시·가중치)하는 별개 아키텍처로 분류하는데, 단일 모델 내 Mixture of Roles가 다중 에이전트 수준의 시너지를 달성한다면 Wiki가 다중 에이전트 연구에서 추구해 온 오케스트레이션·통신·정렬 메커니즘들이 실제로 해결한 문제가 아니라 단일 에이전트의 역할 다양성 부족을 외부적으로 보상한 것에 불과한가?

**날짜**: 2026-08-30
**대상 논문**: One Model, Many Minds: Unlocking Multi-Agent Synergy in a Single Agent via Mixture of Roles
**선택 이유**: 기존 Wiki의 다중 에이전트 오케스트레이션 연구 전반이 '다중 에이전트 필요성'을 전제로 구축되어 있는데, 단일 모델의 내적 역할 다양성이 동등한 시너지를 달성한다면 이 전제 자체가 도전받아 가장 근본적인 패러다임 충돌을 일으키기 때문이다.

## Wiki 답변

# 단일 모델 내 역할 혼합이 다중 에이전트 오케스트레이션의 근거를 해체하는가?

## 핵심 판단: 부분적 환원이지만, 완전한 소거는 아님

질문이 제기하는 의심은 정당하다. 그러나 Wiki의 논문들을 교차 검증하면, 다중 에이전트 메커니즘이 해결한 문제가 **두 개의 이질적 층위**로 분리됨을 알 수 있다. MoR(Mixture of Roles)이 환원 가능한 것은 기능적 다양성 층이며, 환원 불가능한 것은 상태·인프라 분산 층이다.

---

## 1. MoR이 실제로 "외부 보상"이었음을 폭로하는 증거

### 정렬 메커니즘의 내부화 가능성

[[agora-opt]]는 런타임 메모리와 토론 구조를 통해 다중 에이전트 간 정렬을 달성한다. 그런데 동일 엔티티 하에 인용된 MASPO의 논평을 보면:

> "Agora-Opt가 런타임 메모리·토론 구조를 통해 다중 에이전트 정렬을 달성했다면, MASPO는 프롬프트 설계 시점에서 사전 정렬을 보장하는 상보적 경로를 제공하여, 런타임 정렬 메커니즘의 부담을 설계 시점으로 분산시킨다."

정렬의 부담이 런타임 → 설계 시점으로 이동하는 추세 자체가, 정렬 대상이 본질적으로 "에이전트 간"이 아니라 "역할 표현 간"이었을 가능성을 시사한다. MoR이 이를 단일 모델 내 가중치 수준으로 더 밀어넣을 수 있다면, [[agora-opt]]와 MASPO가 해결한 문제는 실제로 **단일 에이전트의 역할 모노리시즘(role monolithicity)**을 외부에서 보상한 것에 가깝다.

### 통신 매체의 내부화

[[agentic-language]](RunAgent)는 자연어를 에이전트 간 통신·계획 해석의 매체로 삼는다. 그러나 단일 모델이 내부적으로 역할을 전환할 수 있다면, 자연어를 통한 "에이전트 간" 통신은 모델 내부의 표현 전환(representation shift)으로 대체 가능하다. 이는 통신 오버헤드가 본질적인 것이 아니라, 역할 분리를 외부적으로 구현한 데서 비롯된 인공적 비용이었음을 의미한다.

### 적응적 추론의 결정 차원 확장과의 유사성

[[adaptive-inference]] 하위의 SpecKV 논평은:

> "적응적 추론의 결정 차원을 모델/라우트 선택에서 추측 길이(γ) 선택으로 확장한다. 기존 컨텍스트 기반 적응이 외부 환경에 반응했다면, SpecKV는 압축이라는 내부 시스템 상태에 반응하는 적응의 새로운 유형을 제시한다."

이와 구조적으로 동일한 패턴이 다중 에이전트 → 단일 모델 MoR 이동에서도 관찰된다: **외부(에이전트 간)에서 결정하던 것을 내부(가중치/표현 수준)로 끌어들이는** 방향 전환이다. SpecKV가 "외부 환경 반응"을 "내부 상태 반응"으로 대체한 것이 다중 에이전트 오케스트레이션의 MoR 내부화와 동일한 패러다임 이동이라면, 오케스트레이션이 해결한 "문제"의 상당 부분은 결정의 위치(location of decision)가 외부에 있었다는 사실 자체였다.

## 2. 그러나 환원 불가능한 잔여가 존재한다

### 상태 분산의 물리적 실재성

[[agentic-harness-engineering]] 하의 Crab 논평은:

> "C/R 런타임이 하네스의 핵심 구성요소(결함 내성·롤백·분기)를 직접 구현하는 인프라 계층으로, 하네스 엔지니어링의 범위를 애플리케이션 로직에서 실행 환경까지 확장함을 시사한다."

이것은 역할 다양성의 문제가 아니다. 결함 내성, 롤백, 분기는 **물리적으로 분산된 상태에서만 의미가 있는** 연산이다. 단일 모델의 순방향 패스 내에서 역할을 전환하더라도, 한 역할이 실행 도중 실패했을 때 다른 역할의 상태로 롤백하는 것은 불가능하다 — 순방향 패스는 되돌릴 수 없기 때문이다.

[[agent-os-semantic-gap]]과 [[algorithm-system-translation-gap]]이 명시하는 간극도 여기에 해당한다:

> "Crab이 이 간극을 구체적 런타임 문제로 현현한다: 에이전트의 의미론적 의존 그래프(어떤 상태에 의존하는가)를 OS의 체크포인트 메커니즘(전체 스냅샷)으로 번역할 때 발생하는 비효율이 간극의 본질이다."

의미론적 의존 그래프가 존재한다는 것 자체가, 에이전트들이 **서로 다른 상태 공간을 점유**하고 있음을 전제한다. 단일 모델 내 MoR은 가중치 공간에서 역할을 분리하지만, 실행 상태(execution state)를 분리하지는 않는다.

### 파이프라인 레벨의 인프라 병목

[[aggregate-pipeline-serving]]의 논평은:

> "다중 서버 MCP 배포에서 파이프라인 전체의 레이턴시 병목이 개별 LLM 호출이 아닌 스키마 축적에 의해 결정됨을 보여주어, 파이프라인 서빙 최적화의 실제 병목 지점을 재정의한다."

스키마 축적 문제는 다중 에이전트가 **각기 다른 툴 스키마에 접근**하는 분산 환경에서만 발생한다. 단일 모델이 모든 역할을 수행하더라도, 툴이 분산되어 있다면 이 병목은 그대로 남는다. 이는 [[agent-native-serving]]의 문제이지 역할 다양성의 문제가 아니다.

### 인식론적 다원주의의 독립성

[[agent-epistemic-pluralism]](슬러그 목록에 존재)은 에이전트들이 서로 다른 인식론적 입장을 취할 때의 메커니즘을 다룬다. 단일 모델 내에서 역할을 전환하는 것과, **독립적으로 경험을 축적하며 믿음 상태가 발산하는** 복수 에이전트를 운영하는 것은 구조적으로 다르다. 전자는 한 모델의 맥락 창 내에서 발생하므로, 맥락 창의 한계가 곧 인식론적 다원성의 한계가 된다.

## 3. 새로운 개념적 연결 발견

### 기능 다양성 vs. 상태 분산의 이분법

위 분석에서 Wiki의 기존 분류 체계가 혼재하고 있었던 두 문제 유형을 분리할 수 있다:

| | 기능적 다양성 부족 | 상태·인프라 분산 필요 |
|---|---|---|
| **본질** | 단일 에이전트가 여러 역할을 수행하지 못함 | 작업이 물리적으로 분산된 상태를 요구함 |
| **다중 에이전트 해법** | 역할 분할 할당 | 샌드박스, C/R, 파이프라인 |
| **MoR 내부화 가능성** | **가능** | **불가능** |
| **관련 엔티티** | [[agora-opt]], [[agentic-language]], MASPO | [[agentic-harness-engineering]], [[agent-os-semantic-gap]], [[aggregate-pipeline-serving]], [[algorithm-system-translation-gap]] |

### [[capability-cooperation-paradox]]와의 연결

슬러그 목록에 존재하는 이 엔티티는 "더 유능한 에이전트를 추가해도 시스템 성능이 선형적으로 향상하지 않는 역설"을 다룰 것으로 추정된다. MoR이 이 역설을 해소하는 경로는 명확하다 — 협업 오버헤드(coordination overhead)를 제거함으로써. 그러나 이 역설의 **원인이 무엇이었는지**에 따라 평가가 달라진다: 기능적 중복이 원인이었다면 MoR이 해결하지만, 상태 동기화 비용이 원인이었다면 MoR은 무관하다.

### 명시적 새 연결: [[agent-boundary-semantic-collapse]]

슬러그 목록에 이 엔티티가 존재한다. MoR이 단일 모델 내에서 에이전트 경계를 모호하게 만드는 것은, 다중 에이전트 시스템이 에이전트 경계를 유지하려던 시도([[agent-identity]], [[agent-knowledge-separation]])가 **경계 자체가 인공적 구성물이었을 가능성**을 시사한다. 즉, "에이전트 경계의 의미론적 붕괴"가 버그가 아니라 피처가 될 수 있는 지점이다.

## 결론

Wiki가 다중 에이전트 연구에서 추구해 온 메커니즘들은 **단일 문제가 아니라 두 개의 문제**를 동시에 해결하고 있었다:

1. **역할 모노리시즘의 외부 보상** (→ MoR이 환원 가능): [[agora-opt]]의 런타임 정렬, [[agentic-language]]의 자연어 통신, MASPO의 설계 시점 정렬은 이 범주에 속하며, 질문의 의심이 정확하다.

2. **분산 상태의 물리적 관리** (→ MoR이 환원 불가능): [[agentic-harness-engineering]]의 C/R 인프라, [[agent-os-semantic-gap]]의 의미론적 의존 그래프, [[aggregate-pipeline-serving]]의 스키마 축적 병목은 에이전트가 "여럿"이어야만 존재하는 문제다.

따라서 다중 에이전트 연구가 "해결한 문제"를 단일 평가로 환원하는 것은 오류이다. 그러나 동시에, Wiki가 이 두 문제를 명시적으로 구분하지 않았다는 것은 **분류 체계의 결함**으로 기록되어야 한다. MoR 논문은 이 결함을 강제로 노출시키는 촉매로서 기능한다.

## 핵심 통찰

MoR(역할 혼합)이 환원 가능한 것은 기능적 다양성 층(역할 모노리시즘의 외부 보상)뿐이며, 결함 내성·롤백·스키마 축적 같은 상태 분산 층위는 단일 모델 내부화로 소거 불가능하다.
