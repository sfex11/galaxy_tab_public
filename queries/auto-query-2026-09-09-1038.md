## 1. 왜곡의 근거: Wiki 내부의 증언들

### 1-1. CUA-Universe는 이 왜곡을 직접 실증하고 있다

[[4d-state-transition-graph]] 개념 페이지의 최근 논문 목록에 **"CUA-Universe: A Scalable and Dynamic Environment for Hybrid GUI+CLI Agents"**가 있습니다. 그 초록은 정확히 이 질문의 전제를 말합니다:

> "Computer-use agents have advanced on benchmarks like OSWorld and AndroidWorld, but still act mostly through the GUI, often producing **inefficient trajectories**. Real-world computer work is hybrid."

주목할 점은 이것이 정확도 오류가 아니라 **궤적 효율성 차원의 병리**라는 것입니다. 단일 모달리티 벤치마크에서 "잘 하는" 에이전트가 실제 작업에서는 비효율적인 궤적을 낸다 — 즉 분리된 평가는 *틀린 점수*를 주는 것을 넘어, *없는 능력 축*(인터페이스 선택·전환)을 아예 측정하지 못합니다.

### 1-2. 능력은 결합형으로 실재한다: [[agentic-vlm]]의 "간극" 실증

[[agentic-vlm]] 페이지의 **Three-Step Nav** 주석은 제로샷 VLN에서 MLLM 에이전트의 구조적 실패(경로 이탈·조기 정지)를 "'단계별 판단'과 '다단계 경로 기획' 사이의 간극"으로 진단합니다. 이 간극 논리를 그대로 GUI/CLI에 이식하면:

- **시각적 상태 확인 능력**(단계별 판단)과 **정밀·고처리량 조작 능력**(실행) 사이의 *전환 간극*
- 이 간극은 두 모달리티를 따로 평가하면 **원리적으로 관찰 불가**합니다. 각 축에서 높은 점수를 내면서도 하이브리드 작업에서 실패하는 에이전트가 존재할 수 있기 때문입니다.

[[agent-scene-instruction-triad]](AwareVLN)도 같은 방향을 시사합니다. 장면–지시–에이전트의 삼각 구조에서 인터페이스는 환경 인식과 지시 해석 사이의 **매개 계층**이지, 도메인 구분선이 아닙니다.

### 1-3. 행동 표현 계약의 분열: [[action-tokenization]] ↔ [[action-interface-latent-alignment]]

**Continuous Actions from Discrete Minds** 주석은 액션 토크나이저를 "연속 행동 공간을 이산 어휘로 번역하는 '표현 계약'"으로, "토크나이저 설계가 곧 물리 제약의 인코딩 방식을 결정"한다고 정리합니다. GUI 클릭(좌표·시각 그라운딩 계약)과 CLI 명령(구문적 정밀성 계약)은 **서로 다른 표현 계약**입니다. 그리고 위키에는 이미 [[action-interface-latent-alignment]]라는 슬러그가 존재하는데 — 인터페이스와 잠재 표현의 정렬 자체가 능력이라면, 모달리티 분리 평가는 이 정렬 능력을 표본에서 **체계적으로 제외**하는 셈입니다.

### 1-4. 측정론적 문제: 포맷 맹점과 명세 간극의 중첩

- [[benchmark-format-blindspot]]: 벤치마크 포맷 특유의 맹점이 존재한다면, 모달리티별 포맷 분리는 맹점을 모달리티별로 **복제**합니다.
- [[benchmark-specification-gap]]: GUI 점수와 터미널 점수의 단순 합산은 서로 다른 명세 간극을 지닌 측정값의 가산이 됩니다.
- [[capability-task-quality-decoupling]] 관점에서 "모달리티별 점수"와 "실제 작업 품질"의 decoupling 위험.

같은 최근 논문 목록의 **Molecular Déjà Vu**가 주는 교훈도 유용합니다 — 정확도는 "예측"과 "인출"을 구분하지 못한다. 벤치마크 점수가 능력 구조를 대변하지 않는다는 것은 위키가 이미 기록한 사실입니다.

### 1-5. 불확실성 관리는 인터페이스 결합 함수다

**"How to Speculate about Uncertainty in Agentic Coding? A Draft-Model Gate Method"**는 코딩 에이전트가 "confidently wrong"하며 실패가 비용 큰 실행 후에야 발견됨을 지적하고 실행 전 불확실성 게이트를 제시합니다([[action-level-speculation]]과 짝을 이루는 논의). 그런데 GUI의 시각적 확인은 CLI 실행 위험을 **헤지하는 수단**이 될 수 있습니다. "GUI 확인으로 CLI 고위험 명령을 검증하는 능력"은 분리 평가에서 존재하지 않는 능력입니다. [[blind-tool-invocation]]·[[blind-tool-suppression]]이 기록한 도구 사용 병리도, 고처리량 CLI 조작이 개입하는 하이브리드 궤적에서 더 정확하게 관찰될 것입니다.

### 1-6. 환경 생성 연구의 파편화: [[agent-environment-generation]]

이 페이지는 이미 스펙트럼을 기록하고 있습니다 — **Gym-Anything**(범용 소프트웨어→환경 변환) vs **Nemobot Games**(게임 도메인 특화). 그러나 양쪽 모두 단일 인터페이스의 "실행 무대"입니다. 반면 CUA-Universe가 [[4d-state-transition-graph]] 아래 편입된 것은 주목할 사건입니다. 환경을 "인터페이스 불변의 상태 전이 구조"로 형식화하면 GUI와 CLI는 그 상태를 읽고 쓰는 **채널의 집합**일 뿐입니다. 위키 자체가 이 방향으로 표류하고 있다는 신호입니다.

### 1-7. 인프라와 감사의 공통 기반이 가려진다

- **Crab**([[agent-os-semantic-gap]], [[agentic-harness-engineering]]): 체크포인트/복원 런타임은 모달리티 불문한 **상태 관리 문제**입니다([[agent-sandbox-state-management]]). GUI/CLI 축 분리는 이 공통 인프라 관점을 가립니다.
- **TRACE**([[agent-execution-semantic-opacity]]): CLI 명령의 언어적 불투명성과 GUI 액션의 시각적 기록은 감사 가능성 자체가 모달리티의 **결합 함수**임을 보여줍니다.
- **Design Docs Are All You Need**([[abstraction-layer-mismatch]]): "오늘의 추상화에 구워진 가정은 내일의 모델과 시스템에 의해 무효화된다" — 모달리티 경계를 평가의 **고정 축**으로 삼는 것의 위험에 대한 위키 내부의 또 다른 경고입니다.

## 2. 반대 방향의 뉘앙스: 분리 평가의 잔존 가치

왜곡이 "분리 자체"에서 오는 것은 아닙니다. 모달리티 고유의 실패 모드는 실재합니다 — VLN의 조기 정지, 코딩의 confident-wrong, 그리고 **"When LLM Decompilers Recompile More and Preserve Less"**가 보여주는 CLI/바이너리 도메인 고유의 정보 손실. 문제는 세 가지입니다:

1. 분리 축을 **독립 능력 축으로 취급**하는 것
2. **교차 항**(전환 비용, 상태 이월, 인터페이스 라우팅)의 계측 부재
3. 집계 시 단순 합산으로 능력 구조를 오독하는 것

또한 GUI/CLI **이분법 자체가 불완전**합니다. 같은 최근 논문 목록의 **"Multi-Step Tool-Calling over Korean Open Public APIs"**는 API라는 제3의 인터페이스가 실무의 주전공임을 보여주며, [[agentic-language]]가 기록한 NLIP는 자연어가 에이전트 간 표준 인터페이스로 제도화된 사례입니다. 인터페이스는 이원적 도메인 구분이 아니라 **다원적이고 설계 가능한 계층**입니다.

## 3. 새로 발견된 연결 및 신규 개념 제안

**기존 슬러그 간 신규 간선:**

- [[4d-state-transition-graph]] → [[agent-environment-generation]]: 환경 생성을 "상태 전이 구조 + 인터페이스 채널 집합"의 정의로 재편
- [[action-tokenization]] ↔ [[action-interface-latent-alignment]]: 인터페이스별 표현 계약의 상호 정렬을 능력으로 승격
- [[adaptive-validity]]의 확장: 모델 업그레이드 시 메모리 유효성 문제 → **인터페이스 혼용 시 에이전트 상태 유효성** 문제로 확장(GUI에서 확인한 정보가 CLI 조작 계획에서 "같은 의미로 해석되는가")
- [[agent-interchangeability]] / [[agent-identity]]의 확장: 역할 교체 가능성 테스트 → **인터페이스 교체 가능성** 테스트로

**신규 개념 후보**(아직 슬러그가 없어 링크 없이 제안):

- **interface-routing-capability**: 작업 하위목표별 최적 인터페이스를 선택·전환하는 능력 — CUA-Universe의 "비효율 궤적"이 바로 이 능력의 결손
- **cross-interface-state-carryover**: 한 인터페이스의 관찰 결과를 다른 인터페이스의 조작 계획으로 이월하는 능력
- **modality-split-evaluation-distortion**: 평가 분리가 만드는 능력 구조 왜곡 자체를 다루는 메타 개념

## 4. 실천적 재구성 제안

1. **상위층**: CUA-Universe형 하이브리드 환경에서의 통합 평가를 기본 축으로 (API 인터페이스 포함)
2. **중위층**: 기존 모달리티별 평가(GUI/터미널)는 능력 축이 아니라 **진단 하위층**으로 격하 — 고유 실패 모드 진단용
3. **환경 생성**: "단일 인터페이스의 실행 무대" → "인터페이스 집합을 가진 상태 전이 구조"로 정의 전환

요컨대, 현 구조는 에이전트가 실제로 지니는 가장 가치 있는 능력 — **인터페이스를 오가며 상태를 이어가는 능력** — 을 평가의 사각지대에 두고 있습니다. 위키는 이미 그 반례(CUA-Universe)와 그 반례를 수용할 틀([[4d-state-transition-graph]])을 모두 보유하고 있으므로, 필요한 것은 새 지식의 축적이 아니라 기존 항목들의 **재배선**입니다.
