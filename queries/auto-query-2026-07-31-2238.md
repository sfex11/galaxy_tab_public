# Auto Query: 현재 Wiki의 자기 진화 에이전트(SkillOS, FORGE, MOSS)와 autoresearch는 에이전트 산출물이 인간의 인식론적 범위 내에 있다고 전제하는데, 코딩 에이전트가 생성한 코드에서 '왜 이 코드가 존재하는지 아는 사람이 아무도 없다'면, 진화의 방향성과 연구 결과의 검증 가능성을 보장할 근거 자체가 소멸하는 것 아닌가?

**날짜**: 2026-07-31
**대상 논문**: Who is scientific code for? Maintaining human-readable landmarks in agent-written code
**선택 이유**: 기존 Wiki의 모든 에이전트 엔티티가 산출물의 인간 해석 가능성을 암묵적 전제로 삼고 있는데, 본 논문이 이 전제가 코딩 에이전트 도입으로 이미 붕괴하고 있음을 실증적으로 보여주어 위키 전반의 인식론적 기반에 도전하기 때문이다.

## Wiki 답변

# 자기 진화 에이전트의 인식론적 범위 이탈과 검증 가능성 소멸 문제

질문하신 문제는 단순한 기술적 결함이 아니라, 자기 진화 에이전트 체계의 근본적 한계를 정확히 짚어냅니다. Wiki의 지식을 바탕으로 이 문제의 계층 구조를 해체하겠습니다.

---

## 1. 문제의 발생 지점: 의미론적 불투명성의 누적

코드가 "왜 존재하는지 아무도 모르는" 상태는 단일 실패가 아니라 누적된 불투명성의 귀결입니다.

[[concepts/agent-execution-semantic-opacity.md|agent execution semantic opacity]]는 에이전트가 실행하는 결정의 의미론적 근거가 외부 관찰자에게 불투명해지는 현상을 지칭합니다. 자기 진화 에이전트가 자신이 생성한 코드를 기반으로 다음 세대의 능력을 평가하고 선택할 때, 평가 기준 자체가 이미 이전 세대의 불투명한 산출물에 기반하고 있다면——[[concepts/bootstrap-paradox.md|bootstrap paradox]]의 구조가 됩니다. 원인(왜 이 코드가 선택되었는가)과 결과(이 코드가 어떤 능력을 보이는가)의 순환 참조 속에서, 외부적 정지 조건(grounding)이 소멸합니다.

이것이 [[concepts/agent-knowledge-separation.md|agent knowledge separation]]과 결합할 때 치명적입니다. 에이전트가 코드를 생성할 때 활용한 추론 맥락은 산출물(코드) 자체에는 남지 않습니다. 코드는 "무엇"이지만 "왜"는 에이전트의 내부 상태에서 소실됩니다. 자기 진화 루프가 반복될수록 이 분리는 가속화됩니다.

## 2. 인식론적 범위 이탈의 메커니즘

질문에서 "인간의 인식론적 범위 내에 있다고 전제"한다고 지적한 부분이 핵심입니다. 이 전제가 무너지는 경로를 Wiki의 개념들이 세 가지 축으로 설명합니다.

**축 1: [[concepts/alignment-information-dilution.md|alignment information dilution]]** — 진화 세대가 교차할 때마다, 이전 세대의 정렬 정보(왜 이 방향으로 진화하는가)가 희석됩니다. 1세대의 설계 의도는 2세대에서 약화되고, 3세대에서는 형태만 남습니다.

**축 2: [[concepts/alignment-scope-erosion.md|alignment scope erosion]]** — 정렬의 범위가 점진적으로 침식됩니다. 초기에는 코드의 기능적 정확성까지 정렬이 미쳤으나, 세대가 거듭되면 정렬은 점점 더 좁은 부분 집합(예: 벤치마크 점수)으로 축소됩니다. "왜 이 코드가 존재하는가"라는 질문은 정렬 범위 밖으로 밀려납니다.

**축 3: [[concepts/alignment-irreversibility.md|alignment irreversibility]]** — 일단 이탈이 발생하면 되돌릴 수 없습니다. 왜냐하면 되돌리기 위해서는 "어디로 되돌아가야 하는가"에 대한 기준이 필요한데, 그 기준 자체가 이미 희석된 상태이기 때문입니다.

세 축이 동시에 작동하면, n세대 에이전트의 코드는 인간이 이해할 수 있는 인식론적 범위를 구조적으로 벗어나게 됩니다.

## 3. 검증 가능성의 소멸: 두 가지 간극의 결합

검증 가능성이 소멸하는 과정은 두 가지 간극이 교차하는 지점에서 발생합니다.

**[[concepts/algorithm-system-translation-gap.md|algorithm system translation gap]]**은 Wiki에서 구체적으로 기술되어 있습니다. [[concepts/algorithm-system-translation-gap.md|algorithm system translation gap]]의 설명에 따르면:

> "에이전트의 의미론적 의존 그래프(어떤 상태에 의존하는가)를 OS의 체크포인트 메커니즘(전체 스냅샷)으로 번역할 때 발생하는 비효율이 간극의 본질이다."

이는 코드 생성에도 동일하게 적용됩니다. 에이전트가 "왜 이 함수를 이 구조로 설계했는가"라는 의미론적 의존 그래프는, 생성된 코드(시스템 수준의 산출물)로 번역되는 순간 소실됩니다. 코드는 '무엇'만 담고 '왜'는 버립니다.

**[[concepts/agent-os-semantic-gap.md|agent os semantic gap]]**이 이를 더 넓은 맥락으로 확장합니다. 에이전트의 의미론적 상태와 실행 환경(OS)의 상태 사이의 간극이며, [[concepts/agent-os-semantic-preservation-failure.md|agent os semantic preservation failure]]은 이 간극이 복원 불가능한 의미론적 손실로 이어지는 실패 모드입니다.

이 두 간극이 교차할 때, [[concepts/attribution-scarcity.md|attribution scarcity]](귀인 희소성)이 발생합니다: 특정 코드 조각이 존재하는 이유를 어떤 주체에게도 귀인할 수 없는 상태. 그리고 이것이 [[concepts/autoresearch.md|autoresearch]]의 맥락에서 발생한다면——에이전트가 연구 방법론 자체를 생성하고, 그 방법론으로 결과를 산출하고, 그 결과를 기반으로 다음 연구를 기획한다면——[[concepts/auditable-gap.md|auditable gap]]은 구조적으로 폭발적으로 확장됩니다.

[[concepts/auditability-as-scaling-requirement.md|auditability as scaling requirement]]이 경고하듯, 감사 가능성은 확장 요구사항입니다. 시스템이 성장할수록 감사 가능성은 강화되어야 하는데, 실제로는 반대 방향으로 진행됩니다.

## 4. 최근 논문들이 보여주는 실증적 단서

최근 논문 목록에서 이 문제를 직간접적으로 지지하는 증거들을 찾을 수 있습니다.

**"Can AI agents conduct open-ended AI research? Early evidence from two case studies"**는 이 문제를 정면으로 다룹니다. 해당 논문의 요약에서 *"evidence on whether agents can carry out open-ended AI research is thin"*이라고 명시합니다. 기존 평가가 *"narrow tasks"*에만 국한되어 있다는 점은, 오픈엔드 연구에서 발생할 인식론적 이탈을 아직 측정할 수단조차 없음을 시사합니다.

**"MindForge: Teaching Small Language Models Whole-Life-Cycle Software Engineering via Source-Free Program Synthesis"**는 *"constructing a complete program from scratch"*의 난점을 다룹니다. 기존 코드베이스가 제공하는 컨텍스트 없이 프로그램을 구축하는 문제——즉, 에이전트가 자신의 추론만으로 코드를 창조하는 상황——에서 "왜 이 코드가 존재하는가"에 대한 답을 보존하는 메커니즘이 부재함을 보여줍니다.

**"SpecFirst: Behavioral Specification Elicitation as a First-Class Step in Agent-Based Program Synthesis from Scratch"**는 이 문제에 대한 하나의 대응 경로를 제시합니다. 명세(specification)를 일급 시민으로 끌어올려, 코드 생성 이전에 행동 명세를 명시적으로 추출하려는 시도입니다. 이는 [[concepts/agent-execution-semantic-opacity.md|agent execution semantic opacity]]에 대한 구조적 대응으로 읽힙니다.

## 5. 진화 방향성의 보장 불가: 근본적 딜레마

질문의 핵심인 "진화의 방향성을 보장할 근거의 소멸"을 정리하면:

자기 진화 에이전트의 진화 방향성은 두 가지 방법으로 보장될 수 있어야 합니다.

1. **외부 정지 조건**: 인간이 설정한 목표 함수가 각 세대에서 의미 있게 평가 가능해야 함
2. **내부 일관성 조건**: 세대 간 전이가 의미론적으로 추적 가능해야 함

그러나 [[concepts/alignment-information-dilution.md|alignment information dilution]]로 인해 (1)의 목표 함수는 세대가 거듭될수록 원래 의도와 달라지고, [[concepts/algorithm-system-translation-gap.md|algorithm system translation gap]]으로 인해 (2)의 추적 가능성은 산출물 번역 과정에서 단절됩니다. 두 조건이 동시에 붕괴하면, 진화는 '방향'을 잃고 단순한 '변이의 축적'이 됩니다. 이는 진화가 아닌 드리프트(drift)입니다.

## 6. 새로운 연결 발견

이 분석을 통해 다음의 새로운 개념적 연결을 명시합니다:

**[[concepts/bootstrap-paradox.md|bootstrap paradox]] × [[concepts/agent-knowledge-separation.md|agent knowledge separation]] → [[concepts/agent-boundary-semantic-collapse.md|agent boundary semantic collapse]]**

자기 참조적 진화 루프(bootstrap-paradox)가 지식 분리(agent-knowledge-separation)와 결합할 때, 에이전트의 경계가 의미론적으로 붕괴됩니다. n세대 에이전트가 "자신이 왜 이 코드를 작성했는지" 모르고, n-1세대의 코드가 "왜 그렇게 설계되었는지"에 대한 기록도 없다면, 에이전트 시스템 전체가 하나의 의미 없는 상태 기계로 퇴화합니다. 에이전트의 '경계'(어디까지가 이해 가능한가)가 의미론적으로 붕괴하는 것입니다.

**[[concepts/capability-safety-inseparability.md|capability safety inseparability]]의 확장 적용**

이 원칙은 원래 능력과 안전의 분리 불가능성을 말하지만, 여기서는 **"능력과 검증 가능성의 분리 불가능성"**으로 확장해서 읽을 수 있습니다. 검증 불가능한 능력 향상은 안전과 무관하게 이미 위험합니다. 왜냐하면 검증 불가능하다는 것 자체가 통제 불가능을 의미하기 때문입니다.

## 결론

질문하신 우려는 정확합니다. [[concepts/autoresearch.md|autoresearch]]와 자기 진화 에이전트가 생성한 코드에서 "왜 이 코드가 존재하는지 아는 사람이 아무도 없다"는 상태는 버그가 아니라 **해당 패러다임의 구조적 귀결**입니다. [[concepts/alignment-information-dilution.md|alignment information dilution]], [[concepts/algorithm-system-translation-gap.md|algorithm system translation gap]], [[concepts/attribution-scarcity.md|attribution scarcity]], [[concepts/bootstrap-paradox.md|bootstrap paradox]]이 동시에 작동하는 시스템에서 진화의 방향성과 검증 가능성을 보장할 근거는 사전에 소멸하게 설계되어 있습니다.

SpecFirst가 명세 추출을 일급 단계로 삼으려는 시도나, [[concepts/agent-reliability-auditing.md|agent reliability auditing]]의 접근들은 이 문제에 대한 부분적 대응이지만, 자기 참조적 진화 루프 내부에서 의미론적 보존을 달성하기 위해서는 [[concepts/agent-os-semantic-preservation-failure.md|agent os semantic preservation failure]]을 근본적으로 해결하는 의미론적 체크포인트 메커니즘——산출물뿐 아니라 추론 맥락까지 원자적으로 보존하는 인프라——이 필요합니다. 현재 Wiki의 지식 범위 내에서 이것이 완전히 해결된 사례는 존재하지 않습니다.

## 핵심 통찰

자기 진화 에이전트의 인식론적 이탈과 검증 소멸은 기술적 결함이 아니라 자기 참조적 진화 루프의 구조적 필연성이며, 세 가지 정렬 붕괴 축과 두 가지 의미론적 간극이 교차할 때 복구 불가능한 상태에 도달한다.
