## 1. 논문 발견의 재구성

**Does Your Agent's Memory Survive a Model Upgrade? A Controlled Study of Memory Portability** (2026-09-08, [[adaptive-validity]]와 연결)는 "모델 업그레이드는 일상적이지만 메모리 마이그레이션은 아니다"라는 진단에서 출발한다. 세 가지 고장 모드로 요약된다:

1. **재해석 불일치** — 새 모델이 동일한 과거 기록을 다르게 해석함
2. **검색 계층 붕괴** — 혼재된 임베딩 버전이 retrieval을 깨뜨림
3. **비가역성** — 원본 증거 없이는 복구 불가능

핵심은 "에이전트는 **동일한 메모리 저장소를 유지하고도 잊을 수 있다**"는 역설이다. 저장소의 존속 ≠ 메모리의 존속이다.

## 2. Wiki 내 아키텍처 중심 메모리 설계와의 대조

- [[adema]] (ADEMA: A Knowledge-State Orchestration Architecture, 2026-04-30): 메모리를 모델과 독립된 **지식 상태 오케스트레이션 아키텍처**로 보는 관점의 대표 사례다. 그러나 본 논문은 그 인프라가 보존하는 "내용"이 모델 버전에 상대적임을 실증하여, 아키텍처 중심 설계의 암묵적 전제 — *저장소가 살아 있으면 메모리도 살아 있다* — 을 무너뜨린다.
- [[agent-os-semantic-gap]] / [[agent-sandbox-state-management]] (Crab, 2026-05-03): 체크포인트/리스토어에서 **바이트는 보존되지만 의미 해석은 보존되지 않는 갭**을 다룬다. 메모리 포터빌리티 문제와 정확히 동형 구조다 — 상태 보존 ≠ 의미 보존.
- [[abstraction-layer-mismatch]] (Design Docs Are All You Need, 2026-09-08): "오늘의 추상화에 구워진 가정이 내일의 모델과 시스템에 의해 무효화된다"는 진단. 메모리 스키마와 임베딩 공간도 동일한 수명 역학을 공유한다.

## 3. 정체성(identity) 문제와의 연결

- [[agent-interchangeability]] + [[agent-identity]] (Testing Interchangeability in LLM Agent Teams, 2026-09-08): "역할을 채우는 에이전트는 교환 가능하다"는 운영상 가정을 직접 테스트한 논문. 메모리 논문은 그 이질적 쌍생으로, **"동일 저장소 = 동일 메모리"라는 가정이 깨진다**는 점에서 같은 질문이다: *구성요소 교체 후에도 시스템의 연속성과 정체성이 유지되는가?*
- [[black-box-instrument-drift]]: 모델은 과거 기록의 **해석 장치(계측기)** 이기도 한데, 계측기 자체가 드리프트하면 과거 계측값(노트)의 의미가 소급적으로 변한다.

## 4. 질문에 대한 정밀한 답

**"메모리의 수명과 정체성이 모델 라이프사이클에 종속되는가?"** — 실효적 수명과 해석적 정체성에 대해서는 **예스**. 그러나 이것이 "메모리 = 모델 종속물"로의 설계 후퇴를 요구하지는 않는다. 논문의 함의는 책임 분리다:

- **아키텍처 계층의 책임**: 원본 증거(raw evidence) 보존, 임베딩 버전의 명시적 태깅, 재해석 파이프라인 — [[agentic-harness-engineering]] (Crab)이 하네스를 실행 환경까지 확장했듯, 메모리 **이식성도 하네스/인프라의 1급 책임**으로 격상되어야 한다.
- **모델 계층의 상대성**: [[adaptive-validity]]의 관점 확장 — 메모리 항목의 유효성은 모델 버전에 대해 **적응적으로 재평가**되어야 하는 성질이 된다.
- [[belief-state-grounding]]: 원본 증거는 재해석 시의 앵커 역할을 하며, 이는 감사 가능성과 직결된다 ([[auditability-as-scaling-requirement]], [[agent-reliability-auditing]]).

## 5. 새로 발견된 연결 (위키에 아직 명시적 링크 없음)

1. **메모리 이식성 ↔ 에이전트 교체 가능성**: [[agent-interchangeability]]와 메모리 포터빌리티는 "구성요소 스왑 후 시스템 연속성"이라는 동일 질문의 두 사례. 통합 엔티티화 가치가 있음.
2. **상태 보존 ≠ 의미 보존**: [[agent-os-semantic-preservation-failure]]를 체크포인트 도메인에서 메모리 도메인으로 확장하는 간선.
3. **임베딩 버전 혼재 = 검색 인프라의 [[black-box-instrument-drift]]**: 드리프트 주체가 모델 출력이 아니라 인덱스 자체인 변형.
4. **업그레이드 강제 망각 ↔ 기능적 망각**: [[adaptive-forgetting]]·[[adaptive-forgetting-as-function]]과 대비하여, 본 논문의 망각은 **비통제 손실**이라는 점에서 구별 필요 — 통제된 마이그레이션(의도적 재인코딩)과 비통제 손실의 구분이 새 개념 후보.
5. **근거 보존 ↔ 감사 가능성**: 비가역 복구 불가능성은 [[auditability-as-scaling-requirement]]의 새 근거가 된다.

## 결론

본 논문은 메모리의 실효 수명과 정체성이 업그레이드 순간에 모델 라이프사이클과 결합함을 실증한다. 따라서 메모리 설계의 목표는 "모델 불가지론적(agnostic) 아키텍처"가 아니라, **모델 버전을 명시적 매개변수로 받아들이는 이식 가능 아키텍처**로 재정의되어야 한다 — [[adema]]류의 아키텍처 자율성 가정과 본 논문의 실증 사이의 긴장이, 앞으로 이 위키에서 메모리 연구의 중심 축이 될 것이다.

## 핵심 통찰

메모리는 저장 계층(비트)과 해석 계층(의미)이 분리되어 있고 해석 계층이 모델 버전에 상대적이므로 저장소가 살아 있어도 메모리는 죽을 수 있으며, 메모리 수명의 보증 주체는 아키텍처 단독이 아니라 '아키텍처 × 모델 라이프사이클'의 결합으로 이동했다.
