## 1. 현재 아키텍처의 단일 신뢰 경계 전제와 그 한계

### [[entities/agentic-harness-engineering.md|agentic harness engineering]]의 모놀리식 전제

Crab 논문에 따르면, C/R 런타임이 하네스의 핵심 구성요소(결함 내성·롤백·분기)를 직접 구현하는 인프라 계층으로 기능합니다. 그러나 이 설명은 **하네스가 관리하는 상태가 단일 신뢰 경계 내에 있다**를 암묵적으로 전제합니다. 체크포인트가 "에이전트 전체 스냅샷"인 이상, 페르소나의 진화 상태와 실행체의 감사 추적 가능 상태가 동일한 스냅샷에 묶이게 됩니다.

### [[concepts/algorithm-system-translation-gap.md|algorithm system translation gap]]이 현현하는 신뢰 경계 침해

이 간극의 본질은 **에이전트의 의미론적 의존 그래프(어떤 상태에 의존하는가)를 OS의 체크포인트 메커니즘(전체 스냅샷)으로 번역할 때 발생하는 비효율**입니다. 여기서 "의미론적 의존 그래프"가 페르소나-실행 분리(PES) 관점에서 재검토되면, 그래프 자체가 **두 개의 독립된 신뢰 도메인에 걸쳐 있는 의존**을 포함하게 됩니다. 단일 스냅샷으로 이를 캡처하는 것은 신뢰 경계를 횡단하는 상태 결합을 영속화하는 결과를 낳습니다.

### [[concepts/agent-os-semantic-gap.md|agent os semantic gap]]의 심화

OS가 제공하는 체크포인트 의미론(프로세스 단위 스냅샷)과 에이전트가 요구하는 의미론(페르소나 상태 vs 실행 상태의 구분) 사이의 간극은, PES가 도입되면 단순한 "비효율"을 넘어 **구조적 불일치**로 격상됩니다. OS는 두 신뢰 도메인의 구분을 모르기 때문입니다.

## 2. [[concepts/agentic-language.md|agentic language]]의 계획 실행에서의 분리 필요성

RunAgent가 자연어 계획을 제약 기반으로 해석하는 과정은, 계획의 "의도(페르소나 영역)"와 "실행(실행체 영역)"이 동일한 언어 표면에 섞여 있다는 전제 위에 서 있습니다.

PES 관점에서 자연어 계획은 사실 **두 가지 독립적 아티팩트**여야 합니다:
- **페르소나 계획**: 어조, 자기표현, 커뮤니케이션 스타일의 진화 방향
- **실행 계획**: 상태 있고 감사 가능한 작업의 순서

이들이 단일 [[concepts/agentic-language.md|agentic language]] 표현으로 통합되면, 페르소나의 자유로운 진화가 실행체의 감사 추적성을 오염시키거나, 반대로 감사 제약이 페르소나 진화를 억제하는 [[concepts/alignment-scope-erosion.md|alignment scope erosion]]이 발생합니다.

## 3. 최소 단위 재정의의 구체적 함의

### 재정의된 최소 단위

| 기존 단위 | 재정의된 단위 | 신뢰 경계 | 핵심 속성 |
|---|---|---|---|
| Agent | Persona | 진화 자유, 무감사 | 지시, 어조, 자기표현 |
| (포함됨) | Executor | 감사 필수, 불변 추적 | 상태 있는 작업, 도구 호출 |

### [[entities/agentic-harness-engineering.md|agentic harness engineering]]의 재구조화

하네스는 더 이상 단일 에이전트를 관리하지 않고, **페르소나-실행체 간의 신뢰 경계 인터페이스**를 관리해야 합니다. 롤백은 실행체 수준에서만 발생해야 하며, 페르소나 상태의 롤백은 의도적 진화의 역사를 훼손합니다.

### [[concepts/checkpoint-restore-efficiency-spectrum.md|checkpoint restore efficiency spectrum]]의 신뢰 경계 축 추가

기존의 효율 스펙트럼은 "얼마나 적은 상태를 캡처하는가"였지만, PES 이후에는 **"어느 신뢰 도메인의 상태를 캡처하는가"**라는 새로운 축이 추가되어야 합니다.

## 4. 새로운 개념 연결 발견

이 분석에서 다음 연결들이 새롭게 드러납니다:

1. **[[concepts/agent-boundary-semantic-collapse.md|agent boundary semantic collapse]] ↔ PES**: 기존에 "에이전트 경계의 의미론적 붕괴"로 기술된 현상이, PES 관점에서는 **"페르소나 경계와 실행 경계가 의미론적으로 구분 없이 붕괴되는 것"**으로 재해석됩니다.

2. **[[concepts/agent-execution-semantic-opacity.md|agent execution semantic opacity]] ↔ PES**: 실행의 의미론적 불투명성은 단순히 "실행이 불투명하다"가 아니라, **"페르소나가 실행의 의미를 투명하게 관찰할 수 있는가"**라는 신뢰 경계 문제로 재구성됩니다. PES에서 페르소나는 실행체의 내부 상태를 직접 관찰하면 안 됩니다.

3. **[[concepts/agent-reliability-auditing.md|agent reliability auditing]] ↔ [[concepts/auditable-gap.md|auditable gap]]**: PES가 요구하는 "실행의 추적 가능성"은 [[concepts/auditable-gap.md|auditable gap]]을 페르소나-실행 분리 차원에서 구체화합니다. 감사 가능한 것은 오직 실행체이며, 페르소나는 감사 대상이 아닙니다.

4. **[[concepts/authority-delegation-topology.md|authority delegation topology]]의 새로운 의미**: 페르소나가 실행체에 작업을 위임하는 토폴로지가, 단일 에이전트 내 위임이 아닌 **신뢰 도메인 간 위임**으로 재설계되어야 합니다.

5. **[[concepts/authority-boundary-penetration.md|authority boundary penetration]]의 방향성 전환**: 기존에는 외부→에이전트 침투에 초점이 있었으나, PES에서는 **페르소나↔실행체 간의 내부 경계 침투**가 새로운 위협 모델이 됩니다.

## 결론

현재 Wiki의 [[concepts/agent-os-semantic-gap.md|agent os semantic gap]], [[entities/agentic-harness-engineering.md|agentic harness engineering]], [[concepts/algorithm-system-translation-gap.md|algorithm system translation gap]], [[concepts/agentic-language.md|agentic language]]는 모두 **에이전트를 단일 신뢰 경계로 전제**하고 설계되었습니다. PES가 이 전제를 해체한다면, 최소 단위의 재정의는 선택이 아니라 필수입니다.

다만, 이 재정의는 단순한 분할이 아닙니다. 페르소나와 실행체 사이에 **어떤 인터페이스 의미론을 둘 것인가**(페르소나가 실행체에 어떤 형태의 지시를 전달하고, 실행체가 어떤 형태의 피드백을 반환하는가)가 새로운 핵심 설계 문제로 부상하며, 이는 기존 Wiki의 어떤 엔티티로도 완전히 커버되지 않는 **새로운 개념 영역**입니다.
