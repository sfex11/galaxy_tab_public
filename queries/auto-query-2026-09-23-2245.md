## 1. 직접적 근거 두 편

### Harness-Zero: Harness Distillation via Agent-as-Harness

- **문제 진술**: "Agent harnesses... can substantially improve agent performance, but **their gains remain tied to the harness at deployment**" — 하네스의 이득이 배포 시점에 외부 시스템에 결합되어 있다는 것을 명시적 한계로 규정한다. 이는 질문이 지적한 "인프라 증폭" 프레임 그 자체다.
- **해법**: 하네스 성능 이득을 **증류(distillation)**하여 모델 자체로 이전한다. 즉, 동일한 성능 이득이 (a) 하네스에 상주하거나 (b) 증류 후 가중치에 상주할 수 있음을 실증한다.
- **핵심 함의**: 경계의 위치가 아키텍처가 강제하는 사실이 아니라, **"증류할 것인가"라는 설계 결정**이 정하는 것이 된다.
- **부수적 발견**: "Agent-as-Harness"라는 역발상 — 에이전트 자신을 증류용 하네스로 사용한다. 하네스가 일방적으로 모델을 감싸는 구조가 아니라, 하네스 층에서 축적된 지능이 모델 안으로 흡수되는 **방향성 역전**을 보여준다.

### RRSI: Regularized Recursive Self-Improvement of Agent Harnesses

- **하네스 정의 확정**: "prompts, control flow, tooling, memory, and context management surrounding the **frozen backbone** model"
- **핵심 함의**: 하네스라는 계층의 존재 자체가 **"백본 동결"이라는 제약의 함수**다. 백본을 업데이트할 수 있다면(증류·학습), 그 제약이 사라지면서 하네스에 뒀던 로직을 가중치로 옮길 자격이 생긴다. Harness-Zero가 바로 그 자격을 행사한 사례.
- RRSI는 하네스 층에서도 정규화된 재귀 개선이 가능함을 보여주므로, **개선 루프 자체도 두 계층 중 어디에든 배치 가능**하다.

## 2. 두 논문의 조합이 보여주는 경계의 이동성

두 논문은 같은 문제 공간의 양 끝을 담당한다:

- **RRSI** = 인프라 쪽에서 능력을 키우는 축 (하네스 층 재귀 개선)
- **Harness-Zero** = 그 산출물을 모델 쪽으로 옮기는 축 (인프라 → 가중치 경계 이동)

즉 "능력 증폭"이라는 동일한 기능이 두 구현 계층 중 하나에 배치될 수 있고, 선택 기준은 필연이 아니라 트레이드오프다:

| 축 | 하네스 층 구현 | 모델 내면화 |
|---|---|---|
| 반복 속도 | 빠름 (재학습 불필요) | 느림 (증류·학습 필요) |
| 이식성 | 낮음 (하네스 결합) | 높음 (단일 모델 배포) |
| 백본 제약 | 동결 유지 가능 | 업데이트 필요 |
| 서빙 부담 | [[aggregate-pipeline-serving]] 등 인프라 오버헤드 | 모델 크기 비용으로 전환 |

이 관점에서 [[agentic-harness-engineering]]은 "하네스 층을 설계 대상으로 다루는 기술"이고, Harness-Zero는 거기에 **"설계 산출물을 가중치로 컴파일"하는 선택지를 추가**한 것으로 읽힌다.

## 3. 단, 이동은 '조건부'다 — 경계가 소거되는 것은 아니다

- 실제 도구 접근, 외부 메모리 저장소, 샌드박스 상태([[agent-sandbox-state-management]])는 본질적으로 외부 자원이라 가중치로 내면화할 수 없다.
- 내면화되는 것은 주로 프롬프트 전략·제어 흐름 휴리스틱 같은 **절차적 지식**으로 추정된다.
- 증류는 본질적으로 손실을 동반하는 변환이다. Harness-Zero가 "distillation"이라는 표현을 쓰는 것은 무손실 이식이 아님을 시사한다.

따라서 정확한 결론은: 경계는 "고정된 선"에서 **"이동 가능하지만 소거되지 않는 경계면"**으로 바뀐다.

## 4. 새로 발견된 연결·개념 (Wiki 미축적분)

1. **[[agentic-distillation]] ↔ Harness-Zero**: 하네스 증류는 에이전트 증류의 하위 유형으로, 상위 개념–하위 사례 관계가 성립한다. 정의 축적 시 연결 가치가 높다.
2. **[[agent-loop-as-computation]] ↔ 증류 = 인라인화**: 에이전트 루프를 계산으로 보면, 하네스 증류는 인프라에서 실행되던 계산을 가중치로 **인라인화하는 컴파일**에 해당한다.
3. **[[agent-native-serving]]과의 긴장**: 하네스가 모델로 흡수되면 서빙 계층의 역할(하네스 실행 환경 제공)이 재정의된다 — 증류는 agent-native serving의 부담 구조를 바꾸는 선행 조건이다.
4. **[[artifact-bound-optimization]]과의 동형성** (스페큘러티브): "gains remain tied to the harness"는 능력이 특정 아티팩트에 결합되는 문제로, artifact-bound-optimization 개념과 구조적으로 유사하다. 정의 축적 후 확인 필요.
5. **제안 엔티티 (아직 위키에 없음)**:
   - `harness-capability-boundary` — 모델 능력과 인프라 증폭의 경계를 설계 시점 선택 변수로 다루는 개념
   - `capability-internalization` — 인프라 계층에 구현된 능력의 가중치 이식 과정

**요약**: RRSI가 "하네스 = 동결 백본 주변의 인프라"라는 정의로 출발점을 확정했다면, Harness-Zero는 그 경계를 증류로 넘을 수 있음을 실증했다. 따라서 질문의 직관대로, 모델 능력과 인프라 증폭의 경계는 아키텍처 사실이 아니라 **최적화 예산·배포 제약·이식성 요구에 따라 배치를 선택하는 이동 경계**이며, 다만 도구·상태 같은 본질적 외부성 때문에 완전히 소거되지는 않는다.

## 핵심 통찰

하네스와 모델 가중치 사이의 경계는 고정된 선이 아니라 증류라는 설계 결정으로 이동 가능한 선택 변수이되, 증류의 본질적 손실과 외부 자원 의존성 때문에 소거되지는 않는다.
