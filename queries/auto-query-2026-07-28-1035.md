## Wiki 답변

# TRACE-ROUTER가 드러내는 두 축 분리 분석의 근본적 한계

## 1. 직교성 가정의 붕괴: 독립 라우팅 ↔ 정적 병목의 상호침투

현재 Wiki에서 [[concepts/adaptive-inference.md|adaptive inference]]와 [[concepts/aggregate-pipeline-serving.md|aggregate pipeline serving]]은 서로 다른 차원의 문제로 분리되어 있다.

- **[[concepts/adaptive-inference.md|adaptive inference]]**는 개별 LLM 호출을 독립적 단위 연산으로 취급하여 최적 모델/전략을 선택하는 문제로 기술된다. SpecKV 논문에서 보듯, 적응의 결정 차원을 모델/라우트 선택에서 추측 길이(γ) 선택으로 **확장**하더라도, 그 적응은 여전히 **단일 호출의 내부 상태**(압축률 등)에 반응할 뿐이다.
- **[[concepts/aggregate-pipeline-serving.md|aggregate pipeline serving]]**는 "Tool Attention Is All You Need" 논문이 보여주듯, 다중 서버 MCP 배포에서 파이프라인 전체의 레이턴시 병목이 **개별 LLM 호출이 아닌 스키마 축적**에 의해 결정된다는 점을 밝히며, 병목을 "정적 구조적 요인"으로 재정의한다.

그런데 TRACE-ROUTER의 지적——*"Existing routers primarily make independent routing"*——은 이 두 축이 실제로는 직교하지 않음을 폭로한다. 스키마 축적량(aggregate-pipeline-serving의 핵심 병목) 자체가 **이전 라우팅 결정의 결과물**이다. 작은 모델을 라우팅한 호출이 불필요한 툴 스키마를 로드하게 만들었다면, 개별 호출 수준의 "최적"이 파이프라인 수준의 "최악"을 낳는다. 즉, 두 축은 분리될 수 없는 **인과 사슬**로 연결되어 있다.

## 2. [[concepts/bottleneck-misattribution.md|bottleneck misattribution]]: 잘못된 추상화 계층에 대한 병목 귀인

이 분리 분석이 은폐하는 가장 위험한 왜곡은 [[concepts/bottleneck-misattribution.md|bottleneck misattribution]]이다.

"Tool Attention" 논문은 병목의 원인을 "스키마 축적"이라는 **파이프라인 구조적 요인**으로 귀인한다. 그러나 TRACE-ROUTER의 관점에서 이 귀인은 불완전하다:

- 스키마 축적량 = f(라우팅 경로 선택, 툴 호출 시퀀스, 이전 호출의 출력 품질)
- 라우팅 경로 선택 = g(개별 호출 단위의 독립적 최적화)

즉, "스키마 축적이 병목이다"라는 진단은 **증상**을 원인으로 간주한 것이다. 진정한 병목은 **개별 호출 단위의 독립적 라우팅이 경로 수준의 의존성을 무시한다는 구조적 결함**에 있다. aggregate-pipeline-serving이 "정적 병목"으로 진단한 것을, TRACE-ROUTER는 "라우팅 경로의 함수로서의 동적 병목"으로 재귀인한다.

## 3. [[concepts/abstraction-layer-mismatch.md|abstraction layer mismatch]]: 최적화 단위의 근본적 오정렬

SpecKV가 적응적 추론의 결정 차원을 "어떤 모델/라우트를 선택할 것인가"에서 "추측 길이 γ를 어떻게 선택할 것인가"로 확장한 것은, 동일한 추상화 계층(단일 호출) 내에서의 차원 확장이었다. CADENCE가 외부 환경에 반응하고 SpecKV가 내부 압축 상태에 반응하더라도, **반응의 단위는 여전히 개별 호출**이다.

TRACE-ROUTER는 최적화가 일어나야 할 추상화 계층이 "호출"이 아니라 **"워크플로우 경로"**임을 보여준다. 이는 [[concepts/abstraction-layer-mismatch.md|abstraction layer mismatch]]——에이전트의 의미론적 의존 그래프(어떤 상태에 의존하는가)를 OS의 체크포인트 메커니즘(전체 스냅샷)으로 번역할 때 발생하는 비효율로 [[concepts/algorithm-system-translation-gap.md|algorithm system translation gap]]이 기술하는 문제와 **동형적 구조**를 공유한다. 단위 연산의 최적화가 상위 계층의 의미론을 보존하지 못하는 간극이 동일한 패턴으로 재현된다.

## 4. 새로운 개념 연결: 워크플로우 수준 라우팅의 부재

TRACE-ROUTER의 지적은 현재 Wiki의 엔티티 스펙트럼에서 **명시적으로 포착되지 않는 간극**을 드러낸다:

| 기존 엔티티 | 포착하는 것 | 포착하지 못하는 것 |
|---|---|---|
| [[concepts/adaptive-inference.md|adaptive inference]] | 단일 호출의 최적 모델/전략 선택 | 호출 간 경로 의존성 |
| [[concepts/aggregate-pipeline-serving.md|aggregate pipeline serving]] | 파이프라인 구조적 병목 (스키마 축적) | 병목 자체가 라우팅 결정의 함수라는 점 |
| [[concepts/agent-native-serving.md|agent native serving]] | 에이전트 워크플로우에 최적화된 서빙 | 경로 의존적 트레이드오프의 온라인 해결 |
| [[concepts/bottleneck-misattribution.md|bottleneck misattribution]] | 병목 원인의 오귀인 | 워크플로우 경로를 최적화 단위로 삼아야 한다는 정언명령 |

TRACE-ROUTER가 요구하는 것은 **"경로 일관적(path-consistent) 온라인 라우팅"**이라는 새로운 최적화 범주다. 이것은 [[concepts/adaptive-inference.md|adaptive inference]]의 "호출 수준 적응"과 [[concepts/aggregate-pipeline-serving.md|aggregate pipeline serving]]의 "파이프라인 수준 정적 최적화" 사이에 존재하는 **빈 축**——**"경로 수준 동적 적응"**——을 요구한다.

## 결론: 두 축의 분석은 "부분 최적의 합이 전체 최적이 아니다"라는 고전적 함정을 재생산한다

[[concepts/adaptive-inference.md|adaptive inference]]가 각 호출을 독립적으로 최적화하고, [[concepts/aggregate-pipeline-serving.md|aggregate pipeline serving]]이 정적 구조적 병목을 해결한다고 할 때, 두 축의 합은 에이전트 워크플로우의 비용-품질 트레이드오프를 보장하지 못한다. TRACE-ROUTER는 이것이 단순한 "미포착 영역"이 아니라, **분리 분석의 방법론 자체가 만들어내는 시각적 맹점**임을 보여준다. 독립 라우팅 가정은 병목의 동적 기원을 은폐하고, 정적 병목 가정은 라우팅의 경로 효과를 은폐한다. 두 가정이 상호 보완적으로 작동하여 **진정한 병목——경로 수준의 라우팅 일관성 부재——을 구조적으로 숨긴다.**

## 핵심 통찰

개별 호출 단위의 독립적 라우팅 가정과 파이프라인 수준의 정적 병목 가정이 상호 보완적으로 작동하여, 진정한 병목인 '경로 수준 라우팅 일관성 부재'를 구조적으로 은폐한다.
