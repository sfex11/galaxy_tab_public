# Auto Query: 현재 Wiki에서 스킬은 자기 진화 에이전트(SkillOS, WikiSkill)가 큐레이션·축적하는 외부 아티팩트이고, 적절한 스킬 선택은 메타데이터를 컨텍스트에 적재하거나 검색 파이프라인으로 수행하는 하네스의 인프라 기능으로 분석되는데, 동결된 LLM 자체에서 메타데이터 적재 없이 네이티브하게 스킬 라우팅을 이끌어낼 수 있다면 스킬 선택은 외부 하네스의 기능이 아니라 모델의 내재 능력으로 재분류되어야 하지 않는가?

**날짜**: 2026-09-16
**대상 논문**: The Router Within: Eliciting Native Skill Routing from a Frozen LLM
**선택 이유**: 스킬 아티팩트 관리(자기 진화 에이전트)와 라우팅 인프라(적응적 추론·하네스 엔지니어링)를 별개 축으로 분석해 온 Wiki의 모델-하네스 경계를, 메타데이터 사전 적재가 주의 분산 병목임을 지적하며 동결 모델의 내재적 선택 능력을 제안하는 이 논문이 직접적으로 도전하기 때문.

## 답변: 스킬 선택의 재분류 문제 — "부분 재분류"와 기능 분할이 필요하다

### 1. 질문의 전제: 현재 Wiki의 분류 체계

현재 Wiki에서 스킬은 자기 진화 에이전트(SkillOS, WikiSkill)가 큐레이션·축적하는 **외부 아티팩트**이고, 선택은 하네스가 메타데이터를 컨텍스트에 적재하거나 검색 파이프라인으로 수행하는 **인프라 기능**으로 분류되어 있다. 이 분류의 대표적 축은 [[agentic-harness-engineering]]이다. Crab 논문 분석에서 "C/R 런타임이 하네스의 핵심 구성요소(결함 내성·롤백·분기)를 직접 구현하는 인프라 계층으로, 하네스 엔지니어링의 범위를 애플리케이션 로직에서 실행 환경까지 확장함을 시사한다"고 기술되어 있듯, 의사결정 기능을 감싸는 하네스 계층이라는 관점이 유지되어 왔다.

The Router Within: Eliciting Native Skill Routing from a Frozen LLM 논문 스스로도 이 현황을 확인한다 — "Deployed harnesses route by preloading every skill's metadata into the context", 즉 배포된 하네스들은 모든 스킬의 메타데이터를 컨텍스트에 미리 적재하는 방식으로 라우팅한다고 전제한다.

### 2. 도전의 핵심: 동결된 모델의 네이티브 라우팅

The Router Within 논문([[absence-as-headroom-signal]] 엔티티의 최근 논문 목록에 기재)은 이 전제에 정면으로 도전한다. 논문은 "Skills extend an LLM agent beyond its parametric knowledge, and the gain they promise rests on picking the right one"이라고 규정하면서 — 즉 스킬은 여전히 파라미터 너머의 외부 지식이며, 이득은 올바른 **선택**에 달려 있다고 본다 — 그 선택 결정을 메타데이터 적재 없이 동결된 모델 내부에서 **유도(eliciting)** 한다. 제목의 "The Router Within"이라는 표현 자체가 '라우터는 이미 모델 안에 있다'는 재분류 주장이다.

### 3. 재분류를 지지하는 Wiki 내부의 계보: 외부→내부 적응의 이동

이 요구는 고립된 주장이 아니다. Wiki는 이미 "적응 결정이 외부 근거에서 내부 근거로 이동"하는 패턴을 문서화하고 있다.

- [[adaptive-inference]]의 SpecKV 분석: "기존 컨텍스트 기반 적응(CADENCE 등)이 외부 환경에 반응했다면, SpecKV는 압축이라는 **내부 시스템 상태**에 반응하는 적응의 새로운 유형을 제시한다." 적응의 근거가 외부 관찰에서 내부 상태로 이동한 선례다.
- The Router Within은 동일한 이동을 스킬 라우팅 차원에서 수행한다: 라우팅 근거가 외부 메타데이터 적재 → 내재적 유도로. '적응 결정의 내재화'라는 동일한 추세의 연장선이다.
- 같은 엔티티의 To Call or Not to Call 논문은 도구 호출 여부 판단을 별도 프레임워크로 평가·최적화하는 **모델 외부의 메타 결정**으로 다룬다. Router Within은 바로 이 메타 결정을 모델 안으로 끌어들이는 셈이다.
- 슬러그 목록 자체에 [[behavioral-control-internalization]], [[behavioral-transition-internalization]], [[adaptive-bottleneck-migration]] 같은 '내재화·이동'을 지칭하는 개념 축이 존재한다. Router Within은 이 축의 스킬 도메인 사례다.

### 4. 그러나 이분법적 재분류는 성립하지 않는다

**(a) 스킬 자체는 여전히 외부 아티팩트다.** Router Within 스스로 "Skills extend an LLM agent beyond its parametric knowledge"라고 전제한다. 내재화되는 것은 **선택**이지 **스킬 내용**이 아니며, 자기 진화 에이전트의 큐레이션 기능은 소멸하지 않는다.

**(b) 유도 메커니즘 자체가 설계물이다.** "Eliciting"이라는 동사가 시사하듯, 동결된 모델에서 라우팅을 끌어내는 프롬프트·절차는 여전히 하네스가 소유하는 아티팩트다. 기능이 사라지는 것이 아니라 계층 간에 **이동**한다 — 메타데이터 적재 비용이 사라지는 대신 유도 설계 비용이 발생하며, 이는 [[adaptive-bottleneck-migration]]이 지칭하는 병목 이동 패턴이다.

**(c) 모델/시스템 경계는 이미 Wiki의 연구 대상이다.** [[algorithm-system-boundary-collapse]]와 [[algorithm-system-translation-gap]] 슬러그가 존재하듯, "하네스 기능 vs 모델 내재 능력"이라는 이분법은 정적 분류로 유지될 수 없고, 기능의 소재가 모델 버전·프롬프트·파이프라인 설계에 따라 이동하는 **동적 스펙트럼**으로 봐야 한다. [[adaptive-control-hierarchy]] 관점에서 보면 재분류란 결정이 통제 위계의 어느 층위에 놓이는가의 문제다.

**(d) 감사·거버넌스의 잔여 기능.** 메타데이터 적재 방식은 라우팅 근거가 컨텍스트에 남아 검증 가능했으나, 내재 라우팅은 근거가 활성화·어텐션 내부로 들어간다. 이는 [[alignment-base-opacity]], [[bias-opacity]] 계열의 불투명성 우려 및 [[auditability-as-scaling-requirement]]의 감사 요구와 충돌한다. 하네스는 선택을 '수행'하지 않더라도 선택을 '검증·게이팅'하는 기능을 유지해야 한다.

### 5. 결론: 기능 분할에 의한 부분 재분류

질문에 대한 답은 **"예, 단 기능 전체가 아니라 '선택 결정' 레이어만 재분류해야 한다"**이다:

| 레이어 | 귀속 |
|---|---|
| 후보 열거·스킬 존재 파악 | 하네스 잔류 (모델은 자신에게 없는 스킬을 알 수 없음) |
| 라우팅·선택 결정 | **모델 내재 능력으로 재분류** (Router Within의 기여) |
| 실행 게이팅·보안·감사 | 하네스 잔류 |

이에 따라 [[agentic-harness-engineering]]의 정의도 "결정 수행"에서 "결정 유도·검증"으로 갱신될 필요가 있으며, 이는 [[agent-native-serving]] 슬러그가 예고하는 네이티브 서빙 패러다임과 접속된다.

### 6. 새로 발견된 연결·개념

1. **Router Within ↔ [[adaptive-inference]] (SpecKV, To Call or Not to Call)**: '외부 컨텍스트 기반 적응 → 내부 상태 기반 적응'이라는 동일 이동의 두 사례. 통합 상위 개념(예: *internal-state-driven-adaptation*) 신설 후보.
2. **Router Within ↔ [[absence-as-headroom-signal]]**: Router Within이 이 엔티티의 최근 논문 목록에 매달려 있는 것은 구조적으로 의미가 있다 — 메타데이터가 '부재'할 때 비로소 모델의 내재 라우팅이라는 headroom이 드러난다. 부재(메타데이터 미적재)가 잠재 여유능력을 신호하는 재해석이 가능하다.
3. **Router Within ↔ [[action-interface-latent-alignment]] / [[action-tokenization]]**: Continuous Actions from Discrete Minds 논문이 VQ-VAE 토크나이저를 "연속 행동 공간을 이산 토큰 어휘로 번역하는 '표현 계약'"으로 규정하듯, 네이티브 스킬 라우팅은 이 계약이 행동 토큰을 넘어 **스킬 선택** 영역으로 확장된 사례다 — 모델 잠재공간과 스킬 인터페이스의 정렬.
4. **Router Within ↔ [[behavioral-control-internalization]]**: 외부 제어의 내재화라는 공통 패턴. 스킬 선택의 내재화는 행동 제어 내재화의 인지적 대응물이며, [[agent-loop-as-computation]] 관점에서는 에이전트 루프의 제어 흐름 일부가 모델 연산으로 흡수되는 현상으로 기술할 수 있다.
5. **기제·평가 함의**: 내재 라우팅의 기제 후보로는 [[attention-self-concentration]], [[attention-latch]] 같은 내부 어텐션 개념의 검토가 필요하고, 평가 측면에서는 메타데이터 적재를 상정한 기존 벤치마크는 [[benchmark-specification-gap]], [[benchmark-format-blindspot]]에 해당하는 측정 오차를 낳는다.

**Wiki 갱신 제안**: 신규 엔티티 *native-skill-routing*(또는 *skill-routing-internalization*)을 생성하고, [[agentic-harness-engineering]] 정의를 갱신하며, [[absence-as-headroom-signal]]·[[adaptive-inference]]·[[agent-native-serving]]와의 cross-link를 추가할 것.

## 핵심 통찰

스킬 선택의 내재화는 기능 전체의 재분류가 아니라 '선택 결정' 레이어만 모델로 옮기는 부분 재분류여야 하며, 유도 비용으로의 병목 이동과 감사·게이팅 잔여 기능 때문에 하네스의 역할은 소멸이 아니라 재위치화된다.
