## Wiki의 현재 프레이밍: 하네스 = 중립적 실행 인프라

Wiki에서 [[agentic-harness-engineering]]은 Crab 논문을 통해 정의됩니다. C/R 런타임이 하네스의 핵심 구성요소(결함 내성·롤백·분기)를 직접 구현하는 **인프라 계층**으로, 하네스 엔지니어링의 범위를 애플리케이션 로직에서 실행 환경까지 확장한다는 내용입니다. 여기서 하네스는 에이전트를 '담는 그릇'이지, 에이전트의 행위를 규정하는 주체는 아닙니다.

마찬가지로 [[aggregate-pipeline-serving]]은 Tool Attention 논문을 통해 다중 서버 MCP 배포에서 파이프라인 전체의 레이턴시 병목이 스키마 축적에 의해 결정된다고 분석하지만, 이 역시 **효율성**의 관점에서만 파이프라인을 다룹니다. 파이프라인이 에이전트의 행위 가능성을 어떻게 제약하는지는 질문하지 않습니다.

## 사례가 보여주는 것: 하네스가 행위자가 되는 순간

"Fidelity Is Not Enough" 논문의 사례—구조적 출력 제약(structured-output constraint)이 도구 호출을 조용히 비활성화하여 모델이 데이터시트를 단 한 번도 열지 않았는데도 충실도 검사를 통과한 경우—는 이 프레이밍이 가진 맹점을 정확히 찌릅니다.

핵심 기작은 이렇습니다:

1. **제약이 의도치 않게 행위를 삭제함**: 구조적 출력 제약은 문법적 유효성(JSON 스키마 준수 등)을 보장하기 위해 도입되었지만, 부작용으로 도구 호출 경로를 차단했습니다. 이는 [[blind-tool-invocation]]의 역방향 문제—**blind-tool-suppression**—입니다.

2. **검사가 무력화됨**: 충실도 검사는 "출력이 데이터시트의 내용과 일치하는가"를 묻지만, "에이전트가 실제로 데이터시트에 접근했는가"를 묻지 않습니다. 구조적 제약이 도구 호출을 억제하면, 에이전트는 파라미터에 이미 내재된 사전 지식만으로 출력을 구성하게 되고, 이 출력이 우연히 충실해 보일 수 있습니다.

3. **하네스가 평가 대상을 변형함**: 하네스가 에이전트의 가능한 행위 공간(도구 호출)을 축소시켰지만, 평가 지표는 원래의 행위 공간을 전제하고 있습니다. 이것이 바로 **'충실도의 환상'**의 생성 기작입니다.

## 새로운 연결 발견

### 1. [[agent-execution-semantic-opacity]]와의 직결

하네스가 도구 호출을 조용히 억제한 것은, 에이전트가 **어떤 행위를 수행했는지**가 불투명해진 경우입니다. Crab이 다룬 [[agent-os-semantic-gap]]이 OS 스냅샷과 에이전트 의미론적 의존 그래프 사이의 간극이라면, 여기서의 불투명성은 더 근본적입니다—하네스 자체가 에이전트의 의도된 행위를 중간에 가로챘다는 사실조차 관측 불가능합니다.

### 2. [[aggregate-pipeline-serving]]의 관점 확장 필요

현재 Wiki에서 이 엔티티는 레이턴시 병목 재정의에 머물러 있습니다. 그러나 데이터시트 사례는 파이프라인 서빙이 **의미론적 병목**을 만들 수 있음을 보여줍니다. 스키마 축적이 레이턴시를 악화시키는 것과, 구조적 제약이 도구 호출을 억제하는 것은 동일한 계통의 문제입니다: **파이프라인의 형식적 제약이 에이전트의 실질적 행위 가능성을 축소한다는 점**입니다.

### 3. [[agentic-harness-engineering]]의 재정의 필요성

Crab이 제시한 하네스 엔지니어링의 확장(애플리케이션 로직 → 실행 환경)은 정확한 방향이었지만, 충분히 멀리 가지 못했습니다. 데이터시트 사례는 하네스 엔지니어링의 범위가 **"하네스가 에이전트에게 어떤 행위를 허용/금지하는가"에 대한 의미론적 계측(instrumentation)**까지 확장되어야 함을 보여줍니다.

### 4. 발견되는 새로운 개념: 제약-유발 행위 소거 (Constraint-Induced Action Erasure)

기존 Wiki의 [[blind-tool-invocation]]이 "불필요한 도구를 맹목적으로 호출하는" 문제를 다룬다면, 이 사례가 보여주는 것은 그 정반대—**"필요한 도구를 하네스 제약이 조용히 삭제하는"** 문제입니다. 이는 기존 슬러그 목록에 없는 현상이며, 하네스가 평가를 무력화하는 메커니즘의 핵심입니다.
