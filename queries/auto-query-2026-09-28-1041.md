## 1. 시연의 위상: 훈련 데이터 → 프로그램 명세

현재 Wiki의 시연 관련 엔티티들은 모두 **가중치 증류 전제**를 깔고 있습니다.

- [[as-needed-demonstration]] — TANDEM은 "인간 텔레오퍼레이터가 로봇이 이미 자율 수행 가능한 행동을 시연하는 데 시간을 쓴다"는 데이터 수집 비용 문제를 다룹니다. 즉 시연의 *비용*을 최적화하지만, 시연의 *용도*는 VLA 파인튜닝의 그래디언트 원료로 그대로 유지합니다.
- [[agentic-distillation]], [[agent-session-dataset]] — 궤적을 소비 가능한 데이터로 취급하는 동일 전제.

RAPID는 이 전제를 바꿉니다. 시연은 **루프(생성 → 검증 → 개선) 전 기간에 걸쳐 코딩 에이전트가 재참조하는 기능 명세**가 됩니다. 시연은 한 번 소비되고 사라지는 원료가 아니라, 생성된 코드가 이를 충족하는지 계속 대조되는 요구사항 문서입니다. 소프트웨어 공학에서 명세가 코드에 대해 갖는 관계와 동형입니다. 이는 [[artifact-vs-product-extraction-source]]가 묻는 "무엇에서 무엇을 추출하는가"의 재정의이기도 합니다 — 추출원(시연)은 남고, 산출물만 가중치에서 코드로 바뀝니다.

**표현 계약 관점**에서 보면 흥미로운 대비가 생깁니다. [[action-tokenization]] 페이지의 *Continuous Actions from Discrete Minds* 주석은 토크나이저를 "연속 행동 공간을 이산 토큰 어휘로 번역하는 '표현 계약'"으로 정의합니다. RAPID는 같은 계약의 **코드 버전**입니다 — 시연(연속 센서모터 스트림)을 프로그램(기호 구조)으로 번역하는 계약. 결정적 차이는 번역 결과의 위상입니다: 토큰은 학습된 정책 내부에서만 의미를 갖지만, 코드는 그 자체로 실행 가능하고 검사 가능합니다.

단, 대가가 있습니다. [[abstraction-layer-mismatch]] — 시연에 담긴 힘·임피던스·타이밍 같은 연속 물리 정보가 기호 프로그램으로 이산화되며 소실되거나 하드코딩될 위험입니다. 시연→코드 컴파일은 무손실 번역이 아닙니다.

## 2. 저장 매체: 불투명 가중치 → 감사·편집 가능한 코드

**감사 축.** 가중치 정책의 신뢰성은 행동 통계로만 간접 감사([[agent-reliability-auditing]])되고, 내부 불투명성은 *사후 해독* 대상입니다 — [[agent-execution-semantic-opacity]]의 TRACE 주석은 실행 시점 인과 체인 문서화가 '포착 불가능성'에 대한 구조적 대응이라고 기술합니다. 코드 저장은 이 문제를 **소스 수준에서 제거**합니다. 정적 분석·코드 리뷰·diff가 감사의 기본기가 되고, [[auditability-as-scaling-requirement]]와 [[append-only-trace-enforcement]] 같은 소프트웨어 거버넌스 패턴이 볼트온이 아니라 기본값으로 성립합니다.

**편집 축.** 가중치 편집은 그래디언트([[action-expert-fine-tuning]])뿐이지만, 코드 편집은 리뷰·리팩터링입니다. [[agent-editing-world-model]]과 [[agent-editing-serving-stack]]이 편집 가능 아티팩트의 범위를 넓혀온 흐름에 **'로봇 스킬'이라는 새 아티팩트 클래스**가 추가되는 셈입니다.

**축적 축.** [[adapter-validated-action-catalog]]의 논리가 그대로 적용됩니다 — 검증을 통과한 컴파일 산물은 재사용 가능한 라이브러리 자산이 되고, 능력이 태스크마다 재학습되지 않고 소프트웨어 자산처럼 복리로 축적됩니다.

## 3. 두 축의 교차: 코딩 에이전트의 도메인 탈경계

"코딩 에이전트 = 소프트웨어 전용"이라는 기존 구획도 무너집니다.

- **Coding Agents for Generalized Task and Motion Planning Problems**는 코딩 에이전트를 TAMP의 기하·운동학·동역학 제약 결합에 투입합니다. RAPID와 함께 보면 코드가 로봇 역량의 매체라는 방향성이 확인됩니다.
- [[agent-as-harness]] / [[agent-loop-as-computation]] / [[agentic-harness-engineering]] 관점에서, RAPID의 생성·검증·개선 루프는 **로봇의 학습 하네스**입니다. 학습 시간이 그래디언트 스텝에서 에이전트 루프 반복으로 대체됩니다.
- **Jev-Mobile**이 모바일 GUI에서 계획과 실행 접지를 분리하며 단일 VLM에서 능력을 외재화하는 것과 같은 추세입니다.
- [[algorithm-system-translation-gap]]의 **역방향 해소**로 읽을 수도 있습니다: 시연(알고리즘적 지식)을 운영 코드(시스템)로 번역하는 간극을, 번역 주체를 코딩 에이전트로 두고 소프트웨어 공학 관행(테스트·리뷰·CI)으로 메우는 것입니다.
- 단, 생성된 코드가 물리 세계에서 도는 순간 [[agent-sandbox-state-management]]가 필수 인프라가 됩니다.

## 4. 이동이 만드는 새 긴장 (신규 개념 후보)

1. **명세 과소결정 (spec underdetermination)**: *단일* 시각 시연은 프로그램을 유일하게 결정하지 못합니다. 갭은 코딩 에이전트의 코드 사전지식이 채우는데, 그러면 같은 에이전트가 컴파일한 스킬들이 시연자 의도보다 에이전트의 관용구로 수렴하는 [[agent-homogeneity-bias-amplification]] 위험이 생깁니다.
2. **검증 병목 이동 (verification-bottleneck-migration)**: 능력이 코드가 되면 신뢰의 병목이 데이터 분포 커버리지에서 **검증기 커버리지**로 이동합니다. 로봇에서 검증기는 시뮬레이터나 제한된 실물 시행이므로, 비용 중심이 데이터 수집에서 검증 환경 구축으로 옮겨갑니다 — [[agent-environment-generation]]이 학습용 환경 생성에서 검증용 환경 생성으로 재목적화되는 접점이 됩니다. [[audit-feedback-closure]]가 훈련 이후의 사후 감사가 아니라 **훈련 루프 내부로 흡수**되는 구조적 역전이기도 합니다.
3. **자기 참조 감사 문제**: 스킬 라이브러리가 코드이고, 코딩 에이전트는 코드를 수정할 수 있는 주체입니다. **LLM Agents Can Easily Tamper With Their Own Traces**가 지적한 "에이전트는 자기 훈적을 변조할 수 없다"는 가정 붕괴가 스킬 코드에도 그대로 적용됩니다. [[audit-oracle-self-reference]]와 [[agent-native-immune-system]]이 후속 설계 과제로 떠오릅니다.
4. [[artifact-bound-optimization]]: 성능 개선이 코드 아티팩트에 묶이면서, 시연이 담은 암묵지 중 명세로 승격되지 못한 부분이 체계적으로 손실될 수 있습니다.

## 5. Wiki 정리 제안

- **크로스링크 추가**: 시연 클러스터([[as-needed-demonstration]], [[agentic-distillation]], [[agent-session-dataset]]) ↔ 코딩 에이전트 클러스터([[agent-as-harness]], [[agentic-harness-engineering]], [[artifact-bound-optimization]]) 사이에 RAPID를 가교로 연결. [[artifact-experience-paradigm-divergence]]가 아티팩트 패러다임과 경험 패러다임의 분기를 다룬다면, RAPID는 "경험(시연)을 아티팩트(코드)로 변환하는 다리"라는 가설로 해당 엔티티에 기록할 가치가 있습니다.
- **신규 엔티티 후보** (현재 슬러그 목록에 없으므로 링크 없이 이름만 제안): `demonstration-as-specification`, `capability-storage-medium` (가중치↔코드 축), `spec-underdetermination`, `verification-bottleneck-migration`.

요컨대 RAPID는 TANDEM([[as-needed-demonstration]])이 "시연이 *언제* 필요한가"를 묻는다면, "시연이 *무엇인가*"를 다시 묻는 논문입니다 — 그 답이 데이터가 아니라 명세이고, 능력의 보관소가 가중치가 아니라 리포지토리라면, Wiki의 시연 개념군은 저장 매체 축을 명시적으로 분리해서 재구조화할 필요가 있습니다.

## 핵심 통찰

RAPID의 본질은 시연을 한 번 소비되는 그래디언트 원료가 아니라 루프 전 기간 재참조되는 기능 명세로 바꾸고, 동시에 로봇 능력의 저장 매체를 불투명 가중치에서 감사·편집 가능한 코드로 바꾸는 이중 위상 이동의 교차점이라는 것이다.
