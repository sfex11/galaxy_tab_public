## 판정 요약

질문의 직관 — '적응 방향의 역전'과 '모델 귀인의 재검토' — 는 위키에 이미 흩어져 있는 근거들로 **상당 부분 정당화된다**. 다만 "GUI 실패의 상당 부분이 구조적 인공물"이라는 주장은 전면 채택이 아니라 **귀인 분해 가설**로 정식화할 때 비로소 검증 가능해진다. 위키는 그 분해의 해부학적 도구([[concepts/access-planning-gap.md|access planning gap]])와 설계 시점 해법의 선례([[concepts/agent-execution-semantic-opacity.md|agent execution semantic opacity]], [[concepts/agent-os-semantic-gap.md|agent os semantic gap]])를 이미 보유하고 있다.

## 1. 위키의 현재 분류는 사실 '시점'이 다른 두 축의 혼재다

- GUI 실패 진단(기획적 간극, 표현-행동 불일치)은 **배포 시점 인터페이스 적응** 문제고, 에이전트 환경 생성([[concepts/agent-environment-generation.md|agent environment generation]])은 **학습 시점 무대 구축** 문제다. Nemobot Games 주석이 보여주듯 현재 환경 생성은 "Gym-Anything의 범용 소프트웨어→환경 변환"과 게임 특화 경로의 스펙트럼 확장, 즉 학습 스테이징에 머물러 있다.
- 그러나 위키 내부를 보면 **환경이 에이전트를 향해 적응하는 축이 이미 세 층위로 분화**되어 있다:
  1. **학습 시점**: [[concepts/agent-environment-generation.md|agent environment generation]] (Nemobot Games)
  2. **런타임**: [[concepts/agent-os-semantic-gap.md|agent os semantic gap]] — Crab은 체크포인트/복원 런타임이 에이전트의 의미 구조를 존중하도록 OS 쪽이 양보하는 설계
  3. **설계 시점**: [[concepts/agent-execution-semantic-opacity.md|agent execution semantic opacity]] — TRACE는 에이전트 실행의 의미적 불투명성을 사후에 해독하지 않고 "실행 시점에 인과 체인을 문서화하여 원천적으로 회피"하며, 위키 스스로 이를 "포착 불가능성 진단에 대한 최초의 구조적 대응"으로 기록

즉 질문이 상정하는 역전은 미래의 가정이 아니라 **위키 안에서 이미 진행 중인 흐름**이며, '이중 독자 인터페이스'는 그 세 번째 층위(설계 시점)의 일반화다.

## 2. 최근 유입 논문은 역전을 이미 정례화하고 있다

- **Affora: A Design System for Agent-Friendly Interfaces**(최근 논문): "Computer-use agents increasingly operate software designed for people, but interfaces often leave actions or task state unclear to machine readers" — GUI 실패의 1차 원인을 인터페이스 쪽에 명시적으로 배치하고 사람+기계 이중 독자용 설계 시스템을 제시한다. 질문의 전제를 논문 차원에서 이미 실행한 사례다.
- **Design Docs Are All You Need**([[concepts/abstraction-layer-mismatch.md|abstraction layer mismatch]] 경유): AI-native 엔지니어링에서 문서·아티팩트가 기계 독자 우선으로 재설계된다. 이를 [[concepts/ai-native-software-lifecycle.md|ai native software lifecycle]] 축과 연결하면 '인간 전용 → 이중 독자' 전환은 개별 UI 문제가 아니라 **소프트웨어 생애주기 전반의 방향 전환**으로 확장된다.
- 슬러그 목록에 [[concepts/ai-artifact-design.md|ai artifact design]]가 존재한다는 사실 자체가, 위키가 '아티팩트 설계'를 독립 개념으로 수용하기 시작했음을 시사한다.

## 3. 재귀인의 형식적 경로: 표현 계약

[[concepts/action-tokenization.md|action tokenization]]의 Continuous Actions from Discrete Minds 주석이 결정적이다: "토크나이저 설계가 곧 물리 제약의 인코딩 방식을 결정" — 인터페이스는 중립적 통로가 아니라 **표현 계약**이다. 인간용 GUI는 상태를 시각 레이아웃으로 압축해 기계 독자에게 정보 손실을 강제하는 계약이고, 이 계약 하에서 관측 불가능한 것은 모델 오류로 기장된다. 이중 독자 설계는 계약 재협상이므로, '모델 능력 부족'으로 분류된 실패가 '인코딩 손실'로 재분류되는 것은 개념적으로 자연스럽다. [[concepts/action-interface-latent-alignment.md|action interface latent alignment]]도 액션 인터페이스를 모델 잠재 공간에 정렬한다는 이름 자체가 인터페이스→모델 방향의 정렬을 표방한다.

## 4. 그러나 귀인은 분해되어야 한다 — access-planning-gap의 해부학

Near-Optimal RL with Multi-Step Transition Lookahead([[concepts/access-planning-gap.md|access planning gap]])는 "ℓ-스텝 예지 접근이 관측 데이터를 제공해도, 이를 최적 결정으로 번역하는 것이 구조적으로 어려운 영역이 존재"함을 계산 복잡도로 규명한다. GUI에 사상하면:

- 이중 독자 인터페이스가 제거하는 것은 **접근·관측 측 실패**(상태 불명료, 액션 불명시 — Affora의 진단 영역)다.
- **계획 측 실패**(장기 의존성, 탐색 난이도)는 인터페이스가 아무리 친화해도 잔존한다.

따라서 올바른 정식화는 "GUI 실패의 상당 부분이 인공물이다"가 아니라 **"GUI 실패를 (i) 관측 인공물 (ii) 표현 계약 손실 (iii) 고유 계획 난이도의 세 성분으로 분해하고, (i)·(ii)의 비중이 통상 귀인보다 크다는 가설을 검증하라"**이다.

## 핵심 통찰

GUI 실패 귀인을 '모델 능력'에서 관측 인공물·표현 계약 손실·고유 계획 난이도의 세 성분 분해로 옮기는 순간, 이중 독자 인터페이스는 미래 가정이 아니라 이미 진행 중인 환경→에이전트 적응 축의 설계 시점 층위 일반화로 자리 잡는다.
