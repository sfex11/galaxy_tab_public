## Wiki가 제시하는 병목 진단의 원점

Wiki에서 [[aggregate-pipeline-serving]]은 *"Tool Attention Is All You Need: Dynamic Tool Gating and Lazy Schema Loading"* (2026-04-26)을 인용하며, 다중 서버 MCP 배포에서 **파이프라인 전체 레이턴시 병목이 개별 LLM 호출이 아닌 스키마 축적에 의해 결정된다**고 진단합니다. 이는 파이프라인 서빙 최적화의 실제 병목 지점을 '모델 추론'에서 '스키마 로딩'으로 재정의하는 기여를 합니다.

그러나 질문자가 지적하는 핵심은 이 재정의가 여전히 **표층적 병목**에 머물러 있다는 점입니다.

## 질문자의 논점이 Wiki 엔티티들과 교차하는 지점

### 1. [[bottleneck-misattribution]]과의 구조적 유사성

Wiki 슬러그 목록에 존재하는 `bottleneck-misattribution`은 병목을 잘못 귀인하는 현상을 지칭하는 엔티티입니다. [[aggregate-pipeline-serving]]이 "스키마 축적이 병목"이라고 진단한 것 자체가, 더 근본적인 원인인 **파서가 이미 예측한 구조 정보가 KV 관리에 조건화되지 않는 간극**을 은폐하는 2차적 오귀인일 수 있습니다. 스키마 축적은 증상이지 원인이 아닙니다.

### 2. [[algorithm-system-translation-gap]]의 패턴과의 정합

[[algorithm-system-translation-gap]]에서 *"Crab: A Semantics-Aware Checkpoint/Restore Runtime for Agent Sandboxes"* (2026-05-02)는 **에이전트의 의미론적 의존 그래프를 OS의 체크포인트 메커니즘(전체 스냅샷)으로 번역할 때 발생하는 비효율**을 이 간극의 본질로 규정합니다.

질문자의 관점은 동일한 패턴의 다른 현현입니다:
- **Crab의 경우**: 의미론적 의존 그래프 → OS 스냅샷 (간극)
- **질문자의 경우**: 제약 디코딩 파서의 전이 구조 → KV 캐시 지속성 결정 (간극)

둘 다 **상위 레벨에서 이미 계산된 구조적 정보가 하위 시스템의 관리 결정에 번역되지 않는다**는 동일한 간극 구조를 공유합니다.

### 3. [[adaptive-inference]]와 SpecKV의 시사점

[[adaptive-inference]]에서 *"SpecKV: Adaptive Speculative Decoding with Compression-Aware Gamma Selection"* (2026-05-05)는 적응적 추론의 결정 차원을 **외부 환경 반응(CADENCE 등)에서 내부 시스템 상태(압축) 반응으로 확장**합니다.

질문자의 제안은 이를 한 단계 더 밀어붙이는 것입니다: 적응의 입력을 **파서가 예측한 생성 구조**로 확장하는 것입니다. SpecKV가 압축 상태라는 내부 신호에 반응한다면, 파서 전이가 예측하는 구조적 진행도 역시 동등한 내부 신호로 활용 가능하다는 논리입니다.

## 새로운 연결로서 명시해야 할 점

### 발견된 새로운 개념 연결: **파서-캐시 조건화(parser-cache conditioning)**

Wiki에 현재 이 개념을 포괄하는 엔티티는 없습니다. 기존 엔티티들의 조합으로 설명되지만 자립적 슬러그로 존재하지 않는 새로운 연결입니다:

> 제약 디코딩의 파서 전이가 생성 구조를 예측하므로, 이를 KV 지속성 결정에 조건화하여 불필요한 캐시를 드롭하는 메커니즘.

이는 다음 세 엔티티의 교집합에 위치합니다:
- [[aggregate-pipeline-serving]]: 스키마 축적이 파이프라인 병목이라는 진단
- [[algorithm-system-translation-gap]]: 상위 구조 정보가 하위 시스템 관리에 번역되지 않는 간극
- [[adaptive-inference]]: 내부 시스템 상태에 반응하여 추론을 적응시키는 패러다임

### [[bottleneck-transference]]의 예상 기작

슬러그 목록에 존재하는 `bottleneck-transference`와도 관련이 있습니다. Wiki가 스키마 축적을 병목으로 지적하면, 자연스럽게 **"스키마 로딩을 최적화하자"**는 방향으로 해법이 수렴합니다. 그러나 질문자의 논지에 따르면, 이는 병목을 **제거**한 것이 아니라 다른 형태로 **전이**시킨 것에 불과할 수 있습니다 — 스키마 로딩 병목은 줄었지만, 파서가 이미 가진 구조 정보를 버리고 KV 캐시를 무조건 유지하는 비효율이 잔존합니다.

## 결론

Wiki의 [[aggregate-pipeline-serving]] 진단은 1차 재정의로서 의미가 있지만, 질문자의 지적대로 **진정한 공격면은 외부 스키마 로딩이 아니라 파서-모델 간 구조적 가시성의 미활용**에 있습니다. 이는 [[algorithm-system-translation-gap]]이 Crab 사례에서 보여준 간극 패턴의 새로운 현현이며, [[adaptive-inference]]의 SpecKV가 보여준 '내부 상태 기반 적응'을 파서 구조 예측이라는 추가 차원으로 확장해야 한다는 논점입니다.

다만, 이 구체적 메커니즘(파서 전이 → KV 지속성 조건화)을 직접 검증한 논문은 현재 Wiki에 없으므로, 이는 **새로운 연결**로 기록되어야 합니다.
