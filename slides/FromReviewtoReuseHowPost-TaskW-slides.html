From Review to Reuse

사후 작업 워크플로우가 인간-AI 에이전트 상호작용을 지원하는 방법

완료된 AI 에이전트 실행을 검토 가능하고 재사용 가능한 워크플로우로 변환하는 Trace2Flow 연구

Post-Task Workflow Trace2Flow N = 20 사용자 연구

배경: 자동화는 사용자의 역할을 바꿉니다

AI 에이전트는 단일 자연어 요청을 도구·파일·애플리케이션에 걸친 다단계 프로세스로 자동화합니다. 그러나 자동화는 사용자의 역할을 없애는 것이 아니라 "수행"에서 "감독"으로 전환시킵니다.

위임

사용자는 상위 목표만 프롬프트로 지정

다단계 실행

에이전트가 추론·도구 호출·앱 간 작업 수행

감독의 부담

의도 해석 확인, 행동·출력 검증, 오류 식별

문제: 파편화된 실행 정보

기존 에이전트 인터페이스는 실행 아티팩트(행동 트레이스, 도구 호출, 중간 출력)를 노출하지만, 사용자는 흩어진 정보를 스스로 연결해야 합니다.

  • 최종 출력만으로는 프로세스 전체를 판단하기 어려움
  • 개별 결정·출력의 해석 가능성 연구는 많지만, 종단 간 워크플로우 구조를 표현하는 방식은 미지의 영역
  • 완료된 실행을 재사용하는 방법에 대한 탐구도 부족

핵심 질문: 완성된 에이전트 실행을 어떻게 표현해야 인간의 감독을 지원할 수 있는가?

제안: 사후 작업 워크플로우(Post-Task Workflow)

에이전트의 완료된 실행을 나타내는 편집 가능한 그래프 기반 표현 — 규범적(prescriptive) 사양이 아닌 기술적(descriptive) 아티팩트

  Looking Backward (과거 돌아보기)

  • 프롬프트가 어떻게 구체적 행동으로 변환되었는지 이해
  • 결정과 출력 검증
  • 수정이 필요한 오류 위치 파악

  Looking Forward (미래 내다보기)

  • 검증된 프로세스의 재사용
  • 관련 작업을 위한 적응·편집
  • 유사 작업 자동화 시 프로세스 조정

  상위 프롬프트의 유연성은 유지하면서, 행동·중간 산출물·의존성을 일관된 형태로 구조화

연구 질문

RQ1

사후 작업 워크플로우 표현은 사용자가 에이전트가 무엇을 했는지 이해하고, 작업 결과를 검증하며, 실행 오류를 식별하는 데 어떻게 도움이 되는가?

RQ2

관련된 후속 작업에 대해 사용자는 기존 워크플로우를 재사용·적응하는 것과 프롬프팅으로 에이전트에게 다시 위임하는 것 중 어느 쪽을 선호하는가?

3. Trace2Flow: 연구 프로브 시스템

완료된 프롬프트 기반 에이전트 실행 트레이스를 편집·실행 가능한 대화형 워크플로우로 변환

  채팅 인터페이스

자연어 프롬프트로 작업을 위임하는 익숙한 상호작용 방식

  워크플로우 캔버스

작업 연산·도구 사용·AI 지원 연산과 의존 관계를 노드·엣지 그래프로 시각화

트레이스 → 워크플로우 변환 과정

1
Grounding
실행 트레이스의 정보를 기반 구조에 연결
2
Generation

3
Compilation
실행 가능한 워크플로우로 컴파일

  참가자

내 참가자(within-participant) 설계

  작업 세트

프롬프트 오류 및 에이전트 오류를 포함한 작업 쌍

n8n 분석 기반으로 작업 구성

두 가지 활동

A
완료된 실행 검토·검증 — 프롬프트 전용 조건 vs. 사후 워크플로우 조건에서 에이전트 실행을 이해하고 오류를 탐지
B
후속 작업 수행 — 워크플로우 재사용·적응 vs. 이전 프롬프트 적응 후 재위임

결과 1: 검토 — 이해와 오류 탐지 (RQ1)

  실행 프로세스에 대한 이해

  • 사후 워크플로우가 출력 확인 중심 검토에서 프로세스 검토로 전환 유도
  • 최종 출력만으로는 알기 어려운 에이전트의 해석·행동 파악 가능

  오류 탐지 성공률 향상

  • 프롬프트 오류·에이전트 오류 탐지율이 프롬프트 전용 조건 대비 향상
  • 출력만으로는 식별이 불가능했던 오류도 발견

인터뷰: 워크플로우가 실행 과정의 구조를 한눈에 보여주어 "무엇이 잘못되었는지" 좁혀나가는 데 도움이 됨

결과 1: 검증은 교차 확인에서 성공했습니다

검증 성공의 핵심은 단일 증거에 의존하지 않고 여러 증거 원을 교차 확인하는 것이었습니다.

증거 원확인 내용역할
  프롬프트의도와 요구 사항기준점 제공
  워크플로우 구조실행 단계와 의존 관계프로세스 검토
  중간·최종 출력실행 결과의 정확성결과 검증

  워크플로우는 출력·프롬프트와 연결되는 새로운 검토 지점으로 기능

결과 2: 워크플로우 재사용 vs. 프롬프팅 (RQ2)

워크플로우 적응프롬프트 적응
작업 성공률유의미한 차이 없음유의미한 차이 없음
완료 시간유의미한 차이 없음유의미한 차이 없음
지각된 난이도유의미한 차이 없음유의미한 차이 없음
선호 경향워크플로우 자동화 경험이 있고 수정 범위가 작을 때 선호이전 프롬프트가 있는 경우 전반적으로 선호
  • 워크플로우 재사용은 프롬프트 재사용의 실효적인 대안
  • 많은 참가자가 워크플로우 적응을 선호한다고 응답

논의: 사후 워크플로우의 의의

사후 절차적 투명성

증가하는 에이전트 자율성이 남긴 감독 업무에 구체적 구조를 제공하는 post hoc 투명성

드러내는 것과 못하는 것

워크플로우는 실행 구조를 보여주지만 에이전트 내부 추론의 모든 측면을 포착하지는 못함

지속 가능한 아티팩트

일회성 대화를 넘어 재사용·수정·공유 가능한 영구 자산으로 기능

완료된 실행을 워크플로우로 표현하는 것은 에이전트 자율성이 사용자에게 남기는 감독 업무에 구체적인 구조를 부여합니다.

기여 요약

1
실사용 워크플로우 특성화 — n8n 공개 템플릿 10,803개 분석을 통한 작업 도메인·구조 패턴·노드 기능 규명, 사후 워크플로우 설계 공간과 연구 작업 구성에 활용
2
Trace2Flow — 완료된 프롬프트 기반 에이전트 실행 트레이스를 대화형 사후 워크플로우로 변환하는 완전 동작 연구 프로브
3
실증 결과 — 사후 워크플로우가 실행 이해·검토 과정·검증 성공을 향상시키며, 워크플로우 적응은 프롬프트 재사용의 실행 가능한 대안임을 입증 (선호도는 경험·수정 범위·프롬프트 가용성에 따라 형성)
