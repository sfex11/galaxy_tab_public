Scaling Long-Form Story Generation
via Narrative State Tracking

서사 상태 추적을 통한 장편 이야기 생성의 확장

Zhennan Wan · Jianfei Chen (교신저자)

칭화대학교 컴퓨터과학과 · Tsinghua-Bosch 공동 머신러닝 센터

  NstAgent: 학습 없이(training-free) 인물·과거 사건·미래 요구를 담은 구조화된 서사 상태를 추적하여, 10K에서 100K 단어까지 이야기 일관성과 품질을 유지하는 에이전트 프레임워크

왜 어려운가: 긴 출력 ≠ 소설 쓰기

10K

기존 이야기 생성 연구가 다루는 한계선 (약 1만 단어)

100K

단행본 소설 길이 — 목표 지점

  • 이야기가 길어질수록 인물·사건·복선이 선형적으로 축적
  • 새로 생성되는 모든 문단은 이전의 모든 설정과 모순 없어야 함
  • 일관성 유지 부담은 길이에 대해 초선형(superlinear)으로 증가 → 길이 확장 문제(Length Scaling Problem)

기존 접근법의 세 가지 한계

2차 비용

긴 출력 모델 학습

LongWriter, LongWriter-Zero 등 — 소설 길이의 고품질 감독 데이터가 희소하고, 학습 비용은 길이의 제곱으로 증가. 전체 이야기를 한 번에 생성해야 함

정적 개요

계층적 생성

Re3, DOC 등 — 개요 작성 후 챕터별 집필. 그러나 개요는 쓰기 시작 전에 고정되어, 집필 중 생긴 구체적 설정이 이후 챕터를 구속하지 못함

관리 비용

메모리 기반 생성

검색·압축·전문 재입력, 지식그래프 등 — 자유 텍스트 기억은 구조가 없어 손실되고, 지식그래프는 구축·유지 비용이 큼

확장 가능한 해법의 세 가지 조건

"장편 이야기 생성은 어떻게 확장될 수 있는가?" — viable한 해법은 다음 세 조건을 동시에 만족해야 함

1

선형 비용

생성 절차가 신뢰 가능하고, 총비용이 길이에 대해 대략 선형으로 증가

2

일관성 유지

길이가 늘어나도 서사 일관성이 뚜렷하게 저하되지 않음

3

품질 보존

위 제약을 만족하느라 쓰기 품질을 희생하지 않음

길이 간 비교 가능한 일관성 평가

쓰기 품질

WritingBench

쿼리별 기준에 따라 응답을 채점하는 쓰기 품질 벤치마크

서사 일관성

ConStory-Bench 확장

5개 범주 · 19개 하위유형의 증거 기반 모순을 열거하는 판정 방식을 100K 단어까지 확장

  • 문제: 판정 모델(judge)은 매우 긴 맥락에서 회상 한계 → 오류 밀도가 과소평가되어 길이 간 비교 불가
  • 길이 정규화만으로는 부족 — 고정 크기 terminal window 도입으로 끝부분 오류를 놓치지 않도록 보정

NstAgent의 핵심 아이디어

"서사 텍스트는 한 상태에서 다른 상태로의 시스템 전이를 기록한다."

— Todorov (1977), 서사 이론

  • 이야기 생성을 명시적 서사 상태 위의 통제된 자율 전이로 정식화
  • 자유 텍스트 기억과 달리 상태는 구조화 · 타입화 · 간결
  • 챕터 생성 직후 즉시 상태 갱신 → 생성 내내 상태 추적
  • 학습 불필요: 기존 LLM 위에서 동작하는 에이전트 프레임워크

서사 상태의 세 구성 요소

 인물 상태

신분·특성, 관계, 목표, 현재 처지 등 인물별로 확정된 사실들

 과거 사건

이미 발생하여 결과가 확정된 사건들의 기록 — 반복 서술·모순 방지

 미래 요구

복선·서스펜스·명시적 약속 등 반드시 회수해야 할 서사적 의무

  핵심 차별점: 과거 사실(회고)뿐 아니라 미래 의무(예지)를 함께 기록 — 기존 추적 방법과의 결정적 차이

상태 기반 생성 워크플로우

1
상태 주입
현재 서사 상태를 맥락으로 제공, 필요시 단편 검색·원문 챕터 열람
2
챕터 집필
상태·계획·목표 길이 조건 하에 챕터 본문 생성 (길이 제어 포함)
3
상태 갱신
타입화된 도구(typed tool)로 인물·사건·약속 변화를 즉시 반영
4
반복
다음 챕터로 진행 — 갱신된 상태가 후속 챕터를 구속

  챕터당 고정 비용 × 챕터 수 → 총비용은 길이에 대해 거의 선형

실험 설정

항목내용
데이터모든 길이에서 동일한 50개 프롬프트, 목표 길이 10K–100K 단어
백본 LLMDeepSeek-V4-Flash, GPT-5.6 Luna 등 복수 모델 (일반화 검증)
베이스라인RollSum(롤링 요약) 등 기존 메모리·계층적 생성 방식
일관성 평가확장 ConStory-Bench — 일관성 오류 밀도(CED), 낮을수록 좋음
품질 평가WritingBench — 높을수록 좋음 (두 지표를 하나로 합치지 않음)
프로토콜 검증장문 접두사에서의 판정 회상 실험, 창문-로컬 vs 전역 오류 분석

결과 ① — 10K 단어에서의 비교

항목RollSum (롤링 요약)NstAgent
기억 형태무구조 요약 — 세부 정보 손실타입화된 상태 — 사실·의무 보존
일관성 오류 밀도 (CED)반복 사건·모순 발생더 낮음 ✓
WritingBench 품질기준 이하더 높음 ✓
  • 10K 구간에서도 일관성과 품질 모두에서 우위 — 품질을 희생하지 않으면서 일관성 확보

결과 ② — 10K → 100K 확장성

  NstAgent

길이가 10배 증가해도 CED와 쓰기 품질 모두 뚜렷한 열화 없음 — 그림 1의 두 곡선이 모두 평탄하게 유지

  기존 방법

RollSum 등은 길이가 늘어날수록 오류 밀도가 증가 — 요약 기반 기억의 한계 노출

  • 백본 일반화: 여러 LLM에서 동일한 경향 확인
  • 효율성: 지식그래프 대비 낮은 구축·유지 비용, 선형 스케일링
  • 소거 실험: 상태 추적 제거 시 일관성 저하 → 상태의 기여 정량 확인

사례 연구

Case 1 · 20K

반복 사건 차단

DeepSeek-V4-Flash — RollSum은 같은 사건을 재서술, NstAgent는 사건 상태로 이미 발생한 사건의 반복을 회피

Case 2 · 100K

40챕터 걸친 인물 사실

GPT-5.6 Luna — 신분 정보가 40개 챕터에 걸쳐 일관되게 유지 (초장거리 의존성)

Case 3 · 10K

상태에서의 오류 수정

잘못 기록된 사실이 이후 상태 갱신 단계에서 교정 — 상태는 완벽하지 않아도 수정 가능한 루프를 제공

  상태가 모든 오류를 예방하지는 못하지만, 탐지 → 갱신 → 교정의 순환이 장편 일관성의 핵심 원리

결론

  • 장편 이야기 생성을 길이 확장 문제로 정식화하고, 100K 단어까지 길이 간 비교 가능한 일관성 평가 프로토콜 제시
  • NstAgent: 인물·과거 사건·미래 요구를 명시 추적하는 학습 불필요 에이전트 프레임워크
  • 10K–100K 전 구간에서 일관성·품질 동시 유지, 총비용은 선형 — 단행본 소설 생성으로의 확장 가능성 제시
  • 후속 연구: 강화학습으로 상태 갱신 루브릭 최적화, 판정 모델 회상 한계 보완 등
