Cognitive Extensions for Dual-Process Language Agents

대화형 환경에서의 메모리와 자기 성찰

João Meneses dos Santos · Arlindo L. Oliveira

Instituto Superior Técnico, Universidade de Lisboa · INESC-ID

arxiv.org/abs/2609.19128v1

문제: 대화형 환경에서 언어 에이전트는 여전히 취약하다

장기 상태 추적

시간에 걸쳐 세계 상태를 유지하고 목표를 실행 가능한 하위 목표로 분해

유효한 행동 실행

현재 세계 상태에서 실제로 가능한 행동만 선택

실패 복구

예상치 못한 관찰과 실패한 단계로부터 회복

전형적 실패 패턴: 그럴듯한 상위 계획이 실행 시점에 붕괴 — 오래된 행동 반복, 현재 상태에서 불가능한 행동 제안, 진전 없이 계속되는 탐색

이런 실패는 언어 생성과 환경 전환의 경계에서 발생하므로, 더 큰 프롬프트만으로는 해결하기 어렵다.

배경: 이중과정 아키텍처 SwiftSage와 그 한계

Swift — System 1

효율적인 모델로 빠르게 지역 행동을 제안

Sage — System 2

느린 계획과 그라운딩 수행, 행동 버퍼(action buffer)를 통한 실행

그러나 장기 과제에서 두 가지 결격 사항

  • 영속적 episodic 메모리 부재 — 에피소드 간 중요한 경험을 선택적으로 재사용 불가
  • 실행 직전 행동 검증 부재 — 행동 정체 시 제한적(bounded) 개입 없음

관련 연구(ReAct, Reflexion, Self-Refine, CRITIC, MemGPT, CoALA)는 피드백의 유용성을 보여주지만, 무제한 자기 교정은 비용 증가·성능 저하를 유발할 수 있음 → 경계 설계 필요

제안: 두 가지 모듈식 인지 확장

SwiftSage 실행 기반은 그대로 유지하면서, 서로 다른 인과 인터페이스에 정밀하게 삽입

정보적 인터페이스

AMM — 적응형 메모리 모듈

Salience-gated episodic 저장과 트리거 기반 검색. 무엇을 기억하고 재사용할지를 바꾸지만 최종 행동은 선택하지 않음

제어 인터페이스

SRM — 자기 성찰 모듈

실행 직전 검증과 제한적 교정 개입. 무엇이 환경에 도달하도록 허용될지를 바꿈

두 모듈은 feature-flag 방식으로 동일 실행 기반 위에 구현 → 통제된 소거(ablation) 연구 가능

AMM: 적응형 메모리 모듈

쓰기: salience-gated episodic 기록

정보성 전환(단말 성공, 점수 증가, near-miss 진전, invalid-action 실패 등)일 때만 컴팩트한 반구조화 레코드 저장 — 원문 트랜스크립트가 아닌 태그·유형별 기록

읽기: 트리거 기반 검색

T1 — Swift 실패 복구

유효한 행동 생성 실패 시 관련 에피소드를 검색해 메모리 조건화된 컨텍스트로 재시도

T4 — System 2 계획

Sage 호출 시 성공·near-miss 에피소드를 검색해 숙고적 계획에 주입

  • 메모리는 힌트이지 권위가 아님 — 현재 관찰·인벤토리·허용 행동·런타임 제약이 항상 우선
  • 검색·포맷·프롬프트 구조 검사 실패 시, 수정되지 않은 기본 프롬프트로 안전하게 폴백

SRM: 자기 성찰 모듈 — 실행 시간 제어

1
Gate-1 검증
행동이 환경에 도달하기 직전 유효성 검사
2
정체 감지
단계 후 궤적 신호를 모니터링해 정체·반복 실패 포착
3
제한된 Critic
교정이 정당할 때만 호출, Sage와 동일한 버퍼에 교정 행동 주입
성찰은 항상 켜져 있는 것이 아니라 트리거 게이트 방식으로 실행 지향적으로 동작 — 무제한 자기 교정의 비용·성능 위험을 회피

목표: 유효하지 않은 행동의 환경 스텝 낭비와 측정 가능한 진전 없는 루프를 사전에 차단

전체 시스템: SwiftSage 루프 위의 정밀한 삽입

1
Swift 제안
버퍼가 비었으면 빠른 행동 제안
2
Sage 확장
invalid·무진전·계획 필요 시 상위 계획
3
AMM 보강
Swift/Sage/Critic 프롬프트에 기억 주입
4
SRM 게이트
실행 전 검증·정체 시 개입
5
ScienceWorld
환경 실행 후 관찰 반환

매 타임스텝: 버퍼에 행동이 있으면 실행, 없으면 Swift 호출 → 기저 조건에서 Sage로 확장. AMM은 정보를, SRM은 제어를 담당하며 서로의 인과 경로가 분리됨

실험 설정

ScienceWorld

초등 과학 과제를 그라운드된 순차 행동으로 수행하는 텍스트 기반 대화형 벤치마크 — 정답을 말할 수 있는지가 아니라 과학 지식을 유효한 절차로 변환하는지 평가

분석: 무엇이 병목인가?

실행 시간 제어가 지배적 레버

SRM이 단독으로 가장 강력한 기여 — 실행 전 검증과 정체 개입이 유효하지 않은 행동 낭비와 무진전 루프를 직접 차단

메모리는 안정화 이후에 빛난다

AMM 단독 효과는 작지만, SRM이 런타임 루프를 안정화하면 그 기여가 더 일관되고 응집적으로 나타남

이 설정에서 실행 시간 제어가 개선의 지배적 지렛대이며, episodic 메모리는 이미 제어된 런타임 루프에 제한된 증거로 삽입될 때 가장 유용하다

AMM(정보)과 SRM(제어)의 인터페이스 분리 덕분에 소거 결과를 불투명한 재설계가 아닌 증거와 제어의 협력으로 해석 가능

논의: 설계 교훈

  • 경계(boundedness)가 핵심 — 성찰은 트리거 게이트 방식으로, 메모리 주입은 경계가 있고 명시적으로 구분되어야 한다
  • 인과 인터페이스의 분리 — 정보(AMM)와 제어(SRM)를 나누면 각 모듈의 기여를 해석 가능하게 만들 수 있다
  • 추가 추론 호출 ≠ 개선 — 이중과정 컨트롤러에 무작정 reasoning 호출을 더하는 것과 경계화된 삽입은 다르다
  • 인지과학의 공학적 착안 — 상보적 학습 시스템(CLS)과 이중과정 이론을 인지적 동등성 주장이 아닌 설계 추상화로 활용

결론

1
SwiftSage에 부족했던 두 메커니즘 — AMM(영속적 episodic 재사용)과 SRM(just-in-time 실행 제어) — 을 모듈식으로 추가
2
ScienceWorld에서 전체 시스템이 최고 성능 달성: 최종 점수 64.62, 성공률 43.17%, 효율 19.33 단계
3
실행 시간 제어가 지배적 병목 — episodic 메모리는 런타임 루프가 안정화된 후 보조적 증거로 가장 효과적
