왜 필요한가?

코딩 에이전트는 수백만 토큰에 달하는 컨텍스트를 다루며 복잡한 문제를 해결합니다.

KV-Cache 병목

  • 긴 컨텍스트 처리의 주된 메모리·연산 병목
  • 지연 시간과 추론 비용 크게 증가
  • 컨텍스트가 부풀수록 에이전트 성능 저하

컨텍스트 관리의 딜레마

  • 슬라이딩 윈도우: 창 이동 시 프리픽스 캐시 무효화
  • LLM 요약: 요약의 요약이 반복되며 손실 누적
  • 외부 메모리/RAG: 복잡하고 작업 특화적 설계 필요
핵심 질문: 제한된 컨텍스트로도 전체 컨텍스트 대비 같거나 더 나은 성능을 더 낮은 비용으로 달성할 수 있을까?

핵심 아이디어: 절벽(Cliff)처럼 잘라내기

CliffCompaction은 규칙 기반(rule-based) 컨텍스트 관리 기법으로, 세 가지 설계 선택이 특징입니다.

1
임계값 도달 시 압축
컨텍스트가 미리 정한 토큰 임계값을 넘으면 자동으로 압축 수행
2
축어적 보존
요약이 아니라 원문 발췌를 유지, 도구 호출/출력 등 토큰 다량 부분은 잘라냄
3
이전 압축 폐기
압축을 다시 압축하지 않음 — 항상 원본 콘텐츠만 대상으로 새 압축 블록 생성

Cliff 효과 매 압축 이벤트 후 컨텍스트 길이가 거의 같은 수준으로 가파르게 감소합니다 — 마치 절벽처럼.

절삭 대상: 도구 호출·도구 결과 / 보존 대상: 생각·시스템 프롬프트·작업 설명·최근 대화

정밀도 vs 재현율 — 정밀도를 택하다

Compaction Precision (높음)

보존된 정보의 충실도. 요약은 왜곡·누락을 유발하고, 모델이 "이미 모든 정보를 안다"고 착각하게 만들어 문서·코드 재확인을 건너뛰게 합니다.

CliffCompaction 사용자 지시와 모델 생성을 원본 그대로 두 컴팩션 윈도우 동안 유지 → 미묘하고 지속적인 컨텍스트 드리프트 방지

Compaction Recall (의도적 낮춤)

장기간에 걸쳐 검색 가능한 정보의 양. CliffCompaction은 두 번의 압축 후 직접 정보를 버리므로 재현율은 낮습니다.

요약 기반 기법은 재현율은 높지만 정밀도가 낮음 → 실험 결과, 전체 이력 회상은 필요하지 않음이 입증됨 (§3)

"절대 압축을 다시 압축하지 않는다(never compact a compaction)" — 각 압축은 원본에만 작용하고 이전 압축 출력은 폐기되어, 컨텍스트 드리프트의 누적을 원천 차단합니다.

기존 컨텍스트 관리 기법과의 비교

기법학습 불필요드롭인모델 무관보조 LLM 호출 없음캐시 친화적높은 정밀도
슬라이딩 윈도우—
LLM 요약
학습 기반 압축—
외부 메모리 / RAG—
CliffCompaction

CliffCompaction은 전체 이력 회상(full-history recall)만을 의도적으로 희생하고, 그 대가로 배포 용이성과 정보 충실도를 모두 확보합니다.

실험 설정

벤치마크

  • Terminal-Bench 2.0 (터미널 작업)
  • SWE-bench Verified (실제 GitHub 이슈 해결)
  • KernelBench (CUDA 커널 최적화, 지속 학습)

모델·스캐폴드

  • GLM-5.1, Kimi K2.6, Opus 4.6/4.7, GPT-5.3 Codex
  • OpenHands 등 다양한 스캐폴드
  • 스캐폴드 무관(scaffold-agnostic) API 프록시 구현

통합 방식

  • 컨텍스트 임계값: 16K ~ 32K 토큰
  • 학습 불필요 · 드롭인 · 모델 무관
  • Claude Code, Codex 등 하네스와 호환

결과 2 — 테스트 타임 스케일링을 경제적으로

롤아웃당 절감 효과 덕분에 여러 롤아웃을 병렬로 실행해도 비용이 합리적으로 유지됩니다.

1
단일 uncompacted Kimi K2.6 실행 대비 1.9× 비용으로 롤아웃 3개 실행 → Terminal-Bench에서 +10.5 포인트 향상
2
압축된 Kimi K2.6 다중 롤아웃이 Opus 4.7과 동급, Opus 4.6 및 GPT-5.3 Codex를 더 낮은 비용으로 능가
3
"2회 전체 컨텍스트 실행 비용 미만"으로 10포인트 이상 추가 성능 확보 — 프론티어 모델 대비 효율적인 대안
같은 비용이라면, CliffCompaction은 전체 컨텍스트 설정보다 더 많은 성능을 구매합니다.

결과 3 — 백만 토큰 이상의 지속 학습 (KernelBench)

OpenHands로 CUDA 커널 개발을 반복 수행하며 세션을 넘어 지속적으로 개선합니다.

2.23×

200 스텝 후 CUDA 커널 속도 향상

3.58×

400 스텝 후 속도 향상 (Level 3, 100만+ 토큰 세션)

  • 커널 최적화를 위해 특별히 설계된 탐색 알고리즘·학습된 에이전트보다 우수 — 범용 압축 기법임에도
  • 동일 설정에서 전용 방법론 대비 25% 더 높은 성능, 외부 메모리나 작업 특화 설계 불필요
  • 제한된 컨텍스트 덕분에 스케일링 비용도 저렴 — 가장 저렴하면서 가장 높은 성능

동작 흐름 요약

1
자연 성장
에이전트가 작업을 수행하며 도구 호출·결과와 함께 컨텍스트가 자유롭게 증가
2
임계값 감지
토큰 임계값(예: 16K/32K) 도달 시 압축 자동 트리거
3
절벽 압축
도工具 호출/출력 절단, 원문 발췌·사고·최근 대화 보존, 이전 압축 블록 폐기
4
캐시 친화적 재개
드롭인 방식으로 세션 지속, 컨텍스트 드리프트 없이 다음 윈도우 진행

설계 목표 2가지 (1) 압축 자체의 실용적·효율적 배포 (재프리필 회피) (2) 원본 그대로의 컨텍스트를 최대한 오래 유지

한계와 시사점

한계

  • 전체 이력 회상 불가 — 오래된 직접 정보는 두 번의 압축 후 소실
  • 정보 검색이 중요한 과업에는 재현율 제약이 영향을 줄 수 있음
  • 임계값 등 하이퍼파라미터 선택이 필요

시사점

  • 요약이 항상 정답은 아니다 — 축어적 보존 + 폐기가 드리프트를 막음
  • 간단한 규칙 기반 프런트엔드 기법만으로 비용·성능 동시 개선 가능
  • 테스트 타임 스케일링과 지속 학습의 경제성을 크게 향상
"높은 정밀도를 유지하기 위해 절단·삭제만 사용하고, 재구성이나 재작성은 하지 않는다" — 이것이 CliffCompaction의 효과 핵심입니다.

결론

  • 최대 50% 비용 절감하면서 Terminal-Bench 성능 유지·향상
  • 테스트 타임 스케일링: 압축된 Kimi K2.6이 Opus 4.7과 동급, 더 낮은 비용으로 Opus 4.6·GPT-5.3 Codex 능가
  • KernelBench 지속 학습에서 3.58× 커널 속도 향상 — 전용 기법들을 제치고 SOTA
  • 학습 불필요 · 드롭인 · 모델 무관 · 캐시 친화적 · 보조 LLM 호출 없음
  • 오픈소스 — Claude Code, Codex 등에서 사용 가능한 API 프록시 구현 공개
