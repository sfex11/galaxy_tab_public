문제 제기

프로덕션 에이전트는 왜 실패하는가?

실패의 원인은 추론 능력 부족이 아니라, 컨텍스트 관리 능력 부족이다.

  • 긴 대화에서 사용자가 이전에 말한 내용을 잊어버림
  • 같은 대화에서 도구가 반환한 정보를 누락
  • 멀티 에이전트 전달 시 모순 발생
  • 컨텍스트 과적재로 인한 환각(hallucination)
  • 매 턴마다 토큰 비용이 누적되어 증가

2025년 기준, 기업의 대다수가 AI 에이전트를 실험 중이나 10% 미만만이 실제 단일 비즈니스 기능에 확장 성공

저장소(Store) 중심 사고

  • 쓰기(Write) 최적화
  • 읽기(Read) 최적화
  • 단 두 순간만 다룸

프로덕션 에이전트가
매 턴마다 결정해야 할 것

  • 어떤 것을 보존할 것인가?
  • 어떤 구조로 보존할 것인가?
  • 이번 턴에 무엇이 관련 있는가?
  • 다음 턴에 무엇이 필요할까?
  • 예산 초과 시 어떻게 압축할까?

저장은 수명주기의 한 순간일 뿐, 전부가 아니다.

제안

에이전트 컨텍스트 관리(ACM)

에이전트가 컨텍스트에 무엇을, 언제, 얼마나 오래, 어떤 비용으로 유지해야 하는지를 컨텍스트 획득부터 은퇴까지 전체 수명주기에 걸쳐 결정하는 학문

핵심 아이디어

하나의 원시 연산(primitive)만 잘 해결하는 것은 메모리 도구다.
다섯 개의 원시 연산을 범위(scope) 전반에 걸쳐 일관되게 해결하는 것은 컨텍스트 관리 플랫폼이다.

5개 원시 연산

ACM의 다섯 가지 기본 요소

1
아키텍처 설계
메모리의 형태, 카테고리, 저장소, 보존 기간 결정
2
섭취
원시 신호를 구조화된 검색 가능한 메모리로 변환
3
범위 지정
조직 계층에서 관련성 있는 부분만 선택, 엄격한 격리
4
예측
명시적 요청 전에 필요할 컨텍스트를 사전 준비
5
압축 및 통합
예산 초과 시 검증 가능한 손실 없는 압축 수행

다섯 원시 연산은 서로 결합되어 있어 독립적 도구 조합으로는 해결 불가

원시 연산 상세 ①②

아키텍처 설계 & 섭취

아키텍처 설계 (Architecting)

단일 메모리가 저장되기 전에 결정되어야 하는 것:

  • 어떤 정보 카테고리가 중요한가
  • 어떻게 추출하고 어디에 저장할까
  • 얼마나 오래 유지할까
  • 어떻게 검색하고 압축할까

고정된 범용 스키마가 아닌, 1급 원시 연산으로 취급

섭취 (Ingesting)

원시 신호를 구조화된 메모리로 변환:

  • 대화 턴
  • 멀티모달 문서 업로드
  • 도구 호출 및 응답

핵심 관찰: 검색 품질은 섭취 품질에 의해 상한이 결정됨

"사용자가 가격제를 언급함" → "사용자가 4월 3일 Starter에서 Pro로 업그레이드" 불가

범위 계층

사용자를 넘어 조직 단위로: 범위 계층 구조

클라이언트 (Client)

에이전트 플랫폼 운영자 — 여러 고객 조직에 걸쳐 배포

고객 (Customer)

사용자가 속한 조직 — B2B 환경에서 네트워크 효과 창출

사용자 (User)

개인 또는 서브 에이전트 — 가장 좁은 범위

검색은 항상 좁은 범위 우선(사용자 → 고객 → 클라이언트)으로 해결하며, 엄격한 격리 유지. 별도의 전역 지식 레이어가 공개 엔티티 정체성 등 공통 지식 제공

경제적 논증

관리되지 않은 컨텍스트의 비용은 이차(O(n²))로 성장

전체 누적

모든 이전 턴을 매번 재전송
비용이 대화 길이의 제곱으로 증가

정확도 절벽(accuracy cliff) 발생

위험

방식 3

검증된 압축

O(n)

선형 비용 +
충실도 보존
효율적 프론티어 달성

최적

관리된 수명주기는 사치가 아니라 필수다. 비용과 충실도의 효율적 프론티어에 도달하는 유일한 경로

Maximem Synap: 다섯 원시 연산의 실현

아키텍처 특징

  • 멀티 테넌트 서비스로 구현
  • 5개 원시 연산을 아키텍처 및 관찰 가능한 동작 수준에서 실현
  • 사용자 → 고객 → 클라이언트 범위 계층 지원
  • 전역 지식 레이어로 엔티티 정규화 제공
  • 검증 가능한 손실 없는 압축 파이프라인

설계 원칙

  • 원시 연산 간 결합을 시스템적으로 관리
  • 에이전트 유형별(지원/코딩 등) 아키텍처 차별화
  • 섭취 품질이 검색 품질의 상한을 결정한다는 원칙 적용
  • 사전 페치로 검색을 임계 경로에서 제외

Synap은 카테고리의 참고 구현이며, 논문의 핵심 논증은 카테고리 자체에 대한 것

결정 수준 컨텍스트

단일 에이전트의 대화를 넘어, 에이전트 간 핸드오프 시 컨텍스트가 어떻게 전달·변환되어야 하는가?

다중 에이전트 시스템에서 모순 없는 컨텍스트 일관성 유지

조직 수준 컨텍스트

조직 전체의 에이전트 생태계에서 네트워크 효과를 어떻게 창출하면서도 격리를 유지하는가?

B2B 환경에서 조직 지식이 개별 사용자 경험을 풍부하게 만드는 메커니즘

이러한 차원들은 아직 벤치마크로 포착되지 않지만, 실제 프로덕션 환경에서 에이전트의 안정성과 유용성을 결정하는 핵심 요소
