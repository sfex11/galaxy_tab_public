배경: EHR 시스템으로 들어온 LLM 임상 어시스턴트

  • 각 기관의 EHR에 안전한 LLM 배포가 확대되며, 임상의가 챗 인터페이스로 환자 기록을 탐색하는 흐름으로 전환
  • 환자 병력 질의, 과거 진료 기록 검색, 요약 생성 등 "차트 리뷰" 자동화
  • 길고 복잡한 환자 기록 전체를 탐색하고 종합하는 능력이 요구됨
  • 성능 특성·실패 모드를 파악하려면 임상적으로 현실적인 평가 체계가 필수
그러나 방법론의 발전 속도가 기존 벤치마크 제작 속도를 앞질러, 배포된 임상 검색 시스템의 견고한 평가는 여전히 열린 과제

문제: 정적 벤치마크는 왜 한계에 부딪히는가

구분기존 벤치마크필요한 평가 체계
구축 방식임상의가 직접 문항 작성 → 비용·시간 과다자동 생성 + 임상의 검증
업데이트사실상 고정, 갱신 어려움새 데이터로 지속 재생성
수명학습 데이터 흡수로 곧 무효화(누출)내용을 계속 갱신해 누출 방지
평가 범위배포된 차트 리뷰 질의의 폭을 충분히 반영 못함검색 난제별 체계적 축(축세분화) 제공

성능 수치가 실제 임상 추론이 아닌 암기를 반영할 위험이 커짐

EHR 검색이 어려운 세 가지 이유

정보의 분산

핵심 정보가 여러 진료(encounter)와 여러 문서에 흩어져 있어, 답을 모으려면 기록 전체를 종합해야 함

Copy-forward 중복

임상 관찰이 복사·붙여넣기로 반복 기록되어, 동일 소견이 여러 노트에 중복 등장

시점 혼재

한 노트 안에 현재 진료와 과거 진료 소견이 뒤섞여, 관찰이 "언제" 일어났는지 파악이 어려움

모델이 이 노이즈 속에서 신호를 추출하지 못하면 기록 오해석 → 중요 정보 누락 → 임상 영향으로 이어질 수 있음

핵심 아이디어: 벤치마크가 아닌 생성기를 검증한다

임상의가 문항을 직접 갱신하는 대신, LLM 기반 생성기를 한 번만 검증하고 재사용하는 "살아있는(living)" 벤치마크 패러다임

1
생성기 개발
실제 비식별 환자 기록에서 QA 쌍을 자동 생성하는 확장 가능한 파이프라인
2
임상의 일회성 검증
정기 사용 임상의 19명이 생성 품질을 평가하여 생성기 신뢰성 확보
3
지속 재생성
새 환자 데이터에 생성기를 재실행해 항상 최신 벤치마크 유지

BRIE: Benchmark for Retrieving Information in EHRs — 검증된 답과 비식별 노트를 갖춘 500+ 문항 데이터셋

배포된 임상 검색 시스템의 평가와 지속 모니터링을 동시에 지원

과제 정의: 입원 시점 차트 리뷰

  • 임상의가 환자 입원 시 병력을 빠르게 파악하는 대표적 차트 리뷰 업무를 QA 과제로 형식화
  • 특정 환자·특정 시점(입원 H&P 노트 작성 시점)에 대해, 그 이전까지의 모든 기록만 사용해 답변
  • 출력은 환자의 기존 임상 문서에 근거한 자유 서술형 응답
  • 문항 생성은 H&P 노트에 근거 — 입원 시 임상의가 실제로 궁금해할 질문을 반영
H&P(병력·신체검사 노트)는 당시 임상의가 중요하다고 판단한 정보의 요약이므로, "무엇을 물어야 하는가"의 자연스러운 근거 지점

QA 생성 파이프라인: 2단계 구조

1
사실 추출·중복 제거
H&P 이전의 모든 임상 노트에서 후보 사실을 추출하고, 복사·가져오기로 인한 중복을 제거
2
QA 쌍 생성
추출 사실 + H&P 노트를 함께 입력(Gemini Pro 2.5)하여 질문–응답 생성, 답변은 사실의 부분집합에 연결

핵심 설계 원칙

H&P는 진료 맥락 제공용, 추출된 사실은 허용 가능한 근거 정의용

평가의 공정성

모든 답변은 반드시 추출 사실로만 뒷받침 → H&P에 요약된 정보가 아닌 이전 기록의 검색 능력을 평가

평가 축 분류 체계: 어디서 모델이 실패하는가

Reasoning

Single-hop: 단일 근거에서 답 가능
Multi-hop: 여러 근거를 결합해야 답 가능

Topics

질문이 겨냥하는 임상 개념(주제)별로 문항을 조직

Temporality

근거가 장기 기록의 어디에 위치하는지 — 생성 후에 결정

문항을 축별로 조직하면 어떤 검색 난제에서 접근법이 성공·실패하는지 체계적으로 진단 가능

임상의 검증: 생성기는 신뢰할 만한가

19명

임상 LLM 도구를 정기적으로 사용하는 의사들이 생성기의 품질을 일회성 검증 — 이후 별도 개입 없이 재사용

675쌍

질문·답변·사실 차원 전반에서 높은 품질 비율 확인 — 생성된 QA 쌍이 임상적으로 유의미함을 입증

  • 질문 차원: 임상의가 입원 시 실제로 물을 만한 질문인가
  • 답변 차원: 근거에 의해 뒷받침되고 임상적으로 정확한가
  • 사실 차원: 근거 사실 추출이 정확하고 중복 없는가

평가 설정: 9개 모델 × 5가지 추론 전략

최신 LLM 9종

Gemini 2.5 계열, GPT-5 계열(경량 포함), Claude Haiku 4.5·Opus 4.7, Qwen 3.5, Kimi K2 등 최신 최고 성능 모델

추론 전략 5종

BM25 검색 기반 RAG, 전체 기록 주입, 에이전틱 접근 등 다양한 구성 비교

평가 지점확인된 사실
환각(hallucination)드묾 근거 없는 정보 생성은 드문 편
정보 누락(omission)빈번 임상적으로 중요한 정보를 자주 생략
취약 지점다중 문서·다중 진료 종합이 필요한 multi-hop 질문에서 특히 심각

핵심 발견: 위험한 실패는 환각이 아니라 누락

최신 시스템일수록 "틀린 말"은 적지만, 말해야 할 것을 말하지 않는 경향이 임상적으로 더 큰 위험
  • 답이 기록의 여러 부분에 흩어져 있을 때 관련 사실 누락 급증
  • copy-forward 중복 속에서 최신·고유 정보를 구별하지 못해 중요 소견을 놓침
  • 누락된 정보는 응답이 "그럴듯해 보이게" 만들어 임상의가 오류를 인지하기 어려움

→ 배포 모니터링은 정확도뿐 아니라 재현율(누락 없음) 중심 평가를 요구

살아있는 벤치마크만 할 수 있는 두 가지 분석

다중 참조 답변

검증된 생성기로 임상 해석의 다양성을 반영한 여러 정답을 생성

발견 단일 참조 평가는 모델 능력을 체계적으로 과소평가함

벤치마크 재생성

2년 후 입원 데이터로 BRIE를 전체 재생성 — 임상의 개입 없이 진행

결과 재생성 벤치마크도 난이도가 유지되어 누출 없는 반복 평가 가능

정적 벤치마크로는 불가능한 견고한 성능 평가와 지속적 모니터링을 동시에 실현

결론

  • 확장 가능한 QA 생성기 + 임상의 일회성 검증으로 살아있는 임상 검색 벤치마크 패러다임 제시
  • BRIE는 최신 LLM에서 정보 누락이라는 임상적 실패 모드를 정확히 포착
  • 다중 참조 답변·재생성 등 정적 벤치마크로 불가능한 평가 지원
  • 빠르게 변화하는 의료 환경에 배포되는 임상 LLM의 엄격하고 최신의 평가를 가능하게 함
