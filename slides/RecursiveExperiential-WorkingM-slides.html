문제 정의: 장기 수행에서의 재귀적 자기 개선

LLM 에이전트는 추론·도구 사용·자율 실행에서 강력한 능력을 보이지만, 장기 수행(long-horizon) 작업에서는 재귀적 자기 개선(RSI)이 여전히 어렵다.

  • 상호작용 기록이 길어지면 작업 상태가 모호해짐
  • 누적된 경험과 현재 수행 필요가 정렬되지 않음
  • 기존 방식은 전체 대화 기록에 대해 스킬을 검색 → 신뢰도 저하
  • 최종 성공/실패만으로는 어떤 기억 요소를 고쳐야 할지 알 수 없음

핵심 병목

유용한 경험의 부재가 아니라, 저장된 경험을 현재 수행 필요에 지속적으로 정렬시켜 줄 compact하고 신뢰할 수 있는 작업 상태의 부재가 근본적 한계다.

핵심 통찰: EM–WM 결합

작업기억(Working Memory)이 누락된 상태 표현을 제공한다. WM은 현재 진행 상황과 미해결 목표를 추적하고, 이를 통해 경험기억(Experiential Memory)에서 가장 적절한 스킬을 선택한다.

WM이 현재 진행도

이 폐루프가 구조화된 증거를 생성하여, 실패를 특정 기억 요소에 국지화(localize)할 수 있게 만든다.

Recuris: 기존 방식과의 차이

기존 하니스

  • 성장하는 대화 기록 전체에 대해 검색
  • 미해결 목표 추적 상실
  • 하나의 작업 결과만으로 기억 전체 재작성
  • 어떤 요소를 고쳐야 할지 불명확

Recuris

  • 실행 이벤트에서 검색, WM이 상태 관리
  • 체커가 환경 응답을 검증된 상태 갱신으로 변환
  • 구조화된 궤적에서 실패를 특정 요소에 귀인
  • 관련 요소만 패치, 검증 게이트 통과 시만 반영

Recuris 아키텍처 전체 구조

WM
구조화된 작업 상태 유지 — 목표, 진행도, 제약 조건
EM

과제 간 (Cross-Task)

1

2

3

과제 내: 검증된 EM–WM 결합 상세

구조화된 작업 상태

WM은 목표(goals), 진행 상태(progress), 제약 조건(constraints)을 구조화된 형태로 유지. 대화 기록 전체가 아닌 압축된 상태만 활용.

상태 기반 스킬 호출

WM의 현재 상태를 쿼리로 EM에서 관련 스킬을 검색. 전체 히스토리가 아닌 "지금 필요한 것"에 기반.

증거 기반 상태 갱신

실행 후 환경 피드백을 체커가 검증하여 WM을 갱신. 에이전트의 자기 보고가 아닌 실제 환경 응답에 근거.

이 결합의 핵심 부산물: 각 단계의 (상태, 선택된 스킬, 액션, 실행 결과)가 구조화된 궤적(trace)으로 기록되어, 과제 간 진화에서 실패 원인을 특정 요소에 귀인할 수 있는 근거가 된다.

기저 LLM과 외부 개선 절차는 고정. 재귀는 외부화된 기억-제어 계층 내에서만 발생.

전이ability: 과제 간 · 모델 간 전이

과제 간 전이

특정 과제에서 진화된 스킬 기억이 held-out 과제에서도 일관되게 성능 향상을 달성.

단일 과제 결과만으로 기억을 재작성하는 기존 방식과 달리, 구조화된 국지적 패치는 범용성을 유지.

모델 간 전이

한 모델에서 진화된 스킬 기억이 다른 모델에도 적용 가능. 모델에 구애받지 않는 기억 층의 이점.

기저 모델은 제공사가 배포한 그대로 유지. 모든 개선은 외부 기억 계층에서만 발생.

테스트 타임 적응 모드: 단일 격리 과제에서도 EM–WM 결합과 Meta-Agent가 온라인으로 기억을 적응시켜 성능 향상을 달성.

핵심 요약 및 시사점

상태 기반 기억 사용

장기 수행 RSI에서 누적 경험과 현재 수행 필요의 지속적 정렬이 핵심 요구사항임을 확립

구조화된 증거

EM–WM 결합이 실행을 진단 가능한 증거로 변환하여 표적화된 기억 진화를 가능하게 함

유계 재귀 루프

기억이 행동을 형성하고, 행동이 증거를 생성하고, 증거가 기억을 진화시키는 검증 게이트된 루프

  • 프론티어 모델도 장기 수행 작업에서 포화되지 않음 — Recuris가 SOTA 수준으로 끌어올림
  • 이점은 수평이 길어질수록 확대되는 패턴 (기존 방식과 반대)
  • 기저 모델 수정 없이 외부 기억 계층만으로 달성 — 실용적 배포 가능
  • 재귀적 진화 기억이 RSI의 확장 가능한 기초로 위치함
