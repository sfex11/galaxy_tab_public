TRACE-Router

에이전트 AI를 위한 작업 일관성 및 적응형 온라인 라우팅

Ritik Raj · Souvik Kundu · Sarbartha Banerjee · Dheemanth Joshi · Ishita Vohra · Tushar Krishna

http://arxiv.org/abs/2607.22465v1

문제 정의

기존 LLM 라우팅의 근본적 한계

현재 방식

각 LLM 호출마다 독립적인 라우팅 결정을 수행

  • 단일 턴 추론에는 적합
  • 에이전트 워크플로우에는 부적합

에이전트 워크로드의 특성

상태가 있는 장기 실행 실행 흔적(execution trace)

  • 다수의 LLM 호출 + 도구/검색/검증
  • 피드백은 작업 종료시에만 관측

τ²-Bench에서 소형 모델은 10.4%만 해결, 대형 모델은 60.2% 해결 — 중간에 잘못 라우팅하면 전체 실패

작업 성공/실패는 종료시에만 관측되며, 이 단일 지연 결과를 실행 전반의 모든 라우팅 결정에 귀인해야 함

방법론

TRACE-Router 개요

컨텍스츄얼 밴딧 기반의 작업 수준 온라인 모델 선택 프레임워크

Task-Consistent

작업 입장 시 한 번 할당
전체 트레이스에 고정

Context-Conditioned

거친 난이도 클래스별
독립적 라우팅 정책

Online Adaptive

오프라인 학습 불필요
작업 결과로부터 온라인 학습

기존 라우터: 오프라인에서 라벨링된 데이터로 학습 → 배포 후 정책 고정
TRACE-Router: 완료된 작업의 결과로부터 어느 백엔드를 사용할지 학습

핵심 메커니즘

작업 일관성 라우팅 흐름

작업 입장 (Admission)

입장 시점의 피처로부터 거친 라우팅 컨텍스트 할당

밴딧 선택 (Selection)

해당 컨텍스트의 컨텍스츄얼 밴딧이 하나의 백엔드 선택

고정 실행 (Pinned Execution)

영구 작업 식별자(sticky key)로 모든 후속 호출을 선택된 백엔드에 고정

종료 보상 (Terminal Reward)

정확도 + 지연시간을 스칼라화한 단일 보상으로 해당 밴딧만 업데이트

보상 설계

정확도–지연시간 보상 함수

r = α · accuracy − (1 − α) · normalized_latency

α → 1 (정확도 우선)

더 강한 모델 선호
파레토 프론티어의 상단 영역

α → 0 (지연시간 우선)

더 빠른 모델 선호
파레토 프론티어의 하단 영역

지연 크레딧 할당 (Delayed Credit Assignment): 작업 종료 시 산출된 단일 보상은 결정을 내린 밴딧만 업데이트함으로써, 명시적인 작업 복잡도 추정 없이도 라우팅 정책이 워크로드에 적응하도록 함

알고리즘

Cold-Start Contextual UCB

초기 데이터 부족 문제를 해결하기 위한 사전 웜스타트 방식

일반적인 Cold-Start 문제

  • 새 컨텍스트에 대한 관측치 없음
  • 무작위 탐색으로 많은 작업 낭비
  • 초기 정확도 저하

TRACE-Router의 해결책

  • 유사 컨텍스트의 사전 분포를 공유
  • Warm-start로 초기 불확실성 감소
  • 빠른 수렴과 안정적 초기 성능

핵심: 오프라인 학습 데이터가 전혀 필요 없으며, 컨텍스트 간 사전 지식 전이만으로 콜드 스타트를 극복

추가 분석

컨텍스트 조건화 및 콜드 스타트

컨텍스트 조건화 효과

거친 난이도 클래스별로 독립적 정책 유지가 성능에 필수적

  • 단일 밴딧(컨텍스트 없음)보다 우수
  • 도메인별 성능 특성 차이 반영
  • 워크로드 변화에 자동 적응

콜드 스타트 vs 웜 스타트

사전 웜스타트가 초기 성능 격차를 효과적으로 완화

  • 콜드 스타트도 충분히 수렴 시 유사한 성능
  • 웜스타트는 수렴 속도 크게 개선
  • 실제 배포에서의 안정성 보장
확장성

2개 초과 후보 모델로 확장

TRACE-Router는 4개 후보 모델 환경에서도 일관되게 파레토 프론티어를 달성

τ²-Bench (4 모델)

4개 백엔드 풀에서도 적응형 라우팅이 단일 모델 및 랜덤 혼합 지배

더 많은 선택지가 주어질수록 적응형 라우팅의 이점이 증가

LiveCodeBench (4 모델)

코딩 벤치마크에서도 다양한 α 값에 대응하는 정책 가족 학습 성공

밴딧 아암 수가 증가해도 탐색-활용 균형이 안정적으로 유지

중요: 약한 백엔드가 반드시 빠른 것은 아님 — 모델 간 비용-품질 트레이드오프가 단조롭지 않을 때 적응형 라우팅의 가치가 더욱 커짐

요약

기여 및 핵심 Takeaway

1

작업 수준 라우팅 공식화

라우팅 단위를 피드백 단위에 정렬하여 지연된 보상으로부터 원칙적 크레딧 할당 달성

2

컨텍스트 인식 온라인 라우팅

오프라인 학습 없이, 컨텍스츄얼 밴딧으로 워크로드에 온라인 적응

3

일관되게 개선된 정확도–지연시간 트레이드오프

4개 벤치마크, 2개 백엔드 쌍에서 항상 파레토 프론티어 달성

에이전트 AI 서빙에서 요청(request)이 아닌 작업(task)을 일급 객체로 처리하는 것이 라우팅의 근본적 개선을 이끈다.
