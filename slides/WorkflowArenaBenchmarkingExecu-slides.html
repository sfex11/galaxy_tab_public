WorkflowArena

LLM 기반 멀티 에이전트 시스템의
실행 가능한 워크플로우 오케스트레이션 벤치마크

Navers Lab · Einsia.AI · Tsinghua University

arXiv: 2611.12856

배경: 에이전트의 패러다임 전환

  • LLM 에이전트가 단일 모델에서 멀티 에이전트 시스템으로 진화
  • 최신 에이전트 하네스는 워커 에이전트를 인스턴스화하고, 이를 조율하는 실행 가능한 워크플로우를 직접 작성
  • 시스템 구조 설계 주체가 개발자 → 런타임의 모델로 이동

시스템 지능(System Intelligence): 여러 지능적 구성요소를 하나의 일관되고 적응적인 전체로 조직하는 능력 — 이제 평가가 필요한 독립적 역량

핵심 질문과 기존 벤치마크의 한계

LLM 에이전트는 현실적인 장기 과제를 수행하기 위해 멀티 에이전트 워크플로우를 얼마나 자율적으로 오케스트레이션할 수 있는가?

엔드투엔드 벤치마크

SWE-bench, GAIA 등 — 작업 완수는 측정하지만 업무 분장 과정이 보이지 않음

멀티 에이전트 벤치마크

협업 구조가 벤치마크 설계자가 미리 지정 — 모델이 구조를 결정하지 않음

워크플로우 벤치마크

생성된 플랜을 오프라인·시뮬레이션으로 평가 — 실제 산출물에 적용되지 않음

WorkflowArena 개요

145

장기(Long-horizon) 과제

8

전문 직무 도메인

17

과제 형태(Task Forms)

  • 도메인: 소프트웨어 엔지니어링, 형식 수학, 법률 분석, 3D 프로덕션 등
  • 버전 관리되는 전문 아티팩트 또는 의존성이 완전히 명시된 시나리오로 구축
  • 에이전트가 위임 여부와 방식을 스스로 결정, 모든 위임은 기록됨

과제 설계: 상호 의존적 산출물

1
초기 작업공간
버전 관리된 전문 아티팩트 제공
2
통합형 산출물
상호 의존하는 다수 분리 단위로 구성
3
숨겨진 검증기
과제 계약서 기준으로 채점

핵심 설계: 개별적으로는 옳지만 서로 조율되지 않은 구성요소는 통과할 수 없는 검증 포함 → 분해(decomposition)와 통합(integration) 결정이 결과를 좌우

예: 계약서 포트폴리오 전반에 걸쳐 조율되어야 하는 조항 단위 분석, 이전 결과 위에 쌓이는 증명

평가 프로토콜

기록된 위임 인터페이스

모든 위임이 기록된 인터페이스를 경과 → 산출물 결과와 그것을 만들어낸 워크플로우를 함께 분석 가능

공유 시간 예산

업무를 조직하는 데 드는 시간도 실제 업무와 동일한 예산에서 차감 → 오버헤드가 실제 비용으로 반영

  • 위임 여부 자체도 에이전트의 자율적 결정
  • 산출물 품질 + 작업 조직 방식 + 자원 사용을 동시에 평가

실험 설정

9

평가 대상 모델

25

모델–노력 구성

2

하네스 (Claude Code / Codex)

하네스대표 모델특징
Claude CodeClaude Opus 5.5, Claude Sonnet 5.5워크플로우 실행형 하네스
CodexGPT-6 Astra, GPT-6.1 Sol위임형 하네스

주요 결과 ①: 해결률(Resolved Rate)

36.95%

최고 구성의 평균 해결률
(Claude Opus 5.5 + Claude Code, 최대 노력)

  • 모든 도메인에서 최고인 단일 구성은 존재하지 않음
  • 도메인별로 유리한 시스템이 상이 → 상당한 개선 여지(headroom)
  • 노력(effort) 수준의 효과는 Claude 계열에서 훨씬 큼

주요 결과 ②: 위임 패턴의 차이

Claude + Claude Code

높은 노력 설정에서 워크플로우 실행 횟수는 적지만, 각 워크플로우에 더 큰 워커 그룹 투입

GPT + Codex

위임을 더 자주 수행하며 작은 단위로 분배 (GPT-6 Astra, GPT-6.1 Sol)

도메인이 시스템 내부의 위임 방식을 형성 — 시스템마다 뚜렷이 다른 위임 전략이 관찰됨

주요 결과 ③: 자원 사용

  • 추가 토큰에 대한 수익 반환(returns)은 시스템마다 크게 상이
  • 토큰 기준 비교와 가격 기준 비교의 순위가 뒤집힘 — 비용 구조가 자원 평가를 재정렬
  • 월클록(wall-clock) 회계와 요청 처리 방식까지 포함한 정밀한 실행·비용 추적

성능만 보는 평가로는 불충분 — 오케스트레이션 비용을 과제 예산에 함께 청구하는 것이 WorkflowArena의 핵심 원칙

핵심 실험: 워크플로우 전이 (Transfer)

설정: 실행 모델(executor)을 고정 — 소스 모델은 워크플로우만 작성·수정하고, 모든 워커는 더 약한 실행 모델의 인스턴스

Opus 작성 워크플로우

4개 실행 모델 모두의 연속 점수 향상
평균 +6.41점 (정적 모드, 도전적 과제 부분집합)

Astra 작성 워크플로우

Astra는 실행 모델보다 훨씬 강력함에도 도움이 훨씬 적고, 2개 모델의 점수는 오히려 하락

결론: 워크플로우 오케스트레이션 품질은 단독 과제 수행 능력과 구별되는, 측정 가능한 성능 결정 요인

기여 요약

1

벤치마크

8개 도메인 · 17개 형태의 145개 장기 과제 — 각 산출물 계약에 도메인 특화 숨겨진 검증 결합

2

평가 프로토콜

공유 시간 예산 하의 기록된 위임 인터페이스 — 작업 조직 방식을 결과·자원과 함께 분석

3

실증적 발견

25개 구성 비교 + 고정 실행자 전이 실험으로 오케스트레이션 기여 분리

케이스 스터디: 3D 씬 구성 오케스트레이션 — 실제 프로덕션 도메인에서의 워크플로우 조율 과정 실증

결론

  • 시스템 구조를 모델이 런타임에 결정하는 시대 — 워크플로우 오케스트레이션은 독립적으로 평가해야 할 역량
  • 최고 구성조차 평균 해결률 36.95% — 장기 과제 오케스트레이션에는 여전히 큰 도전 과제
  • 시스템마다 고유한 위임 전략이 존재하며, 도메인에 따라 최적 구성이 달라짐
  • 우수한 워크플로우는 약한 실행자의 성능을 끌어올림 — 조직화 그 자체가 성능의 원천

WorkflowArena는 미래 에이전트 시스템의 "조직 능력"을 측정하는 표준 벤치마크가 될 수 있는 기반
