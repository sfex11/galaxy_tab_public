ScienceBuddy

Recursive-in-Recursive Self-Improvement for Interactive Scientific Agents

연구자와의 협업을 통해 끊임없이 스스로를 개선하는
대화형 과학 연구 워크스페이스

Shuhan Xue, Jianyuan Zhong, Ziyuan Nan 외 · PHAI Labs

연구 동기: 핵심 질문

과학 연구는 분석 → 검토 → 수정의 반복으로 진행됩니다. LLM 에이전트는 증거 검색, DB 질의, 워크플로우 실행을 지원하지만...

대화 중 답을 고치는 것은 과업 간 지속적 개선을 의미하지 않는다

핵심 질문: 과학 에이전트는 어떻게 연구자와의 협업을 작업 절차와 근본 능력의 지속적 향상으로 전환할 수 있는가?

ScienceBuddy 개요

연구자의 요청·피드백·실행 증거를 학습용 과제와 평가 루브릭으로 변환하는 대화형 과학 워크스페이스

기능 모듈
유전체학·분자/암생물학·약리학·바이오이미징·문헌검색·DB 질의

4

과제 패밀리
문헌 읽기·DB 판단·프로토콜 문제해결·유전자/변이 평가

  • 플러그형 프론티어 모델과 에이전트 하네스 지원
  • 온라인 서비스는 유지되며 백그라운드에서 개선 진행

핵심 개념: Recursive-in-Recursive 자기개선

하네스 진화와 모델 강화학습을 결합한 이중 재귀 패러다임

Inner Recursion

내부 재귀: 하네스 개선

모델 고정 상태에서 보조 모델이 실패를 진단하고 지침·스킬·컨텍스트 설정에 제한된 절차적 수정을 제안

Outer Recursion

외부 재귀: 모델 학습

개선된 하네스 하에서 온폴리시 롤아웃을 수집하고 과제별 루브릭 보상으로 GRPO 업데이트 수행

양방향 결합: 하네스 수정은 학습 궤적과 난이도를 형성하고, 모델 업데이트는 상속된 절차의 효과를 변화시킴

상호작용 → 학습 신호 변환

1
연구자 상호작용
요청, 명확화, 실행 기록, 아티팩트 수집
2
과제·루브릭 도출
목표·제약·성공 기준을 과제별 루브릭으로 통합
3
Harbor 과제 패키징
지침·입력·환경을 실행 가능한 과제로 구성
4
진단 & 평가
실행 가능한 검증과 고정 판정자로 절차 진단 및 롤아웃 평가

연구자의 응답은 평가 기준에 반영되지만, 무조건적인 정답 레이블로 사용되지는 않음

내부 재귀: 피드백 기반 하네스 개선

1
피드백 기반 진단
고정된 보조 모델이 실패 사례를 분석하여 절차상 원인 파악
2
하네스 수정
지침·재사용 가능 스킬·컨텍스트 관리 절차에 경계가 있는(bounded) 편집 제안
3
평가와 재귀적 정제
편집 제약 충족 + 쌍별 개발 평가 개선 시에만 후보 채택, 추가 실행이 다음 수정의 증거 제공

하네스를 과학 인프라와 분리함으로써 절차적 변경을 명시적이고 평가 가능하게 만듦

외부 재귀: 지속적 모델 강화학습

Step 1

환경 보강 및 보정

진화 중인 하네스 기준으로 현재 모델에 맞춰 보강된 과제 환경의 난이도 보정

Step 2

과제 적응형 루브릭 보상

새로운 온폴리시 롤아웃 수집, 과제별 루브릭 보상 계산

Step 3

모델 업데이트

루브릭 보상 기반 GRPO 업데이트 — 학습 중 하네스와 루브릭은 고정

  • 과거 상호작용은 과제 정의와 진단 증거로만 활용 (온폴리시 학습 샘플 아님)
  • 재평가 후 업데이트된 모델-하네스 쌍을 함께 배포하여 다음 사이클 시작

재귀 속의 재귀: 전체 사이클 조율

1
연구자 협업
질문·검토·요구 정제
2
내부 재귀
하네스 진화 (모델 고정)
3
외부 재귀
모델 RL (하네스 고정)
4
재평가·배포
다음 사이클 시작

중첩 업데이트 일정

각 외부 사이클은 내부 적응 과정을 통해 학습하고, 다음 사이클에 참여할 모델을 변화시킴

버전 보존

모든 하네스·환경 버전을 보존하여 이후 진화에 활용, 온라인 서비스와 병행 진행

연구자 경험: 워크스페이스 UX

멀티모달 입력

문서·이미지·표·생물학 서열을 통합하고 데이터 업로드 및 실행 가능한 분석 지원

장문 컨텍스트 추론

과학 도구·데이터·지속 파일을 연결하는 지침·스킬·컨텍스트 관리로 장기 에이전트 추론 수행

연구자 상호작용

실행 추적과 아티팩트를 검사하고 후속 대화를 통해 분석을 정제

인터페이스 검증

인터페이스 컨트롤을 통한 증거 검토로 연구자가 결과를 직접 확인

케이스 스터디 1: 실제 연구자 상호작용

JAK1 연구

연구자의 질문과 피드백을 반복하며 JAK1 관련 조사를 정제 — 요청이 과제 명세로 발전하는 과정 관찰

ARL4C 연구

ARL4C 연구에서 증거 간 연결 수행 — 멀티모달 증거 검토와 해석 개선

요청(requests) → 명확화(clarifications) → 실행 기록 → 아티팩트가 함께 과제 명세(task specification)로 변환됨

케이스 스터디 2: 이중 재귀 동역학

한 구성요소를 고정함으로써 다른 구성요소의 변화를 집중적으로 관찰

설정변화하는 요소측정 지표
2-Cycle 동역학 하네스 + 모델 모두 사이클 간 학습 동향 및 과제 성능
모델 고정 하네스만 진화 피드백 접근 가능 평가 과제의 최초 응답 정확도
하네스 고정 모델만 학습 학습 동향 및 문제 커버리지(problem coverage)

벤치마크: LAB-Bench, Biomni-Eval의 4개 과제 패밀리

관련 연구와의 차별성

  • 반성·하네스 최적화 (Reflection 등): 재사용 가능한 지침·절차 수정 → ScienceBuddy는 이를 모델 학습과 결합
  • 상호작용 기반 적응·루브릭 RL: 모델 개선 메커니즘 → ScienceBuddy는 협업 자체에서 과제와 기준을 도출
  • SIA: 하네스+가중치 동시 업데이트 → ScienceBuddy는 중첩된 재귀로 절차와 정책 학습을 조율
  • HELIX: 하네스 진화와 학습 데이터 구성 연결 / AgentBuild: 과학자 작성 루브릭으로 에이전트 구축

ScienceBuddy는 협업 그 자체가 절차 학습과 정책 학습을 조율하는 과제와 평가 기준을 공급하는 최초의 통합 시스템

결론: Discovery Intelligence를 향하여

"에이전트는 짧은 상호작용이 아닌, 경험의 흐름 솔id에서 살아갈 것"
— Silver & Sutton, "Welcome to the Era of Experience" (2025)

  • ScienceBuddy를 연구 제품으로 공개 배포하여 패러다임을 과학 커뮤니티에 제공
  • 연구자의 지속적 협업을 통해 발전하고, 지원하는 연구와 함께 진화하는 과학 AI
  • 협업 → 과제/루브릭 → 하네스 개선 → 모델 학습으로 이어지는 무한 개선 루프 실증
