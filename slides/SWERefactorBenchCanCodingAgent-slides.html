문제 상황: 기술 부채와 마이그레이션

수십 년에 걸친 기술 부채

현대 소프트웨어 시스템은 오랜 개발 기간 동안 기술 부채를 축적하며, 오래된 기술 스택에 묶여 있다.

  • 언어 교체 (C → Rust)
  • 빌드 도구 전환 (Maven → Gradle)
  • 프레임워크 마이그레이션

코딩 에이전트의 진전

버그 수정에서는 점점 더 신뢰할 수 있게 되었지만, 전체 저장소 마이그레이션은 여전히 미지의 영역이다.

"기존 벤치마크는 이 질문에 답할 수 없다"

핵심 질문: 코딩 에이전트가 자율적으로 행동 보존 전체 저장소 마이그레이션을 완수할 수 있는가?

기존 벤치마크의 한계: Blindness

기존 방식 단일 스테이지 평가

고정된 행동 테스트 스위트만으로 평가 → "빨간색에서 초록색으로" 신호에만 의존

  • 마이그레이션 여부 확인 불가
  • 원본 코드 그대로 복사해도 통과
  • 래퍼 패치도 만점 획득

제안 방식 3단계 평가

마이그레이션 완료성과 행동 정확성을 분리하여 독립적으로 검증

  • 마이그레이션 실제 발생 여부 감사
  • 고정 테스트로 행동 정확성 측정
  • 에이전트 검증으로 숨은 차이 탐지
Blindness: 행동만 평가하면 마이그레이션이 일어났는지 확인 없이 만점을 부여할 수 있다. 원본 구현이 테스트를 통과하기 때문이다.

4가지 기술 부채 유형

언어 Language · 7개 과제

프로그래밍 언어 자체를 변경 (예: C → Rust). 가장 난이도가 높은 유형.

프레임워크 Framework · 7개 과제

애플리케이션 프레임워크를 변경. API 계약 변화에 대응 필요.

플랫폼 Platform · 3개 과제

호스트 플랫폼을 변경. 플랫폼 종속 코드를 새 환경에 맞게 재작성.

빌드 도구체인 Build Toolchain · 3개 과제

빌드 시스템 전체를 교체 (예: Maven → Gradle). 에이전트가 가장 잘 수행하는 유형.

설계 원칙: "기술 부채를 먼저 선택하고, 그에 맞는 저장소를 매칭"

3단계 평가 프로토콜

I
마이그레이션 감사
대상 스택이 실제로 기존 구현을 대체했는지 확인. 하나라도 실패하면 즉시 거부 (하드 게이트)
II
행동 테스트
원본 시스템에서 기록한 130,118개 고정 검사 전체 통과 필요. 행동 정확성 측정
III
에이전트 검증
6개 독립 코딩 에이전트가 각 1시간씩 차등 테스트 생성. 실행 가능한 반례로만 거부 가능

각 단계의 방어 목적

깔때기가 좁아지는 3가지 이유

1

마이그레이션을 건너뛴 경우 — 30건

행동을 보존했지만 마이그레이션을 수행하지 않음. 감사 단계에서 거부. "코드를 맞게 짜는 것"과 "마이그레이션을 완수하는 것"은 별개의 능력.

2

마이그레이션했으나 행동을 깬 경우 — 252건

마이그레이션은 완료했으나 기존 행동이 깨짐. 고정 테스트 단계에서 거부. 대다수의 실패가 여기에 해당.

3

고정 테스트는 통과했으나 에이전트 검증에 걸린 경우 — 60건 중 60건

고정 스위트를 통과한 88건 중 에이전트 검증에서 60건이 추가로 거부됨. 고정 테스트만으로는 불충분.

해석

에이전트는 대부분의 마이그레이션 작업을 수행할 수 있지만, 마지막 남은 엣지 케이스를 해결하는 데 어려움을 겪는다. 99%와 100% 사이의 간극이 실제 배포 가능성을 결정한다. 전체 저장소 마이그레이션에서 "거의 맞음"은 "틀림"과 같다.

빌드 도구체인 대비 언어 마이그레이션 난이도: 5.6배 차이

벤치마크 유효성 분석

감사 결정의 일관성

Stage I 감사 결정이 모델 간, 인간 간에 높은 일관성을 보임. 주관적 판단이 아닌 객관적 기준에 기반함을 확인.

에이전트 검증의 가치

고정 테스트가 놓치는 실패를 에이전트 검증이 추가로 발견. 88건 중 60건이 이 단계에서 거부됨.

검증자 구성에 대한 핵심 발견

발견 1: 강력한 코딩 에이전트를 검증자로 사용하는 것이 구성보다 1자리 수 이상 중요

발견 2: 모델은 자신의 계열 모델 작업을 관대하게 평가하지 않음 — 가족 편향(family bias) 미검출

핵심 시사점

"코드를 맞게 짜는 것" ≠ "마이그레이션을 끝내는 것"

두 능력은 반대 방향으로 실패함. 30건은 마이그레이션을 건너뛰고, 252건은 마이그레이션하다 행동을 깸.

둘 다 맞춰도 충분하지 않다

고정 스위트 통과 88건 중 에이전트 검증이 60건을 추가로 거부. 고정 테스트만으로는 안전하지 않다.

마이그레이션 유형에 따라 능력이 크게 다르다

빌드 도구체인 31.4점 vs 언어 5.6점. 단일 점수로 전체 마이그레이션 역량을 평가할 수 없다.

깔때기는 극도로 좁다

520회 실행 중 단 28회(5.4%)만 3단계 전체 통과. 완전한 마이그레이션은 현재 에이전트의 능력을 크게 벗어난다.

결론

SWE Refactor Bench는 장기적, 전체 저장소 스택 마이그레이션을 위한 엄격한 테스트베드를 제공한다. 기존 벤치마크의 Blindness 문제를 식별하고, 3단계 적대적 평가 프로토콜로 해결한다.

기여

  • Blindness 문제 식별 및 벤치마크 구축
  • 3단계 적대적 평가 프로토콜 설계
  • 에이전트 능력 간극의 실험적 증명

향후 방향

  • 마이그레이션 완료성과 행동 보존을 동시에 최적화하는 에이전트 설계
  • 언어 마이그레이션 특화 접근법 연구
  • 마지막 1% 문제 해결을 위한 반복적 검증 전략
"현재 에이전트는 완전하고, 행동을 보존하며, 에이전트 검증에 견고한 마이그레이션을 거의 제공하지 못한다."
