Coding Agents with an Obstacle-Aware Harness for Safe Robot Manipulation

장애물 인식 하니스로 안전을 보장하는 로봇 조작 코딩 에이전트

Bingxin Xu (USC) · Yuzhang Shang (UCF) · Zhen Dong (UCSB) · Emilio Ferrara (USC)

arXiv:2609.20822v1 [cs.RO]

배경: 코딩 에이전트 패러다임

  • 언어 모델이 로봇 제어기를 프로그램으로 작성 — 프로그램이 곧 정책
  • Code as Policies 이후: 실패 후 코드 재작성, 스킬 라이브러리 축적, 테스트 시간 컴퓨팅 확장
  • GPT-6 Astra: 로봇 특화 학습 없이 실제 로봇 구동, 바이맨뮬 접촉 풍부 과제까지 확장
  • Astra 자체에는 로봇 정책이 없음 — 모든 결과는 하니스(도구 호출)에 귀속
학습 없이 코드로 정책을 만드는 패러다임 — 그런데 안전은 아직 물어지지 않았다

문제 제기: 성공 ≠ 안전

기존 평가 방식

벤치마크는 목표 도달 여부만 점수화. 로봇이 가는 길에 무엇을 건드렸는지는 측정하지 않음

현실의 위험

혼잡한 작업 공간에서의 충돌은 하드웨어 손상·인명 피해·재산 파괴로 직결

  • 모델 세대가 올라가도 성공률과 안전성은 반대 방향으로 움직일 수 있음
  • 충돌 없는 시연을 10배 많이 학습해도 충돌률은 3포인트 미만 감소 — 데이터 확장만으론 부족

진단: 원인은 인식도 지시도 아니다

안전 제약 하 평가: 각 과제는 조작 목표 + 만지면 안 되는 장애물로 구성됨

가설검증 결과
인식 문제?아님 — 에이전트는 장애물을 올바르게 식별함
지시 문제?아님 — 프롬프트가 금지를 명시해도, 에이전트는 제약을 재진술한 뒤 위반
계획 문제?예 — 안전 제약이 우선순위가 되지 못함
에이전트는 과제 완수를 유일한 목표로 대우하고, 안전을 등한시함

실패의 두 지점: 경로 ❶과 접촉 ❷

❶ 경로 구간 (자유 공간)

  • 장애물을 피하는 경로 개념이 없어 최단 경로를 선택
  • 경로가 중간에 불가능해져도 재계획 개념이 없음

❷ 접촉 구간 (접촉 풍부 순간)

  • 접촉 실행 자체가 동일한 안전 제약에 묶인다는 인식 부재

더 강한 플래너로도 격차가 해소되지 않음 — 제약이 우선순위로 반영되지 않는 한 계획 품질만 올리는 것은 무의미

SafeHarness: 안전을 1급 목표로

두 개의 장애물 인식 하니스로 안전 제약을 과제 목표와 동등한 최우선 순위로 격상

❶ 장애물 인식 경로 계획

객체를 바운딩 박스로 그라운딩하고 웨이포인트 경로를 그려 계획 → 검증 → 재계획 → 실행

❷ 장애물 인식 접촉 실행

접촉 위치와 그리퍼 회전을 접촉 지점과 장애물의 공간 관계에 따라 결정

첫 안전 점수화 조작 벤치마크에서 하니스 자체가 안전을 보장하는 최초의 코딩 에이전트

장애물 인식 경로 계획 ❶

1
그라운딩
장면 내 객체를 바운딩 박스로 표현
2
경로 생성
웨이포인트 시퀀스로 후보 경로 작성
3
사전 계획·검증
실행 전 경로가 장애물을 피하는지 확인
4
재계획
경로가 불가능해지면 즉시 대체 경로 수립
5
실행
검증이 끝난 경로만 실행

실행 전에 안전을 검증하므로 안전 제약이 항상 과제 목표와 동일한 최우선 순위를 유지

장애물 인식 접촉 실행 ❷

접촉 순간의 안전은 접촉 위치 선택에서 결정됨

접촉 지점 주변 확인 — 접촉 위치 옆에 장애물이 서 있는지 검사
접촉 전략 결정 — 정확한 접촉 위치와 그리퍼(손목) 회전 여부를 장애물 유무에 따라 선택
픽과 플레이스 모두 — 객체를 집는 위치와 놓는 위치에서 동일한 질문을 반복
접촉 자체가 장애물을 피하도록 설계 — 접촉 풍부 구간의 안전 공백 해소

핵심 기여

1. 안전한 코딩 에이전트

코딩 에이전트를 안전 제약 하에서 최초로 평가. 하니스 자체가 접촉 풍부 구간을 포함해 전 과제 안전을 보장하는 최초의 사례

2. SafeHarness

두 장애물 인식 하니스가 안전을 1급 목표로 취급 — ❶ 경로 계획·검증·재계획, ❷ 접촉 위치와 손목 회전 선택

3. 결과

SafeLIBERO에서 71.9% 성공 / 87.5% 충돌 회피로 SOTA 경신, 기존 에이전트 대비 2.3× / 1.5× 개선

결론

코딩 에이전트의 안전은 모델 능력이 아니라 하니스 설계의 문제다. 장애물 인식 경로 계획과 접촉 실행을 통해 안전 제약을 과제 목표와 동등하게 만들면, 학습 없이도 안전한 로봇 조작이 가능하다.
