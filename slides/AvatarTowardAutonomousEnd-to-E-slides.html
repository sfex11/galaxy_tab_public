Avatar

LLM을 활용한 과학 워크플로우의 자율적 엔드투엔드 오케스트레이션을 향하여

Toward Autonomous End-to-End Orchestration of Scientific Workflows using LLMs

Suman Raj · Hai Duc Nguyen · Haochen Pan · Ryan Chard · Kyle Chard · Ian Foster

University of Chicago · Argonne National Laboratory

배경: 과학 워크플로우와 에이전틱 AI의 만남

과학 발견은 점점 더 복잡한 계산 캠페인에 의존하고, LLM 에이전트는 그 운영 방식을 바꾸고 있습니다.

복잡해지는 과학 계산 캠페인

  • 시뮬레이션 · 데이터 분석 · 머신러닝 · 분산 계측기 · 이기종 자원의 결합
  • 연구자는 과학적 의도를 실행 가능한 워크플로우로 번역하는 데 큰 노력 소모
  • 런타임 구성, 모니터링, 실패 진단, 조건 변화에 대한 적응도 연구자의 몫

LLM 에이전트의 가능성

  • 워크플로우 그래프 추론, 작업 계획 수정, 자원 선택
  • 모니터링 피드백 해석, 로그·프로비넌스 기반 실패 진단
  • 워크플로우 관리를 더 적응적이고 자율적인 오케스트레이션으로 전환
Pegasus, Parsl 등 WMS는 이미 필요한 추상화를 제공 → AI 에이전트가 외부 보조 도구가 아닌 오케스트레이션의 직접적 참여자가 되는 흐름

문제: 풀리지 않은 세 가지 질문

LLM 에이전트는 자율적 오케스트레이션을 약속하지만, 실제 도입은 쉽지 않습니다.

1
어디에 도입할 것인가? — 에이전틱 추론을 워크플로우 생애주기의 어느 지점에 넣을 것인가
2
위험은 어떻게 경계할 것인가? — 잘못된 에이전트 결정이 실행에 미칠 피해를 어떻게 제한할 것인가
3
언제 실제로 도움이 되는가? — 기존 규칙 기반 제어보다 나은지는 언제, 어떻게 검증할 것인가

근본적인 아키텍처 간극

기존 WMS는 에이전틱 추론이 아닌 고정된 수작업 규칙과 사람이 구성한 제어 중심으로 설계되었습니다. 성숙한 시스템일수록 규모가 크고 운영이 복잡해 개조 비용이 크며, 공통 지침이 없어 각 시스템이 독자적으로 통합 → 협소하고 일반화·평가가 어려운 결과를 낳습니다.

관련 연구: 세 갈래 접근과 남은 간극

제한적 보조

Pegasus(사양 기반 생성·검증·모니터링), HyperFlow(질문 → 구조화된 의도), Parsl + LangChain/LangGraph(도구 호출)

오류 파급은 제한되지만 에이전틱 추론이 특정 단계에만 국한

추론 기법 강화

Chain-of-Thought, ReAct, Tree-of-Thoughts, Reflexion, AutoGen, AgentGen 등 다단계 계획·자기비판 기법

범용 환경에서 평가되어 과학 워크플로우의 의존성·자원·장기 실행 요구와 단절

실행 권한 확대

SWARM(작업 선택·스케줄링·복구 분산), RHAPSODY(공유 추상화), Academy, FireWorks 기반 자율 캠페인

잘못된 결정의 영향 때문에 특정 계층·결정 클래스로 권한 제한

Avatar: 세 액터로 구성된 참조 아키텍처

특정 LLM·에이전트 프레임워크·WMS가 아니라, 기존 시스템의 반복 책임에서 도출

Orchestrator

논리적 워크플로우 결정 관리 — 무엇을, 언제, 어떤 순서로 수행할지

Executor

런타임 자원 위에서 오케스트레이터의 결정을 실제 실행으로 구현

Provenance Monitor

이후 결정에 필요한 증거를 관찰하고 유지

각 액터는 명시적인 상태(state) · 결정(decision) · 행동(action) 인터페이스를 노출 → 규칙 기반 정책, LLM 에이전트, 하이브리드 방식을 주변 아키텍처 변경 없이 삽입 가능

하나의 코어, 교체 가능한 의사결정 정책

1
상태 관찰
Provenance가 워크플로우 상태·증거 제공
2
정책 결정
규칙 기반 또는 LLM 기반 정책이 결정
3
어댑터 검증
액션 카탈로그로 행동 검증·위험 경계
4
실행
Executor가 런타임 자원에서 실행

어댑터 검증 액션 카탈로그

허용된 행동만 단일 카탈로그를 통해 수행 → LLM 결정의 위험을 구조적으로 경계(bound)

동일 코어, 두 가지 모드

규칙 모드는 기존 실행을 그대로 재현하고, LLM 모드는 자율 오케스트레이션 수행 — 아키텍처는 고정, 정책만 교체

구현: Academy 기반 확장형 프로토타입

  • Academy 프레임워크로 액터 기반 프로토타입 구현 — HPC 시스템, 과학 계측기, 데이터 저장소에 상태 기반 에이전트를 배포·조율
  • 서로 다른 에이전트, 도구, 모니터링 인터페이스, 검증 전략을 체계적으로 통합하고 비교 가능
  • 관례적 제어와 에이전틱 제어가 동일한 코어 위에서 여러 워크로드를 구동

설계 철학

아키텍처를 고정한 채 추론 정책만 교체함으로써, "에이전트가 도움이 되는가?"라는 질문을 통제된 조건에서 실험할 수 있는 공통 기반을 제공

LLM 모드 측정

자율 오케스트레이션이 낭비 계산과 자원 사용에 미치는 영향 분석

핵심 방법론: 아키텍처는 고정하고 추론 정책만 교체 → 규칙 대비 에이전트의 효과를 통제된 조건에서 비교

주요 결과

55%

컴퓨팅 낭비(compute wastage) 감소 — LLM 기반 Avatar가 불필요한 계산을 줄임

40%

GPU 사용(GPU-busy) 시간 감소 — 자원 점유 시간의 유의미한 절감

규칙 모드 = 기존 실행의 충실한 재현

변경되지 않은 단일 코어가 세 워크로드를 모두 구동하며 native 실행을 재현 — 아키텍처의 보수성과 안전성을 입증

상호작용

기존 워크플로우 메커니즘과 어떻게 상호작용하는가

  • 언제 에이전틱 오케스트레이션이 도움되고, 언제 기존 메커니즘이 나은지 — 그리고 어떤 아키텍처 요인이 결과를 결정하는지 통제된 평가
  • 모델·에이전트 구성·워크플로우·인프라 조건 전반에 걸친 체계적 비교 가능
