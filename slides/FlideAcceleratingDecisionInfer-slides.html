배경: 결정 모델의 부상

LLM 에이전트 시스템에서 Jev 같은 결정 모델이 유망한 패러다임으로 떠오름

요청 라우팅

들어온 요청을 적절한 경로로 분류

응답 평가

응답 품질에 대한 신뢰도 판정

에이전트 행동 결정

다음 행동 단계 선택

  • 경량·신뢰할 수 있는 범주형 추론으로 System One 빠른 실행 담당
  • 긴 컨텍스트(대화, 에이전트 궤적)를 보고 여러 질문에 이산 선택 확률 분포 출력
  • 엄격한 확률 임계값이 적용되는 신뢰도 민감형 워크로드

문제: 기존 추론 엔진의 한계

vLLM·SGLang 같은 생성 지향 엔진은 결정 워크로드에 부적합

접두사 재계산

모든 질문을 독립 프롬프트로 취급 → 공유 컨텍스트를 질문마다 반복 계산. 하이브리드 아키텍처에서는 블록 경계 이후 토큰을 매번 재계산

확률 왜곡

Multi-item scoring: 질문 앞마다 구분자 토큰을 붙여 한 시퀀스로 처리 → 구분자가 은닉 상태를 변형시켜 출력 확률이 뒤틀리고 결정이 뒤집힘

비결정론적 배치

동적 배칭에 따라 부동소수점 합산 순서가 변함 → 동일 요청인데 서버 부하에 따라 결정이 흔들림

신뢰성·효율성 동반 저하

속도와 정확성을 동시에 보장하는 결정 모델 서빙이 현실적으로 불가능

근본 원인: 논리 구조와 물리 구조의 불일치

논리적으로 질문들은 공유 상태(trunk)에서 뻗은 나무 가지(branch)이지만, 물리적으로는 하나의 평면적 토큰 스트림으로 실행되어야 한다

생성 엔진 (vLLM 등)

논리 구조 = 물리 구조로 묶음
→ 질문마다 별도 시퀀스, trunk를 다시 계산·리로드

Multi-item scoring

가지를 함께 실행하지만 트리를 시퀀스 자체에 기록
→ 구분자 토큰이 모든 가지의 입력을 오염

해결책: 가지들을 함께 실행하면서도 각 가지가 혼자 실행했을 때와 정확히 동일하게 계산되도록

Flide: 핵심 아이디어

Flat-Graph Inference for Decision Models

요청의 논리적 트리 구조와 GPU 물리 실행을 분리

1
평면화
한 라운드의 요청들을 하나의 flat 토큰 스트림으로 배치
2
메타데이터
의존 관계(트리 구조)를 GPU 상주 인덱스로 기록
3
ForkAttention
Attention·Gated DeltaNet 층이 메타데이터를 따라 의존성 탐색
4
정확성 보장
정확 산술 하에 각 질문이 단독 실행과 동일한 결과 산출
  • trunk를 한 번만 계산하고 여러 짧은 가지가 한 패스에 GPU를 채움
  • 구조가 데이터로 인코딩되어 소수의 기록된 실행 그래프로 다양한 요청 조합 서빙

ForkAttention: 두 종류 층에서의 정확한 포킹

Full-Attention 층

GPU 상주 인덱스로 마스크를 구성해 각 가지가 trunk와 자기 자신만 보도록 제한 — 형제 가지의 간섭 차단

Gated DeltaNet 층

순환 구조는 모든 이전 토큰을 하나의 재현 상태로 압축 → 형제를 상속하는 문제 발생. 각 가지가 trunk의 정확한 상태에서 재시작하도록 상태 포킹 수행

핵심은 trunk를 계산하는 동일한 패스 안에서 각 가지가 trunk의 정확한 상태로 분기하는 것

정확성 보장 (Exactness)

정확 산술 하에서 모든 쿼리 가지가 단독 forward pass와 산술적으로 동일하게 평가됨을 명제로 증명 (부록 A)

Flat-Graph Execution

  • GPU 상주 메타데이터: 스트림 위의 브랜치 태그와 그래프 정보를 호스트 왕복 없이 GPU에서 직접 해석
  • 스트림 길이 기반 그래프: 요청 길이 분포별로 사전 기록된 실행 그래프 집합을 재사용 → 새 요청 조합에도 유연 대응
  • 선택적 판독(Selective Readout): 스트림에서 필요한 가지의 결과만 골라 읽어 반환

증분 상태 포킹

성장하는 에이전트 히스토리가 이전 패스에서 저장한 체크포인트에서 재개 — 매 단계마다 전체 궤적 재계산 불필요

비트 결정론 (선택)

배치 불변 모드로 부동소수점 합산 순서를 고정 → 서버 부하와 무관하게 비트 단위 동일한 답 보장

실험 설정

워크로드

지문당 질문 1개부터 기사·에이전트 궤적에 여러 질문이 붙는 시나리오까지

베이스라인

최신 vLLM, SGLang (multi-item scoring 포함)

지표

지연시간/처리량, 총변동거리(TVD)로 측정한 float32 참조 대비 정확도

모델

공개 하이브리드 모델(Qwen3.5 등 attention + Gated DeltaNet)과 전용 결정 모델

주요 결과: 처리량

최대 9.5×

vLLM·SGLang 대비 빠른 답변 속도

  • 공개 하이브리드 모델에서 최대 한 자릿수(주문 오더) 향상 달성
  • 공유 상태에 여러 질문이 걸리는 경우 모든 동시성 수준에서 처리량 선두
  • 전용 결정 모델에서도 리더십 유지
  • trunk를 한 번만 계산하고 짧은 가지들이 한 패스를 채워 GPU 활용률 극대화

성장하는 상태, 시작 지연, 메모리·GPU 시간 분석 등 심층 분석에서도 Flide의 이점이 일관되게 확인됨

주요 결과: 정답 충실도

속도만이 아닌 수학적 정확성에서도 최고 성능

방식확률 분포 충실도 (TVD)특징
Multi-item scoring 참조에서 이탈 (확률 이동) 구분자 토큰이 결정을 뒤집을 수 있음
Flide float32 참조에 가장 근접 단독 실행과 동일한 출력 보장

"물리 실행 처리량과 수학적 정확성을 통합" — 속도를 위해 정확성을 희생하지 않음

선택적 배치 불변 모드로 비트 단위 재현성까지 확보 가능
