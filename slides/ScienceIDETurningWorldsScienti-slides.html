ScienceIDE

세계의 과학 코드베이스를 에이전트 학습 가능한 환경으로

배경: 과학 코드에는 방대한 지식이 담겨 있다

실행 가능한 인류의 지식

  • 수십 년간 축적된 검증된 수치 모델과 알고리즘
  • 시뮬레이터, 솔버, 데이터 처리 도구
  • 외부에서 검증 가능한 훈련 신호의 원천

코딩 에이전트의 성공 공식

  • 리포지토리·컴파일러·테스트가 행동을 관찰 가능하게 함
  • 결과 검증 → 실패로부터 학습 → 강화학습 가능
  • 텍스트만으로는 얻을 수 있는 경험 이상의 것

그런데 왜 과학 지능은 여전히 어려운가?

핵심 문제: 과학적 경험 병목 (Scientific Experience Bottleneck)

파편화된 툴체인

이기종 도구와 설정 때문에 과학 리포지토리를 재현 가능하게 실행하기 어려움

암묵적 도메인 관례

검증이 물리량·수치 허용오차·문서화되지 않은 관례에 의존

특수한 정답 기준

실행 가능한 코드가 학습 가능한 태스크가 되려면 행동 검증·단계별 피드백이 필요

논문·리포지토리·데이터셋이 있다고 해서 훈련 가능한 환경이 자동으로 만들어지지는 않는다

ScienceIDE란?

세계의 과학 코드를 과학 에이전트를 위한 프로그래밍 가능한 환경으로 바꾸는 개방형 인프라

전문가 주도 설계

도메인 전문가가 과학적 책임 범위, 수용 기준, 보정된 검증 정책을 정의하고 AI 에이전트가 이를 실행

재사용 가능한 환경

하나의 환경이 수리·구현·재현·가속화 태스크를 모두 지원하며, 검증된 상호작용 궤적을 생산

하나의 기반, 세 가지 용도

동일한 환경이 지도 미세조정(SFT), 온라인 강화학습(RL), 평가의 공통 기반으로 작동

핵심 개념 4가지

개념정의역할
과학 모듈
(Module)		 버전 관리되는 코드베이스 내 일관된 과학적 책임과 실행 가능한 커버리지를 가진 단위 환경 구축의 기본 단위
환경
(Environment)		 승인된 모듈 + 런타임 + 과학적 체크의 패키지 태스크 생성·실행·검증 지원
팩토리
(Factory)		 환경별 저작 절차를 특화하여 유효한 태스크를 생성 초기 작업공간·산출물·검증기 지정
에피소드
(Episode)		 태스크에 대한 에이전트의 한 번의 상호작용 결과물·궤적·측정된 성과 생산

구축 파이프라인: 코드베이스에서 실행 환경까지

1
코드베이스 분석
에이전트가 고정된 리비전·의존성·라이선스를 점검하고 빌드·테스트 실행
2
모듈 분해 제안
과학적 책임·입출력·알고리즘 단계·테스트 범위로 모듈 정의
3
전문가 검토
도메인 전문가가 분해와 커버리지를 검토, 모듈 경계와 동등성 계약 소유
4
환경 패키징
편집 가능한 작업공간·체크·비공개 검증기와 함께 런타임 패키징

전문가의 노력은 개별 태스크가 아닌 과학적 경계와 새로운 목표에 집중됨

공식 테스트를 과학적 체크로

코드가 이미 가진 테스트와 전문가 허용오차를 실행 가능한 계약으로 고정하고, 태스크 저작과 분리

보정된 통과 정책

  • 물리량과 수치 허용오차 기반의 판정
  • 공식 테스트에 보정된 pass policy 적용
  • 환경별 실행 가능한 체크로 저장

과학적 동등성 판정

  • 결함 주입부터 고비용 경로 포팅까지
  • 허용오차 내 과학을 복원했는지로 채점
  • 에이전트 작업공간과 검증기는 분리

모든 태스크의 정답 기준 = 허용오차 이내에서 과학적 결과를 회복하는가

  • 코드·추론·지식 범용 벤치마크에서도 선별적 개선
  • 과학 경험 → 일반 능력으로의 양의 전이(positive transfer) 입증

태스크 균형 기준 예산 소진율

하위 집합에서 에이전트들이 주어진 자원 내에 해결하지 못하는 비율

궤적 분석 발견

  • 참조 관례(reference-convention) 불일치가 태스크 균형 실패의 주요 원인
  • 과학적 재구성에는 코드베이스 특유의 관례 이해 필요
  • 지역 테스트 통과 ≠ 과제 완수, 정답 코드 ≠ 완전한 과학적 산출

더 많은 지출이 반드시 더 높은 성공을 보장하지 않음 — 장기 과학 과제의 특성을 보여주는 대표 사례

학습 효과: SFT와 RL

지도 미세조정 (SFT)

  • 과학 환경 전반에서 수리 보상(repair reward) 개선
  • 코드·추론·지식 태스크로 이득 확장
  • 공개 벤치마크에서 스크리닝 기준 향상 확인

강화학습 (RL)

  • 온라인 검증기 피드백이 홀드아웃 과학 보상을 실질적으로 개선
  • 예산 소진은 실패가 아님 — 장기 과제의 종료 처리가 핵심 난제
  • 컨테이너 기반 실행 스택과 종료 진단 체계 구축

과학 코드라는 검증 가능한 환경이 존재하기에 비로소 검증 가능한 보상을 통한 RL이 가능해진다

기여와 의의

  • 병목 해결 인프라 — 파편화된 과학 코드를 실행 가능하고 검증 가능한 학습 환경으로 체계적 전환
  • 전문가 노력의 재사용 — 모듈 경계와 동등성 계약을 한 번 정의하면 팩토리가 태스크를 확장 생산
  • 개방형 레지스트리 — 도메인을 선택해 에이전트를 학습·평가하고, 다시 과학 현장으로 복귀시키는 순환 구조
  • 양의 전이 입증 — 과학 경험이 코드·추론·지식 등 일반 능력을 향상시킴을 실증

인류의 과학 소프트웨어를 과학 지능 개발의 공유 기반(substrate)으로 만드는 통합 작업공간의 토대
