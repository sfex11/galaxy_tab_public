Prime Agent:
A Self-Improving RLM Harness

장기 수평 에이전시를 위한 오픈소스 하니스

Seth Karten, Alex L. Zhang, Kevin Thomas 외 · Princeton University, Prime Intellect, MIT

문제 제기: 언어 모델의 근본적 한계

강한 언어 모델 단독으로는 컴퓨터의 전체 능력을 갖추지 못한다. LLM은 유한 순차적 프로세서이며, 다음 결정은 가중치와 활성 컨텍스트에 노출된 상태 정보만 사용할 수 있다.

순차 처리의 한계

  • 토큰 컨텍스트 외부 정보 접근 불가
  • 외부 계산(코드 실행) 불가
  • 상태 유지 및 복구 불가

하니스가 필요한 이유

  • 툴 호출을 통한 외부 행동 수행
  • 가중치 외부 정보 관리
  • 테스트 타임 컴퓨트 확장

Prime Agent: 핵심 아이디어

하니스는 모델이 세계를 관찰하고 행동하는 막 membrane이다. 모델은 하니스의 한계가 아닌 자신의 진정한 능력 부족 때문에만 평가에서 실패해야 한다.

정보

컨텍스트 처리, 압축, 지속적 이력, 수정 가능한 메모리

계산

프로그램, 툴 호출, 재사용 가능 스킬, 병렬 재귀 서브에이전트

조율

직접 에이전트 간 통신, 인간-에이전트 상호작용

표현력이 핵심: 하나의 워크플로우를 인코딩하는 대신, 모델이 추론 시점에 프로그램, 서브에이전트, 피드백 루프를 구성할 수 있는 원시적 요소를 노출한다.

정보 계층 구조: L0 ~ L3

폰 노이만 아키텍처처럼, 모델은 현재 생성 중인 명령어 외부의 주소 가능한 상태를 읽고, 변환하고, 쓸 수 있다.

L0
모델 가중치
고정, 파인튜닝으로만 변경
L1
활성 컨텍스트
토큰 시퀀스, 압축으로 재작성
L2
REPL + 서브에이전트
에이전트 가비지 컬렉션
L3
디스크 지속 상태
이력, 메모리, 스킬, 개선으로 버전 관리

L1 ↔ L2 경계가 핵심: 토큰 가시적 모델 상태와 명시적으로 관리되는 계산/유지 상태를 분리한다. Python 값과 툴 출력은 L2에 존재하며, 직렬화되어야만 L1(생성)에 진입한다.

아키텍처 개요

지속적 IPython REPL

각 세션이 소유하며, 턴 간 중간 값 유지

재귀 서브에이전트

고유 컨텍스트, 커널, 이력, 워크스페이스 보유

직접 에이전트 간 통신

비동기 데몬 중재 큐, 부모-자식-형제 주소 지정

Continual Harness

궤적 증거를 재사용 가능한 상태로 변환

Agents View

데몬 세션 검사, 첨부, 관리 시각 인터페이스

표준화된 실행

복구, 검증, 리소스 회계 표준화

프로그래밍적 계산과 RLM 추상화

지속적 REPL의 이점

  • 큰 로그, 태스크 사양, 구조화된 출력을 반복 직렬화하지 않음
  • 중간 값이 턴 간 유지되며, 선택될 때까지 활성 컨텍스트 외부에 존재
  • 툴은 Python 모듈로 임포트되어 일반 코드로 파싱·필터링·검증

비동기 rlm 원시적 요소

  • 서브에이전트 세션 생성 및 스케줄링
  • 완료 전 안정적인 핸들 반환 (비동기)
  • 부모는 로컬 계산 계속, 결과는 나중에 도착
  • 압축/재시작 후에도 후속 조치 가능

모델은 로컬 코드, 툴, 순차 위임, 병렬 서브에이전트 중 스스로 선택하며, 고정 워크플로우 그래프가 아닌 Prime Agent가 실행 의미를 정의한다.

재귀적 오케스트레이션과 상호작용

세션 생명주기

R
Running — 턴 또는 툴 연산 중
I
Idle — 로드되었으나 활성 턴 없음
N
Inactive — 언로드되었으나 지속 상태에서 복구 가능

통신 및 복구

  • 데몬이 클라이언트와 독립적으로 세션 소유
  • 클라이언트 분리 시 세션 계속 실행
  • 안정적인 세션/부모 식별자로 재귀 토폴로지 보존
  • 수신자가 다시 활성화되면 큐 메시지 사용 가능
  • 인간이 개별 세션에 검사·메시지·첨부·개입 가능

Continual Harness: 궤적에서 상태로

궤적 증거를 재사용 가능한 상태로 변환하여 이후 계산을 개선하고, 향후 모델 세대의 학습에 활용한다.

이력

추가 전용 이벤트 기록, 커널 스냅샷, 컨텍스트/압축 기록

메모리

선택된 Continual Harness 항목을 후속 프롬프트에 조립

스킬

재사용 가능한 코드 패턴, 서브에이전트 명세 버전 관리

브랜칭/포킹은 이전 이벤트 시퀀스를 삭제하지 않고 새 논리적 연속을 생성한다. 비직렬화 가능한 객체는 저장된 아티팩트나 외부 서비스에서 재생성된다.

장기 실행 및 평가 의미론

평가 메트릭

  • 고정 지출 점수 — 비용/토큰/시간 기준
  • 실용적 안정점 점수 — 시간에 따른 성능 곡선 분석

표준화 제어

  • 실행, 복구, 검증, 리소스 회계 표준화
  • 전략 구성은 모델에 위임
  • 토큰, 시간, 비용을 개별 보고
하니스 실패가 모델 실패가 되지 않도록, 낮은 마찰과 높은 표현력을 갖춘 막을 설계하여 측정된 성능을 모델의 진정한 최대 근본 능력에 가깝게 끌어올린다.

ARC-AGI-3 RHAE 평가 결과

Prime Agent는 ARC-AGI-3 RHAE에서 30% → 95.5%로 극적인 성능 향상을 달성했다.

상호작용적 추론, 프로그래밍적 컨텍스트 처리, 테스트 타임 컴퓨트 확장의 결합이 핵심이다. 모델이 직접 전략을 구성하도록 하면서도, 하니스가 안정적인 실행 기반을 제공한다.

다양한 벤치마크 평가

벤치마크 Prime Agent 비교 대상 결과
장문 코딩 Prime Agent Pi, Claude Code, Codex 동등 또는 우수
GPU 커널 생성 Prime Agent 기타 하니스들 동등 또는 우수
에뮬레이터 구축 Prime Agent Hermes, OpenCode, Kimi-Code 우수
nanoGPT 스피드런 Prime Agent — 85.5시간, 19건 검증 기록

Hermes Agent, OpenCode, Kimi-Code 등 다른 하니스에 대해 일관되게 동등 또는 우수한 성능을 보여, Prime Agent의 범용 하니스로서의 효과성을 입증한다.

Factorio 및 MazeBench: 장기 자율 실행

Factorio

  • 4인 캐릭터 동시 제어
  • 개선(refinement)을 통한 연속 기술 진행
  • 전용 서브에이전트로 병렬 작업 수행
  • 에이전트 간 직접 통신으로 동적 조율

MazeBench

  • 장기 수평 미로 탐색
  • 지속적 상호작용 및 개선
  • 메모리와 스킬의 축적 효과
  • 세션 복구 후에도 상태 유지

이 실험들은 Prime Agent가 수십 시간 단위의 자율 실행에서도 상태 손실 없이 안정적으로 작동함을 보여준다.

핵심 기여 및 결론

기여 요약

1
L0–L3 정보 계층 — 폰 노이만식 상태 관리
2
지속적 REPL + RLM — 프로그래밍적 테스트 타임 컴퓨트
3
Continual Harness — 궤적 → 재사용 가능 상태
4
직접 통신 + Agents View — 스웜 조율 및 인간 개입
5
표준화된 평가 하니스 — 하니스 실패 ≠ 모델 실패

핵심 통찰

표현력이 하니스의 핵심 속성이다. 고정 워크플로우가 아닌 원시적 요소를 노출하여 모델이 추론 시점에 자신만의 전략을 구성하게 한다. 이로써 측정된 성능이 모델의 진정한 근본 능력에 근접하도록 만든다.
