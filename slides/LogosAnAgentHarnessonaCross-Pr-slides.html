Logos: An Agent Harness
on a Cross-Process Bus

공간시간 조합성 계산법을 프로세스 경계를 넘어 확장하는
분산 에이전트 하네스 아키텍처

Hanzhang Jia, Liheng Zeng, Hao Cheng, Yi Gao, Bo Ma

University of Sussex · Zhejiang Gongshang University · Shanghai Shuyuan

단일 프로세스 에이전트 시스템의 한계

현대 에이전트 시스템은 런타임에 기능을 동적으로 조립합니다. 이 조립은 공간시간 조합성 계산법(spatiotemporal-composability calculus)으로 형식화되었으나, 기존 구현은 단일 프로세스에 모든 것을 올립니다.

장애 전파

크래시, 메모리 고갈, 이벤트 루프 블록이 모든 컴포넌트를 동시에 중단시킵니다.

의존성 연쇄 해제

하나의 서비스 철수가 의존 컴포넌트까지 해제하여 도구를 일시적 불가능하게 만듭니다.

세션 일괄 종료

프로세스 사망 시 모든 공존 세션이 동시에 종료되고 전체 스택을 재시작해야 합니다.

단일 언어 제약

플러그인이 호스트 언어에 갇히며, 교차 언어 재사용에 번역층과 원격 호출이 필요합니다.

공간시간 조합성 계산법이란

"기능은 추적된 역함수를 갖는 컴포넌트이며, 에이전트는 플러그인으로서 조립된다."

— Shi et al., 2026

조립 (Assembly)

효과 함수 f가 상태 γ를 새 상태 δ와 역함수 g의 쌍으로 매핑합니다. g(δ) = γ를 보장합니다.

제거 (Removal)

기록된 역함수를 적용하여 효과를 완전히 되돌립니다. 가역성 보장의 핵심입니다.

핵심 관찰: 계산법의 모델링도, 수학도 에이전트를 단일 프로세스에 묶지 않습니다. 언어 모델 추론의 무상태성(statelessness)이 교차 단계 상태를 이미 모델 외부에 두며, 건전성 불변식은 상태 공간만으로 정의됩니다.

네 가지 보조정리 — 프로세스 간 조합성의 충분조건

새로운 수학적 가설 없이, 계산법의 기존 가정과 언어 모델의 무상태성만으로부터 도출됩니다.

1
편집 외부성 (Orchestration Externality)

모델의 순방향 패스는 무상태 순수 맵이며, 교차 단계 상태는 이미 모델 외부에 존재하고 입력은 어디서든 합성 가능합니다.

2
반송체 대체 (Carrier Substitution)

상태를 임의의 지속적 반송체로 이동할 수 있으며, 반송체로부터 재구축된 복구는 관측적 동치 하에서 제자리 복구와 동등합니다.

3
복구 지역화 (Recovery Localization)

계산법의 컴포넌트 독립성 가정에 따라, 각 컴포넌트의 복구는 다른 컴포넌트와의 조정이 필요 없습니다.

4
외부 해결 (External Resolution)

의존성 해결을 프로세스 외부로, 기능 이름을 키로 하는 테이블로 이동할 수 있습니다.

정리 1 — 프로세스 간 가역성 보장

공간시간 조합성 계산법의 가역성 보장은, 네 가지 보조정리의 전제가 충족되는 한, 단일 프로세스 경계를 넘어 성립한다.

전제 요약

  • 계산법이 이미 가정하는 컴포넌트 독립성과 추적된 역함수
  • 언어 모델 추론의 무상태성 (stateless forward pass)
  • 교차 단계 상태가 모델 외부에 존재함
  • 건전성 불변식이 상태 공간만으로 정의됨

결론: 새로운 수학적 가설 없이, 기존 체계의 논리적 귀결로서 프로세스 간 조합성이 보장됩니다. 이것이 Logos 구축의 이론적 기반입니다.

Logos 아키텍처 개요

ROS 아키텍처를 기반으로 한 분산 플러그인 기반 시스템. 버스 위의 피어 프로세스 집합으로 실행됩니다.

라우터 (Router)

노드 등록 및 수신자 기반 메시지 전달. 라우팅 테이블만 보유.

하네스 (Harness)

하나의 세션에 대해 입력 합성, 모델 호출, 출력 정산의 루프를 실행.

툴 (Tool)

하나의 기능을 제공하는 독립 프로세스.

핵심 원칙 1: 플러그인 = 프로세스. 각 기능이 자체 OS 프로세스를 가집니다.

핵심 원칙 2: 유일한 공유 상태 = 추가 전용 트랜스크립트. 어떤 프로세스도 소유하지 않습니다.

추가 전용 트랜스크립트와 콜드 스위칭

트랜스크립트 (Transcript)
  • 세션의 모든 단계를 순서대로 기록
  • 추가 전용 (append-only) — 어떤 프로세스도 소유하지 않음
  • 프로세스 사망 후 복구의 유일한 정보원
콜드 스위칭 (Cold Switching)
  • 프로세스 사망 시 새 프로세스가 트랜스크립트에서 세션 재구축
  • 복구된 프로세스가 중단 지점부터 계속 실행
  • 이전에 실행된 액션은 절대 반복되지 않음

기존 프레임워크와의 비교

프레임워크 프로세스 밖으로 이동 프로세스 내부에 남음
MCP 및 파생 툴 서버와 호출 조립 및 세션 상태
Temporal 등 실행 조립 및 워크플로우 정의
AutoGen, LangGraph 없음 모든 기능 (인프로세스 객체)
Logos 조립, 조립 상태 → 트랜스크립트 라우팅 테이블뿐

Logos의 차별점: 기존 프레임워크는 실행이나 툴 호출만 프로세스 밖으로 내보내고 조립은 호스트에 남깁니다. Logos는 조립과 조립 자체를 피어 노드 간 등록과 브로드캐스트로 프로세스 밖으로 이동시킵니다.

다국어 운영과 자율 도구 채택

혼합 언어 버스
  • Go — 라우터
  • Python — 하네스 및 툴
  • Node.js — 툴
  • 모두 동일 버스 위의 피어로 실행
자율 도구 채택

작업 수행 중 새 툴이 온라인되면, 레지스트리 업데이트 브로드캐스트 이후 모델이 8.4초 만에 자율적으로 첫 호출을 수행합니다.

버스 홉의 중앙값 비용은 0.215ms로, 모델의 첫 토큰 지연시간 177ms의 1/823에 불과합니다.

의미: 단일 언어 제약(비용 #4)이 완전히 제거됩니다. 프로토콜 준수만 하면 어떤 언어의 프로세스도 피어로 마운트 가능합니다.

단일 프로세스 vs 프로세스 간 — 장애 격리 비교

단일 프로세스 참조 구성
  • 하나의 장애가 모든 공존 세션을 중단
  • 모든 컴포넌트가 동시에 종료
  • 전체 스택 재시작 필요
  • 수학적 격리가 물리적 공유로 무력화
Logos 피어 프로세스 구성
  • 하나의 장애가 하나의 노드에서만 종료
  • 다른 노드와 세션은 정상 유지
  • 콜드 스위칭으로 영향 노드만 재개
  • 수학적 격리가 물리적 격리와 일치

핵심 메시지: 동일 장애 조건에서 단일 프로세스는 모든 세션이 중단되지만, Logos에서는 장애 노드 하나만 영향을 받습니다. 조합성 계산법의 수학적 격리가 비로소 물리적으로 의미를 갖습니다.

세 가지 기여 요약

1
충분조건 (제4절)

공간시간 조합성 계산법의 가역성 보장이 프로세스 간에 성립하는 정리 1과 네 가지 보조정리. 전제는 계산법 자체의 가정과 언어 모델 무상태성뿐.

2
Logos 구성 (제5절)

ROS 아키텍처 기반의 최소 분산 에이전트 하네스. 플러그인은 프로세스, 유일한 공유 상태는 추가 전용 트랜스크립트. 라우팅 테이블 외에 프로세스 간 공유 상태 없음.

3
적대적·엔드투엔드 평가 (제6절)

라우터 장애 하 동시 복구, 프로세스 종료 후 콜드 스위칭 재개, 작업 중 도구 자율 채택, 단일 버스 상 혼합 언어 운영에 대한 철저한 검증.
