Do User-Authored Permission Policies Improve Protection Against AI Agent Overreach?

Ting Yan

왜 이 문제가 중요한가

"행동 전 확인하라"고 지시했음에도, 오픈소스 에이전트는 실제 받은편지함의 메시지 삭제를 시작했고 멈추지 않았다.
— Cramer, 2026

  • AI 에이전트가 이메일, 파일, 결제, 개인 데이터를 대신 조작하는 시대
  • 전문 소프트웨어 배경이 없는 일반 사용자가 감독해야 함
  • 자연어 지시만으로는 실행 경계를 강제할 수 없음
  • 도구 이름이 실제 결과(결제, 삭제, 공개 등)를 드러내지 않음

핵심 설계 문제

에이전트 권한 결정을 어떻게 내리는가? — 세 가지 접근이 현실 시스템에 이미 존재하지만, 비교 증거가 부족했다.

HITL

사람 직접 승인

AUTO

사용자가 결과 카테고리별로 허용/질문/금지 규칙 설정

POLICY 설계: 결과 수준 정책

도구 이름 대신 사용자가 인식 가능한 결과에 규칙을 적용한다.

4가지 결과 카테고리

  • 지출 — 결제, 구매, 환불
  • 발송 — 메시지, 이메일 전송
  • 삭제 — 파일, 메시지 삭제
  • 사생활 접근 — 개인 데이터 읽기

3가지 규칙 유형

규칙효과
허용자동 실행
질문실행 시마다 사용자에게 질문
금지항상 차단

핵심 가설: "질문" 규칙은 결정을 미루는 것이므로, 정책이 사전에 결정을 확정하지 못할 수 있다.

핵심 발견: 선호와 약속의 간극

기대했던 것

  • 사용자가 사전에 규칙을 작성하면 더 강한 통제
  • 프롬프트 감소 = 사용자 부담 감소
  • 정책이 실행 경계를 형성

실제로 일어난 것

  • 대부분 "질문" 선택 → 결정이 사전에 확정되지 않음
  • 규칙 설정 시간 포함 시 총 시간 감소 없음
  • 런타임에서 사용자가 직접 과도 행동을 승인

"선호를 표현하는 것"과 "미래 결정을 확정하는 규칙에 약속하는 것"은 다르다. "질문"을 반복 선택하면 사례별 선택권은 보존되지만, 정책이 결정을 앞당겨 해결하지 못한다.

시사점과 한계

설계 시사점

  • 프롬프트 수 단독 측정은 오해의 소지
  • 정책 작성 UI에서 "질문"의 의미를 명확히 전달해야 함
  • 결과 수준 매핑은 실현 가능하지만 메타데이터 신뢰성이 병목
  • HITL이 과도 행동 차단에는 여전히 강함

한계

  • 시뮬레이션 환경 — 실제 서비스와 다를 수 있음
  • 단일 세션 — 장기 학습 효과 미측정
  • 조건 전체를 비교했지 단일 변수 고립 아님
  • 4개 결과 카테고리만 사용
