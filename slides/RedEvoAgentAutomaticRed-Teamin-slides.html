경험 기반 스킬 진화를 갖춘 자동 레드팀 에이전트

Junjie Zhang, Hui Liu, Kecheng Chen, Xianbo Mo, Changsheng Chen, Haoliang Li

City University of Hong Kong · Shenzhen MSU-BIT University

arXiv:2608.27439v1, Aug 2026

배경

LLM 에이전트의 보안 위험 확대

제품 수준 에이전트

  • Claude Code, Codex 등 실제 실행 환경에 배포
  • 로컬 파일 수정, 데이터 전송, 외부 API 호출 가능
  • 단순 텍스트 생성을 넘어선 영구적 상태 변화

탈옥의 심각성

  • 유해한 도구 사용 트리거
  • 시스템 상태의 파괴적 변경
  • 안전하지 않은 텍스트보다 훨씬 큰 위험

"제품 수준 블랙박스 에이전트는 보안 강건성을 특성화하기 위해 적대적 평가가 필요하다."

문제 정의

기존 방법의 한계

고정 공격 방식

GCG, AutoDAN, PAIR, TAP 등

  • 제한된 공격 부분집합만 탐색
  • 대체 메커니즘이 드러내는 취약점을 놓침
  • 실패 확률이 높음

궤적 기반 검색 (RedCodeAgent)

  • 검색 편향으로 오도된 경험 재사용
  • 개별 도구의 기여 불명확 (도구 크레딧 문제)
  • 전체 궤적 컨텍스트 오버헤드 심각
  • 저수준 기록으로 인해 해석·감사 어려움

필요한 것: 경험을 간결하고 해석 가능한 스킬로 추출하고, 검증을 통해 진화시키는 방법

제안

RedEvoAgent 개요

블랙박스 레드팀 에이전트로, 다건 공격 궤적을 간결하고 사람이 읽을 수 있는 공격 스킬로 증류한다.

1
공격 실행
스킬 기반 도구 선택 및 타겟 에이전트 공격
2
경험 수집
성공/실패 궤적과 도구 효과 프로파일 구축
3
스킬 진화
결정 도구 귀인 + 검증 래칫으로 스킬 업데이트
↓

컨텍스트 오버헤드 감소

↑

해석 가능성 향상

⟳

적응적 스킬 진화

방법론

문제 정식화

타겟 에이전트

M_tar = (m_tar, h_tar)

  • m_tar: 타겟 모델 (LLM)
  • h_tar: 실행 하네스 (상호작용 인터페이스 + 도구 환경)

공격자 에이전트

M_att(s) = (m_att, h_att(s, T))

  • m_att: 공격자 모델
  • h_att: ReAct 프레임워크 기반 최적화-공격 루프
  • T: 확장 가능한 공격 툴박스

데이터 분할

Training

경험 수집 · 효과 프로파일링

Validation

래칫 기반 스킬 업데이트 평가

Test

최종 평가용 (잠금)

방법론

공격자 에이전트 아키텍처

공격 툴박스 T

다양한 탈옥 방법을 호출 가능한 도구로 통합

  • GCG — 기울기 기반 탐색
  • FlipAttack — 프롬프트 변환
  • AutoDAN — 진화 탐색
  • PAIR — LLM 기반 반복 개선
  • TAP — 트리 구조 블랙박스 탐색

확장 가능: 새로운 공격 도구 자유롭게 추가

스킬 문서 s

자연어로 작성된 고수준 오케스트레이션 전략

  • 도구 선택 우선순위 명시
  • 공격 전략 조합 가이드
  • 사람이 읽고 감사 가능

공격 워크플로우

ReAct 프레임워크에서 스킬 문서를 시스템 프롬프트로 사용하여 도구를 선택·호출하고 반복적으로 공격 수행

핵심 메커니즘

경험 수집과 도구 효과 프로파일링

도구 효과 프로파일

학습 분할에서 각 공격 도구 t_k의 성공률을 독립적으로 측정

목적: 어떤 도구가 실제로 효과적인지 객관적 기준 제공

→ 빈도와 효과를 분리하여 혼동 방지

결정 도구 귀인 (Deciding-Tool Attribution)

성공 궤적에서 공격 성공을 직접 이끈 도구를 결정 도구로 라벨링

  • 성공 궤적에 자주 등장하지만 실제로는 무관했던 도구와 구분
  • 명확한 도구 선택 신호 제공
  • 잘못된 도구 크레딧 할당 방지

스킬 진화는 프로파일 + 귀인 라벨을 결합하여 도구 우선순위와 공격 전략을 추출

핵심 메커니즘

검증 래칫 (Validation Ratchet)

후보 스킬 업데이트는 독립 검증 분할에서 성능 개선을 보여야만 채택된다.

1

후보 스킬 생성

학습 경험 + 도구 프로파일 + 결정 도구 귀인 결합

2

검증 분할 평가

현재 스킬 vs 후보 스킬의 공격 성공률 비교

개선됨 → 채택

후보 스킬이 새로운 현재 스킬이 됨

미개선 → 유지

이전 스킬 유지, 실패 후보 기록하여 이후 반복에 활용

무관하거나 오도된 업데이트 신호를 효과적으로 차단

설계 철학

"무엇을 배울지"와 "무엇을 유지할지"의 분리

무엇을 배울지

  • 도구 효과 프로파일
  • 결정 도구 귀인
  • 성공/실패 궤적 분석
검증

  • 래칫: 개선 시에만 채택
  • 실패 후보 기록 활용

"일반 에이전트 태스크에서 고수준 스킬 요약이 유사도 기반 궤적 검색을 능가한다는 증거와 일치한다." — Trace2Skill, SkillOpt

제로샷 전이와 스킬 기여 분석

제로샷 전이

  • 공격자 모델 간 전이: 한 모델에서 진화한 스킬을 다른 공격자 모델에 직접 적용 가능
  • 실행 하네스 간 전이: Claude Code에서 학습한 스킬을 Codex 하네스에도 효과적으로 적용
  • 스킬이 모델·하네스 특정적 정보가 아닌 일반화 가능한 공격 전략을 학습함을 시사

스킬은 언제 도움이 되는가?

  • 단일 도구로는 해결하기 어려운 복합 취약점에서 특히 효과적
  • 도구 선택 순서가 중요한 경우 스킬의 오케스트레이션 가이드가 크게 기여
  • 진화가 진행될수록 스킬의 도구 우선순위가 점진적으로 정교화
