A2M: Trace-Optimized Agent Hijacking
in the MCP Ecosystem

MCP 생태계에서 실행 트레이스로 최적화된 에이전트 하이재킹

Attraction(유인)에서 Manipulation(조작)까지 — 2단계 블랙박스 공격 프레임워크

Shenzhen Institutes of Advanced Technology, CAS · NTU · Univ. of Macau

배경: MCP와 도구 기반 에이전트

  • LLM은 대화형 시스템에서 외부 도구를 호출하는 자율 에이전트로 진화
  • Model Context Protocol (MCP): 이기종 데이터 소스와 서드파티 서비스를 통합하는 표준 인터페이스
  • 도구 선택은 시맨틱 매칭(도구 이름·설명)에 크게 의존
  • 체계적인 검증·감사가 없는 개방형 도구 생태계 → 시맨틱 공급망 공격 위험 노출
공격자가 제어하는 메타데이터와 도구 반환값을 통해 신뢰된 인터페이스로 공격이 전달됨

위협 모델

위협 표면: 도구 통합 계층

사용자→에이전트 프롬프트 공격과 달리, 사용자와 에이전트 모두 정상적으로 동작할 수 있음. 도구 선택을 유도하는 메타데이터 t=(n,d)와 이후 추론에 반영되는 반환값이 공격 지점

공격자 능력

  • 서드파티 MCP 서버에 악성 도구 등록 가능 (블랙박스)
  • 도구 이름·설명 등 메타데이터 제어
  • 도구 호출 시 반환되는 출력 내용 제어

핵심 도구 반환값은 신뢰할 수 없는 텍스트가 아닌 신뢰된 환경 피드백으로 처리됨 — 시스템 상태·실행 결과로 위장한 제어 정보 삽입 가능

핵심 아이디어: 두 가지 결합된 목표

Attraction (유인)

선택 단계 목표 — 경쟁하는 정상 도구들 사이에서 에이전트가 악성 도구를 호출할 확률을 극대화

도구 이름·설명 등 메타데이터 최적화

Manipulation (조작)

호출 이후 목표 — 도구 반환값을 조작해 에이전트의 후속 추론을 공격자 지정 목표로 유도

실행 트레이스 기반 페이로드 정제

실행 시에는 결합되어 있지만, 블랙박스 탐색을 가능하게 하기 위해 두 단계로 분리해 최적화 — 선택되지 않으면 페이로드가 무의미하고, 선택되어도 반환값이 거부되면 실패

A2M 프레임워크 개요

1
Attraction
도구 메타데이터 최적화로 호출 확률 향상
2
도구 선택·실행
에이전트가 시맨틱 매칭으로 악성 도구 호출
3
Manipulation
실행 트레이스 분석 후 반환 페이로드 정제
  • 완전 블랙박스: 모델 내부 가중치나 로짓 접근 불필요
  • Analyzer–Optimizer 아키텍처: 실행 트레이스로 실패 원인(시맨틱 모호성, 안전 거부 등) 진단 → 무작위 탐색이 아닌 표적 반복 개선

Phase I: Attraction — 메타데이터 최적화

  • 도구 이름과 설명을 반복적으로 변형하여 에이전트의 도구 선택 편향을 공격 방향으로 조작
  • 쿼리별 승률(winning share)을 피트니스 신호로 사용하여 경쟁 정상 도구 대비 선택 우위 확보
  • 쿼리 간 일반화를 고려 — 특정 쿼리에만 과적합되지 않는 범용적 메타데이터 탐색

기존 연구(ToolHijacker, MPMA, AMA, ToolTweak)는 주로 이 선택 단계에만 집중 — A2M은 여기서 멈추지 않고 전체 공격 사슬을 표적으로 삼음

Phase II: Manipulation — 트레이스 기반 페이로드 정제

Analyzer

에이전트의 실행 트레이스(추론, 도구 사용, 거부 여부)를 분석하여 공격 실패 원인 진단

예: 시맨틱 모호성, 안전 정책 거부, 페이로드 무시

Optimizer

진단 결과를 반영해 반환 페이로드를 표적으로 반복 개선

무작위 변형이 아닌 지향적 탐색으로 수렴 속도와 안정성 향상

피트니스 설계 공격 시나리오별 목표(C-DoS 토큰 비용, 정보 유출량 등)에 맞춘 적응형 피트니스 함수로 최적화 방향 결정

4가지 공격 시나리오

C-DoS (인지 서비스 거부)

에이전트를 비생산적 반복 작업에 빠져들게 하여 토큰 비용을 대폭 증가시켜 자원 고갈 유도

IE (정보 유출)

에이전트 환경의 민감 정보를 공격자 지정 경로로 유출하도록 유도

EIC (환경 무결성 훼손)

파일 수정 등 사용자 의도와 다른 부작용 행동을 수행하게 만들어 환경 오염

RD (추론 탈선)

에이전트의 추론 궤적을 공격자가 지정한 방향으로 이탈시켜 원래 작업 수행 방해

시사점 및 방어 방향

  • 도구 심사 강화: 이름·설명 등 시맨틱 메타데이터의 오용 탐지, MCP 마켓플레이스 검증 체계 필요
  • 런타임 격리: 도구 반환값을 신뢰된 피드백이 아닌 검증 대상 콘텐츠로 처리
  • 정보 흐름 제어 (FIDES 스타일): 외부 콘텐츠가 민감 정보 접근·후속 도구 호출을 유도하지 못하도록 차단
  • LLM 감사자(auditor): 에이전트 행동 전 악성 지시 여부를 검토하는 보조 검증 계층

결론

  • MCP 에이전트를 위한 시맨틱 공급망 위협 모델 공식화 및 Attraction–Manipulation 2단계 정식화
  • A2M 프레임워크: Analyzer–Optimizer 아키텍처로 메타데이터와 반환 페이로드를 공동 최적화, 선택 이후 추론 하이재킹까지 안정적으로 달성
  • LiveMCPBench에서 4개 공격 시나리오 × 5개 모델에 걸쳐 직접 공격과 전이 공격, 도구 호출과 전체 공격 성공을 구분해 정밀 분석
도구 생태계의 개방성이 곧 공격 표면 — 강화된 도구 검증과 런타임 격리가 MCP 생태계의 필수 요건
