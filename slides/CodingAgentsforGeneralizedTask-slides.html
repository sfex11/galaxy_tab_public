Coding Agents for Generalized Task and Motion Planning Problems

Matteo Merler · Bowen Li · Josh Roy · Yichao Liang · Qianwei Wang · Yixuan Huang · Tom Silver

Fondazione Bruno Kessler · Carnegie Mellon · Princeton · Cambridge

배경: TAMP는 여전히 어렵다

  • 완전 관측 + 객체 중심 상태여도 문제는 형식적으로 어려움
  • 긴 호라이즌, 희소한 보상, 타이트하게 결합된 제약들
  • 이산적 선택(무엇을 조작할까?)이 연속적 기하·운동역학·동역학 제약과 결합
  • 객체 수가 늘어날수록 충돌 제약이 급증, 실행 가능한 행동 영역은 협소
남은 핵심 난제는 물리적 추론(physical reasoning)이다

Generalized TAMP와 한계

Generalized TAMP = 문제 인스턴스들 간의 규칙성(regularity)을 활용해 새 인스턴스에서 계획 노력을 줄이는 접근

기존 방법이 학습하는 것

  • 샘플러
  • 실현 가능성 예측기
  • 탐색 휴리스틱
  • 추상화

문제점

기존 방법들은 상당한 TAMP 특화 엔지니어링을 요구
(술어, 연산자, 샘플러, 스킬 등을 수작업 설계)

연구 질문

최신 코딩 에이전트는 TAMP의 일반화 문제를
스스로 해결할 수 있을까?

성공한다면
TAMP 방법론에 요구되는 도메인 특화 엔지니어링을 대폭 축소 가능

실패한다면
현재 에이전트의 구체적 한계를 규명하는 단서 확보

문제 설정

유한 호라이즌 MDP

ℳ = ⟨𝒮, 𝒜, P, R, ρ, H⟩
· 완전 관측, 객체 중심 상태
· 희소 보상: 목표 달성 여부만 표시
· ρ가 객체 수·구성·기하가 다른 인스턴스 생성

시뮬레이터 접근

· reset: s₀ ~ ρ 샘플링
· step: 행동 실행 후 다음 상태·보상·종료 신호 반환

합성 시점: 작업 설명 d + 시뮬레이터 → 고정 예산 내 프로그램 생성
평가 시점: 프로그램 동결, LLM 부재, 학습 때 숨긴 인스턴스로 성공률 측정

확장성: 객체 수가 늘어나도 견고

성공률 유지

객체 수가 증가해도 에이전트 프로그램은 플래너보다 높은 성공률 유지
플래너는 시간이 더 걸리고 푸는 인스턴스가 줄어듦

계산 효율

인스턴스당 평균 계산 시간이 플래너 대비 약 10분의 1

에이전트가 발견한 전략 유형:

  • 목표 경로를 막는 장애물을 먼저 식별해 행동 탐색 범위 축소
  • 탐색 없이 인스턴스에 맞춰 고정 조작 시퀀스를 적응시키는 프로그램
  • 상호작용 로그로 물리 모델 보정·엣지 케이스 테스트·전략 개선

예상 밖의 성공 전략들

로그 분석 결과, 기존 벤치마크 해법에 없던 창의적 전략 발견

비악력 조작

잡지 않고 밀어내는 등 non-prehensile 기동 활용

환경 레이아웃 활용

환경 구조 자체를 전략의 일부로 편성

발표된 어떤 해법에도 없던 전략은 학습 데이터 암기로는 설명하기 어렵다 — 이 연구에서 가장 강력한 정성적 증거

한계와 추가 분석

남은 실패

동적 3차원 환경은 기본 설정에서 대부분 미해결
특히 작은 객체를 많이 쓸어담거나 붓는(sweeping/pouring) 과업

소스 코드 접근

환경 소스 코드를 제공하면 기본 설정에서 실패한 환경에서도 성공
완전한 지표로서의 참고 설정 역할

상호작용의 역할: 에이전트는 시뮬레이터 탐침으로 환경 역학을 추론하고, 인스턴스 간 규칙성을 활용하는 전략을 개발·검증

결론

코딩 에이전트는 일반화 TAMP의 강력한 베이스라인이다
  • TAMP 특화 엔지니어링 없이 손수 설계된 플래너를 평균 성공률에서 능가
  • 객체 수 증가 시에도 높은 성공률 + 10배 낮은 계산량
  • 기존 문헌에 없던 창의적 물리 전략 발견 (비악력 조작 등)
  • 코드·전체 프롬프트 전부 공개 — 향후 연구의 기준점 제시
