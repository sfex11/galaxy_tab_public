동기와 문제 제기

"스킬을 추가하면 평균 성능이 올라간다" — 그런데 이 지표가 숨기는 비용이 있다.

기존 평가의 한계

  • 평균 성능 향상만 측정
  • 스킬이 깨뜨리는 작업을 무시
  • 같은 평균 향상이라도 회귀 수준이 다를 수 있음

기존 해결책의 한계

  • 유해 스킬을 탐지해 제거/억제
  • 어떤 스킬을 버릴지는 알되 왜 회귀가 발생하는지 불명확
  • 스킬 본문이 호출되지 않아도 설명만으로 행동 변화 가능

핵심 개념: 성능 변화의 분해

통과율 변화 = (성공→성공 유지) + (실패→성공 이득) − (성공→실패 회귀) − (실패→실패 잔존)

회귀세 (Regression Tax)

59%

순이득 중 회귀가 상쇄한 비율

324건 회귀 / 553건 순이득

최고 성능 스킬 라이브러리가 다른 라이브러리보다 나은 이유는 더 많이 얻어서가 아니라, 덜 회귀해서다.

동일한 평균 향상이라도 회귀 분포가 완전히 다를 수 있음

핵심 발견: 순 통과율 변화만 보면 "스킬이 도움이 된다"고 결론 내리지만, 이득의 과반을 회귀가 잠식하고 있음

분해가 해석을 어떻게 바꾸는가

집계만 보면

라이브러리 A와 B가 동일한 순 향상을 보이면 "동등하다"고 평가됨. 어느 쪽이 더 많은 작업을 깨뜨리는지 알 수 없음.

분해하면

A는 이득이 많고 회귀도 많음. B는 이득이 적지만 회귀가 거의 없음. 신뢰성 관점에서 B가 우월함이 드러남.

통계적 불확실성까지 고려하면, 일부 조건에서는 회귀가 우연이 아닌 체계적 패턴임이 확인됨

회귀 메커니즘 세 가지

1

스킬 설명 삼투 (Skill-Description Osmosis)

스킬 본문이 호출되지 않아도, 시스템 프롬프트에 있는 설명만으로 에이전트 행동이 변함

2

접지 전이 (Grounding Displacement)

스킬이 제시한 절차가 에이전트의 입력 해석 방식을 덮어씌움 — 올바른 계산을 잘못된 값에 수행

3

검증 전이 (Verification Displacement)

스킬 절차가 에이전트가 원래 수행했을 출력 검사를 억제함 — 크기는 맞지만 검증 없는 결과

메커니즘 1: 스킬 설명 삼투

현상

스킬 이름과 설명이 매 스텝의 시스템 프롬프트에 존재함. 본문이 한 번도 호출되지 않았음에도 에이전트의 답변이 뒤바뀜.

사례

스프레드시트 작업에서 스킬 설명이 특정 해석을 암시 → 에이전트가 문서 본문을 읽지 않고 설명에만 의존해 잘못된 값 도출

핵심: 기존 선택 기반 방법(ASSAY, GRASP 등)은 스킬이 검색/호출될 때만 작동하므로 이 "존재만으로" 발생하는 효과를 포착하지 못함

메커니즘 2 & 3: 접지 전이와 검증 전이

접지 전이

스킬이 제시한 읽기 방식이 에이전트의 원래 입력 판독을 대체함.

사례: 올바른 표를 찾아 정확히 계산했으나, 스킬이 지정한 다른 표의 값을 읽어 잘못된 결과 도출

검증 전이

스킬 절차를 따르는 것만으로 "완료"로 간주하여 출력 검사를 생략함.

사례: 결과 크기는 맞으나 단위/형식 오류. 원래라면 자체 점검으로 잡았을 오류

두 메커니즘은 종종 동시에 발생함: 잘못 읽은 값(접지 전이)을 검증 없이 그대로 출력(검증 전이)

잔존 실패 분석과 평가 보정

잔존 실패의 패턴

  • 접지 단계가 지배적 오류 원인
  • 검증 단계가 그다음
  • 방법 단계의 오류는 상대적으로 적음

평가 아티팩트 보정

  • 스프레드시트 채점기가 구조적 참조/최신 함수 미지원
  • 올바른 수식을 실패로 오분류
  • 226건 재채점 수행

결과: 많은 회귀와 잔존 실패가 더 나은 접지·검증 지원으로 회복 가능함이 트레이스 분석을 통해 확인됨

시사점: 스킬 라이브러리 설계 원칙

삼투 회피: 스킬 설명이 존재만으로 행동을 왜곡하지 않도록 설명 최소화

접지 전이 회피: 스킬이 입력 판독 방식을 강제 지정하지 않도록 설계

검증 전이 회피: 절차 완료 후 반드시 독립적 출력 검사 단계 포함

접지·검증 지원 강화: 방법(절차) 지침보다 입력 읽기와 출력 확인에 더 많은 스킬 자원 할당

결론

  • 순 통과율 향상만으로 스킬을 평가하는 것은 불충분함
  • 이득과 회귀를 분해해야 스킬 라이브러리 간 신뢰성 차이가 드러남
  • 관측된 회귀가 순이득의 59%를 상쇄 — 무시할 수 없는 규모
  • 세 가지 회귀 메커니즘(삼투, 접지 전이, 검증 전이)을 식별
  • 신뢰성은 절차적 스킬 선택보다 접지와 검증에 더 의존함

"절차적 스킬은 순효과를 이득과 회귀로 분해하여 평가되어야 하며, 집계 향상만으로는 부족하다."
