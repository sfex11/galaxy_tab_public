10⁴–10⁵ 호스트가 형성하는 끊임없이 변하는 인증 그래프

LLM을 API 제품군에 연결해 "드롭인 분석가"로 쓰는 접근은 데모에서는 인상적이지만, 실제 운영 스트레스 아래에서는 무너진다.

LLM 에이전트의 두 가지 구조적 한계

① 유한한 컨텍스트 윈도우

  • 수천 호스트 규모의 인증 그래프를 프롬프트에 담을 수 없음
  • 공격자의 측면 이동 추적에 필요한 위상 정보 손실
  • 컨텍스트가 소진되면 모델은 추측 — 격리 결정이 공격 경로를 끊는지 아니면 단지 피벗만 유도하는지 판단 불가

② 자유로운 텍스트 생성

  • isolate-host, block-ip, disable-account 등은 비즈니스 연속성에 직접 영향
  • 차단 조치에는 경질 규칙, 감사 가능성, 버전 간 일관성이 필요
  • 확률적 텍스트 완성은 이런 보장을 전혀 제공하지 못함

핵심 아이디어: 위상 추론과 의미 추론의 분리

LLM이 잘하는 것에만 LLM을 제한하고, 토폴로지 기반 의사결정은 학습된 정책에 위임하는 신경-기호 하이브리드 접근

1
HetGAT 인코더
실시간 인증 서브그래프를 고정 차원 상태로 요약
2
PPO 정책
상태를 제한된 조사 행동 집합에 매핑
3
LLM 에이전트 루프
정책 권고를 소비해 분석가용 서술 생성 (critic 게이팅)

위상 추론 → 그래프 신경망 + 강화학습

의미 추론 → LLM (쿼리 작성, 요약, 보고서 초안)

위협 모델

공격자

  • 초기 침투 직후 단계부터 가정 (침투 수단은 무관)
  • 유효 계정 남용 T1078
  • 원격 서비스 악용 T1021
  • MITRE ATT&CK TA0008 — 측면 이동

방어자

  • 전 환경 인증 텔레메트리 실시간 수집
  • Neo4j 그래프에 토폴로지 근실시간 매핑
  • SOAR API로 호스트 격리·계정 잠금 실행 가능
  • 단, 감염 자산에 대해서는 초기에 완전 블라인드

신뢰 가정

  • LLM 환각(hallucination)은 불가피하다고 가정
  • 우회 불가능한 검증 체인: 내부 critic → 정책 감사자 → 인간 승인 게이트
  • RL 정책이 항상 최적 선택을 한다고 낙관적으로 가정하지 않음

Sentinel-RL 4계층 아키텍처

데이터 플레인

전략 플레인

HetGAT 인코더 + PPO 정책 — 전략적 의사결정 엔진

텔레메트리 플레인

인증 이벤트 수집 파이프라인 + 슬라이딩 윈도우 알림 엔진

오케스트레이션 플레인

사용자 인터페이스 + LLM 에이전트 루프, 안전 표면(safety surface) 포함
