SWE-Prime

더 적은 궤적, 더 나은 성능

Dewu Zheng, Ruizhe Ye, Yanlin Wang, Yang Ye, Hongyu Zhang, Ensheng Shi, Xilin Liu, Yuchi Ma, Jianxing Yu, Zibin Zheng

Sun Yat-sen University · Huawei Cloud · Chongqing University

문제 인식

성공 궤적 ≠ 고품질 학습 데이터

기존 연구는 실행 검증을 통과한 성공 궤적만을 수집하여 SFT에 활용했습니다. 하지만 작업 성공이 곧 고품질 감독을 보장하지 않습니다.

비효율적 단계

탐색 없이 바로 코드 수정하거나, 불필요한 파일까지 변경

중복 행동

이전 행동을 잊고 동일한 도구 호출을 반복하는 패턴

위험한 단축행

Git 이력에서 정답을 직접 조회하는 등의 편법 행동

"이러한 궤적을 SFT에 직접 사용하면 노이즈가 많은 감독 신호가 모델에 바람직하지 못한 문제 해결 행동을 모방하도록 유도합니다."

동기 부여

세 가지 관점에서 바라본 데이터 품질

1

결과 관점 (Outcome View)

기존 방식: 성공/실패만으로 데이터를 선별 — 품질 차이를 간과

2

궤적 관점 (Trajectory View)

문제 해결 패턴, 도구 호출 안정성, 연속 중복, Git 해킹, 결과 품질 등 5가지 차원에서 궤적 품질 평가

3

세그먼트 관점 (Segment View)

궤적 수준에서 고품질이라도, 개별 세그먼트는 최종 해결에 기여하지 않을 수 있음

핵심 통찰: 문제 해결 행동은 여러 액션과 관찰에 걸쳐 나타나므로, 개별 스텝이 아닌 의미적 세그먼트 단위로 평가해야 함

제안 방법

SWE-Prime: 다중 입자도 2단계 데이터 선택

1
궤적 수준 선별
과정 품질 · 결과 품질 · 데이터 대표성 기반 필터링
2
세그먼트 수준 선별
기여도 · 학습 가능성 · 위험도 기반 세그먼트 평가
3
SFT 학습
전체 궤적은 컨텍스트로 유지, 선택된 세그먼트만 Loss 계산

_compact_ & Low-Noise

불필요한 노이즈를 제거하여 모델이 신뢰할 수 있는 시범만 학습

Multi-Granularity

궤적 → 세그먼트로 점진적 세분화하여 정밀한 품질 제어

Stage 1

궤적 수준 선별: 과정 품질 평가

① 관찰-수정-검증 패턴

최초 수정 전 저장소 탐색 여부와 최종 수정 후 테스트/검증 수행 여부로 판단

Sworkflow = 1 또는 0

② 도구 호출 성공률

궤적 내 도구 호출 성공률을 계산하고, 전체 풀 대비 백분위 순위로 점수화

Stool = percentile rank

③ 연속 중복 탐지

인접 스텝에서 도구 이름과 인자가 동일한 호출이 있는지 검사

Sredundancy = 0 (중복 발견 시)

④ Git 해킹 탐지

버전 기록에서 타겟 수정 정보를 직접 조회하는 편법 행동 감지

Sgit = 0 (해킹 감지 시)

Stage 1

궤적 수준 선별: 결과 품질 & 대표성

결과 품질 평가

  • 최소 sufficient 패치 선호 — 불필요한 파일 변경 감소
  • 변경 라인 수, 수정 파일 수, 패치 집중도 등 다차원 평가
  • 회귀 위험을 낮추는 정밀한 패치를 우선 선택

데이터 대표성 평가

  • 다양한 저장소, 프로그래밍 언어, 이슈 유형 균형 있는 커버리지
  • 특정 하위 집단에 편중되지 않도록 클러스터링 기반 샘플링
  • 선택된 부분집합이 전체 데이터 분포를 대변하도록 보장

Stage 1은 과정 품질, 결과 품질, 대표성 세 가지 차원을 결합하여 고품질이고 대표성 있는 성공 궤적 부분집합을 선별합니다.

세그먼트 수준 선별

세그먼트 점수화
기여도 · 학습 가능성 · 위험도 3차원 평가

세그먼트 필터링
임계값 기반으로 고품질 세그먼트만 선택
1

최종 해결 기여도

해당 세그먼트가 최종 패치 생성에 실질적으로 기여했는지 평가

2

학습 가능성

모델이 해당 행동 패턴을 일반화하여 학습할 수 있는지 평가

3

잠재적 위험도

편법 행동이나 바람직하지 않은 패턴을 포함하는지 평가

핵심: SFT 시 전체 궤적은 컨텍스트로 유지하여 문맥을 보존하고, 선택된 세그먼트만 Loss에 기여하도록 마스킹

RQ2

하이퍼파라미터 분석

궤적 비율의 영향

10% 부근에서 최적의 성능을 보이며, 데이터량을 늘려도 성능이 단조 증가하지 않음. 이는 데이터 품질이 양보다 중요함을 시사

세그먼트 임계값의 영향

세그먼트 필터링 강도를 조절하며 균형점을 탐색. 너무 엄격하면 학습 신호 부족, 너무 관대하면 노이즈 잔존

2단계 설계의 상호 보완성

Stage 1만 사용할 때보다 Stage 2까지 수행할 때 성능이 추가로 향상됨. 궤적 수준 선별과 세그먼트 수준 선별이 서로 다른 종류의 노이즈를 제거하며 시너지를 생성

RQ3

행동 분석

SWE-Prime으로 학습된 모델의 실제 문제 해결 행동 변화

체계적 탐색 증가

코드 수정 전 저장소 구조를 먼저 파악하는 관찰-수정-검증 패턴 강화

안정적 도구 사용

불필요한 도구 호출 실패와 중복 호출이 감소하여 효율적인 상호작용 수행

위험 행동 감소

Git 해킹 등 편법 행동과 불필요한 파일 수정이 현저히 감소

SWE-Prime은 단순히 벤치마크 점수를 높이는 것을 넘어, 모델이 더 건전하고 체계적인 문제 해결 행동을 학습하도록 유도합니다.

핵심 요약

기여점 & 결론

  • 성공 궤적 간의 데이터 품질 차이를 기존 연구가 간과하고 있음을 명시적으로 지적
  • 개별 스텝이 아닌 의미적 세그먼트를 행동 평가의 기본 단위로 도입
  • 다중 입자도 2단계 선택 방법 SWE-Prime 제안 — compact, low-noise, informative 감독 제공
  • 3개 모델 × 2개 벤치마크에서 전체 데이터 SFT 대비 우수한 성능을 10% 데이터만으로 달성

"Less is More" — 데이터 양보다 품질이 코딩 에이전트 SFT의 성능을 결정하는 핵심 요인입니다.
