Yihao Chen, Shi Chang, Khaled Chawa, Feng Lin, Boyuan Chen, Shaowei Wang, Ahmed E. Hassan

문제 정의: 처음부터 프로그램을 만드는 난제

기존 코딩 에이전트의 성과

  • 버그 수정 (Bug Fixing)
  • 기능 구현 (Feature Implementation)
  • 코드 자동 완성 (Code Completion)

→ 모두 기존 코드베이스 수정에 집중

처음부터 구성의 어려움

  • 명세 추론 (Specification Inference)
  • 아키텍처 설계 (Architecture Design)
  • 구현, 디버깅, 테스트 작성, 반복 개선

→ ProgramBench에서 최신 모델조차 완전 해결률 1% 미만

GPT-5.5조차 ProgramBench에서 완전 해결(fully resolve)한 작업은 1% 미만 — 처음부터 프로그램을 구성하는 것은 여전히 열린 과제

기존 접근법의 한계

프레임워크 접근 방식 한계
SWE-Smith 기존 파이썬 코드에 결함 주입 → 버그 수정 태스크 합성 소스 코드 접근 필요, 수정만 학습
SWE-Gym 실제 이슈 + 실행 가능한 저장소 환경 페어링 기존 코드베이스 확장에만 한정
ProgramBench 소스 프리 환경에서 평가 평가 전용, 훈련 데이터 생성 불가
MirrorCode 소스 프리 프로그램 재구현 평가 평가에만 활용

공통 한계: 기존 프레임워크는 소스 코드에 접근 가능한 환경을 가정하며, 소프트웨어 개발 단일 단계에만 집중 → 전 수명 주기 훈련 환경 부재

MindForge 파이프라인 개요

오픈소스 CLI 프로그램을 소스 프리 환경으로 변환하고, 강력한 교사 에이전트로 전 수명 주기 궤적을 수집하는 자동화 파이프라인

1
환경 구성
오픈소스 저장소 → 컴파일된 실행 파일 + 문서만 노출
2
궤적 수집
GLM-5.2 교사 에이전트가 소스 없이 프로그램 재구현
3
궤적 정제
인프라 오류 복구 + 추론 재작성
4
지식 증류
정제된 궤적으로 Qwen3.6-27B SFT

핵심 아이디어: 평가용으로만 쓰이던 소스 프리 설정을 훈련 데이터 생성으로 전환

소스 프리 실행 환경 구성

1
저장소 선정

저장소 및 커밋 고정, 벤치마크와 중복 제외 (오염 방지)

2
오프라인 사전 심사 (Explorer Agent)

소스 코드와 문서만 읽고 자립형 CLI 도구 여부 판별 — 인터넷, 자격증명, 특수 하드웨어 의존 시 거부

3
빌드 및 검증 (Build Agent)

컴파일 후 실행 파일과 문서만 남기고 소스 코드 제거

4
커버리지 검증

다양한 프로그래밍 언어와 기능 카테고리 균형 확보

소스 프리: 에이전트에게는 컴파일된 참조 실행 파일과 공개 문서만 제공 — 소스 코드 접근 불가

궤적 수집 및 정제

궤적 수집

  • 교사 에이전트: GLM-5.2
  • 소스 프리 환경에서 처음부터 프로그램 재구현
  • 유효한 빌드 가능한 제출물을 생성한 궤적만 보존

궤적 정제 (2단계)

① 인프라 노이즈 복구

일시적인 스캐폴드/인프라 오류로 조기 종료된 궤적 복원

② 추론 재작성 메커니즘

실제 도구 사용 실수에 영향받은 추론만 재작성 — 도구 호출 및 환경 상호작용은 그대로 유지

설계 원칙: 교사의 실제 도구 호출과 환경 상호작용을 보존하면서, 잘못된 추론만 선택적으로 수정하여 일관성 유지
