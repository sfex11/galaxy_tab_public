WikiSkill

에이전트 경험을 지속적 지식으로 컴파일하여
스킬 진화를 이끄는 프레임워크

Liyan Tang, Cyrus Rashtchian, Chun-Sung Ferng, Andrew Tomkins, Da-Cheng Juan, Tu Vu

Google Research · Virginia Tech

동기와 문제 정의

에이전트 스킬의 등장

전문 지식과 워크플로우를 재사용 가능한 모듈로 패키징하여 AI 에이전트의 능력을 확장하는 경량 포맷

  • 모델 파라미터 업데이트 불필요
  • 일관되고 감사 가능한 지식 표현
  • 점진적 공개(progressive disclosure) 지원

기존 방법의 한계

자동 스킬 발견 연구가 등장했으나, 스킬 개발 과정에서 얻은 인사이트가 최적화 기록에 산재되어 체계적 재사용이 불가

  • EvoSkill: 제안 이력만 누적
  • Trace2Skill: 궤적에서教训 추출
  • SkillOpt: 거절 피드백만 활용
  • 공통점: 별도의 지식 표현 유지 안 함

에이전트 경험을 지속적이고 복리되는 지식으로 컴파일할 수 있는가?

WikiSkill 핵심 아이디어

원시 경험과 실행 가능한 스킬 사이에 구조화된 지식 계층을 추가하여, 스킬 개발이 점진적으로 축적된 지식 위에서 이루어지도록 설계

1
실행 경험 생성
에이전트가 현재 스킬로 태스크 수행
2
위키 통합
경험을 지속적 지식으로 정리·축적
3
스킬 제안
위키 기반으로 스킬 업데이트 생성
4
검증 & 롤백
성능 향상 시만 스킬 반영

핵심 원칙: 스킬 업데이트는 롤백될 수 있지만, 위키는 영속되어 미래 업데이트가 축적된 지식 위에서 구축됨

3계층 지식 아키텍처

1

Raw Layer

raw/

불변의 실행 궤적을 저장
관찰(observation)과 행동(action)의 원본 시퀀스

2

Wiki Layer

wiki/

구조화된 지식을 유지
패턴, 원인, 해결책 등 정리된 인사이트

3

Skills Layer

skills/

진화하는 절차적 지식
SKILL.md 기반 실행 가능한 모듈

지식 흐름: Raw → Wiki(통합·축적) → Skills(실행 가능한 절차로 변환) — 위키를 거치지 않고 직접 스킬로 가는 것보다 체계적 지식 재사용이 가능

4가지 핵심 컴포넌트

Inference Agent

현재 스킬 세트를 사용해 훈련 태스크에서 롤아웃 실행. 툴(셸, 검색 API 등)과 스킬을 활용해 실행 궤적 생성

Wiki Maintainer

Raw Layer의 실행 궤적을 분석하여 Wiki Layer에 패턴을 통합. 성공/실패 사례에서 반복 가능한 인사이트 추출

Skill Proposer

Wiki와 Raw 궤적을 함께 참조하여 스킬 업데이트 제안. ReAct 모드로 문제 분석 후 구체적 수정안 생성

Gating & Rollback

제안된 스킬 업데이트를 검증셋에서 평가. 성능 향상 시에만 스킬 반영, 아니면 롤백. 위키는 롤백하지 않음

진화 루프의 핵심 설계

스킬 프로비저닝: Inference Agent는 태스크 설명을 기반으로 관련 스킬만 선택적 로딩. 모든 스킬을 한번에 로드하지 않아 컨텍스트 공간 절약

패턴 통합: Wiki Maintainer는 궤적을 분석해 패턴을 식별 — 오류 원인, 성공 전략, 반복 실패 패턴 등을 구조화된 위키 문서로 정리

위키 기반 스킬 제안: Skill Proposer가 위키의 축적된 지식을 참조하여, 단일 궤적 수준을 넘어선 일반화된 스킬 개선안을 생성

게이팅 메커니즘: 검증셋 정확도가 향상된 업데이트만 수용. 스킬은 롤백되지만 위키는 영속적으로 유지되어 다음 반복에서 활용

이러한 설계는 "경험 → 지식 축적 → 더 나은 스킬 → 더 나은 경험"의 선순환 루프를 형성

전이 성공 조건

전이 실패 조건

스킬 발견(skill discovery)과 스킬 실행(skill execution)은 독립적인 능력

지속적 지식의 역할: 절제 연구

위키 있음 vs 없음

위키 없이 스킬만 진화시키는 경우 최종 스킬 품질이 크게 저하

위키가 없으면 각 반복이 이전 궤적에서만 학습하고, 축적된 패턴 없이 동일한 실수를 반복

Inference Agent의 위키 접근

진화 과정에서 Inference Agent가 위키에 접근하면 오히려 최종 스킬 품질 저하

위키는 Skill Proposer만 참조해야 함. 에이전트가 위키에 의존하면 스킬 자체의 완성도가 떨어짐

정성적 분석 결과

  • WikiSkill은 진화 과정 전반에 걸쳐 위키 패턴을 지속적으로 축적
  • 스킬은 점진적으로 더 간결하고 정확하게 다듬어짐
  • 위키의 패턴이 스킬 업데이트의 근거로 활용되어 더 일반화된 스킬 생성

핵심 시사점

지식 분리의 가치 — 원시 경험, 축적 지식, 실행 스킬을 명확히 분리하면 각 계층이 독립적으로 발전하면서도 시너지를 낼 수 있음

지식의 복리 효과 — 위키에 축적된 지식이 이후 스킬 업데이트의 품질을 점진적으로 높이는 선순환 구조 달성

스케일링과의 상호보완 — 스킬 진화는 모델 스케일업과 대안적/보완적 능력 향상 경로. 작은 모델 + 스킬이 큰 모델을 압도 가능

스킬의 이식성 — 잘 진화된 스킬은 모델 간 전이 가능하며, 강한 모델이 만든 스킬이 약한 모델의 자체 스킬보다 우수할 수 있음

설계 주의점 — 위키는 스킬 제안자만 참조해야 하며, 추론 에이전트가 위키에 의존하면 스킬 자체의 품질이 저하됨
