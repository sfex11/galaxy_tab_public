문제 제기

문헌 합성의 현실적 어려움

화학자의 실제 질문

"CO₂ 환원을 CO로 변환하는 전기촉매는 무엇이며, 패러데이 효율은 얼마인가?"

→ 답이 여러 논문에 분산되어 있음

기존 시스템의 한계

  • 문서 단위 검색만 반환
  • 사용자가 직접 논문 열어 증거 탐색
  • 수치 검증 및 교차 논문 조립 수동 수행
  • LLM 에이전트도 동일 한계 상속

문서 중심 인터페이스는 과학자와 AI 에이전트의 실제 사용 방식과 점점 더 불일치

핵심 아이디어

검색 단위를 논문에서 클레임으로 전환

Segment Anything Model이 이미지를 재사용 가능한 영역으로 분해했듯, LLM로 논문을 클레임으로 분해한다.

기존 방식

논문 → 문서 목록 반환

패러다임 전환

논문 → 원자적 클레임 분해

AskChem 방식

클레임 → 증거 기반 교차 합성

클레임(Claim)이란? 논문에서 추출된 원자적·유형화된 과학적 주장으로, 출처 DOI와 축어적 인용구(verbatim quote)로 근거가 부착된 객체
아키텍처 개요

세 가지 상보적 구조

공유 클레임 저장소 위에 세 가지 구조를 노출하여 검색과 합성을 지원

안정화 패싯 분류법

반응 유형, 물질 클래스, 응용, 기법, 메커니즘 등 패싯별 계층적 검색 및 탐색

증거 그래프

supports, contradicts, extends, derives_from 등 유형화된 관계로 클레임 간 연결

탐색적 생명 분류법

원리, 이론, 모델, 메커니즘 중심으로 논문을 과학적 맥락에 배치

클레임 표현

출처 부착 클레임의 구조

클레임 레코드 구성

  • 클레임 유형 (측정값, 가설, 한계 등)
  • 출처 DOI
  • 축어적 인용구 (verbatim quote)
  • 구조화 필드 (반응물, 조건, 측정값 등)
  • 추출 신뢰도 점수

연관 구조

  • Source: 논문 메타데이터 (DOI, 학회, 연도, 인용 수)
  • TreeNode: 패싯 분류법 경로 배치
  • Edge: 클레임 간 유형화 관계

모든 구조가 공유 클레임 ID에 고정되어 검색·탐색·그래프 순회가 동일한 근거 객체를 반환

패싯 분류법

안정화 패싯 분류법

사전 정의 온톨로지가 아닌, 코퍼스에서 유도 후 안정화된 L1/L2/L3 경로

안정화 과정

  • 논문 소화 중 카테고리 경로 유도
  • 정규 최상위 라우팅 (canonical top-level routing)
  • 동의어 정규화
  • 유사 하위 카테고리 퍼지 클러스터링

8가지 운용 뷰

  • 반응 유형 (by_reaction_type)
  • 물질 클래스 (by_substance_class)
  • 응용 분야 (by_application)
  • 기법 (by_technique)
  • 메커니즘 주제 (by_mechanism_topic)
  • 클레임 유형 / 데이터 / 시간 / 저자

예: coupling/cross_coupling/suzuki — 동일 클레임이 여러 뷰에서 다르게 분해되어 탐색 (Figure 4)
