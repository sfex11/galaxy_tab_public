제어 가능한 환경 합성으로 밝혀낸 도구 사용 에이전트의 스케일링 법칙

Andrew Szot · Samira Abnar · Omar Attia · Abbas Kazerouni · Michael Kirchhof · Cheng-Yu Hsieh · Raviteja Vemulapalli · Alexander Toshev

Apple  ·  arXiv:2610.37648

왜 도구 사용 에이전트인가?

  • LLM 에이전트는 복잡한 상태 기반(stateful) 환경과 상호작용하며 다단계 작업을 수행
  • 도구를 선택·조합하고, 상태 변화를 추적하며, 새로운 API 환경으로 일반화해야 함
  • 그러나 다단계 도구 상호작용 데이터는 인터넷 텍스트에 극히 희소
  • 진전을 위해 현실적 작업 + 다양한 도구 + 풍부한 환경 데이터의 대규모 확장이 필수
핵심 질문: 합성 환경 데이터의 구성(composition)이 에이전트의 학습과 일반화에 어떤 영향을 미치는가?

기존 접근법의 한계

LLM 시뮬레이션 방식

Nemotron-Agentic(335k 궤적), SimSAT 등이 도구 응답까지 LLM으로 생성

복잡한 도구 출력과 상태 전이를 신뢰성 있게 시뮬레이션하기 어려움

실행 가능 환경 합성

영구 데이터베이스 기반의 실행 가능한 도구 환경을 코드로 합성

데이터 양 확장에만 집중 — 어떤 속성이 성능을 좌우하는지 미규명

필요한 것: 도구·작업·데이터의 다양성을 명시적으로 제어할 수 있는 합성 파이프라인

SynthAPI: 제어 가능한 환경 합성 파이프라인

1
앱(App) 생성
LLM이 구조화된 데이터베이스를 읽고 수정하는 Python 도구들로 앱을 구현
2
작업 생성
초기 DB 상태(데이터 프로필)와 실행 가능한 성공 검증기를 갖춘 다단계 작업 생성
3
구성 제어
도구·작업·데이터 프로필의 다양성과 복잡도를 명시적으로 조절
기존 실행 환경 합성과의 차이: 다양성·복잡도에 대한 명시적 제어를 통해 데이터 구성 효과를 분리 분석 가능

세 가지 제어 축과 핵심 연구 질문

도구 (Tools)

사용 가능한 Python 도구/API의 다양성

작업 (Tasks)

작업 지시문의 수와 다양성

데이터 프로필

도구가 동작하는 초기 DB 상태의 다양성·복잡도

모델 크기

  • SynthAPI의 생성 제어를 체계적으로 변화시키며 다운스트림 일반화 예측
  • 평가: AppWorld · BFCL · ASTRA-Bench 등 4개 벤치마크

발견 1: 다양성이 단순 작업 수보다 중요

  • 작업 예산이 커질수록 도구 다양성 확장이 동일 도구 내 추가 작업 생성보다 효과적
  • 새 작업을 만드는 것보다 동일 작업을 다양한 데이터 프로필로 반복하는 편이 유리
  • 최적 데이터 구성은 스케일에 따라 변화 — 소규모와 대규모에서 최적 배분이 다름
단순히 작업 수를 늘리는 것보다 도구·데이터 프로필 다양성에 투자하는 것이 일반화에 유리

발견 2: 복잡도가 이끄는 추가 이득

스케일과 복잡도

데이터 예산이 커질수록 더 복잡한 데이터 프로필을 사용할 때 더 큰 성능 향상을 얻음

예측 가능한 관계

환경 구성 요인(도구·작업·프로필의 규모와 다양성)과 다운스트림 일반화 사이에 예측 가능한 관계 성립

→ 이 관계를 정량화한 것이 환경 구성 의존(environment composition dependent) 스케일링 법칙

스케일링 법칙의 외삽 검증

  • 학습 FLOPs 상위 25% 실행(run)을 홀드아웃하여 법칙 검증
  • 피팅에 사용한 최대 예산의 최대 16배 FLOPs 구간까지 성공적 외삽
예측 모델정규화 다운스트림 점수 MAE
환경 구성 인자 기반 (제안)0.0285
작업 수만 고려 (구성 무시)0.1706
데이터 구성을 반영해야만 대규모 예산에서의 성능을 정확히 예측할 수 있음
