Ensemble Methodology for Reference-Free Confidence Estimation in LLM-based Code Summarization

참조 요약 없이 LLM 생성 COBOL 코드 요약의 신뢰도를 추정하는 앙상블 프레임워크

Marco Colombo · Sumit Tokkar (UIUC) / Balaji A J · Sowmyakumari Selvaraj · Animesh Kumar · Ravishankar Shetty (Infosys) / Aravinda Prasad Sistla · Rigel Gjomemo (UIC)

배경: 여전히 세상을 지탱하는 COBOL

수십억 줄

금융·보험·정부·의료 분야 프로덕션 환경에서 운영 중인 레거시 코드

미션 크리티컬

거래 처리(TPF), 코어 뱅킹, 클레임 처리, 규제 준수 등 핵심 운영 담당

  • 수십 년간의 점진적 수정, 벤더별 확장으로 코드베이스 복잡도 누적
  • 적절한 문서화 없이 진화한 비즈니스 로직 → 심각한 지식 관리 문제

현대화 압력과 문서화 공백

개발자 감소

COBOL 숙련 개발자의 고령화와 신규 인력 부족 → 지속가능성 위험

통합 장벽

클라우드 네이티브·마이크로서비스·API 생태계와 연동 곤란

유지보수 비용

노후 메인프레임 인프라 유지에 막대한 비용 발생

문서화 공백: 대부분의 레거시 COBOL 프로그램에는 주석·외부 문서·설계 명세가 없고, 원 개발자들은 은퇴하며 암묵지를 함께 가져갔습니다. 안전한 마이그레이션에는 각 프로그램의 정확한 동작 설명이 필수적입니다.

핵심 질문

"정답(ground truth)이 존재하지 않을 때, AI 생성 문서의 품질·정확성·신뢰성을 어떻게 평가할 수 있을까?"

  • GPT-4, Claude, LLaMA 등 최신 LLM은 코드 요약 생성이 가능 — 대규모 자동 문서화의 기회
  • 그러나 참조 문서가 없어 출력 검증이 불가능하다는 근본적 문제

기존 평가 방법의 한계

참조 기반 지표

BLEU · ROUGE · CodeBLEU · BERTScore

인간 작성 정답 요약이 필수 → 참조 문서가 없는 레거시 COBOL에는 근본적으로 부적합

모델 내부 신호

Perplexity · 로짓 확률

유창하면서도 비즈니스 로직을 완전히 잘못 해석하는 "확신에 찬 오류"는 탐지 불가

단일 LLM-as-Judge

한 모델이 타 모델 출력 평가

평가자의 체계적 편향, COBOL·메인프레임 패러다임 이해 부족, 비일관 판단 위험

어떤 단일 지표도 도메인 특화 레거시 코드의 참조 없는 평가를 충족하지 못함

요구되는 평가 지표의 6가지 요건

참조 불필요

정답 비교 없이 동작

정량화 가능

우선순위화·품질 게이팅을 지원하는 수치 신뢰도

해석 가능

저신뢰 판정 이유를 설명하는 실행 가능한 신호

다차원

정확성·완전성·일관성 축의 종합 평가

강건성

단일 모델 편향·프롬프트 아티팩트에 저항

확장성

수백만 라인 문서화에 적용 가능

제안: 다지표 앙상블 프레임워크

① 모델 간 합의 (LLM-as-Judge)

다양한 모델로 요약 생성 후, 구조화된 쌍별 비교로 의미 수준 일치도 측정

② 보정된 집계

선형 풀링으로 지지 증거 결합 + 상호 검증된 모순에만 conjunctive penalty 부여

③ 토큰 수준 신뢰도

Perplexity·로짓 확률 분석으로 생성 확실성 측정

④ 코드 커버리지 (G-Eval)

문서화 완전성 정량화 및 체계적 누락 탐지

핵심 직관: 의미에 대한 모델 간 합의는 진실에 대한 정보가 된다

구성 요소 ① LLM-as-Judge 쌍별 평가

  • 다양한 LLM들이 동일한 COBOL 코드에 대한 요약을 각각 생성
  • LLM 평가자가 요약 쌍을 비교하여 구조화된 판단(structured judgment) 출력
  • 앵커 기반(anchor) 쌍별 비교로 평가의 일관성 확보
  • 세분도(granularity) 제어로 비교 수준의 균일성 유지

문자열·임베딩 유사도 기반 지표보다 의미 수준의 쌍별 평가가 더 높은 충실도를 제공한다

구성 요소 ② 보정된 집계 규칙

1
선형 풀링 (Linear Pooling)
여러 평가 판단의 지지 증거를 결합하여 종합 신뢰도 점수 산출
2
Conjunctive Penalty (연립 벌점)
단일 평가자의 지적이 아닌, 상호 검증(corroborated)된 모순에만 감점 적용
  • 일부 평가자의 편향·오류가 최종 점수를 왜곡하지 않도록 방지
  • 지지 증거는 결합하고, 검증된 모순만 벌점 반영 → 균형 잡힌 신뢰도 산출

구성 요소 ③④ 토큰 신뢰도 & 코드 커버리지

토큰 수준 신뢰도

  • 로짓 확률·perplexity로 생성 확실성 측정
  • 신뢰도 점수 정규화 및 임계값 보정
  • 앙상블 점수와 통합

G-Eval 커버리지 평가

  • 요약이 코드 요소를 얼마나 포괄하는지 평가
  • 체계적 누락(systematic omission) 탐지
  • 휴리스틱 대신 LLM 평가의 유연성 채택

네 지표가 상호 보완적으로 작동하여 정확성·완전성·일관성을 다차원적으로 커버

전체 파이프라인

1
요약 생성
다양한 LLM이 COBOL 코드 요약 생성
2
쌍별 평가
LLM-as-Judge가 구조화된 판단 출력
3
집계
선형 풀링 + 검증된 모순 감점
4
신뢰도 산출
토큰 신뢰도·커버리지 통합 최종 점수

참조 문서 없이 자동 트리아지(triage) 실현 — 수백만 라인 문서화에 확장 가능

엔터프라이즈 적용: 자동 품질 게이팅

고신뢰

"모델 간 합의가 높고 코드 커버리지가 완전함 → 다운스트림 사용 가능"

저신뢰

"모순 존재 및 잠재적 누락 감지 → 전문가 검토 필요"

  • Infosys 내부에 구현되어 대규모 코드베이스 요약·비즈니스 규칙 추출에 실제 활용
  • 개발자가 현대화 대상 비즈니스 로직을 신뢰할 수 있도록 품질 게이팅 제공

결론

  • 참조 문서 없이도 LLM 생성 COBOL 요약의 신뢰도를 정량 추정하는 앙상블 기법 제시
  • 모델 간 의미 합의 + LLM-as-Judge + 보정된 집계 + 토큰 신뢰도 + G-Eval의 유기적 결합
  • 레거시 시스템 현대화에서 AI 문서화의 신뢰 문제에 대한 실용적 해법
