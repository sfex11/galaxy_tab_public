핵심 아이디어: 코드 자체에서 환경을 만들다

소스 코드를 유일한 태스크별 입력으로 사용

  • 구현된 기능은 태스크의 기반이자 후보 솔루션이 됨
  • 공개 인터페이스와 관찰 가능한 동작이 에이전트가 구현할 내용을 정의
  • 원본 코드 실행이 테스트 기대값의 근거를 제공
  • 주변 코드베이스는 실제 프로젝트 구조·의존성을 보존하는 개발 시작점으로 변환

요구되는 동작은 태스크 문장에 명시하되, 내부 구현 선택은 열어두어야 함

태스크 설계 및 코드베이스 적응

행동 명세 공식화

에이전트가 코드베이스의 구현된 기능을 탐색하여 동작 명세를 작성

무엇을 구현할지는 명확히, 어떻게 구현할지는 자율적으로

개발 시작점 변환

대상 기능이 아직 구현되지 않은 상태로 코드베이스를 적응

실제 프로젝트 구조와 의존성을 그대로 유지

  • 이슈·커밋·테스트·문서 없이도 태스크 문장 생성 가능
  • 개발 기록의 커버리지 밖에 있는 기능까지 태스크화 → 태스크 다양성 확대

실행 기반 테스트 구성과 검증

  • 실행에 근거한 테스트: 원본 코드를 직접 실행하여 그 결과에서 테스트 기대값을 도출
  • 실행 일관성 검사: 원본 코드와 후보 구현의 실행 결과가 일치하는지 확인
  • 양방향 판별: 잘못된 솔루션은 거부하되, 대안적인 올바른 구현은 수용해야 함

좋은 테스트 오라클이야말로 신뢰할 수 있는 실행 보상의 전제 조건 — 기존 테스트 스위트만으로는 놓치는 오류가 존재
