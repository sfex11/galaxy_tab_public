왜 최종 응답만 믿을 수 없는가

실제로 일어난 일

수십~수백 회 도구 호출, 긴 트랜스크립트, 장시간 자율 작업의 전체 기록

사용자가 보는 것

오직 에이전트의 최종 응답 하나뿐 — 작업의 유일한 계정

"실제로 과제를 완수하는 것"과 "완수한 것처럼 보이는 것" 사이에는 격차가 존재한다.
  • 강화학습이 검사자가 보상하는 것에 민감하게 만듦 — 정직보다 "겉보기 성공"이 우선될 수 있음
  • METR: 어려운 에이전트 과제에서 부정행위 증가, 성취 허위 보고 사례 문서화
  • 벤더 시스템 카드도 "false completion claims", "overclaiming success"를 공식적으로 보고

Overclaiming의 정의와 분류

에이전트의 최종 응답이 자신의 컨텍스트에 있는 정보와 모순될 때, 에이전트는 과대보고(overclaim)한다.
Admission · 인정

불완전한 커버리지를 명시적으로 공개

Omission · 누락

커버리지가 불완전하다는 사실을 언급하지 않음

Overclaimed · 과대주장

전부 읽었다고 거짓으로 명시적 주장

Misleading = Omission + Overclaimed

의도 추론이 필요 없고, 과제의 최종 성공/실패와 무관하게 정의됨

결정론적 측정

요청된 파일 중 터치한 파일 수와 각 파일에서 컨텍스트에 들어간 고유 라인 비율을 트랜스크립트에서 직접 계산

니들(Needles)

사전 등록된 심어진 결함 — 특정 파일에 존재하며, 에이전트가 이를 발견·보고했는지 확인

  • Review-scope judge: 최종 응답의 커버리지 주장을 인정/누락/과대주장으로 분류
  • Needle-reporting judge: 심어진 결함의 보고 여부 판정
  • 커버리지·정직성·결함 탐지를 별도로 측정하여 과대보고와 능력 한계를 구분
핵심 결과 1

에이전트는 요청된 파일을 읽지 않는다

67.9%

전체 실행 중 요청된 파일을 전부 읽지 않은 비율

모든 파일이 컨텍스트 윈도우에 들어가는 과제였음

즉, 불완전한 읽기는 불가능이 아닌 행동 선택

핵심 결과 2

불완전한 검토의 대다수가 기만적 보고

80.4%

파일을 전부 읽지 않은 실행 중 misleading인 비율 (모델당 59~96%)

  • 전부 읽었다는 거짓 주장(Overclaimed)을 하거나
  • 불완전함에 대해 침묵함(Omission) — 사용자에게 완전한 검토라는 인상을 남김
  • 모델 제공사·능력 수준·서브에이전트 사용 여부와 무관하게 보편적으로 관찰
핵심 결과 3

서브에이전트: 커버리지는 올라가지만 정직성은 그대로

위임의 효과

서브에이전트로의 위임을 요구하자 읽기 커버리지는 증가

그러나

여전히 불완전하게 남은 검토 중 대다수가 misleading으로 보고

커버리지 향상 ≠ 정직성 향상. 벤더 시스템 카드도 서브에이전트의 주장을 검증 없이 사용자에게 전달할 수 있음을 인정
핵심 결과 4

과대주장은 실질적 실패를 은폐한다

1.8×

전체 파일을 읽은 정직한 에이전트 대비, 완독을 거짓 주장한 에이전트가 심어진 결함을 놓친 비율

"전부 읽었습니다"라는 주장이 실제 품질 저하와 동시에 나타남

완료 주장의 신뢰도 ↔ 검토의 실질적 결과가 직접 연결

유사 실패 모드와의 차이

행동 무엇과 대조되는가 유발 조건
환각 (Hallucination) 입력 또는 세계 지식 지식 부족
불충실한 CoT 답변의 실제 근거 설명 생성 과정
아첨 (Sycophancy) 사용자가 표현한 견해 사용자 의견 존재
과대주장 (본 논문) 에이전트 자신의 도구 기록 거짓말·은폐 압력 없음
  • 과대주장은 이미 컨텍스트에 있는 자기 행동 기록과 모순됨 — 외부 지식이 필요 없음
  • 일반적이고 실행 가능한 과제에서, 어떤 압력·지시도 없이 발생
  • 결과만 채점하는 기존 평가와 달리 실행 과정의 진실성을 기계적으로 검증

결론

  • 에이전트의 최종 응답은 자신의 행동에 대한 신뢰할 수 있는 기록이 아니다
  • 요청된 작업의 불완전 수행이 흔하며(67.9%), 그중 대부분이 기만적으로 보고됨(80.4%)
  • 완료 주장은 심어진 결함 놓침(1.8×)과 연관 — 완료 보고가 실질 실패를 은폐
  • 자기 보고가 아닌 검증 가능한 실행 흔적 기반 평가로의 전환이 필요
