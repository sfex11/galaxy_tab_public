Text-to-SQL · 테이블 검색 · Learning to Rank

FERN

Feature-Engineered Ranking with No generative LLM

Frozen Retriever와 학습된 랭킹으로 구현하는 교차 벤치마크 테이블 검색

Arjun Rao · Nishant Gopinath (SAP)

2026년 11월 · arXiv:2611.14477

문제 정의

대규모 통합 카탈로그에서의 테이블 검색

Text-to-SQL 시스템이 충실한 쿼리를 작성하려면, 질문에 필요한 테이블을 먼저 찾아야 합니다.

테이블이 누락되면

골드 SQL이 사용하는 테이블이 빠지면 쿼리 자체가 틀립니다.

테이블이 많으면

여분의 스키마가 생성기의 컨텍스트를 낭비합니다.

대상 데이터베이스가 주어지지 않은 채, 여러 데이터베이스의 수백 개 테이블이 하나로 합쳐진 카탈로그(pooled catalog)에서 검색 — 이 단계를 스키마 링킹(schema linking)이라 합니다.

기존 접근과 그 비용

LLM 기반 스키마 링킹: RASL

  • Claude 3.5 Haiku로 질문에서 키워드를 추출해 스키마 엔티티 검색
  • Claude 3.5 Sonnet v2가 후보 스키마를 읽고 테이블을 선택
  • BIRD·Spider·Fiben 통합 카탈로그에서 공개된 테이블 recall 기준점 제공

생성형 링킹의 대가

BIRD 100쿼리당 종단 간 입력 토큰 비용 $1.85 — 호스팅 모델 호출이 필수입니다.

엔터프라이즈 환경에서는 스키마와 질문 텍스트를 외부 서비스로 보내는 것 자체가 받아들여지지 않을 수 있습니다.

연구 질문

이 논문이 던지는 질문

"공개 벤치마크에 한 번만 학습한 랭커가, 생성 모델 없이 frozen retriever만으로 통합 카탈로그의 테이블 검색을 어디까지 해낼 수 있는가?"

  • 검색 경로에 호스팅 생성형 LLM 일절 없음 — 전부 로컬 실행 가능
  • 재료는 고전 IR의 검증된 조합: 어휘 검색 + 오프더셸프 임베딩 + 스키마 통계 + learning to rank
  • BIRD 학습 질문으로 랭커를 한 번 학습 후, Spider·Fiben·BEAVER에 그대로 적용
핵심 아이디어

FERN의 세 가지 구성 요소

Frozen Retriever ×3

학습하지 않는 검색기 3종을 융합해 질문당 100개 후보 테이블을 제안합니다.

최대 120개 특징

질문·카탈로그·검색기 점수에서 각 후보를 설명하는 스키마 특화 특징을 계산합니다.

LightGBM 랭커

BIRD 학습 질문에 한 번만 학습된 그래디언트 부스팅 랭커가 후보를 재정렬합니다.

evidence 유무·셀 값·컬럼 타입에 따라 세 가지 변형(variant)을 제공합니다.

방법

검색 파이프라인

1
후보 생성
3개 frozen retriever 융합 → 100개 후보
2
특징 계산
질문·카탈로그·검색기 점수 → 최대 120개 특징
3
학습된 재정렬
BIRD로 한 번 학습한 LightGBM 랭커
4
상위 k 반환
호스팅 모델 호출 없이 결과 제공

핵심: 약한 관련성 신호 여럿을 학습된 랭커로 결합하는 고전 IR 레시피를, 생성 모델 없이 테이블 검색에 적용한 것이 FERN입니다.

평가 설정

벤치마크와 프로토콜

카탈로그

  • BIRD · Spider · Fiben 통합 카탈로그
  • BEAVER: 실제 기업 웨어하우스 3개, 121개 실제 질문

규칙

  • 랭커는 BIRD 학습 질문에만 학습
  • Spider·Fiben은 설계 결정에 사용하지 않음
  • BEAVER·Fiben에는 학습 없이 그대로 전이

recall@k: 상위 k개에 골드 테이블이 포함된 질문 비율 · complete@k: 모든 골드 테이블이 상위 k개 안에 들어온 질문 비율

어떤 특징이 어디서 기여하는가

검색 신호만으로

BIRD dev + evidence에서 검색 신호만(또는 비검색 특징만)으로 랭킹해도 recall@15는 약 98에 도달합니다.

비검색 특징의 가치

비검색 특징을 추가하면 complete@5가 +7.7점 향상됩니다.

탐색적 소거 실험: 데이터베이스 지원 특징 또는 조인 그래프 특징 제거 시 complete@5 점 추정치가 각각 −0.8점 하락 (나머지 특징군의 구간은 0을 포함).

→ 스키마 구조를 이해하는 특징이 "모든 필요 테이블을 모으는" 능력을 좌우합니다.

결론

요약과 시사점

  • 검증된 결론: frozen retriever 융합 + BIRD 단일 학습 랭커만으로 Spider·BIRD(evidence)에서 LLM 기반 링킹에 소폭 차이(≈1점 이내)로 근접
  • 강점: 작은 예산에서의 complete@k 향상, 208ms 로컬 실행, 외부 데이터 유출 없음
  • 한계: evidence 힌트 의존성(−7.3점), 불투명 스키마(Fiben)에서의 상위 재정렬 실패, 기업 벤치마크에서 complete-set 복원 열세
