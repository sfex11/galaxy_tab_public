왜 아랍어 Speech-LLM인가?

  • Speech-LLM은 빠르게 다국어화되고 있지만, 아랍어는 여전히 크게 소외
  • ASR 외 태스크(SER, SQA 등)의 공개 아랍어 음성 코퍼스가 극도로 부족
  • 음성 instruction-tuning 데이터는 대부분 영어 — 진짜 아랍어 음성-지시 쌍은 거의 없음
  • 아랍어 음성 LLM을 위한 널리 쓰이는 평가 벤치마크 부재

기존 모델의 한계

Octopus 계열

  • 아랍어 중심 Speech-LLM (ASR, 영어 번역, 방언 식별)
  • 태스크 커버리지가 매우 제한적
  • Zero-shot 일반화 부족
  • 비공개 데이터 위주 → 재현성 저하

Qwen 계열

  • Qwen2-Audio: 아랍어 지시 수행 능력 검증 안 됨
  • Qwen2.5-Omni: 29개 언어 지원, 그러나 예시는 영어·중국어 위주
  • Qwen3-Omni: 아랍어를 명시적 지원 (19개 음성 입력 언어)
  • 아랍어 성능의 체계적 평가는 여전히 부재

Nuha-Speech: 3대 축

데이터 구축 → 모델 학습 → 체계적 평가로 이어지는 종합 이니셔티브

핵심 태스크 상세 (1): 이해 중심

ASR

4개 대규모 다방언 공개 데이터셋 활용, 1~10초 구간으로 필터링해 학습 효율 최적화. ~790K 샘플

AST

CoVoST-v2 아랍어→영어 분 사용. 샘플 부족으로 ASR 전사 15만 건을 Qwen3-32B로 번역해 보강

SQA

MGB-2 전사 기반 Qwen3-32B로 폐쇄형 150K + 개방형 150K QA 쌍 생성. 구조적 검색과 추론 능력 동시 강화

모든 샘플은 {speech, instruction, output} 튜플로 통일 — 단일 의미 공간에서 태스크 통합. GPT-5로 다양한 지시문 세트를 설계해 zero-shot 일반화 확보

핵심 태스크 상세 (2): 부가정보 & 복합

방언 식별 (DI)

아랍어의 핵심 특징인 방언 다양성 반영. ADI-17에서 17개 방언 분류용 150K 샘플 채택

감정 인식 (SER)

ElevenLabs 감정 변환 TTS로 4개 감정(화남/기쁨/슬픔/중립) 균형 20K 합성. 화자 8인으로 편향 최소화

나이·성별 인식 (AR/GR)

나이 3그룹(청년/성인/노년) 20K + SADA 기반 성별 균형 51K. TTS로 3그룹 각 10명 화자 합성 보강

Multi-SQA

성별·나이·ASR 통합 분석형 멀티턴 5K + 감정-전사 간 상관 추론 크로스모달 QA 10K (Qwen3-32B 생성)

데이터 구축 전략

  • 공개 데이터셋 우선 — 연구 커뮤니티가 재현할 수 있는 투명한 큐레이션 전략
  • Qwen3-32B로 번역(AST)·QA 생성(SQA)·크로스모달 추론(Multi-SQA) 데이터 생성
  • ElevenLabs TTS로 부족한 감정·나이 데이터 합성 (스타일 과장 + 화자 유사도 제어)
  • 텍스트 출력 중심 학습으로 제한된 자원 조건에 맞춘 현실적 설계

Instruction Tuning 설정

Qwen-Omni 시리즈를 베이스라인으로 채택

  • 내장 음성 입력 지원 + 음성 이해 능력 활용
  • Qwen LLM 백본은 아랍어 같은 저자원 언어에서 검증된 일반화 성능

결과: Fine-tuned 모델이 전 태스크에서 명확한 성능 향상 달성

기여 요약

  • 150만+ 아랍어 음성 instruction-following 코퍼스 구축 (8개 태스크)
  • 공개 데이터 + 재현 가능한 큐레이션으로 커뮤니티 복제 가능성 확보
  • 3개 Qwen-Omni 스케일(3B/7B/30B)에 Arabic comprehension 이식
  • 태스크별 맞춤 지표를 갖춘 아랍어 음성 다중 태스크 벤치마크 제안
  • 제한된 자원 환경에서 범용 아랍어 Speech-LLM 구축의 기반 인프라 확립
