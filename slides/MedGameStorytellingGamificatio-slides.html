문제 제기

정적 임상 사례 vs. 동적 임상 추론

기존 방식의 한계

  • 임상 사례를 정적 텍스트로만 제공
  • 추론 과정을 사후에만 확인 가능
  • QA나 단일 턴 피드백에 국한된 상호작용
  • 전체 임상 경로를 아우르는 학습 경험 부재

필요한 접근

  • 부분 정보를 해석하는 순차적 추론
  • 다음 질문/검사를 결정하는 의사결정 노드
  • 새로운 증거에 따른 이해 업데이트
  • 발표에서 해결까지의 완전한 학습 궤적

"LLM이 정적 임상 사례를 구조화되고 실행 가능하며 대화형 학습 궤적으로 변환할 수 있는가?"

서술자 (Screenwriter)

임상 기록을 장면, 등장인물, 의사결정 노드가 포함된 계층적 스토리라인으로 변환

감독 (Director)

스토리라인을 DAG 형태의 다중모달 생성 프리미티브로 매핑하여 의존성 관리

형식 정의

막(Act), 장면(Scene), 의사결정 노드

Level 0: 임상 스토리 트리

전체 임상 사례의 뿌리 노드. 사례 메타데이터와 전체 구조를 포함

Level 1: 막 (Act)

임상 단계별 그룹: 초진, 검사, 진단, 치료 등

Level 2: 장면 (Scene)

특정 임상 위치에서의 상호작용 단위. 대화, 설명, 질문 포함

Level 3: 장면 항목 (Scene Items)

장면 내 세부 요소: 캐릭터 대화, 내레이션, 이미지 프롬프트, 의사결정 노드

Level 4: 옵션 (Options)

의사결정 노드의 선택지. 각 옵션은 정오답, 피드백, 다음 장면 링크 포함

엔진 1

Medical Narrative Designer

임상 기록을 사례에 근거한 계층적 스토리라인으로 합성

핵심 요구사항

  • 원본 사례에 대한 충실성 유지
  • 의미 있는 의사결정 체크포인트 노출
  • 의학적 타당성 보장
  • 기계 실행 가능한 구조 출력 (JSON)

서술 요소

  • 임상 위치 세트 (ℒ)
  • 의료진 페르소나 (𝒫)
  • 장면 내레이션, 캐릭터 대화
  • 의사결정 옵션 + 피드백

출력 구조 예시

Clinical_Story_Tree
├─ Act: "초진"
│ ├─ Scene: "응급실"
│ │ ├─ Narrative: "환자가..."
│ │ ├─ Character: "김 의사"
│ │ └─ DecisionNode:
│ │ ├─ Option A → Scene_2
│ │ └─ Option B → Scene_3
│ └─ Scene: "검사실"
├─ Act: "진단"
└─ Act: "치료"

RQ1

기존 LLM의 MedGame Bench 성능

상용 모델 vs 오픈소스 모델 비교 평가

주요 발견

  • 상용 모델(GPT-4o 등)이 전반적으로 우수한 성능
  • 오픈소스 모델은 구조적 유효성에서 상대적으로 낮은 점수
  • 의학적 정확도(CDA, MEA)에서 모델 간 격차가 두드러짐
  • 서사 품질(NQ)은 비의학 모델도 비교적 잘 달성

차원별 성능 패턴

  • Clinical Decision Accuracy: 상용-오픈소스 간 가장 큰 격차
  • Narrative Quality: 격차가 상대적으로 작음
  • Feedback Quality: 중간 수준의 격차
  • 의학 도메인 사전 학습이 정확도 지표에 핵심적 역할

의학적 정확도는 단순한 언어 능력이 아닌 도메인 지식에 크게 의존하며, 이는 오픈소스 모델 파인튜닝의 동기를 제공

RQ2

오픈소스 모델 파인튜닝 효과

태스크 특화 파인튜닝이 상용 모델과의 격차를 어떻게 줄이는가?

파인튜닝의 효과

  • 오픈소스 모델의 모든 평가 차원에서 substantial 향상
  • 특히 의학적 정확도(CDA, MEA)에서 큰 폭 개선
  • 구조적 유효성 문제 대부분 해결
  • 상용 모델과의 격차를 유의미하게 축소

의학 도메인 사전학습의 영향

  • 의학 사전학습 모델이 일반 모델보다 파인튜닝 후 더 높은 정확도 달성
  • 사전학습은 파인튜닝 효율을 높이는 보조 역할
  • 서사 품질에는 사전학습 효과가 제한적

유사 사례의 영향

훈련 데이터에 유사 사례가 포함되면 해당 카테고리에서 성능이 추가로 향상되나, 과적합 리스크도 존재

RQ3

LLM-as-a-Judge 신뢰도 및 전문가 검수

LLM 판사 신뢰도

  • 다차원 평가 프롬프트 설계로 일관성 확보
  • 인간 평가와의 상관관계 분석 통해 타당성 검증
  • 구조 검증 파이프라인(L1-L4)과 결합하여 평가 견고성 강화
  • 자동 평가의 규모 확장성 확보

전문가 인-더-루프 수정

  • 의학 전문가가 생성된 교육 콘텐츠 직접 검수
  • 전문가 수정이 생성 콘텐츠의 교육적 품질을 크게 강화
  • 특히 의학적 정확도와 피드백 품질에서 수정 효과가 두드러짐
  • 인간-AI 협업 파이프라인의 실증적 가치 확인

자동 평가로 대규모 필터링을 수행하고, 전문가 검수로 핵심 품질을 보장하는 하이브리드 접근이 효과적
