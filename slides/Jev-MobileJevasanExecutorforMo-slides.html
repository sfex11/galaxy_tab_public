Jev-Mobile

Jev as an Executor for Mobile GUI Agents

저빈도 VLM 계획 + 고빈도 경량 실행으로
모바일 GUI 에이전트의 지연 시간과 API 비용을 획기적으로 절감

arXiv:2609.30186  ·  Linghua Zhang (Rice University)

배경: 기존 VLM 기반 모바일 에이전트의 한계

매 단계 VLM 호출

기존 시스템은 계획(planning)과 액션 그라운딩(grounding)을 거의 모든 상호작용 단계에서 VLM에 의존합니다.

지연 · 비용 문제

단순 터치 하나에도 대형 VLM 추론이 필요해 상당한 지연 시간과 모델 서빙 비용이 발생합니다.

핵심 질문: VLM이 로컬 목표만 지정하면, 별도의 빠른 결정 모델이 여러 그라운딩된 액션을 대신 수행할 수 있는가?

핵심 아이디어: 계획과 실행의 분리

1
VLM 계획 (저빈도)
태스크·화면·액션 이력을 읽고 로컬 목표와 정확한 입력 텍스트를 지정
2
Jev 실행 (고빈도)
접근성 트리 기반 액션 공간에서 타입화된 결정 모델이 반복적으로 액션 선택
3
재관찰 및 갱신
각 액션 후 새 접근성 트리로 후보를 재구성하고 적응적으로 반복
N:1

VLM 결정 1회당 여러 GUI 액션 실행

고가의 VLM 추론 호출 대폭 감소

↑적응성

화면 변화에 따른 적응형 상호작용 유지

문제 설정 (Problem Setup)

액션 at 이후 관찰: ot = (It, Tt, zt) — 스크린샷 · 접근성 트리 · 기기 컨텍스트

VLM이 보는 것

  • 스크린샷 It 와 접근성 트리 Tt
  • 목표별로 그룹화된 실제 액션 이력

Jev가 보는 것

  • 텍스트 트리 + 현재 로컬 목표
  • 위임 중 수행한 이전 액션 + 실행 가능 후보 설명

숨겨진 태스크 파라미터나 평가자의 정답은 어느 역할에게도 노출되지 않으며, 종단 상태는 AndroidWorld가 독립적으로 채점합니다.

제어 흐름: 위임 상태와 핸드오프

1
Main VLM
dk ∈ {delegate, finish, blocked} + 로컬 목표 gk + 정확 텍스트 vk 출력
2
Jev Decisions
후보 ID 선택 또는 DONE / BLOCKED 반환
3
Android 실행기
후보 검증 후 액션 1개 수행, 새 화면·트리로 피드백

DONE  제어를 VLM에 반환 → 다음 로컬 목표 결정

BLOCKED  해석 요청 또는 실행 가능한 액션 부족 보고

VLM은 위임 후 요약을 생성하지 않으며, 전체 성공 여부는 독립 평가기가 판정합니다.

접근성 트리 기반 결정론적 후보 구성

Ct = f(Tt, zt, vk) — 원시 트리를 순회하여 실행 가능한 액션 후보를 열거

  • 가시·활성·유효 경계 노드만 클릭 / 길게 누르기 / 스크롤 / 포커스 액션 생성
  • VLM이 제공한 정확한 텍스트 vk가 있으면 포커스 필드에 입력 액션 생성
  • Back · Home · Enter · 앱 열기 등 기기 상태가 지원할 때 시스템 액션 추가
  • 액션 1회마다 재관찰 → 새 후보 Ct+1 구성, 이전 ID·좌표는 무효화
  • 비-멱등 액션의 모호한 응답 시 맹목 재제출 대신 점검 수행
보장의 범위: "선택된 후보는 특정 관찰에서 유도된 실행 가능한 액션이다" — 화면이 바뀌어도 유사해 보이는 노드에 조용히 잘못 바인딩되지 않습니다.

타입화된 지역 결정과 이벤트 이력

하나의 타입화된 선택

  • 후보 ID · DONE · BLOCKED 중 하나를 선택
  • 상태: gk, 관찰 ID, 트리, 현재 위임의 액션 이력
  • 어댑터가 실행 전 타입·ID 검증 (출력 공간은 제한되나 정확성은 보장되지 않음)

이벤트 장부

  • 선택 ID, 실제 파라미터, 실행 상태 기록
  • 전/후 관찰 ID + 결정론적 변경 설명
  • 제출 전 거부된 오래된 선택은 이력에서 제외

핸드오프 시 VLM은 현재 스크린샷·트리와 목표별로 그룹화된 실제 액션 이력만 수신 — 오래된 스크린샷, 예측 액션, 모델이 쓴 요약은 전달하지 않습니다.

예산, 실패 처리, 구현 경계

에피소드 예산

벽시계 시간 · 액션 수 · 호출 수 · 대기 · 재시도가 하나의 공유 예산을 소비합니다. 잘못된 출력, stale ID, 오버플로, API 오류는 모두 이벤트 장부에 남습니다.

의도된 한계

시각적 대상에 트리 후보가 없으면 VLM이 목표를 재해석해도 좌표 생성 시각 폴백이 없어 도달 불가 — 이는 후보 커버리지 또는 핸드오프 실패로 측정됩니다.

  • 새로운 학습 · 계층 복구 · 시맨틱 필드 바인딩 · 구조화된 완료 술어가 불필요
  • "로컬"은 의사결정 범위를 의미할 뿐, 온디바이스 추론을 뜻하지 않음 (Jev는 원격 Decisions 서비스)

실험 설계

벤치마크

AndroidWorld 전체 태스크 스위트, 독립적인 종단 상태 채점

비교 대상

Step-wise VLM (매 단계 VLM 호출)
SeeAct-V (UI-TARS 그라운딩)
동일한 일반 VLM(Qwen3.8-Max) 공유

지표

태스크 성공률, 종단 실행 시간, 모델 API 비용 + 커버리지 / 선택 / 핸드오프를 성공과 분리해 측정

비교 시스템은 각자의 실행 메커니즘을 유지하므로, 결과는 Jev 단독 효과가 아닌 전체 시스템의 특성을 나타냅니다.

분석: 결정 모델을 실행자로

커버리지

수용 가능한 후보가 트리에 존재하는가?

선택

Jev가 그 후보를 올바르게 선택하는가?

핸드오프

제어가 적시에 적절히 반환되는가?

  • 성공률은 SeeAct-V와 근접(79% vs 78%)하면서 지연과 비용은 두 비교 시스템보다 낮음
  • Jev 요청과 관찰이 VLM 호출 수를 상쇄 — 단순 재관찰이 아니라 재관찰 기반으로 적응적 반복 실행
  • 학습된 라우터나 교차 태스크 메모리 없이도 효율 개선 달성

한계 (Limitations)

  • 좌표 생성 시각 폴백 부재 — 이미지로만 존재하는 요소(아이콘 등)는 트리에 없으면 도달 불가
  • 원시 트리를 시맨틱 그래프로 압축하지 않음 — 길거나 노이즈 많은 트리가 잠재적 실패 모드
  • 현재 입력 도구는 지원하지 않는 비-ASCII 텍스트를 거부
  • 성공률은 Step-wise VLM(84%)보다 5%p 낮음 — 효율과 성공률의 트레이드오프 존재

첫 버전은 누락된 시각 좌표 추론, UI 계층 복구, 시맨틱 필드 완성 규칙을 의도적으로 제외하고 그 손실을 커버리지·핸드오프 실패로 투명하게 측정합니다.

결론

  • 구현 기여: 관찰에 바인딩된 Android 후보와 위임 후 요약 없는 VLM–Jev 루프
  • 평가 기여: AndroidWorld 전체 스위트에서 타입화된 결정 모델 실행의 실측
  • 고수준 VLM 추론과 저수준 액션 실행의 분리가 경쟁력 있는 성공률을 유지하며 효율을 크게 개선
