StrataFlux

Memory-Hierarchy-Native Low-Bit LLM Inference

메모리 계층 전체를 네이티브하게 활용해 정확도와 속도를 동시에 잡는 저비트 LLM 추론 프레임워크

저비트 양자화 × 선택적 고정밀 복원 × 지연 시간 은닉

배경 — LLM 추론의 진짜 병목은 메모리다

자동회귀 디코딩 특성상, 연산보다 데이터 이동이 지배하는 워크로드

매 토큰마다 가중치 로드

토큰 하나를 생성할 때마다 수십 GB 규모의 모델 가중치를 반복해서 읽어야 함

대역폭 제약

디코딩 단계는 연산 유닛을 충분히 쓰지 못하고 메모리 접근에 대기하는 memory-bound 구간

커지는 모델 크기

파라미터 수 급증으로 단일 메모리 계층의 용량과 대역폭 모두 한계에 도달

기존 해법의 딜레마 — 정확도 아니면 속도?

경로 A · 저비트 양자화

가중치를 낮은 비트로 압축

  • 메모리 용량·대역폭 수요를 크게 절감 → 빠른 생성
  • 정밀도 손실로 정확도 저하 발생
경로 B · 고정밀 데이터 오프로딩

느린 계층에서 고정밀 데이터 확보

  • 필요한 순간 고정밀 데이터를 가져와 정확도 유지
  • 느린 계층 접근이 병목 → 생성 정체(stall) 발생

"정확도를 지키면 느려지고, 빠르게 하면 성능이 무너진다" — 양자화 연구의 오랜 트레이드오프

핵심 인사이트 — 메모리 계층을 하나의 자원으로

"메모리 계층은 '빠른 계층 vs 느린 계층'의 경쟁이 아니라, 함께 설계할 수 있는 하나의 추론 자원이다"

  • 계층 전체 용량의 총합은 크다 — HBM·DRAM·NVMe를 묶으면 단일 계층보다 훨씬 큰 저장 공간 확보
  • 정확도에 민감한 데이터는 소수 — 대부분의 가중치는 저비트로 충분하고, 일부만 고정밀이 필요
  • 접근 패턴은 예측 가능 — 레이어 실행 순서가 정해져 있어 느린 계층 접근을 미리 준비할 수 있음

StrataFlux — 트레이드오프를 넘어서는 프레임워크

저비트 양자화의 속도 이점을 유지하면서, 잃어버린 정확도를 메모리 계층 전반에서 회수

계층 네이티브 설계

각 계층의 용량·대역폭·지연을 설계 변수로 명시적으로 활용

선택적 고정밀 복원

정확도 손실의 대부분을 만드는 소수의 민감 데이터만 고정밀로 유지·회수

정체 없는 생성

느린 계층 접근을 연산과 겹쳐(overlap) 토큰 생성이 멈추지 않도록 보장

핵심 질문: "어떤 데이터를 어느 계층에 두고, 언제 옮길 것인가?"

StrataFlux의 동작 흐름

1
민감도 분석
어느 레이어·텐서가 저비트에서 정확도를 크게 잃는지 측정
2
계층별 배치
민감 데이터는 고정밀로 상위 계층, 나머지는 저비트로 하위 계층
3
프리페치·오버랩
현재 레이어 연산 중 다음에 필요한 데이터를 미리 이동
4
혼합 정밀도 연산
커널이 필요한 시점에 필요한 정밀도의 데이터를 읽어 연산

추론 중 3~4 단계가 반복되며, 느린 계층 접근은 항상 연산 뒤에 숨겨짐

핵심 기법 ① — 민감도 기반 데이터 계층화

모든 가중치가 똑같이 중요하지 않다는 관찰에서 출발

저비트 유지 · 다수

민감도가 낮은 가중치

전체의 대부분을 2~4비트 수준으로 압축해 용량·대역폭 수요를 최소화

고정밀 보관 · 소수

정확도를 지배하는 민감 구성 요소

고정밀 사본을 메모리 계층에 전략적으로 배치해 양자화 오차를 상쇄

  • 정확도 손실의 상당 부분이 소수의 레이어·채널(예: outlier)에 집중됨
  • 계층 배치는 정적 분석과 실행 중 접근 패턴을 함께 고려해 결정

핵심 기법 ② — 지연 시간 은닉으로 정체 제거

1
미리 가져오기(prefetch) — 현재 레이어를 계산하는 동안 다음 레이어가 필요로 하는 고정밀 데이터를 느린 계층에서 선제 이동
2
연산·전송 중첩(overlap) — 데이터 이동이 완료될 때까지 가속기가 놀지 않도록 스트림·스케줄로 두 작업을 겹침
3
계층 간 대역폭 분산 — 여러 계층 경로를 동시에 활용해 단일 병목 지점을 해소

결과적으로 느린 계층에 데이터가 있어도 토큰 생성은 멈추지 않음 — "오프로딩 정체" 문제의 직접적 해법

기존 접근법과의 비교

접근법메모리 절감정확도생성 지속성
저비트 양자화큼 (비트 수에 비례)저하원활
고정밀 오프로딩제한적유지정체 발생
StrataFlux큼 (저비트 유지)복원원활 (지연 은닉)

두 접근의 장점만을 결합 — 양자화의 속도 + 고정밀 데이터의 정확도

StrataFlux가 목표하는 세 가지 성과

1

정확도 복원

저비트 가중치(및 활성·KV 데이터)로 손실된 정확도를 고정밀 데이터로 회수

2

정체 없는 처리량

오프로딩으로 인한 생성 중단 없이 토큰 생성을 지속

3

계층 자원 활용 극대화

HBM·DRAM·NVMe 전체의 용량과 대역폭을 추론에 직접 동원

의의와 향후 전망

  • 패러다임 전환 — 양자화 vs 오프로딩의 이분법을 넘어, 메모리 계층을 추론 시스템의 일급 자원으로 재정의
  • 확장성 — 모델이 커져도 계층 전체 용량으로 대응 가능, 단일 가속기 메모리 한계 완화
  • 응용 범위 — 엣지 디바이스부터 데이터센터까지 다양한 하드웨어 구성에 적용 가능한 범용 프레임워크
  • 후속 연구 방향 — 활성·KV 캐시의 계층화, 적응적 스케줄링, 민감도 분석 자동화로 확장

결론

StrataFlux는 메모리 계층 전체를 네이티브하게 활용해, 저비트 양자화의 속도 이점을 유지하면서도 잃어버린 정확도를 되찾는다
