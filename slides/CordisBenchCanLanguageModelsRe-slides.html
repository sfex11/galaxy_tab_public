Can Language Models Reason About Component Lifecycles in Dynamic Agent Harnesses?

언어 모델은 동적 에이전트 하네스의 컴포넌트 라이프사이클을 추론할 수 있는가?

Damien Sileo  ·  Dimitri Kachler

Univ. Lille · Inria · CNRS · Centrale Lille · UMR 9189 CRIStAL

arXiv: 2609.01600

배경: 런타임에 변하는 에이전트 하네스

유연성의 새로운 대가

  • 에이전트가 필요에 따라 플러그인·서비스·메모리 정책·도구를 실행 중에 추가·제거·재구성
  • 하네스 자체가 에이전트의 진화하는 상태의 일부가 됨
  • 로컬 플러그인 하나의 변경이 의존성과 정리(cleanup)를 통해 전파

실제 사례: DeepSeek Harness

  • 모델이 동적 플러그인을 직접 구성하고 조작
  • Cordis 런타임이 의존성·수명·정리를 관리
  • Cordis는 변경을 충실히 수행하지만, 결과 상태가 의도와 일치하는지는 모델이 예측해야 함
핵심 질문 — 기호적 도움도 실행 피드백도 없이 스스로 결과를 예측해야 할 때, 이 라이프사이클 추론은 규모가 커져도 안정적인가?

문제 예시: 순서에 민감한 정리(cleanup)

두 플러그인이 같은 설정값을 임시 수정 — 각자 시작 시 값을 저장하고, 종료 시 저장한 값을 복원

두 가지 평가 설정

  • 형식(formal) 설정 — 컴팩트한 형식 언어로 통제된 인스턴스 구성
  • Cordis 네이티브 설정 — 실제 Cordis 런타임에서 플러그인 프로그램 실행
  • 출력은 구조화된 집합·상태 시퀀스·정수·액션 집합, 결정론적 작업별 채점

5가지 작업 군(Task Families)

Localization

요청된 변경의 영향을 받을 수 있는 컴포넌트·슬롯 식별 — 최종 상태 계산 전 의존성 추적 능력 평가

Schedule Prediction

주어진 해체 순서의 결과인 응용 관찰 상태 반환 — 더 큰 문제는 추적할 상태 변화만 추가

Guaranteed Conditions

모든 고려된 순서에서 성립하는 조건 전체 반환 — 보편적(universal) 추론 요구

Reachable Conditions

적어도 하나의 순서에서 성립하는 조건 전체 반환 — 동일한 대안들에 대한 존재적(existential) 추론

Reconfiguration (Cordis 네이티브)

모든 나열된 해체 순서에서 목표 달성을 위한 최소 선제 제거 종속 집합 반환 — 제안은 실제 dispose(...) 실행으로 채점

Outcome Count (진단)

서로 다른 최종 관찰의 개수 반환 — 기본 작업과 분리하여 별도 보고

대표 예시: Cordis 네이티브 재구성

초기 상태: 슬롯 S = 488151  →  제공자 P의 두 종속이 순서대로 시작: A가 36000 기록, 이후 B가 934261 기록

해체 순서: dispose(P) 시 s₁: A→B, s₂: B→A  ·  각 플러그인 정리는 자신이 시작할 때 본 값을 복원

목표: 모든 나열된 순서에서 S를 488151로 복원하는 최소 선제 제거 집합은?  →  참조 답: ["B"]

1

두 종속이 같은 슬롯을 수정
2

모델은 각 효과가 시작 시 캡처한 값을 추적하며, 두 해체 순서 모두에서 목표가 성립하도록 제거할 종속을 결정해야 함

"상호작용"의 의미

  • Formal 설정 — 효과 그룹: 같은 인접 상태 엔트리 쌍에 닿는 컴포넌트들의 집합
  • Cordis 네이티브 — 관찰된 슬롯을 바꿀 수 있는 종속(queried dependent)
  • 허니 사이즈가 아니라 동시에 고려해야 할 상호작용의 수를 측정 — 작업과 설정이 고정된 상태에서만 비교
질문 형태·답 형식·채점 규칙은 그대로 유지한 채, 추적해야 하는 상호작용만 2개에서 32개로 증가

두 설정과 유한 참조 의미론

형식(Formal) 설정

  • 응용 상태 = 고정 폭 정수 벡터 (mod m)
  • 효과 = 엔트리에 대한 짧은 산술 프로그램
  • 컴포넌트 의존성과 대상 변경을 명시

Cordis 네이티브 설정

  • 동일 라이프사이클 패턴을 Cordis 플러그인으로 컴파일
  • Cordis 4.0.0-rc.7에서 실제 실행
  • 효과는 활성화 시 상태를 캡처, Cordis가 의존성 해소·종속 정리

유한 참조 의미론(Finite Reference Semantics)

  • 생성된 시스템이 유한하므로, 답에 영향을 주는 모든 법적 라이프사이클 연속을 열거하여 종단까지 실행
  • 종단 관찰로 5개 작업의 정확한 참조 답 산출
  • Cordis의 전역 복원·수렴 보장 조건을 의도적으로 벗어나는 간섭 사례 포함 — 모델이 직접 추론해야 함

실험 설정

모델과 조건

  • 효율 지향 모델 3개를 낮은 추론 노력(low reasoning effort)으로 평가
  • 상호작용 수 6단계: 2, 4, 8, 16, 24, 32
  • 구조화된 출력 형식 강제: 집합·상태 시퀀스·정수·액션 집합

채점과 통제

  • 결정론적 작업별 채점 — 구조화 출력과 참조 의미론만으로 검증 가능
  • 재구성 제안은 Cordis dispose(...) 연산으로 변환 후 실제 실행
  • 출력 한도·고정 일정·결과 개수 등 별도 진단으로 원인 분리
단답·객관식이 아닌 구조화 출력 + 실행 검증으로, 그럴듯한 그릇된 답을 배제

결과 ① 규모가 커질수록 저하, 작업마다 속도는 다르다

잘 되는 것

  • 소규모 시스템(2~4 상호작용)은 대체로 안정적으로 처리
  • Localization은 상대적으로 완만하게 저하 — 의존성 추적 자체는 유지됨

어려워지는 것

  • 최종 상태 예측(schedule prediction)이 크게 저하
  • 해체 순서 전반의 추론(보편/도달 조건)도 급격히 감소
  • 추가 상호작용은 무관한 맥락이 아니라 추적해야 할 실제 효과를 늘림
핵심 발견: 작은 시스템에서의 성능이 더 큰 구성으로 신뢰롭게 전이되지 않는다 — 출력 한도·고정 일정 진단이 이 저하가 과제 자체의 어려움임을 확인

결과 ② 추가 추론은 신뢰도를 높이지만, 비용이 크다

비용-편익 분석

  • 추가 추론 노력이 일부 모델에서 뚜렷한 신뢰도 회복을 가져옴
  • 그러나 이 통제된 인스턴스에서는 그 비용이 불필요
  • 독립적인 유한 참조 의미론이 모든 관찰·액션 결과를 기계적으로 계산·검증 가능
모델의 자발적 야기적 예측과 기계적 검증 사이에는 실질적인 비용 격차가 존재 — 하네스 설계 시 어느 쪽에 맡길지가 중요한 판단 기준
