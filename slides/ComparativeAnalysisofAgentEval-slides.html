왜 이 연구가 필요한가?

엔터프라이즈 팀은 민감한 비즈니스 데이터 위에서 SQL 생성 · 도구 호출 · 답변 종합을 수행하는 LLM 분석 에이전트를 배포하고 있습니다.

보이지 않는 치명적 오류

자동 평가가 발견한 체계적 SQL 버그: 문법적으로 유효하여 수동 검토를 통과했지만, 한 유형의 쿼리 전체에서 0행을 반환하는 침묵하는 실패

수동 검토의 한계

현재 대부분의 팀은 임시방식(ad-hoc) 스팟 체크에 의존 → 72개 정답 실패 중 9개(12.5%)를 놓침 — 문법은 맞지만 의미가 틀린 사례

연구 격차와 3가지 질문

에이전트 시스템은 확률적 행동과 다단계 워크플로우로 단순 정확도 검증이 어렵습니다. 세 가지 평가 패러다임(LLM 심판, 결정론적 휴리스틱, 하이브리드)에 대한 체계적 비교는 부재했습니다.

RQ1

안정성
반복 측정에서 평가 출력은 얼마나 안정적인가?

RQ2

탐지
알려진 실패를 가장 신뢰하게 탐지하는 프레임워크는? 실패 유형에 따라 달라지는가?

RQ3

발견
자동 테스트 생성으로 예상치 못한 실패를 가장 잘 드러내는 프레임워크는?

평가 대상 3개 프레임워크

7개 후보 프레임워크의 정성 평가를 통해 선정 — 각기 다른 평가 철학을 대표

프레임워크평가 방식심판이 보는 정보특징
Strands Evals트레이스 기반 LLM 심판전체 실행 트레이스 OpenTelemetry 접근도구 궤적·SQL까지 검증 가능

실험 설계

2개 후보 에이전트 (소매 공급망 예측)

  • Agent A: 카테고리별 수요 예측 (9개 도구, 중규모 데이터)
  • Agent B: 제품별 리드타임 예측 (코드 인터프리터 포함 9개 도구, 대규모 운영 테이블)
  • 서로 다른 SQL 오류 패턴 — 구조적 vs. 의미적

공정 비교를 위한 통제

  • 모든 단계에서 동결된(frozen) 실행 트레이스 사용
  • LLM 심판 3종: Claude Sonnet 4.6, Claude Haiku, Qwen3 32B
  • 프레임워크당 5회 반복 측정

* 통제된 연구 환경에서 수행 — 실제 운영 배포를 기술하지 않음

Phase 1 · 평가 하니스 안정성 (RQ1)

97%

모든 구성이 안정성 임계값 충족
에이전트별 케이스 20개 × 심판 모델 3종 × 5회 반복

안정성 측정 지표

  • 결정 일관성: 반복 측정에서 동일한 합격/불합격 판정 확률
  • 케이스 내 표준편차 ≤ 0.15 (임계값) — 임계 근처 점수의 변동성 통제

안정성 패턴은 에이전트에 독립적 — 하니스·심판 구성이 안정성을 좌우하며, 평가 대상 에이전트의 특성은 좌우하지 않음

Phase 3 · 미지의 위험 발견 (RQ3)

24

자동 테스트 생성으로 발견된 새로운 신규 실패

0

기능 테스트와 보안 레드팀 간 중복 실패 수 (zero overlap)

9

인간 검토자가 초기에 잘못 라벨링했다가 평가기의 플래그로 수정된 정답 실패

기능 테스트와 보안 평가는 상호 보완적 — 대체 불가능하며, 서로 다른 실패 공간을 커버

발견된 신규 실패 사례

기능적 실패 (Strands)

  • SUBSTR 음수 인덱스 버그 — 한 쿼리 클래스 전체가 조용히 0행 반환
  • 스키마 조작(fabrication) — 존재하지 않는 테이블·컬럼 생성

보안적 실패 (PromptFoo)

  • 스키마·테이블명 누출 및 저장 경로·리소스 노출
  • 시스템 프롬프트 공개, 적대적 프롬프트 인젝션 하 과도한 권한 행사(excessive agency)

LLM 기반 평가 하니스는 인간 검토자가 놓치는 미묘한 오류를 표면화함

F1 = 0.90, 10% FPR에서 91% 탐지

보안 검증 → 적대적 레드팀

텍스트 기반 레드팀 프레임워크로 프롬프트 인젝션·정보 누출·과도한 권한을 공격적으로 탐색
기능 테스트와 0% 중복의 고유 실패 발견

단일 프레임워크로는 불충분 — 정보 접근과 공격 관점이 다른 두 프레임워크의 조합이 엔터프라이즈 에이전트의 신뢰성을 완성한다

결론

  • 3단계 비교 연구(안정성 → 탐지 → 발견)로 평가 패러다임의 강점을 정량화
  • 정보 접근 계층: 트레이스 > 텍스트 > 문자열 — 하니스의 정보가 품질을 결정
  • 72개 케이스에서 F1 0.90(트레이스) vs. 거짓 경보 5×(텍스트 전용)
  • 24개 신규 실패, 기능·보안 간 중복 0 — 두 평가는 필수적 쌍
