RAFT

A Stateful Retrieval-Augmented Framework for Troubleshooting Agents

트러블슈팅 에이전트를 위한 상태 기반 검색 증강 프레임워크

Mingxuan Zhang · Xiaowen Wang · Anupma Sharan · Zhengyi Chen · Chenyu Diana Zhang · Shanshan Yang · Chittibabu Pacharu

Microsoft, Redmond, WA

배경: 엔터프라이즈 고객 지원과 검색

지원 에이전트는 폐쇄된 과거 케이스 코퍼스에서 유사 사례의 실행 가능한 해결 가이드를 검색해야 합니다.

파인튜닝의 한계

  • 높은 연산 비용
  • 오픈 웨이트 모델에만 적용 가능
  • 치명적 망각(catastrophic forgetting) 위험
  • 새 케이스 유입 시 주기적 재학습 필요

RAG의 장점과 새로운 과제

파라미터 변경 없이 추론 시점에 프라이빗 지식베이스를 근거로 제공하는 실용적 대안

그러나 지식베이스가 커질수록 검색된 컨텍스트가 방대하고 조직적이지 못하며 노이즈가 많아져 검색 정확도와 추론 능력 모두 저하

기존 RAG의 4가지 근본 한계

1. 노이즈 많은 비정형 데이터

원시 케이스에는 비기술적 내용이 섞여 있고, 진단 신호는 여러 턴에 흩어져 있어 유사 케이스 식별 자체가 어려움

2. 비일관된 검색 청크

격리된 청크만으로는 케이스 전체를 파악할 수 없어 토큰 낭비와 함께 검색당 확인 가능한 사례 수가 크게 제한됨

3. 정적 문서 취급

케이스의 다단계·상태적(stateful) 특성을 무시하고 단일 정적 문서로 처리

4. 엔티티 중심 GraphRAG

개별 조사의 진행 과정을 표현하지 못하고, 그래프 구축 비용이 크며 모델·에이전트 변화에 적응이 어려움

문제 정의: 상태 인식(State-Aware) 검색

트러블슈팅은 일회성 작업이 아니라 다단계 조사 과정입니다.

1
증상 보고
오류 코드, 행위 묘사
2
가설·정보 수집
로그·진단 도구 반복 탐색
3
원인 규명
근본 원인 식별
4
해결
표적화된 조치 수행

쿼리는 케이스 진행에 따라 계속 갱신됩니다 — 초기에는 유사 초기 증상을, 이후에는 유사 중간 조사 상태를 가진 사례를 반환해야 합니다.

RAFT: 핵심 아이디어

  • 폐쇄된 케이스를 타임라인 엔트리의 방향성 체인으로 추상화 — 각 엔트리는 조사의 의미 있는 단계에서의 기술적 상태를 기록
  • 케이스 레벨이 아닌 엔트리 레벨 임베딩·검색으로 중간 상태가 일치하는 사례 발굴
  • 매칭된 상태에 고정(anchored)된 부모 케이스 궤적(trajectory)을 반환
  • 설정 가능한 유사성 표현으로 케이스를 연결하는 선택적 케이스 레벨 그래프

아키텍처 ① 인덱싱

1
케이스 평가·필터링
실행 가능한 지침을 제공하는 케이스만 선별하고 민감 정보 보호
2
타임라인 엔트리
조사의 각 의미 있는 단계별 기술 상태를 방향성 체인으로 기록
3
케이스 레벨 그래프
설정 가능한 유사성 표현으로 케이스 간 연결 (선택적)

오프라인에서 한 번 구축 → 온라인 검색은 가볍고 빠르게 유지

아키텍처 ② 검색: 접근법 비교

접근법 표현 단위 반환 내용 특징
바닐라 RAG 정적 문서 / 청크 격리된 청크 케이스 전체 맥락 상실, 노이즈에 취약
GraphRAG 엔티티·관계 그래프 청크 + 엔티티 관계 조사 진행 미표현, 구축 불안정·고비용
RAFT 타임라인 엔트리 체인 매칭 상태에 고정된 부모 케이스 궤적 전술적 가이드 + 전략적 맥락 동시 제공

엔트리 레벨 검색이 주는 두 가지

전술적 가이드

현재 조사 단계와 중간 상태가 일치하는 사례를 찾아 지금 당장 수행할 다음 행동에 대한 구체적 근거 제공

전략적 맥락

유사 케이스가 결국 어디로 이어졌는지 — 근본 원인과 해결 궤적까지 함께 반환

케이스 간 관계·원인 군집화 같은 고차원 추론은 오프라인 인덱스에 고정하지 않고 에이전트가 온라인에서 수행 — 검색 계층은 유사 사례 발굴에 집중

평가 설정

합성 개발 벤치마크

826

Microsoft Learn Windows Server 문서에서 구축한 지원 케이스

케이스 진행의 여러 단계를 탐색(probe)하는 재현 가능한 프로토콜

Apache Jira

실제 이슈 + 사람이 생성한 중복 레이블을 유사성 정답으로 활용

합성 결과가 실제 케이스 히스토리로 전이되는지 검증

전체 에이전트 시스템이 아닌 검색 계층을 직접 평가 → 프로덕션 배포 없이 재현·비교·확장 가능

결과

  • 케이스 진행의 모든 단계에서 바닐라 RAG·GraphRAG 대비 Case Hit 향상
  • 가장 강한 베이스라인 대비 통계적으로 유의한 개선 달성
  • Apache Jira 실제 사례에서도 방향성 있는 전이 증거 확인

지표 1

Case Hit

유사 케이스 검색 성공 여부

지표 2

Root Cause Coverage

근본 원인 정보 포함 여부

지표 3

Resolution Steps

해결 단계 정보 포함 여부

기여 요약

  • 상태 기반 RAG 아키텍처 — 케이스를 타임라인 엔트리 체인으로 표현하고, 진화하는 중간 상태를 검색하며, 매칭 상태에 고정된 부모 케이스 궤적 반환
  • 케이스 레벨 그래프 — 설정 가능한 케이스 속성으로 케이스를 연결해, 초기 엔트리 매칭을 넘어선 원칙적인 확장 가능
  • 공개 벤치마크 — Microsoft Learn Windows Server 문서 기반 합성 케이스 826건과 재현 가능한 다단계 평가 프로토콜

결론

트러블슈팅 케이스의 다단계·상태적 본질을 검색에 반영하면, 조사의 모든 단계에서 더 정확한 유사 사례와 해결 궤적을 얻을 수 있습니다.
