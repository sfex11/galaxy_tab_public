슬롯 병렬 의미론적 스페큘레이티브 검증으로
LLM 에이전트 컨텍스트 압축 가속화

Yulu An · Yifei Feng · Xiangyang Yin (New York University)

arXiv: 2611.06876

문제: 컨텍스트 압축의 지연 시간 딜레마

계속 성장하는 에이전트 이력

  • 긴 호라이즌 작업에서 사용자 요청, 도구 출력, 중간 결정이 축적
  • 긴 컨텍스트 창은 성능을 높이지만 이력 관리 비용도 증가

압축 자체가 병목

  • 컨텍스트 압축은 긴 이력 전체를 처리해 요약을 토큰 단위로 디코딩
  • 대형 모델의 요약 생성 지연이 사용자 경험을 크게 저하
컨텍스트 압축은 정보 보존(retention)과 요약 생성 지연(latency) 사이의 균형이 필요하다.

기존 가속 기법으로는 부족한 이유

접근법장점한계
토큰 수준 스페큘레이티브 디코딩 소형 드래프터 + 타깃 검증으로 무손실 가속 문안만 다른 요약도 거부 → 요약의 표현 유연성을 활용 못함
시맨틱 스페큘레이션
(SpecReasons, DREAM-R)		 문장·추론 단위 의미 판단으로 수용률 향상 단일 요약에 적용 시 여전히 순차 생성 → 긴 컨텍스트에 느림
비동기·병렬 압축 요약과 실행 중첩, 입력 블록 동시 요약 요약 구조 자체를 활용한 검증·수리는 미해결
핵심 질문: 요약의 구조 자체가 병렬 생성과 타깃 모델 검증을 유도할 수 있을까?

핵심 관찰: 슬롯은 독립적으로 생성 가능하다

OpenClaw·Hermes 압축 템플릿의 필드를 슬롯(slot)이라 지칭 — Goal · Constraints & Preferences · Progress · Key Decisions · Next Steps · Critical Context (6개)

4.73

독립 생성 vs 일괄 생성(4.44) 평균 점수 — LLM judge, 0–5점, 100개 트라젝토리 × 6슬롯

93%

≤ 0.03

관찰: 다른 슬롯의 출력 없이도 각 슬롯은 이력에서 필요한 정보를 보존할 수 있다 → 공유 이력 기반 병렬 슬롯 생성의 근거

2
병렬 슬롯 드래프팅
공유 이력에서 6개 슬롯을 동시 생성
3
의미 검증·수리
타깃 모델이 라인별 검증, 거부 시 로컬 대체 생성
4
컨텍스트 조립
완료된 슬롯들을 구조화된 요약으로 결합
  • 슬롯 단위 draft–verify–repair 루프가 서로 다른 슬롯에서 병렬 실행
  • 드래프팅은 수용된 해당 슬롯의 프리픽스만 조건으로 사용
  • 시스템 수준 최적화로 반복 컨텍스트 처리와 모델 호출을 추가 절감
  • 결과는 OpenClaw 스키마를 따르는 구조화된 요약

Slot-Conditioned Drafting

6-슬롯 스키마

  • OpenClaw 스키마 채택: Goal / Constraints & Preferences / Progress / Key Decisions / Next Steps / Critical Context
  • 슬롯마다 내용과 출력 형식을 규정하는 슬롯 지시문(계약) 부여
  • 요청에는 공유 이력과 전체 스키마를 포함하되, 요청된 슬롯만 생성

소형 드래프터 학습

  • 타깃 모델 + 생성 프롬프트로 지도 학습 데이터 구축
  • 독립 소형 모델 Qwen3-0.6B를 드래프터로 파인튜닝
  • 시맨틱 스페큘레이션은 무손실 제약이 없어 작은 드래프터도 자유롭게 사용 가능

각 드래프팅 요청은 공유 이력 + 자신의 수용 프리픽스에만 의존 → 슬롯 간 완전한 독립성 보장

Semantic Verification: 검증 후 로컬 수리

1
라인 제안 — 드래프터가 해당 슬롯의 다음 라인을 제안
2
타깃 검증 — 타깃 모델이 이력에 근거하는지 + 수용된 슬롯 프리픽스와 일치하는지 판단
3
수용 또는 수리 — 수용 시 프리픽스에 추가, 거부 시 타깃 모델이 로컬 대체 라인 생성
4
재개 — 업데이트된 슬롯 프리픽스에서 드래프팅 계속
토큰 일치가 아닌 의미 보존 기준 판단: 문안이 달라도 이후 행동에 필요한 정보가 유지되면 수용

효율적인 슬롯 병렬 실행: 시스템 최적화

독립 슬롯 스케줄링

슬롯 간 의존성이 없어 상호 대기 없이 개별 스케줄링

공유 프리픽스 캐싱

공유 이력 프리픽스 재처리를 최소화해 반복 컨텍스트 처리 절감

드래프트 버퍼링

검증 대기 드래프트를 버퍼링해 모델 호출 횟수 감소

라인 인식 중단

라인 경계에서 드래프트를 멈춰 검증 단위를 정합적으로 유지

검사 및 종료

슬롯 완성 검사와 안전한 종료 조건으로 불필요한 호출 방지

효과

실행 오버헤드 감소로 압축 지연 시간 추가 단축

실험 설정

벤치마크·모델

  • 에이전트 벤치마크: AppWorld, τ³
  • 타깃 모델 2종 (Gemma4-31B-IT 등)
  • 드래프터: 파인튜닝된 Qwen3-0.6B

비교 대상·평가 축

  • 기준선: Hermes 스타일 요약
  • 평가: 압축 효율(속도), 에이전트 작업 성공률, 롱컨텍스트 성능, 최적화 효과, 사용자 연구
  • 압축 품질과 다운스트림 성능은 별도 평가로 측정

주요 결과: 압축 가속

2.04–5.63×

AppWorld·τ³ 벤치마크, 두 타깃 모델에서 Hermes 스타일 요약 대비 압축 속도 향상

8.68×

Hermes 프레임워크 내 사용자 연구에서 측정한 중앙값(median) 압축 속도 향상

검증·수리까지 포함한 전체 루프에서 속도 향상이 달성 — 드래프팅 병렬화와 시스템 최적화가 정보 보존을 유지하면서 지연을 크게 줄임

다운스트림 성능과 트레이드오프

관찰된 결과

  • 별도 다운스트림 평가에서 압축 속도와 작업 성공률을 함께 측정
  • 성능 변화는 모델 및 작업에 따라 다른 트레이드오프 양상
  • 슬롯 기반 구조화 요약이 후속 행동에 필요한 정보를 보존하는 것이 핵심 요건

사용자 연구 (Hermes)

  • 실제 에이전트 프레임워크 Hermes에 통합해 검증
  • 중앙값 8.68× 압축 속도 향상 확인
  • 실사용 환경에서도 압축 지연 절감 효과가 유지됨

해석: 속도 향상은 모델·작업 조합에 따라 다운스트림 품질과의 균형점을 찾아 적용해야 함

기여 요약과 한계

기여

  • 요약 슬롯이 타 슬롯 조건화 없이도 정보를 보존함을 실증 — 병렬 압축 단위로 적합
  • 학습 + 병렬 드래프팅 + 라인 단위 의미 검증·로컬 수리를 결합한 SpecCompact 제안
  • 시스템 최적화로 반복 컨텍스트 처리·모델 호출 절감
  • 2.04–5.63× 가속 실증 + 다운스트림 평가 + Hermes 사용자 연구

한계·논의

  • 시맨틱 스페큘레이션은 lossy — 검증 후에도 미세한 정보 손실 가능
  • 다운스트림 성능이 모델·작업에 따라 달라지는 트레이드오프 존재
  • 슬롯 수·스키마 변경 시 일반화 성능에 대한 추가 검토 필요

결론

구조화된 요약 슬롯은 병렬화의 자연스러운 단위이다. 슬롯 병렬 드래프팅 + 의미 검증·로컬 수리로 에이전트 컨텍스트 압축의 지연 시간을 크게 줄일 수 있다.
  • 독립적 슬롯 생성의 정보 보존 실증 (4.73/5, 순서 무관)
  • Hermes 스타일 요약 대비 2.04–5.63× 압축 가속
  • Hermes 사용자 연구에서 8.68× 중앙값 속도 향상
