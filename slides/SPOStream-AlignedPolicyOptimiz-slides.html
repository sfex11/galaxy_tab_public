Stream-Aligned Policy Optimization for Asynchronous Agentic RL

Kai Ruan · Jinghao Lin · Qianshan Wei · Ziqi Zhou · Zihe Huang

中国人民大学 · 中科院自动化所 · Duke University · 中科院计算所

문제 정의: 그룹 기반 RL의 병목

GRPO의 방식

하나의 프롬프트에 대해 여러 개의 출력을 샘플링하여 그룹 내 상대적 advantage를 추정

  • 크리틱 네트워크 불필요
  • 단순한 구현

에이전트 환경에서의 문제

환경 상호작용과 도구 호출로 인해 완료 시간의 긴 꼬리 분포 발생

  • 가장 느린 형제 롤아웃을 대기해야 함
  • 비동기 실행과 본질적으로 충돌

그룹은 추정의 기반이지만, 동시에 에이전트 학습의 병목이 된다.

SPO: 단일 스트림 정책 최적화

핵심 아이디어

일시적인 그룹 베이스라인을 지속적인 프롬프트 수준의 증거로 대체 → 프롬프트당 하나의 온라인 롤아웃만 사용

1
프롬프트 증거
성공/실패 카운트
(αₓ, βₓ) 유지
2
베이스라인 추정
v̂ₓ = αₓ/(αₓ+βₓ)
3
Advantage 계산
Aᵢ = Rᵢ − v̂ₓ
4
증거 갱신
유지 인자 ρ로 감쇠

그룹 의존성 제거로 비동기 실행에 적합해지지만, 두 가지 정합성 문제가 노출됨

SPO의 두 가지 불일치 문제

불일치 1

수신 순서 의존성

순차적 증거 갱신이 학습자 수신 순서에 의존

→ 시스템 타이밍에 따라 베이스라인이 달라짐

불일치 2

측도 불일치

궤적 단위 표준화 후 토큰 평균 손실을 사용

→ 응답 길이가 최적화가 보는 중심값을 은연중에 변경

SPO++는 이 두 불일치를 각각 이벤트 시간 메모리와 액션-토큰 측도 정규화로 해결

해결책 1: 이벤트 시간 프롬프트 메모리

핵심 변경

베이스라인을 디스패치 시점에 동결하고, 반환된 결과를 정책 이벤트 좌표에 기록

정책 이벤트 좌표 zᵢ

각 액터 스냅샷이 고유 좌표를 가짐

k개 정책 이벤트 전의 결과는 ρᵏ의 가중치를 받음

ρ = 0.875 (고정 유지 인자)

수신 순서 불변성 (Remark 1)

고정된 가시 이력 ℋ_q(x)와 이벤트 좌표에 대해, 공식은 수신 순열에 불변

재정렬은 유한 합의 순열만 변경

SPO의 사후 갱신 토큰 드리프트 기반 유지와 달리, SPO++는 학습자 독립적인 기하 좌표를 사용

해결책 2: 액션-토큰 측도 정규화

이 논문의 가장 중요한 기여

문제의 수학적 본질

궤적 단위 표준화: ΣÃᵢ^traj = 0 을 보장하지만,

토큰 평균 손실이 보는 것: Cov(L, Ã^traj) / L̄

→ 토큰 수와 advantage가 공변하면 잔차가 일반적으로 0이 아님

SPO++의 해결: 토큰 가중 표준화

μ_tok = Σ LᵢAᵢ / Σ Lᵢ   (토큰 가중 평균)

σ²_tok = Σ Lᵢ(Aᵢ − μ_tok)² / (Σ Lᵢ − 1)   (토큰 가중 분산)

→ 정규화 측도와 손실 측도가 일치하여 잔차가 정확히 0

궤적 수준의 크레딧 세분성은 그대로 유지됨

측도 불일치의 직관적 이해

advantage: +1.5

50

SPO (궤적 단위)

3개 궤적 모두 동일 가중치로 평균/표준편차 계산

하지만 손실은 58개 토큰에 대해 평균

→ 긴 궤적이 압도적 비중 차지

SPO++ (토큰 단위)

토큰 수로 가중평균/가중분산 계산

손실의 실제 측도와 정확히 일치

→ 숨겨진 편향 제거

SPO++ 전체 구조

디스패치

프롬프트 베이스라인 v̂ₓ를 동결하고 정책 이벤트 좌표 z_q 기록

롤아웃 실행

단일 온라인 롤아웃 per 프롬프트 — 그룹 대기 불필요

이벤트 연결

반환된 결과 Rᵢ를 생성에 사용된 정책 이벤트 좌표 zᵢ에 부착

액션-토큰 측도 정규화

토큰 가중 평균/표준편차로 advantage 표준화

토큰 평균 액터 손실 최적화

Dual-Clip (c=2), 불확실도 샘플러, 중요도 비율 상한=2

실험 설정

ALFWorld

도구 사용 에이전트

  • 128개 정규 ALFWorld 작업
  • Qwen3.5-0.8B (3회 반복)
  • Qwen3.5-2B (4회 반복)
  • 메트릭: 사다리꼴 AUC
Math-TIR

수학 추론 + 도구

  • DAPO-Math-17K 1,500예제 학습 분할
  • Qwen3.5-0.8B + Python 도구
  • 100스텝 = 25,600 온라인 궤적
  • 메트릭: 스텝 평균 (정규화 사각형 AUC)

완전 매칭 실행: 동일 모델 체크포인트, 프롬프트 집합, 오프라인 초기화, 디코딩, 궤적 예산, 최적화 설정, 비동기 런타임

학습 효율성

SPO++는 동일 예산 내에서 더 높은 보상 곡선 면적을 달성 — 세 도메인 모두 일관되게 관찰

최종 성능

마지막 5스텝 평균 보상에서도 SPO++가 우세하며, 매칭된 반복 간 편차 내에서 안정적

제거 연구: 정규화 측도의 효과

페어드 제거 연구 설계

SPO 레시피에서 정규화 측도만 토큰 가중으로 변경하고, 나머지 (드리프트 의존 유지, c=10)는 그대로 유지

핵심 발견

액션-토큰 측도 정규화가 테스트된 모든 구성 요소 중 가장 강한 효과를 보임

단일 구성 요소만 교체해도 SPO 대비 유의미한 개선 관찰

측도 불일치가 중요한 경우

토큰 수와 advantage 간 공분산이 클 때 효과가 두드러짐 — 성공한 궤적이 실패한 궤적보다 체계적으로 길거나 짧은 환경

최적화 진단

SPO++의 토큰 가중 표준화는 손실 기울기의 방향을 더 일관되게 만들어 학습 안정성 향상

관련 연구와 위치

단일 롤아웃 advantage 추정

GRPO 계열은 다중 샘플 기반, ReMax는 순위 기반 단일 샘플 추정

SPO++는 지속적 증거 기반으로 단일 롤아웃에서도 안정적인 베이스라인 제공

학습된 및 암묵적 가치

GAE, critic 기반 방법들은 별도 가치 네트워크 필요

SPO++는 크리틱 없이 프롬프트 수준 이진 증거만으로 가치 추정

비동기 정책 최적화

IMPALA, ACER 등은 중앙 집중식 버퍼 기반

SPO++는 프롬프트 단위 비동기성으로 더 세분화된 제어

감독 세분성

과정 감독(PROCESS), 토큰 수준 보상 등

SPO++는 터미널 결과만 사용하면서 측도 정합성으로 세분성 보존

한계점

이진 결과에 한정

현재 프롬프트 증거 모델은 성공/실패 이진 결과에 특화. 연속 보상으로의 확장은 추가 연구 needed

하이퍼파라미터 의존성

고정 유지 인자 ρ=0.875, Dual-Clip c=2 등의 선택이 도메인에 따라 재조정 필요할 수 있음

벤치마크 범위

ALFWorld와 Math-TIR로만 평가. 웹 에이전트, 코드 에이전트 등 더 다양한 도메인에서의 검증 필요

모델 규모

0.8B와 2B 규모에서만 검증. 대규모 모델에서의 스케일링 동작은 미확인

결론

SPO++는 비동기 에이전트 RL에서 SPO의 두 가지 정합성 문제를 해결하여 온라인 학습 효율성을 일관되게 개선

  • 측도 불일치 식별 및 해결: 궤적 표준화 + 토큰 평균 손실의 잔차를 액션-토큰 측도 정규화로 제거
  • 이벤트 시간 프롬프트 트래커: 디스패치-인과적이며 수신 순서에 불변인 베이스라인 공식화
  • 실증적 검증: ALFWorld 두 규모와 Math-TIR에서 일관된 개선, 정규화 측도가 가장 강한 구성 요소로 확인

"정규화는 보이지 않는 편향을 만들 수 있다 — 손실이 소비하는 측도와 정규화가 사용하는 측도를 일치시키는 것이 핵심이다."
