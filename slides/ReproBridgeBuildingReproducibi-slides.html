ReproBridge: Building Reproducibility into ML Research Artifacts

Yubo Wang (University of Waterloo) · Rui Meng · Jaehyun Nam · Tomas Pfister · Jinsung Yoon (Google)

문제: ML 실험 재현은 왜 어려운가?

재현에는 논문·공개 코드·부속 아티팩트에 흩어진 정보를 다시 조립하는 작업이 필요합니다.

  • 호환되지 않는 의존성 해결, 의도된 구성 식별, 데이터 로더 수리
  • 실행 출력이 보고된 점수로 어떻게 변하는지 스스로 알아내야 함
  • 성공한 시도조차 결정들이 대화·셸 히스토리에 묻혀 다음 재현자가 같은 조사를 반복

코딩 에이전트 벤치마크에서도 의존성 미해결, 구현 세부사항 누락, 완료되지 않는 실험 계획이 반복적으로 관찰됩니다.

연구 질문과 가설

재현 성공은 공개된 아티팩트에 의존하는가, 아니면 재현자가 빠진 세부사항을 채우는 능력에 의존하는가?

가설: 재현 과정에서 회복된 절차와 결정을 보존하면 계산 재현성이 향상된다.

논문

태스크당 인간 검증 참조 점수 5개로 수치 호환성 판정 — 관측된 실행과 그 변동성을 함께 고려

논문에 명시된 설정이 충돌하는 코드보다 우선하며, 태스크는 연구 분야별로 배정됩니다.

오류 모델: 측정을 어떻게 해석하는가

Y = μ + D + ε

μ
명시된 실험을 충실하게 실행했을 때의 기댓값

D
실행 선택이 사양에서 이탈한 체계적 편차

ε
조건부 무작위 변동 (확률적 학습의 실행 간 차이)

발표 점수는 오류 없는 μ가 아니라 하나의 관측값 — 5개 참조 관측으로 참조 분포를 추정

정제 아티팩트의 4가지 구성요소

정제된 코드베이스

버그 수정과 명확화가 반영된 코드, 수정 이유와 영향받는 태스크 문서화

환경 설정

의존성 해결 절차가 고정된, 세션 간 이식 가능한 실행 환경

실험 런처

실험 발견·실행 절차를 전용 진입점으로 표준화

재현 가이드

측정 사양 병합, 설정, 결과를 점수로 집계하는 방법까지 안내

실행 가능한 절차와 그 설정·수리의 이유까지 함께 보존

평가 프로토콜

신규 Reproducer 세션

원본 코드 또는 정제 아티팩트를 받은 독립 세션에서 재현 시도

별도 Auditor

실행 증거를 감사 — 숫자 일치만으로는 대체된 측정이 숨겨질 수 있음

  • 실행 무결성 감사: 보고된 수치가 실제 실행에서 나왔는지 검증
  • 무효화 기준: 참조 분포와의 수치 호환성 + 절차 정당성
  • 4개 코딩 에이전트 대상, 인간 검증으로 감사 판정 교차 확인

컴포넌트 제거 실험: 어떤 요소를 빼도 성공률 하락 — 특히 코드 제거와 환경 제거에서 손실 최대

논문별 이질성, 더 엄격한 수치 호환성 기준, 참조 변동성 계층에서도 개선이 지속됩니다.

시사점과 한계

  • 실행 지식 보존은 원본 코드 성공률이 낮은 모델일수록 상대적으로 큰 도움 — 재현을 더 신뢰성 있고 저비용으로
  • 구축 비용은 아티팩트의 반복 재사용으로 상쇄 가능
  • 회수된 구성이 실행 가능해짐: 누락 설정 복원(HELIX), 세션 간 환경 이전(WBMM), 코드 버그 수정 등

한계: 논문-코드 불일치가 존재하는 태스크, 유한 예산에서의 수치적 취약성, 일부 잔여 수치 불일치는 여전히 남음

결론

재현 과정에서 회복한 절차와 결정을 아티팩트에 담아 전달하면, 재현 성공률은 76.4% → 92.6%로, API 비용은 평균 19.7% 절감됩니다. 실행 지식의 보존은 재현성의 핵심입니다.
