왜 디코딩 길이를 미리 알아야 하는가?

Prefill 단계

입력 프롬프트를 병렬로 처리하는 연산 바운드(compute-bound) 단계

Decode 단계

토큰을 자기회귀적으로 생성하는 메모리 바운드(memory-bound) 단계

  • Decode 단계가 end-to-end 지연 시간과 에너지 소비를 지배
  • 디코딩 시작 전에 생성 길이를 알면 배치 스케줄링, PD 분리, 자원 할당에 결정적
  • 최신 방법들은 prefill 시점의 hidden state만으로 디코딩 길이를 예측

공정성 문제: 벤치마크가 예측기 성능과 과제 난이도를 뒤섞는다

동일한 예측기 구조인데, 대상 모델·데이터셋·샘플링 설정만 바꿔도 보고된 정확도가 붕괴

평가 설정MAE
ForeLen long-sequence split + Qwen2.5-7B≈ 80
ShareGPT + Qwen3-32B> 150
RL 샘플링 데이터> 260
예측기는 그대로인데 성능이 무너진다 → 오차의 지배적 원인은 예측기 설계가 아니다

핵심 통찰: 디코딩 길이는 확률 변수다

디코딩 길이의 분산이 큰 프롬프트에서는, 어떤 prefill 측 예측기도 하나의 결정론적 길이를 정확히 맞힐 수 없다 — 길이 자체가 무작위로 결정되기 때문

  • 오차의 두 근원: 예측기의 한계(모델 오차) vs 생성의 고유한 확률성(시스템 오차)
  • 기존 벤치마크는 이 둘을 구분하지 않음 → 서로 비교 불가능한 수치
  • 본 논문: 디코딩을 정지 시간(stopping time)으로 모델링하여 모든 prefill 측 방법이 지켜야 하는 하한을 유도

세 가지 기여

오차의 이론적 기원

비상수 hazard를 가진 정지 시간으로 모델링 → CLT와 Berry–Esseen 오차항, 아핀 분산 법칙, 예측 오차 하한 유도

경험적 검증

300개 ShareGPT 프롬프트 × 200회 디코딩으로 정규 근사를 검증하고, 법칙이 깨지는 지점까지 확인

구조 불문 평가

MLP·EGTP·FiLM·소프트라벨·MoE 예측기를 고정 조건에서 비교 → 모두 이론 하한 근처로 수렴

문제 정식화와 평가 지표

설정: 프롬프트 x를 토큰열 x1:L로 토크나이즈, prefill 시 layer l의 hidden state h(l)1:L 계산

목표 Y: EOS 토큰 직전까지 생성되는 새 토큰 수 (디코딩 길이)

예측기: ŷ = f(x, {h(l)}) — prefill 관측 정보만 사용

  • MAE = (1/N) Σ |ŷi − Yi|
  • acc@τ = Pr(|ŷ − Y| < τ) — 허용 오차 τ 이내 비율 (acc@100, acc@200, acc@500)
  • x(p90): acc@τ ≥ 90%가 되는 최소 τ

특징 추출: 모든 레이어를 연결(concatenate)하는 방식이 이 과제에서 가장 풍부한 표현을 제공

이론 ① — 디코딩은 정지 시간이다

1
비상수 hazard
응답 종료 확률이 상수가 아니라 수백 스텝에 걸쳐 상승
2
국소 결정 누적
응답이 어디서 끝날지 정하는 수많은 국소 결정
3
중심극한정리
프롬프트별 디코딩 길이가 점근적으로 정규분포

→ 프롬프트별 정규성 + 명시적 Berry–Esseen 오차항으로 오차의 형태를 정량적으로 기술

이론 ② — 아핀 분산 법칙

σ = αμ + b
  • 평균 디코딩 길이 μ가 커질수록 표준편차 σ가 직선적으로 증가
  • 기울기 α = 응답 세그먼트 수의 변동계수(coefficient of variation)
  • (α, b)는 대상 모델과 post-training 레시피에 따라 크게 달라짐 → 과제 난이도의 정량적 지표
모델·데이터·샘플링을 바꾸면 σ 자체가 바뀐다 — 절대 MAE만으로는 예측기의 우열을 가릴 수 없다

이론 ③ — 모든 prefill 측 예측기가 지켜야 하는 하한

  • 정규 법칙으로부터 MAE 하한 유도: 이상적 예측기의 MAE ≈ σ√(2/π)
  • pass-rate(acc@τ) 상한의 sharpened 형태 제시
  • 초과 위험(excess risk)의 정확한 분해: 시스템 항 + 모델 항

시스템 오차

디코딩 자체의 확률성이 만드는 피할 수 없는 오차 — 어떤 prefill 정보로도 제거 불가

모델 오차

예측기 구조가 만드는 오차 — 좋은 설계로 줄일 수 있으나 이론적 하한 이하로는 불가

중위수 왜도 / 초과 첨도 — 샘플링 노이즈 보정이 예측한 크기와 방향 (mild right skew)

  • σ는 아핀 법칙 σ = αμ + b를 따름 — (α, b)는 모델·post-training에 따라 크게 변동
  • 정규성에서 벗어난 잔차(왜도·첨도)도 이론이 예측한 샘플링 노이즈 보정과 일치

구조 불문 평가 — 시스템 오차가 모델 오차를 지배

모델·데이터·샘플링 설정을 고정한 뒤 다양한 예측기 설계를 비교

아키텍처설명
MLP 회귀연결된 hidden state에 대한 단순 회귀
EGTP엔트로피 기반 토큰 풀링 (softmax(H) 가중)
FiLMfeature-wise 선형 조건화
소프트라벨길이 분포를 분류 문제로 학습
MoE라우팅 기반 전문가 혼합
모든 방법이 이론 하한에 가까운 유사 성능으로 수렴 → 예측기 설계를 바꿔도 얻을 것이 거의 없다

더 공정한 벤치마크를 위한 제안

1
조건 고정 — 대상 모델, 데이터셋, 샘플링 파라미터를 고정하는 평가 프로토콜 채택
2
상대 오차 병기 — 절대 MAE와 함께 σ√(2/π) 등 하한 대비 상대 오차 메트릭 보고
3
난이도 지표 명시 — 아핀 법칙의 (α, b) 계수로 과제 난이도를 정량적으로 기술
  • 반복 예측(ELIS 등)은 더 풍부한 정보(x, y<t)를 사용하므로 prefill 측 하한과 모순되지 않음 → 불확실성 감소 관점으로 이해
  • 하한은 PD 분리(PD-disaggregated) 생성의 스케줄링 의사결정과 런타임 연산 일관성 문제에 직접 활용 가능

결론

  • 디코딩 길이 예측 오차의 지배적 원인은 예측기가 아니라 자기회귀 디코딩의 고유한 확률성
  • CLT와 아핀 분산 법칙(σ = αμ + b)이 모든 prefill 측 방법의 한계를 규정
  • 고정 조건에서는 다양한 아키텍처가 하한 근처로 수렴 — 시스템 오차 > 모델 오차
  • 공정한 비교를 위해 모델·데이터·샘플링 고정 + 상대 오차 메트릭 병행을 권고
