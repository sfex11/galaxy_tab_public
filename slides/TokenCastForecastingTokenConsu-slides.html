TokenCast
LLM 에이전트 실행 중 토큰 소비 예측

Forecasting Token Consumption During LLM Agent Execution

같은 작업도 실행할 때마다 토큰 소비가 최대 30배까지 달라진다면, 에이전트의 비용은 어떻게 예측할 수 있을까?

문제
실행 전 비용 예측이 어려움
해결
구성 가능한 세그먼트 비용 표현
성과
MAE 14.5% 감소, 토큰 21.3% 절감

왜 토큰 소비 예측이 어려운가?

30×

동일한 작업을 실행했을 때
실행 간 토큰 소비 편차

  • 에이전트는 도구 피드백과 중간 결과에 따라 다음 행동을 결정 — 실행 전에는 경로를 알 수 없음
  • 대화와 도구 출력이 컨텍스트에 누적되어 이후 모든 호출의 입력 크기를 지속적으로 증가시킴
  • 같은 입력에도 다른 행동·다른 길이의 출력을 생성하여 검증/재시도 횟수가 달라짐
  • 소비가 단계 간 상호 의존적으로 누적·증폭됨

네 가지 토큰 소비 예측 설정

예측 범위(호출 vs 작업) × 관측 시점(실행 전 vs 실행 중)

호출 수준 ① 생성 전 응답 길이
입력 프롬프트가 알려진 상태에서 응답 길이 예측 — 리소스 할당에 활용
호출 수준 ② 생성 중 잔여 응답 길이
디코딩 중간 상태나 엔트로피 통계로 예측을 지속 갱신
작업 수준 ③ 실행 전 총 소비량
작업 설명이나 모델 자신의 비용 평가로 총 토큰 소비 추정
작업 수준 ④ 실행 중 잔여 소비량 ← TokenCast
호출이 완료되고 컨텍스트가 쌓이는 동안 잔여 소비를 갱신

열린 에이전트는 실행 전 의존성 그래프가 존재하지 않아 설정 ④가 가장 어렵고 실용적으로 중요

기존 연구와 그 한계

접근대표 방법핵심 가정한계

TokenCast는 실행 중 관측된 실행 증거만으로 잔여 소비를 갱신하며, 추가 LLM 호출 없이 비용을 예측한다.

케이스 스터디 & 절제 연구

코드 수리

반복 테스트·수정 루프에서 재시도 횟수가 늘어나는 지점을 조기에 포착, 잔여 소비 급증을 미리 경고

장문 컨텍스트 QA

긴 컨텍스트 + 짧은 출력 패턴에서 반복 입력 비용이 지배적 — 항등식 기반 예측이 특히 효과적

  • 절제 연구: 구성 경로를 제거하면 오차가 유의미하게 증가 — 반복 입력 비용 반영이 성능의 핵심
  • 온라인 갱신 주기를 조절해도 견고한 성능 유지

결론

  • 세그먼트 비용 분해와 정확한 구성 항등식으로 호출 간 반복 입력 소비를 명시적으로 계량
  • 직접 + 접두-접미 구성 예측을 결합한 단계적 예측기가 실행 증거만으로 실시간 갱신 — 추가 LLM 호출 불필요
  • 4개 벤치마크 × 6개 모델, 96개 조합에서 평균 14.5% MAE 감소, 예산 제어에서 21.3% 토큰 절감
  • 실행 가능한 비용 예측으로 LLM 에이전트의 계획·예산 관리에 실용적 기반 제공
