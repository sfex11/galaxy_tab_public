기존 언어 세계 모델의 한계

기존 접근법은 환경 관측값을 예측하는 것에 집중해 왔습니다

관측 예측형 세계 모델

Mobs(ot | st) — 액션 조건부 다음 관측값을 재구성하는 환경 중심 목표

  • 검색 결과는 변화하는 웹 콘텐츠와 불투명한 랭킹에 의존
  • 터미널 출력은 파일시스템·런타임 상태에 의존

근본적 문제: 높은 엔트로피

도구 응답은 high-entropy, execution-dependent

  • 예측이 어렵고, 실제 도구가 grounded 피드백을 제공하면 가치가 제한적
  • 시뮬레이션은 근거 없는 증거를 만들어낼 수 있음

핵심 질문: 신뢰할 수 있는 장기 과제(long-horizon) 에이전트를 지원하려면, 언어 세계 모델은 무엇을 예측해야 하는가?

핵심 문제: Task-State Contamination

에이전트의 상태 오염이 이후 판단을 왜곡하는 반복적 실패 메커니즘

근거 없는 가정의 사실화

뒷받침되지 않은 가정을 사실로 수용하고 히스토리에 누적

낡은 계획의 고집

모순된 피드백에도 불구하고 outdated된 계획을 유지

조기 완료 오판

부분적 진행 상황을 과제 완료로 착각

오류는 히스토리에 남아 locally plausible한 액션을 통해 복합적으로 누적됩니다 — 반박된 검색 후보 추구, 검증되지 않은 코드 기반 구축 등

제안: Agent-Editing World Model (AEWM)

관측값을 재구성하는 대신, 추론과 액션이 미래의 과제 진행을 어떻게 바꾸는지를 모델링

사전 실행 상태 (Pre-execution State)

st = ht ⊕ (r̂t, ât)

과제 + 상호작용 히스토리 ht + 제안된 추론–액션 쌍 (r̂t, ât)

Action Judge

제안된 결정을 세 유형으로 판별

Critical Exploratory Noisy

해결 진행 · 불확실성 감소 · 비생산적 방향

State Revision

Noisy 판정을 받은 결정을, 동일한 관측된 히스토리에서 생성된 수정된 추론–액션으로 교체

비판만 제공하는 것이 아니라 상태를 직접 편집

EditAct: 편집과 실행의 통합

AEWM을 실제 에이전트 추론에 직접 통합하는 메커니즘

1
제안
에이전트가 히스토리 ht에서 추론–액션 (r̂t, ât) 생성
2
판별
Action Judge가 Critical / Exploratory / Noisy 판정
3
편집
생산적 결정은 유지, Noisy 결정은 State Revision으로 교체
4
실행
선택된 액션을 실제 환경에서 실행, 관측값이 이후 히스토리에 반영

단순히 비판(critique)을 제공하는 대신, 이후 추론의 기반이 되는 상태를 직접 변경합니다

학습 데이터 합성

세 도메인 — Search, Terminal, Software Engineering — 에서 궤적 합성

Action Judge 데이터

  • 어노테이션 에이전트가 턴 단위 라벨링 수행
  • Critical / Exploratory / Noisy 3-class 판정 라벨 생성
  • 3,000개 결정으로 구성된 크로스 도메인 벤치마크 구축

State Revision 데이터

  • 제안 에이전트(proposal)와 수정 에이전트(revision)가 협력하여 구성
  • Noisy 추론–액션 쌍에 대한 수정 예시 생성
  • 동일한 관측된 히스토리를 조건으로 사용

품질 관리: 구조적 검증 → 의미 감사 → 다양성 인식 선택을 통해 고품질 예시만 선별

2단계 학습 파이프라인

Stage 1

Mid-Training

52B

토큰 기반 중간 학습으로 상호작용 지식을 주입

에이전트 환경에서의 판단·수정에 필요한 도메인 지식 학습

Stage 2

Supervised Fine-Tuning

120K

선별된 예시로 판단과 수정 능력을 활성화·보정

Action Judge + State Revision 능력을 동시에 최적화

추가로, EditAct 궤적을 수집하여 AEWM-RFT(거절 샘플링 미세조정)로 에이전트에 AEWM 유도 패턴을 이식

AEWM-RFT: 학습된 편집 능력의 내재화

검증된 EditAct 궤적으로 거절 샘플링 미세조정(Rejection Sampling Fine-Tuning)

절차

  • EditAct로 에이전트 궤적 수집
  • 실제 환경 피드백에 근거한 궤적만 검증·선별
  • 선별된 궤적으로 에이전트를 미세조정

핵심 장점

  • 추론 시점에 AEWM 온라인 가이던스 불필요
  • AEWM 유도 의사결정 패턴이 에이전트 자체로 이식
  • Self-RFT 대비 세 도메인 모두에서 일관된 향상

실험 결과 ① — Action Judge 벤치마크

70.5%

Macro-F1 on Action Judge Benchmark

+10.6

최강 프론티어 베이스라인 대비 향상 (points)

  • 3,000개 결정으로 구성된 크로스 도메인 벤치마크 (Search · Terminal · SWE)
  • 비교된 모든 프론티어 모델(GPT, Claude, Gemini 등)을 능가
  • 3-class 판별(Critical / Exploratory / Noisy)의 일반화 능력 입증

실험 결과 ② — 메인 벤치마크 (EditAct)

6개 벤치마크 × 3개 에이전트 백본 전체에서 일관된 향상

에이전트 백본 평균 점수 향상 (최강 베이스라인 대비) 비교 대상
Qwen3.5-4B +6.7 ReAct, Step-level Best@3, Trajectory-level Best@3
Qwen3.5-9B +5.2 동일 — 6개 벤치마크 전체에서 우위
Qwen3.5-35B-A3B +3.2 동일 — 대형 모델에서도 유효

벤치마크: BrowseComp, DeepSearchQA, Terminal-Bench 2.0, SWE-Bench Pro, Doc2Repo, NL2Repo

AEWM-RFT: 온라인 AEWM 가이던스 없이 Self-RFT 대비 +2.2 ~ +2.6

어블레이션: 단순 후보 선택 이상의 효과

추론 어블레이션

  • ReAct·Random Gate 대비 명확한 우위 — 판별 기반 게이팅의 가치
  • Agent Resampling 능가 — 비판 유도 재생성보다 직접 교체가 우수
  • AEWM Hint 능가 — 힌트 제공이 아닌 상태 편집이 핵심
  • Action-only / Reasoning-only Revision, Self-WM, 외부 WM 대비 우위

학습 어블레이션

  • Mid-training + SFT 2단계 구성의 효과 검증
  • 판단·수정 두 능력의 공동 학습이 상호 시너지
  • AEWM-RFT로 편집 패턴이 에이전트에 이식 가능함을 확인

결론: EditAct의 이득은 Best@3 같은 후보 선택이 아닌, 현재 추론–액션 연속체의 직접 교체에서 비롯됩니다

AEWM은 어떻게 에이전트를 편집하는가

행동 유형 분포 분석과 도메인별 오류 복구 사례

Search

가설–증거 정합 검사

반박된 검색 후보를 버리고 가설을 증거와 대조하여 복구

Terminal

필수 동작 검증

출력만 확인하는 대신 필요한 실행 검증을 수행하도록 수정

SWE

결함 진단 & 호환성 유지

검증되지 않은 코드 위의 구축을 중단하고 호환성을 보존

행동 유형 분포: AEWM은 Noisy 결정을 효과적으로 걸러내고, Critical/Exploratory 결정은 보존하여 오염된 상태가 이후 단계로 전파되는 것을 차단

결론 및 기여

①

패러다임 전환

환경 관측 예측 → 결정 효과 모델링과 에이전트 상태 편집으로 세계 모델링 재정의

②

크로스 도메인 학습 프레임워크

궤적 합성 + 2단계 학습으로 Action Judge와 State Revision을 학습, 3,000결정 벤치마크와 AEWM-RFT 제안

③

효과성·전이성 입증

Search·Terminal·SWE 전 도메인에서 일관된 향상과 이식 가능성 확인

신뢰할 수 있는 장기 과제 에이전트를 위한 세계 모델은 환경을 재구성하는 것이 아니라, 에이전트의 상태를 편집해야 한다
