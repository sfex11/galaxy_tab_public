배경: 왜 장기 의료 메모리인가?

  • LLM 의료 어시스턴트는 만성질환 관리, 약물 지도 등 여러 진료에 걸친 케어를 지원
  • 환자의 현재 복용 약물과 보고된 알레르기를 정확히 추적해야 함
  • 중단된 약물을 추천하거나 알레르기를 간과하면 안전하지 않은 조언으로 이어짐
  • 기존 벤치마크: 세션 간 의료 추론에서 어려움을 보고, 방해 세션이 쌓일수록 메모리 정확도가 하락

환자의 임상 상태는 진료 사이에서 계속 변한다 — 약물은 시작·조절·중단되고, 측정값은 새로 기록된다. 과거 질문에는 과거 상태로 답해야 한다.

오답 분석: 5개 메모리 시스템의 실패 원인

5개 메모리 시스템의 150개 오답(시스템당 30개)과 응답 모델에 제공된 증거를 분석

도전 과제 1

상태 유효성 (State Validity)

동일한 임상 항목(약물, 혈압 등)은 시간에 따라 다른 값이나 상태를 가질 수 있다.

덮어쓰기 문제 — Mem0류

새 정보가 도착하면 이전 기록을 덮어쓰거나 삭제 → 과거 질문에 답할 기록이 사라짐

현재성 표시 문제 — MemOS류

관련 기록을 보존하지만 검색된 증거에서 어느 것이 현재 상태인지 표시하지 않음

사례: LightMem이 9월 10일의 걷기 거리 측정값을 놓쳐, 더 오래된 측정값 기반으로 답변

→ 메모리는 과거 상태를 보존하면서 해당 시점의 상태를 식별해야 한다.

도전 과제 2

주제 귀속 (Subject Attribution)

장기 의료 대화에는 여러 주제(subject)의 건강 정보가 섞여 등장한다 — 환자 본인, 가족, 대리 상담 등.

명확한 귀속이 없다면

환자가 아닌 다른 사람의 임상 정보가 환자 자신의 것으로 오인될 수 있음

분석 결과

150개 오답 중 108개에서 증거에 타인 정보가 포함

사례: MemOS가 환자 본인 증상 질문에 아버지의 약물을 검색해 답변

→ 모든 임상 팩트는 자신이 기술하는 주제와의 명시적 연결이 필요하다.

도전 과제 3

안전 우선순위 (Safety Prioritization)

안전 정보(알레르기, 부작용 등)는 처음 보고된 지 오래 지나도 이후 진료의 결정을 제약한다.

예시

  • 문서화된 알레르기는 이후 처방 결정에 영향
  • 질의 관련성이 낮아도 안전 제약은 모든 답변에 접근 가능해야 함

사례: REMem이 기록된 co-trimoxazole 알레르기를 누락한 채 항생제 관련 후속 질문에 답변

150개 중 18개 오답에서 필요한 안전 사실이 증거에서 누락

→ 메모리는 안전 핵심 정보를 항상 가용하게 유지해야 한다

MedGraph: 3계층 메모리 아키텍처

세 가지 도전 과제에 맞춰 설계된 다계층 그래프 메모리

L1
원본 대화
모든 세션의 원시 대화 텍스트 보존
L2
임상 팩트 그래프
주제 귀속·날짜가 있는 타입화된 팩트 노드와 체인
L3
환자 프로필
기록된 모든 안전 사실을 나열

날짜가 있는 팩트

값과 단위를 보존하며 이벤트 날짜 기록

Supersedes 엣지

약물 변경·반복 측정 등 동일 항목의 연속 기록 연결

Causal 엣지

세션 내 관련 팩트들을 연결

메모리 구축 (L1 → L2)

1
추출
세션에서 주제·이벤트 날짜를 기록한 타입화 팩트 노드 추출 (값·단위 보존)
2
체인 형성
약물·진단·측정 기록을 임상 항목별 체인으로 연결, 반복 언급 처리
3
체인 갱신
새 기록이 이전 상태를 대체(supersede)하되 이전 상태는 보존
4
인덱싱
검색을 위한 인덱스 구축

이벤트 날짜 ≠ 세션 날짜

환자가 몇 주 전 변경 사실을 보고하는 경우, 실제 이벤트 날짜를 기록

유형별 갱신

상태 변화(약물 중단)와 반복 관찰(혈압 재측정)을 구분

검색 및 응답

  • 주제 필터링·랭킹: 환자의 체인을 단위로 랭킹 — 체인 밖 팩트도 함께 검색
  • 체인 컨텍스트: 질문이 묻는 시점 기준으로 각 체인을 읽어 올바른 상태 제공
  • 확장: 관련 팩트와 원본 대화 텍스트를 함께 추가
  • 프로필 첨부: 환자 프로필(L3)이 모든 질문에 함께 제공되어 안전 제약이 항상 가용

핵심 아이디어: 질의-관련성에 관계없이 안전 사실을 프로필로 전달함으로써, 검색 실패로 인한 안전 정보 누락을 원천 차단

실험 설정

벤치마크

MedMemoryBench — 장기 의료 대화 평가, 대리 상담(proxy consultation) 포함

베이스라인

기존 메모리 시스템 5종 비교 (RAG, GraphRAG, Mem0, MemOS, LightMem, REMem 계열)

백본

두 가지 LLM 백본: GPT 및 오픈 모델 Qwen

질문 유형: 고정된 초기 질문, 변경된 상태 질문, 주제 귀속 질문, 안전 의존 질문으로 평가

주요 결과: 두 백본 모두에서 최고 정확도

+10.5pp

GPT 백본 — 5개 베이스라인 중 최강 대비 전체 정확도 향상

+10.4pp

Qwen 백본 — 오픈 모델에서도 동일하게 최고 정확도 달성

평가 항목결과

메모리 구축·응답GPT 설정에서 효율적 구축 및 답변

분석: 세 가지 도전 과제에서의 우위

상태 유효성

변경된 상태 질문에서 가장 정확 — 체인이 시점별 상태를 그대로 보존

주제 귀속

타인의 팩트가 증거에 섞이지 않음 — 팩트 단위 주제 귀속 덕분

안전 우선순위

프로필이 안전 팩트를 질문과 무관하게 공급

오류 분석

베이스라인 실패 대부분은 팩트 누락 또는 잘못된 저장에서 발생

기여도 분해

원문 텍스트 대비 향상의 절반 이상이 팩트 구축에서 발생, 검색은 TLA·IG에 가장 크게 기여

비용과 효율성

정확도–비용 프론티어의 유일한 LLM 구축 메모리

MedGraph는 최고 정확도를 달성하면서도, 메모리 구축과 응답 모두에서 효율적입니다 (GPT 설정 기준).

구축 비용

세션당 타입화된 팩트 추출로 불필요한 재처리 없이 체인 갱신

응답 비용

랭킹된 체인 단위 검색으로 컴팩트한 증거 구성

결론

  • 문제 정식화: 장기 의료 대화의 실패 분석을 통해 세 가지 메모리 요구사항 도출 — 상태 유효성, 주제 귀속, 안전 우선순위
  • MedGraph 제안: 주제 귀속된 임상 팩트를 날짜 체인으로 연결하는 다계층 메모리, 환자 프로필(L3)이 모든 답변에 동행
  • 일관된 성능: 두 백본에서 각각 +10.5pp / +10.4pp 정확도 향상, 효율적인 구축·응답

영속 메모리, 시간 상태 추적, 임상 정보 추출을 결합하여 — 진료에 걸친 환자 정보를 정확하고 안전하게 유지한다.
