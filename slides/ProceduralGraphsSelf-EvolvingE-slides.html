Procedural Graphs:
Self-Evolving Execution Structures
for LLM Agents

LLM 에이전트를 위한 자가 진화형 실행 구조

Yuxing Lu · Yicheng Chen · Shanchan Wu · Sercan Ö. Arık

Google · Georgia Institute of Technology · Peking University

문제: LLM 에이전트의 절차적 무질서

대부분의 에이전트는 누적되는 평면적 로그 위에서 자유로운 생성으로 행동을 선택합니다. 절차적 지식 — 무엇을, 어떤 순서로, 어떤 조건에서 할지 — 이 암묵적으로만 존재합니다.

목표 상실

궤적이 길어지면 에이전트가 원래 목표를 잃어버림

도구 호출 순서 오류

의존 관계를 무시하고 도구를 잘못된 순서로 호출

반복 루프

생산적이지 않은 행동을 계속 반복

기존 접근법의 한계

접근법예시한계
메모리 · 자기성찰 Reflexion, ExpeL 자유 텍스트 기록 → 매 단계마다 솔버가 적용법을 재구성해야 함
상태 조건 가이드라인 State-conditioned rules 규칙은 제공하지만 연속된 절차 단계 간 연결이 없음
워크플로 · 상태 머신 Workflow, FSM 단계를 명시적으로 제약하지만 대부분 수동 설계 필요
자동 워크플로 탐색 Offline search 현재 진행 상황에 조건화된 실행 중 안내가 부족

필요한 것: 편집 가능한 절차 표현 + 현재 진행 상황에 조건화된 안내

핵심 아이디어: 지식 그래프 → 절차 그래프

Knowledge Graph

(엔티티, 관계, 엔티티) 삼중항

사실적 지식을 구조화하여 "무엇인가(what-is)" 질문에 답함

Procedural Graph

(절차, 관계, 절차) 삼중항

절차적 지식을 구조화하여 "무엇을 할까(what-to-do)" 질문에 답함

  • 노드: 도구 함수, 스킬, 내부 추론 단계, 작업 상태를 추상화
  • 엣지: 허용 가능한 전이를 인코딩, 텍스트 속성으로 "언제/어떻게/무엇을 피할지" 기술
  • 모델 가중치 밖에 절차 지식을 저장 → 검사·검색·재학습 없이 편집 가능

프레임워크 개요: 두 개의 상보적 위상

1
온라인 추론
그래프는 고정. 궤적과 결합해 동적 상황 안내 생성
2
오프라인 진화
학습 태스크 배치 실행 후 LLM 리파이너가 토폴로지·속성 수정

수식: 𝒢 = (𝒱, ℛ, ℰ, Φ), ℰ ⊆ 𝒱 × ℛ × 𝒱

방향성 속성 그래프 — 각 엣지 e = (u, r, v)는 관계 r 하에서 노드 v가 u 다음에 허용됨을 의미

엣지 속성 condition · guidance · pitfalls (적용 조건, 진행 방법, 피해야 할 함정)

온라인: 생성형 PG 안내 (Generative PG Guidance)

1
활성 노드 위치 파악
현재 궤적에서 에이전트의 활성 노드 u_t를 지역화
2
서브그래프 검색
2-홉 이웃 𝒢_t 검색 (매칭 실패 시 전체 그래프 사용)
3
상황 안내 생성
안내 LLM이 위상적 맥락과 함께 다음 행동용 안내 g_t로 변환

편향이지 강제가 아님 — 솔버의 다음 행동을 유도하되 지시하지 않음

추론 자유 보존 — 구조적 사전 안에서 유연한 판단 유지

오프라인: 그래프 자가 진화 루프

1
실행 피드백 수집

학습 태스크 배치 실행 후 실패 궤적과 성공 궤적을 대조 분석

2
편집 제안

누락된 노드·엣지 추가, 실패 유발 요소 가지치기, 엣지 속성 수정

3
검증 게이트

헬드아웃 검증 성능이 유지·향상되는 구조적으로 유효한 후보만 채택

4
거부 메모리

기각된 후보를 음의 제약으로 보관하여 반복적인 실패 제안 억제

실험 설정

벤치마크

  • BFCL — 도구 호출 정확성
  • HotpotQA — 다중 홉 QA
  • MultiChallenge — 복합 과제
  • EnterpriseArena — 장기 기업 환경 위기 시나리오

비교 대상

메모리 기반 베이스라인, 자기성찰, 상태 조건 가이드라인, 수동 설계 워크플로 등

설정: 다양한 LLM 솔버 + 안내 모델, 최소 스켈레톤에서 시작하는 진화 / 전문가 사전 / 결함 있는 전문가 사先 복구

핵심 질문 그래프 없이도 자가 진화가 수동 설계를 능가할 수 있는가?

주요 결과: 일관된 성능 향상

✓

메모리 베이스라인 대비

다양한 데이터셋 · 태스크 유형 · LLM에서 일관된 향상

≥

수동 설계 대등 이상

최소 스켈레톤からの 자가 진화가 수작업 그래프와 대등하거나 능가

+

추가 진화 이득

수동 엔지니어링 없이 자가 진화로 성능 추가 향상

결함 있는 전문가 사전도 복구 가능 — 진화 루프가 잘못된 사전 지식의 토폴로지와 속성을 자동 수정

장기 호라이zon 의사결정과 회복력

EnterpriseArena는 시간에 따른 위기 일정(crisis schedule)을 포함한 장기 기업 환경 — 에이전트의 지속력과 회복력을 시험

  • PG 안내는 위기 도래 시에도 목표를 추적하고 유효한 전이를 유지
  • 생존 분석(survival analysis)에서 PG 에이전트가 더 오래 유효 실행 유지
  • 라운드별 자가 진화 분석: 후보 스크리닝과 위상 변화가 단계마다 실제 성능에 반영
  • 케이스 스터디: 동일 위기에서 베이스라인 에이전트는 반복·이탈, PG 에이전트는 절차 준수

부수 발견 HotpotQA에서는 단순화된 그래프로 수렴(창발적 단순성), MultiChallenge에서는 잘못된 사전을 정정하고 회복

효율성 분석

솔버 단계 · 지연 시간

PG는 목표 지향적 안내로 불필요한 단계를 줄여 전체 실행 단계 수와 지연 시간을 절감

토큰 사용

그래프 직렬화 컨텍스트는 지역적(2-홉) 검색으로 컴팩트하게 유지 — 전체 로그 재주입 방식보다 효율적

파싱 견고성

행동 형식화·파싱 실패율 감소 — 유효 전이 안내가 형식 오류를 사전 차단

진화 비용

오프라인 진화는 배치 단위로 수행되어 온라인 추론 경로에 런타임 오버헤드를 추가하지 않음

결론

  • Procedural Graph — 추론 유연성을 보존하면서 LLM 에이전트 실행을 유도하는 명시적·편집 가능한 절차 지식 그래프
  • 생성형 PG 안내 — 정적 그래프와 실시간 궤적을 단계별 상황 안내로 변환하는 온라인 메커니즘
  • 자가 진화 루프 — 실행 피드백으로 그래프 토폴로지와 속성을 정제
  • 실증 검증 — 다양한 태스크와 LLM에서 메모리 베이스라인을 지속적으로 능가, 진화 그래프는 수동 설계와 대등 이상, 결함 사전도 복구

지식 그래프가 "무엇이 참인가"를 답한다면, 절차 그래프는 "무엇을 해야 하는가"를 답한다.
