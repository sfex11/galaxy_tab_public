LLM은 코드를 잘 쓰지만, ML 개발은 다른 문제

격리된 문제

잘 정의된 단일 태스크에서 LLM은 정확한 코드를 생성

  • 입출력이 명확
  • 피드백 루프가 짧음
  • 한 번의 시도로 해결

자율 ML 개발

수 시간의 피드백 속에서 파이프라인·모델·검증을 반복 수정

  • 데이터 전처리 → 모델 → 검증 순환
  • 접근법 전환(pivot) 필요
  • 대부분의 대회에서 인간에 미달

결과 기반 벤치마크는 격차를 기록하지만 원인을 설명하지 못한다 — 최종 제출만 평가하고 개발 과정을 버리기 때문

TraceML: 통합 궤적 표현

인간의 Kaggle 노트북 기록과 에이전트의 CLI/탐색 로그를 하나의 버전 수준 스키마로 통합

1
원본 수집
Kaggle 노트북, Git 커밋, 탐색 트리 저널
2
계보 재구성
DAG 기반 개발 순서 복원, 포크 관계 연결
3
필터링
마감 후 편집, 얕은 궤적, 점수 낚시 제거
4
정규화 + 주석
공통 스키마로 변환, 액션·의도·편집 크기 라벨링

각 버전이 포함하는 정보: 리더보드 점수 · 타임스탬프 · 코드 내용 라벨 · 액션 유형 · 의도 · 편집 크기 · 점수 효과

Codex (18 궤적)

OpenAI Codex CLI 에이전트 — 단일 edit-run-observe 루프, 브랜치 이력 없음

MLEvolve (189 궤적)

진화적 탐색 에이전트 — 후보 솔루션 트리 성장, 다중 브랜치 유지

두 에이전트 모두 gpt-5.4-mini 백엔드, 동일 태스크 프롬프트, 동일 예산 사용

발견 1: 액션 프로필 — 거친 입자에서는 희미하게, 세밀한 입자에서는 선명하게

인간 전문가

  • 데이터 작업, 검증, 모델 변경, 앙상블을 균형 있게 교차
  • 거시적 액션 분포는 에이전트와 유사해 보임
  • 세밀한 액션 수준에서 차이가 명확히 드러남

에이전트

  • Codex: 제출 측면의 사무적 편집에 대부분의 스텝 소모
  • MLEvolve: 로컬 모델·학습 변이에 집중
  • 두 scaffold 모두 좁은 루프로 수렴

거친 액션 카테고리로는 격차가 보이지 않지만, 세부 액션 수준에서 에이전트의 행동 붕괴(collapse)가 명확하게 관찰됨

발견 2: 에이전트는 너무 적게 또는 너무 많이 전환한다

인간의 pivot 패턴

점수가 정체되면 전략적으로 접근법을 전환

  • 데이터 파이프라인 → 다른 모델 패밀리
  • 단일 모델 → 앙상블로 전환
  • 이전에 보류한 접근법 재개

에이전트의 pivot 패턴

인간의 pivot 비율과 일치하지 않음

  • Codex: 거의 pivot 없이 한 방향만 고집
  • MLEvolve: 무의미한 미세 변이만 반복
  • 단위 당 새로운 영역 탐사에 더 많은 예산 소모

발견 3 & 4: 점수는 회복해도 접근법은 되살리지 못함 · 앙상블은 이름뿐

점수 회복 vs 접근법 회복

에이전트는 점수 하락 후 숫자는 되돌리지만, 포기한 접근법 자체를 재개하지는 않음

인간은 과거에 시도했던 방법론으로 되돌아가 수정을 가함

형식적 앙상블

Codex는 스텝의 대부분을 앙상블 가중치 재조정과 제출 튜닝에 소모

인간의 앙상블: 다양한 모델 패밀리 결합 · 에이전트의 앙상블: 유사 모델의 반복적 가중치 조정

공통 패턴: 에이전트는 형태만 인간을 흉내하고, 실제로는 좁은 행동 공간에 갇힘

인간-에이전트 격차를 인과적으로 요약

탐색 부족 — 에이전트는 초기 방향에서 벗어나지 못하고 좁은 루프에 갇힘

비정상적 pivot — 인간의 전략적 전환 빈도와 불일치 (너무 적거나 무의미하게 많음)

포기한 접근법 미재개 — 점수는 복구해도 과거의 다양한 시도로 돌아가지 않음

형식적 앙상블 — 다양한 모델 결합 대신 유사 모델의 가중치만 반복 조정

낮은 예산 효율 — 단위 당 새로운 영역 탐사에 인간보다 더 많은 스텝 소모

계획 하니스: 관찰에서 개입으로

발견된 격차를 바탕으로 인간 실무에서 추출한 짧은 계획 프롬프트를 에이전트에 부착

하니스 구성

  • 기존 태스크 프롬프트 유지
  • 계획 스킬 블록 추가 (인간 행동 패턴 기술)
  • 주기적 리마인더로 행동 유지

기대 효과

  • 행동 프로필을 인간 쪽으로 이동
  • 일부 대회에서 점수 상승
  • 코드 변경 없이 프롬프트만으로 적용

핵심 질문: 지시어로 환원되는 부분은 닫힐 수 있지만, 전체 격차를 지시어가 메우지는 못한다

하니스 실험 결과

성공한 부분

  • 명명된 행동들이 인간 프로필 방향으로 이동
  • 일부 대회에서 리더보드 점수 향상
  • 프롬프트만으로 접근 가능한 개입

남은 한계

  • 노력 프로필은 여전히 에이전트 형태
  • 모든 대회에서 점수 상승하지는 않음
  • 프롬프트가 도달하지 못하는 행동 영역 존재

핵심 메시지: 지시어는 지시어로 환원 가능한 격차만 좁힌다 — 진정한 계획 능력은 아키텍처 수준의 변화가 필요할 수 있다

논의 및 한계

시사점

  • 프로세스 수준 진단이 결과 기반 평가를 보완해야 함
  • 행동 붕괴는 모델 능력이 아니라 탐색 구조의 문제
  • 인간 실무 관찰이 에이전트 개선의 직접적 출처
  • 단기 프롬프트 개입과 장기 아키텍처 개선의 구분 필요

한계

  • 에이전트 매칭은 7개 대회에 한정
  • 단일 백엔드(gpt-5.4-mini)만 테스트
  • 인간 궤적은 공개 노트북만 포함 (비공개 작업 누락)
  • Kaggle 환경에 국한된 generalizability

결론

1

TraceML 데이터셋 — 134개 대회, 4,465개 인간 궤적과 207개 에이전트 궤적을 통합 스키마로 제공

2

행동 격차의 구체화 — 탐색 부족, 비정상적 pivot, 접근법 미재개, 형식적 앙상블, 낮은 예산 효율

3

계획 하니스 — 인간 관찰에서 추출한 프롬프트가 일부 행동과 점수를 개선하나, 노력 프로필은 불변

4

메시지 — 지시어로 환원되는 격차와 그렇지 않은 격차를 구분하는 것이 다음 연구의 출발점
