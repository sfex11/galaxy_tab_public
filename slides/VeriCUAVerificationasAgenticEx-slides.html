VeriCUA
Verification as Agentic Exploration
for Computer-Using Agents

컴퓨터 사용 에이전트(CUA)를 위한 탐색형 에이전트 검증 프레임워크

Google · The University of Hong Kong

왜 CUA 검증이 중요한가?

Vision-Language Model(VLM) 기반 컴퓨터 사용 에이전트(CUA)는 데스크톱·모바일·웹 환경에서 자연어 명령을 수행하며, 신뢰할 수 있는 작업 완료 검증이 필수적입니다.

데이터 큐레이션

트라젝토리 합성 파이프라인에서 검증 점수로 좋은 예시를 선별

평가

작업별 체커가 없는 애플리케이션에서도 성공 여부를 판단

강화학습

환경 적응 과정에서 자동화된 보상 피드백 제공

핵심 문제: 부분적 관점에 의존하는 기존 검증

VLM 판정자

  • 제공된 관측 프레임만으로 트라젝토리 판단
  • 결정적 증거가 화면에 없으면 판단 불가
  • 저장되지 않은 편집을 성공으로 오판 위험

자동 생성 체커

  • 모델이 작성한 프로그램으로 앱 상태 검사
  • 접근 가능한 상태에 의존 — 접근 제약 존재
  • 검증 질문에 답하지 않는 상태를 조회할 위험

행동은 시도했지만 실제 효과가 없는 경우가 존재 — False Positive(거짓 완료 보고 수용)가 검증의 핵심 난제

VeriCUA: 검증 = 탐색적 에이전트 활동

플랫폼·접근 환경에 구애받지 않는 단일 검증 절차 — 검증을 동적 증거 수집과 평가로 재정의

1
맥락 탐색
환경·녹화물을 먼저 살펴 앱과 아티팩트 이해
2
루브릭 구성
명령어 + 관찰로 세분화된 요구사항 목록 생성
3
증거 수집
GUI 또는 코드 도구로 미해결 요구사항 검사
4
판정 통합
명시적 증거 규칙으로 최종 판정 도출

검증 워크플로우와 증거 접근 인터페이스를 분리 — 온라인/오프라인 모두 동일 절차 적용

환경 인지 루브릭 합성

사전 맥락 조사

검증 시작 전 실행 에이전트가 남긴 환경 상태 또는 녹화 트라젝토리를 탐색하여 앱 구조, 작업 아티팩트, 데이터 위치를 파악

세분화된 요구사항

명령어를 관찰 결과와 결합해 fine-grained 요구사항 루브릭 생성 — 낯선 애플리케이션에서도 개념 해석과 증거 위치 파악 가능

"작업 완료 보고"는 검증해야 할 하나의 주장(claim)일 뿐 — 루브릭의 각 항목이 독립적으로 확인 대상

적응형 하이브리드 액션 스페이스

검증기는 각 요구사항에 대해 두 종류의 검사 도구를 선택적으로 사용

GUI 검사

  • 화면 렌더링, 시각적 표현 확인
  • UI 요소 상태·액세서빌리티 트리 탐색
  • 녹화 프레임 및 액션 로그 탐색 (오프라인)

코드 검사

  • 파일, 데이터베이스, 시스템 서비스 조회
  • 상태 지속성 등 근본적 질문에 답변
  • 읽기 전용(read-only) 강제로 안전성 보장

예: 액션 로그는 "편집 시도"를 기록, 파일 읽기는 "편집 내용이 실제 저장됐는지" 확인 — 서로 다른 질문에 답하는 상호 보완적 증거

증거 규율(Evidence Discipline)

1

근거 기반 판정

모든 판단은 관찰에 명시적으로 연결 — 근거 없는 결론 방지

2

소자 인지 증거

프레임 타이밍, 상태 지속성 등 증거 출처의 속성까지 기록

3

규칙 기반 중재

명시적 규칙으로 판정 통합 — 지원·반박·미해결 요구사항 구분 유지

단순한 pass/fail이 아니라 어떤 요구사항이 근거 있이 충족되었는지 투명하게 남기는 것이 핵심

온라인 vs 오프라인 검증

구분오프라인 검증온라인 검증
대상보존된 트라젝토리 (프레임·액션 로그)실행 에이전트가 남긴 실제 머신 상태
증거 원천스크린 프레임, 액세서빌리티 트리 등 구조화 관측파일, DB, 시스템 서비스 (GUI + 코드)
강점재현 불가능한 실행 사후 분석거짓 완료 보고 강력한 거부
절차동일한 공유 절차 — 인터페이스만 교체

플랫폼별 검증기를 따로 만드는 엔지니어링 비용 제거 — 하나의 프레임워크로 데스크톱·모바일·웹 커버

실험 결과 요약

오프라인
↑ 정확도

베이스라인 대비 참조 레이블과의 일치도 향상 — 어려운 사례에서 최대 향상

온라인
↑ 거부율

VLM 판정자보다 거짓 완료 보고를 더 많이 거부 (False Positive 감소)

액션 스페이스
↑ 커버리지

코드 기반 상태 조회 추가로 False Positive 증가 없이 더 많은 판정 가능

평가 환경: AndroidWorld, OSWorld, ScienceBoard, WebArena 등 다중 플랫폼 · VLM 판정자, 자동 생성 체커, 다수결 투표 등 베이스라인 비교

분석: 무엇이 향상을 만드는가?

  • GUI 단독 vs 하이브리드 — 코드 기반 상태 읽기 추가 시 판정 결정률 상승, False Positive는 유지
  • 관측 입력 효과 — 액세서빌리티 트리 등 구조화 관측과 스크린샷의 결합이 검증 품질 향상
  • 테스트 타임 탐색 — 동일 예산의 반복 패스보다 시각적 증거 추가 패스가 일치도·커버리지 모두 개선
  • 강한 백본 — 상위 VLM 백본 사용 시 온라인 환경에서도 성능 이득 유지

핵심 통찰: 성능 향상은 상호 보완적인 증거원 접근과 테스트 타임 탐색에서 비롯

기여 정리

범용 에이전트 검증

CUA 검증을 탐색적 에이전트 활동으로 정식화 — 오프라인/온라인, 다중 플랫폼 공유 패러다임

적응형 증거 수집

맥락 탐색 기반 루브릭 + GUI/코드 검사 선택 + 소자별 증거 규칙 통합

다중 플랫폼 평가

전 플랫폼에서 참조 레이블 일치도 향상 + 증거 접근·탐색이 신뢰성에 미치는 영향 분석

데이터 큐레이션·평가·강화학습 전반에 필요한 신뢰 가능한 작업 완료 검증의 새로운 표준 제시
