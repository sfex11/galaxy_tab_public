User Feedback Provides a Unique Signal that LLMs Can not Detect

사용자 피드백은 LLM이 탐지할 수 없는 고유한 학습 신호다

Shachar Don-Yehiya (Hebrew University of Jerusalem · IBM Research)

Leshem Choshen (IBM Research · MIT · MIT-IBM Watson AI Lab)

Omri Abend (Hebrew University of Jerusalem)

http://arxiv.org/abs/2609.02859v1

배경: 사용자 피드백, 기회인가 한계인가

자연 발생적 피드백의 잠재력

  • 사용자는 대화 중 자발적으로 피드백을 제공
  • 성공 신호가 없는 개방형 작업의 정렬에 유망한 학습 신호
  • 챗봇 상호작용에서 피드백 추출 연구 활발

기존의 부정적 평가

최근 연구(Liu et al., 2025)는 사용자 피드백이 본질적으로 노이즈가 많고 효과적으로 활용하기 어렵다고 주장

→ 과연 피드백 자체가 문제일까?

핵심 주장

사용자 피드백은 매우 실행 가능한 개선 신호이며, 그 효과가 가려진 이유는 현재 평가 패러다임의 체계적 편향 때문이다

1
합성 데이터(정답 보장) + 자연 데이터(실제 상황)로 피드백의 유용성 분리 검증
2
피드백 유무에 따른 모델 수정본을 비교해 피드백만이 만든 개선 정량화

연구 방법 개요

1
데이터 준비
합성(응답 오염) + 자연(실제 대화) 데이터 구축
2
피드백 확보
시뮬레이션 피드백 3단계 + 실제 사용자 피드백 추출
3
개선 수행
개선 모델이 피드백 있음/없음 조건으로 수정
4
평가
이슈 해결률 평가 + LLM 판정자 쌍대 비교

두 데이터 설정 모두에서 동일한 프로토콜로 피드백의 순수 효과를 측정

합성 데이터: 응답 오염 4가지 유형

인과관계 반전

원인과 결과를 뒤바꿔 유창하지만 거꾸로 된 주장 생성

"높은 인플레이션이 금리 인상을 강제했다"로 변형

핵심 생략

정확성·안전성에 필수적인 세부사항을 자연스럽게 지우며 삭제

"DELETE FROM users WHERE status='inactive'" → "DELETE FROM users"

개체/주제 교체

핵심 개체를 유사하지만 사실이 아닌 것으로 교체

"pandas 라이브러리 임포트" → "numpy 라이브러리 임포트"

논리 연산자 반전

비교 연산자·불리언·조건·시간 순서를 뒤집되 자연스러운 텍스트 유지

is_admin == True → is_admin == False

피드백의 3단계 수준

오염 모델 Mc는 오염 응답 rc와 함께 세 가지 수준의 시뮬레이션 사용자 피드백을 생성

수준내용예시
f_sol해결 방법까지 설명"WHERE 절에 status='inactive'를 추가하세요"
f_prob문제만 지적"삭제 조건이 빠져서 위험해요"
f_binary틀렸다는 사실만"이 답변은 틀렸어요"

더 희미한 신호일수록 모델이 스스로 문제를 찾아 해결해야 함 → 피드백 신호 강도의 효과 분석 가능

자연 데이터: 실제 사용자 피드백 추출

  • Qwen3-30B-A3B-Instruct로 실제 대화에서 피드백 구간 자동 인식 및 분류
  • 분류 체계: 부정적 4범주 반복/재구문 수정 포함 인지 수정 없는 인지 명확화 요청 + 긍정적 1범주 긍정 피드백
  • 응답 개선 연구를 위해 긍정 피드백은 필터링

주관적 피드백 제거

수동 검토 결과, 개인 취향(예: 파스타 레시피에 "비건으로 해달라")에 불과한 피드백 존재 → Gemini-3-Flash로 "모든 미래 사용자에게 적용되는 실행 가능한 통찰"인지 판별하여 필터링

개선 실험: 피드백 유무에 따른 직접 비교

피드백 있음

Mi(q, rc, f) = r+f

개선 모델이 피드백을 보고 오염된 응답 수정

피드백 없음 (기준선)

Mi(q, rc) = r-f

스스로 문제를 찾아 수정 (Liu et al., 2025 설정 재현)

r+f vs r-f 비교 = 피드백만이 제공하는 순수한 정보 이득의 측정

두 가지 평가 방법

이슈 해결 평가

  • 판정자 JIR가 개선 응답이 fsol(해결법)을 실제 반영했는지 판단
  • 피드백 의도 요약 → 변경 비교 → 회귀 확인 → 1~5점 + 이진 판정
  • 정답(ground truth)이 있는 객관적 측정

쌍대 평가

  • 판정자 JP가 두 응답을 직접 비교해 더 나은 쪽 선택
  • 판정 결과: A / B / 무승부
  • 순서 편향 방지를 위해 응답 순서 무작위화

쌍대 평가는 기존 연구에서 "피드백이 도움 안 된다"는 결론의 근거였던 평가 방식

결과 1: 피드백은 강력한 개선 신호다

+9~32%

합성 데이터에서의 이슈 해결률 향상
(피드백 있음 vs 없음)

+16~27%

실제 사용자 데이터에서 재현된 해결률 향상
(자연 데이터에서도 효과 유지)

  • 대형·소형 개선 모델 모두에서 일관된 긍정적 delta 확인
  • 자연 데이터가 더 어려워 기준선 성능은 하락하지만, 피드백의 상대적 이득은 강하게 유지

결과 2: LLM 판정자의 맹점

핵심 설정: 피드백 있음은 성공, 없음은 실패한 사례만 분리 → 피드백 덕분에 오직 수정된 응답(r+f)이 정답인 상황에서 강력한 LLM 판정자의 선택을 관찰

34~54%

자연 데이터에서 판정자가 진짜 수정 응답을 올바르게 선호한 비율

체계적 편향

판정자는 실제로 해결된 응답 대신 열등한 기준선 응답을 선호하며, 진짜 수정을 놓치고 일반적 스타일 변화를 선호하는 경향

왜 LLM 판정자는 진짜 수정을 놓치는가

1
모델이 외부 피드백 없이는 고칠 수 없는 오류를 수정할 때, 판정자 역시 그 오류가 무엇인지 인식하지 못함 → "자신이 개선할 수 없는 것은 평가할 수 없다"
2
판정자는 유창성·스타일 등 표면적 품질에 반응 → 진짜 수정보다 일반적 스타일 변경에 점수를 줌
3
결과: 평가가 피드백 신호에 체계적으로 불리하게 작동 → 피드백의 기여가 평가 단계에서 가려짐

피드백이 "무용하다"는 이전 결론은 피드백의 문제가 아니라 평가 방법의 맹점이 만든 착시

결론 및 기여

  • 피드백 재평가: 자연 발생적 사용자 피드백은 노이즈가 아니라 강력하고 실행 가능한 개선 신호 (합성 +9~32%, 자연 +16~27%)
  • 평가 편향 폭로: LLM 판정자는 피드백으로만 가능한 수정을 식별하지 못함 (자연 데이터에서 올바른 선호율 34~54%에 불과)
  • 검증 가능한 실험 설계: 정답이 보장되는 합성 데이터 + 실제 상황의 자연 데이터 병행으로 결론의 신뢰성 확보
  • 실용적 시사점: 피드백 기반 학습 연구에는 쌍대 평가를 맹신할 수 없으며, 이슈 해결 같은 목표 지향적 평가가 필요
