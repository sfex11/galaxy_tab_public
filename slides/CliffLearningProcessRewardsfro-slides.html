배경: RLVR의 성공과 한계

RLVR (검증 가능한 보상을 활용한 강화학습)은 LLM 포스트트레이닝의 표준 패러다임 — 인간 주석 없이 확장 가능하고 편향 없는 학습을 가능하게 함

하지만 outcome reward는 지나치게 성글다 (coarse-grained)

  • 최종 결과만 평가 → 중간 추론 과정에 대한 가이던스 부족
  • 사소한 오류 1개만 있는 거의 완성된 풀이와 완전히 틀린 풀이가 동일한 벌점
  • 어디서 성공/실패했는지 알 수 없어 credit assignment가 어렵고 학습 효율 저하

기존 세밀한 감독 접근법의 한계

두 가지 주요 방향 모두 추가 제약 조건이 존재

Process Reward Model (PRM)

  • 추가 보상 모델 학습 필요 → 일반화가 어려움
  • 일반화를 위해 대규모 데이터 요구
  • 보상 해킹(reward hacking)에 취약

On-Policy Distillation (OPD)

  • 학생이 자신의 궤적 위에서 교사의 행동을 모방
  • 동일한 tokenizer와 추론 패턴 필요
  • 교사·학생이 같은 계열일 때만 최적 성능

핵심 질문: 프로세스 신호는 얼마나 세밀해야 하는가?

"모든 중간 단계·토큰을 정밀 평가할 필요는 없다.
추론이 처음 잘못되기 시작한 지점만 찾으면 충분하다."

형식논리의 Vacuous Implication

전건 A가 거짓이면 함의 "A → B"는 B와 무관하게 참 — 잘못된 prefix에 조건부된 이후 추론은 추가 정보가 제한적

디자인 원칙

이후의 모든 것을 정밀 평가하는 대신, 추론이 처음 어긋나는 지점만 식별하는 것으로 프로세스 감독이 가능

Cliff: 롤아웃을 단 한 번 분할

기반 알고리즘: GRPO

Cliff는 GRPO를 확장 — objective는 동일, advantage만 교체

Ai,j = ( R(q, ai) − mean[R(q, a1..N)] ) / std[R(q, a1..N)]

  • 질문 하나당 N개의 롤아웃을 그룹으로 샘플링, 그룹 내 상대 비교
  • 실제 구현은 DAPO의 token-level loss aggregation 채택
  • 한계: 같은 롤아웃의 모든 토큰이 동일한 결과 기반 advantage 공유 → 어디가 틀렸는지 정보 없음

방법 ① — Pitfall Step 식별

교사 모델의 감독은 두 단계로 수행

Stage 1 — 교사 스스로 검증

  • 교사가 질문에 대한 참조 풀이(reference solution)를 독립적으로 생성
  • 자동 검증기(verifier)로 교사 풀이를 평가, 정답 그룹만 유지
  • 교사가 오답이면 → 해당 그룹은 vanilla GRPO로 fallback (신뢰할 수 없는 지도 방지)

Stage 2 — 학생 롤아웃 판정

  • 교사가 질문 + 자신의 검증된 풀이를 근거로 학생 답안을 판정
  • 오답으로 판정되면 첫 실수가 발생한 위치를 특정
  • 경계(boundary)를 기준으로 올바른 prefix / 잘못된 suffix로 분할

방법 ② — Cliff Advantage 할당

첫 실수 이전 — 올바른 prefix

+

상대적으로 높은(양수) advantage 부여 → 옳은 추론 경로 강화, 계수 λ로 강도 조절

첫 실수 이후 — 잘못된 suffix

−

GRPO와 동일하게 결과 보상 기반 음(−)의 피드백 — 이미 무효한 prefix에 조건부된 토큰들

  단 하나의 결과 보상을 정보가 풍부한 프로세스 수준 피드백으로 변환 — 토큰/단계별 보상 모델이 전혀 필요 없음

교사는 첫 실수를 잘 찾아낼 수 있는가?

판정 품질(Judge Quality) 분석 결과

판정 정확도

교사 LLM이 학생 답안을 판정하고 첫 문제 지점을 정확하게 식별 — 교사 자체 풀이 성능이 완벽하지 않아도 가능

참조 풀이의 역할

검증된 참조 풀이를 함께 제공하면 판정 품질 향상 — 특히 약한 judge 모델에는 ground truth 활용이 유익

분석: 왜 잘 동작하는가?

Ground Truth 필터

교사 풀이가 검증을 통과한 그룹만 Cliff 적용 — 필터 없이도 동작하지만, 약한 judge에서는 ground truth 활용이 유익

계수 λ의 선택

prefix advantage의 강도를 조절하는 하이퍼파라미터 — λ 값에 따라 성능이 민감하게 변화

학습 동역학

올바른 prefix를 강화하며 GRPO와 다른 수렴 패턴 — truncation과 응답 길이 편향(length bias)에도 강건

보상 해킹 저항성

보상이 "첫 실수의 위치"로 결정 → 실수를 늦추는 것이 항상 유리, 완전히 올바른 롤아웃은 정의상 최적

왜 Cliff인가? — 세 가지 매력 포인트

단순함

RLVR의 간단한 공식을 그대로 유지 — 전용 보상 모델·복잡한 파이프라인 불필요, 롤아웃을 단 한 번만 분할

범용성

모델·과제에 구애 없음(model/task-agnostic) — 추론이 특정 지점까지 옳은지만 확인하면 되므로 다양한 도메인에 적용 가능

해킹 저항

같은 실수라면 늦게 저지르는 쪽이 항상 더 높은 보상 → 실수를 미루거나 우회하는 전략으로 보상을 속일 수 없음

성글며 성긴(coarse) 결과 보상을 정보가 풍부한 학습 신호로 바꾸는 단순하고, 일반적이며, 효과적인 접근법

Cliff: Learning Process Rewards
from the First Mistake

첫 실수 지점에서의 분할 하나로 coarse한 결과 보상을 세밀한 프로세스 감독으로 — RLVR을 위한 간단하고 견고한 확장

  • 교사가 판정한 첫 실수로 prefix(+) / suffix(−) 분할 → 토큰별 advantage
  • 12개 시나리오에서 OPD 대비 15%, GRPO 대비 7% 향상
  • 모델·과제에 범용적이며, 보상 해킹에 자연 저항
