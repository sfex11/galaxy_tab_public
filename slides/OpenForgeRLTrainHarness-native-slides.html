OpenForge RL

어떤 환경에서든 하네스 네이티브 에이전트를
엔드투엔드로 학습시키는 오픈소스 프레임워크

Xiao Yu, Baolin Peng, Ruize Xu, Hao Zou, Qianhui Wu, Hao Cheng, Wenlin Yao, Nikhil Singh, Zhou Yu, Jianfeng Gao

Columbia University · Dartmouth College · Microsoft Research

왜 하네스 기반 에이전트 학습이 어려운가?

최신 AI 에이전트는 Claude Code, Codex, OpenClaw 같은 복잡한 추론 하네스에 의존하여 멀티턴 추론, 도구 사용, 외부 시스템 접근을 수행합니다. 하지만 이 하네스들은 에이전트를 엔드투엔드로 학습시키는 것을 매우 어렵게 만듭니다.

하네스의 복잡성

상태 유지, 다중 프로세스, 중첩 도구 호출, 서브에이전트, 장기 컨텍스트를 포함하는 복잡한 추론 절차

학습–배포 불일치

기존 오픈 소스 SFT/RL 스택은 이러한 하네스 추론을 표현할 수 없어, 학습용 단순화된 하네스를 별도로 구현해야 함

두 가지 핵심 장벽

1
표현 불가능성
오픈 RL 프레임워크(veRL, Slime 등)는 단일 턴 생성 또는 가벼운 도구 호출만 가정. 하네스의 상태 기반 다중 프로세스 추론을 네이티브로 표현할 수 없음
2
환경 분리 문제
하네스 실행에는 전용 컨테이너화된 환경(브라우저, GUI, MCP 서버 등)이 필요하나, 대부분의 RL 프레임워크는 로컬 롤아웃을 가정

기존 오픈 노력은 특정 태스크마다 학습 루프를 크게 수정해야 했고, 이로 인해 코드베이스 확장과 유지보수가 극도로 어려웠습니다.

OpenForge RL: 개요

어떤 하네스 × 어떤 환경 조합도 표준 RL 코드베이스에 연결하는 오픈소스 프레임워크

경량 프록시

  • 하네스의 모델 호출을 가로채어 프록시 서버로 처리
  • 기록된 프롬프트-응답 쌍을 자동으로 트래젝토리로 재구성
  • veRL 등 기존 RL 코드베이스와 호환되는 표준 샘플 생성

K8s 오케스트레이터

  • 각 롤아웃을 독립적인 원격 컨테이너로 실행
  • Microsoft Azure 등 클라우드에서 탄력적 확장
  • 학습 노드와 환경 노드의 분리 달성

아키텍처: 학습 ↔ 추론 분리

1

하네스 실행

하네스가 자체 로직에 따라 멀티턴 추론 수행 (도구 호출, 서브에이전트 등)

2

프록시 중계

하네스의 모델 API 호출을 경량 프록시가 가로채어 실제 모델로 전달

3

트래젝토리 기록

모든 프롬프트-응답 쌍을 순서대로 기록하고 자동 재구성

4

표준 RL 학습

재구성된 트래젝토리를 veRL 등 표준 RL 코드베이스에 직접 공급

핵심: 하네스는 자신의 추론 방식을 그대로 유지하고, 학습 측은 표준 인터페이스만 다룸 → 학습–배포 불일치 제거

롤아웃 오케스트레이션 상세

비동기 롤아웃 & 타임아웃

  • 롤아웃은 비동기적으로 실행되어 학습 병목 최소화
  • 개별 롤아웃별 타임아웃 설정으로 무한 루프 방지
  • 완료된 롤아웃의 트래젝토리를 즉시 학습 큐에 전달

오류 처리

  • 컨테이너 충돌, 네트워크 오류 등을 자동 감지
  • 실패한 롤아웃을 재시도하거나 건너뛰어 학습 안정성 유지
  • 부분 트래젝토리도 보상 계산에 활용 가능

Orchard Env (Peng et al., 2026)를 기반으로 구축되어, 다양한 클라우드 제공자에서 일관된 환경 관리를 제공합니다.

하네스 선택이 학습에 미치는 영향

실제 배포 하네스에서 학습하므로, 하네스 간 난이도 차이를 처음으로 정량적으로 분석할 수 있었습니다.

ZeroClaw

상대적 쉬움

단순한 ReACT 루프 구조로 학습이 비교적 용이

OpenClaw

중간 난이도

더 복잡한 오케스트레이션 로직 포함

Codex

가장 어려움

서브에이전트, 파일 스캐닝 등 복잡한 내부 로직

단순하고 잘 정렬된 하네스일수록 에이전트가 더 빠르게 학습하지만, 유사한 하네스 간에는 일반화도 관찰됨

RL이 에이전트 행동에 미치는 영향

개선되는 능력

  • 자가 검증 — 결과를 스스로 확인하는 행동 증가
  • 도구 커버리지 — 사용 가능한 도구를 더 폭넓게 활용
  • 다단계 계획 완료 — 긴 작업 시퀀스를 끝까지 수행
  • 에이전트 신뢰성 — 전반적인 성공률 향상

여전히 취약한 능력

  • 오류 복구 — 실패 후 정확한 원인 파악 및 복구 불가
  • 비정상 상태 처리 — 예상치 못한 환경 상태에 취약
  • 장기간 추론 일관성 — 긴 트래젝토리에서 드리프트 발생

RL은 에이전트의 "신뢰성"을 크게 높이지만, "복원력"을 얻는 것은 여전히 근본적인 도전 과제로 남습니다.

기여 요약

1

확장 가능한 학습 인프라

어떤 하네스 × 어떤 환경 조합도 veRL 등 표준 RL 코드베이스에 연결하는 경량 프록시 + K8s 오케스트레이터

2

광범위한 실증 연구

Claw 및 GUI(브라우저/컴퓨터 사용) 에이전트 across 6개 벤치마크에서 동급 모델 대비 우수, 대형 모델과 동등한 성능 달성

3

하네스-RL 행동 분석

하네스 난이도 차이 규명, 유사 하네스 간 일반화 확인, RL이 신뢰성은 높이되 오류 복구는 여전히 취약함을 입증

코드, 데이터, 모델 모두 오픈 소스로 공개 예정

결론

OpenForge RL은 학습과 추론의 분리라는 단순하지만 강력한 원칙을 통해, 복잡한 하네스 기반 에이전트를 오픈 인프라에서도 엔드투엔드로 학습할 수 있게 합니다.
