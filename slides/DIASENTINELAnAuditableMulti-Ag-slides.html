감사 가능한(Auditable) 가이드라인 기반 당뇨병 위험 선별 멀티에이전트 시스템

전자의무기록(EHR) 기반 1년 신규 발생 제2형 당뇨병(T2DM) 위험 선별 및 가이드라인 근거 보고서 생성

완전 온프레미스
개인정보 보호

멀티에이전트
LangGraph 오케스트레이션

검증 계층
규칙 기반 + LLM 함의 검사

배경: 제2형 당뇨병의 임상적 과제

5억+

2024년 당뇨병을 앓는 전 세계 성인 수 (국제당뇨병연맹, IDF)

1/9

전 세계 성인 약 9명 중 1명이 당뇨병 유병

  • T2DM은 무증상이지만 수정 가능한 고위험 기간이 선행됨
  • 조기 식별과 개입으로 발병 지연·예방 및 합병증 감소 가능
  • HbA1c, 공복혈당, BMI, 혈압, 지질 검사 등 정기 문서화 필요 → 근소년 위험 지표 요구

LLM 의료 적용의 3대 리스크

기존 LLM 기반 임상 의사결정 지원은 배포 가능성보다 알고리즘 개선에 집중해 왔음

리스크 1

보정 실패
(Poor Calibration)

예측 확률이 실제 관찰된 질병 발생률을 반영하지 못함

리스크 2

환각
(Hallucination)

환자 기록이나 임상 가이드라인에 근거 없는 검사 수치·소견·권고 생성

리스크 3

인용 표류
(Citation Drift)

RAG에서 유효한 권고가 잘못된 출처와 연결되어 신뢰성 훼손

이러한 한계는 LLM 기반 의사결정 지원의 해석 가능성·검증 가능성·임상 신뢰성을 저해한다.

핵심 기여 3가지

1

보정된 LLM 위험 예측기

Qwen2.5-14B를 LoRA로 파인튜닝하고 Platt scaling으로 확률을 보정하여 실제 1년 T2DM 발생률과 정렬, 임상적으로 의미 있는 위험 계층화 지원

2

2단계 가이드라인 검색 파이프라인

ADA Standardization of Care 코퍼스 대상 밀도 검색 + 크로스 인코더 재순위를 상호순위융합(RRF)으로 결합, 재순위기 단독 사용 시의 길이 편향 완화

3

인더룹(In-the-loop) 검증 에이전트

4가지 결정론적 검사와 LLM 기반 함의(entailment) 검사를 결합하여 사실 일관성·미지원 내용·인용 표류를 임상가에게 보고 전에 감사

시스템 아키텍처 개요

LangGraph로 오케스트레이션된 온프레미스 임상 의사결정 지원 파이프라인

모드 A

배치 위험 선별

Risk Function이 모든 대상 환자에게 보정된 1년 T2DM 위험 확률과 고/중/저 위험 등급을 부여

모드 B

상세 보고서 생성

임상가가 선택한 환자에 대해 종단 EHR 검색 → 임상 신호 추출 → 가이드라인 근거 검색 → 구조화 보고서 합성 → 검증 후 표시

LLM 사용 (파란색)
위험 예측 · 보고서 합성 · 의미 검증

결정론적 처리 (회색)
EHR 검색 · 사실 추출 · 수치 비교 · 근거 검색

하이브리드 (보라색)
규칙 + LLM 결합 검증 계층

Risk Function: 보정된 위험 예측

1
구조화된 EHR 특징
검사 결과·생체 지표 등 환자 특징 입력
2
LoRA 파인튜닝 Qwen2.5-14B
1년 신규 발생 T2DM 위험 추정
3
토큰 로그 확률 → Softmax
토큰 수준 확률을 원시 위험 추정치로 변환
4
Platt Scaling 보정
실제 발생률과 정렬된 보정 점수 산출
  • 보정된 점수는 대시보드·보고서 요약·감사 검사 전반에서 캐시되어 재사용 → 일관성 보장
  • 임상적으로 의미 있는 고위험 / 중위험 / 저위험 3단계 계층화 제공

결정론적 임상 추적: Explanation Agent

실시간 검색 시스템

SQLAlchemy로 병원 DB에서 1년 시간 창의 SOAP 기록·검사 결과·간호 평가를 검색

6가지 결정론적 임계값 규칙

HbA1c · 공복혈당 · BMI · 혈압 · LDL 콜레스테롤 · 대사증후군 지질 패턴(고중성지방 + 저HDL)

규칙 발동 시 변수 · 관측값 · 심각도 · 간결한 근거를 포함한 구조화 신호를 출력
예: "HbA1c 6.1%는 당뇨병 전단계 범위에 해당합니다"

  • 생성된 신호는 임상 우선순위에 따라 정렬되어 Synthesizer가 가장 관련성 높은 위험 요인을 먼저 제시

Trend Agent: 종단 추세 추적

동일한 365일 창에서 시간에 따른 변화를 요약

노이즈 허용 밴드
변수별 허용 오차 범위 내에서 최초값과 최신값 비교

트렌드 라벨 부여
stable · rising · improving · insufficient_data

임계점 기록
임상적으로 의미 있는 절단점(cut point) 통과 여부 추적

Synthesizer는 원시 수치에서 추세를 재추론하지 않고 에이전트의 자연어 요약(summary_nl)을 그대로 재사용하도록 지시됨 → 수치 환각의 기회를 추가로 차단

Evidence Agent: 가이드라인 근거 검색

1
로컬 코퍼스 구축
ADA Standards of Care in Diabetes (2026) · Docling으로 382개 섹션 인식 청크 분할 (최대 512토큰)
2
임베딩 & 인덱싱
bge-m3 임베딩 · Chroma에 출처·섹션·페이지 메타데이터와 함께 색인
3
2단계 검색 + RRF
밀도 검색 후보 → bge-reranker-v2-m3 재순위 → 상호순위융합(RRF)으로 최종 evidence_chunks 결정
4
메타데이터 바인딩
각 권고를 출처·섹션·페이지에 명시적 연결, 미지원 문장은 비인용 일반 안내로만 렌더링
  • 재순위기 단독 사용 시 관찰되는 길이 편향을 RRF로 완화
  • 메타데이터 기반 설계로 조작된 인용(fabricated citations)을 원천 차단

Verification Agent: 임상 신뢰성 검증

보고서가 임상가에게 제시되기 전 업스트림 구조화 출력과 대조 검증

결정론적 검사 4종
  • ① 예측 위험 점수 및 등급 일관성
  • ② EHR 유래 수치값 일치
  • ③ 종단(longitudinal) 소견 일치
  • ④ 검색된 가이드라인 인용 검증
LLM 함의 검사

Qwen2.5-14B-Instruct가 권고사항이 검색된 가이드라인 구절에 의미론적으로 뒷받침되는지 확인

탐지 오류: 값 변조 · 잘못된 위험 계층화 · 미지원 추세 · 인용 표류

Annotate-only 원칙: 각 검사는 pass / flag / skipped를 반환하며, 결과는 추가 전용(append-only) JSONL 감사 로그에 기록되고 보고서 수정 없이 임상가에게 표시됨 → 투명성과 임상가 권한 보존

시연: 두 가지 인터페이스

대사질환 임상가의 환자 상태 및 신규 당뇨병 위험 신속 평가 지원

인터페이스 1

일일 배치 선별 대시보드

  • "Run Screening" 클릭으로 전체 대상 환자 일괄 평가
  • 실시간 진행 상황 표시 및 위험 등급 모니터링
인터페이스 2

환자별 상세 보고서

  • 인용된 권고사항이 포함된 5부분 임상 보고서
  • 검증 결과 및 원본 EHR 대조 뷰 제공

프로덕션 시스템은 병원 온프레미스에 배치되며, 공개 데모(diasentinel-demo.onrender.com)는 개인정보 보호를 위해 합성 환자 데이터만 사용

평가 및 윤리적 고려사항

평가 차원

  • 위험 함수 성능 — 표 형태(tabular) 베이스라인과 비교
  • 가이드라인 검색 성능 — RRF 결합 파이프라인 검증
  • 검증 에이전트 평가 — 오류 탐지 능력 측정

윤리 및 한계

  • 의사결정 지원, 대체 아님 — 최종 판단은 임상가의 권한
  • 공정성 및 하위그룹 강건성은 아직 충분히 평가되지 않음

결론

DiaSentinel은 보정된 예측 · 결정론적 신호 추출 · RRF 기반 가이드라인 검색 · 하이브리드 검증을 결합하여 신뢰할 수 있고, 감사 가능하며, 개인정보를 보호하는 LLM 기반 임상 의사결정 지원의 실용적 프레임워크를 제시
