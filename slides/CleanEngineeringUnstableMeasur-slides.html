연구 설계: 두 번의 사전등록 캠페인

부분 추론 흔적으로부터 문제 풀이 진행 상황을 읽어내는 관측자(observer)를 검증하는 연구였습니다.

1
사전등록

2
기기 검증 게이트
관측자의 측정 안정성 확인
3
과학적 주장 검증

결과: 두 캠페인 모두 기기 검증 단계를 통과하지 못한 채 종료 — 과학적 주장 자체를 시험할 수 없었습니다.

엔지니어링은 완벽했다

실행 기록은 천장(ceiling) 수준이었습니다. 문제는 엔지니어링이 아니었습니다.

  • 모든 요청이 정상 전달됨
  • 모든 응답이 스키마 유효성 충족
  • 모든 요청 본문 해시가 동결된 계획과 바이트 단위 일치
  • 기록된 메타데이터 필드가 모두 일정하게 유지됨

엔지니어링 계층의 완벽함은 측정 계층의 신뢰성을 전혀 보장하지 않는다 — 두 층은 반드시 따로 보고되어야 합니다.

세 가지 실패 메커니즘 C2

M1

레이블-의미 사상 편향

레이블→의미 매핑이 신호 자체만큼 강하게 판독값을 왜곡

M2

근사 퇴화 측정 대상

후보 간 격차가 기기 자체 잡음 바닥보다 7자릿수 낮음 → 순위 반복 시 불안정

M3

바이트 동일 입력, 다른 출력

동일 입력에 다른 순위 반환 — 순열 판독이 이 잡음을 증폭

세 메커니즘은 하나의 뿌리 구조를 공유하며, 순열 기반 판독이 이를 단일 관측값으로 증폭합니다. 토큰 하나만 뒤집혀도 기록 전체가 무효화됩니다.

3단계 스냅샷 정체성 사다리

플랫폼 메타데이터가 증명할 수 있는 것과 없는 것을 구분하는 프레임워크

1
요청 동일성
해시·스키마·설정 기록 — 메타데이터로 확인 가능
2
서빙 정체성
커널·배치 상태 — 블랙박스에서 관측 불가
3
측정 안정성
반복 판독 일치 — 직접 측정으로만 입증 가능

모델 이름은 1단계만 보증합니다. 2·3단계는 평가자가 직접 측정해야 하는 대상입니다.

8가지 설계 규칙 C6

  • 스냅샷을 먼저 고정 — 안정성 게이트 신뢰 전에 (← M3)
  • 측정된 적 없는 양에 게이트를 걸지 않는다 (← C1, C4)
  • 정보 있는 쌍에만 순위 게이트 조건화 (← M2)
  • 등가 밴드가 있는 연속 판독 선호 (← C3)
  • 집계를 측정 정의 안에 포함 (← M3)
  • 측정 대상이 존재하게 만든다 (← M2)
  • 고정 체크리스트로 보고 (Appendix D)
  • Fail closed — 파싱 불가한 가드는 반드시 거부 (← §12.1)

핵심 교훈: 연구 호출량의 약 2%만으로 구성된 파일럿이 두 개의 도달 불가능한 게이트를 사전에 드러냈을 것입니다.

결론

공유 엔드포인트 위에서 모델 이름은 동결된 기기가 아니다. 사전등록된 평가는 게이트를 동결하기 전에 반드시 기기를 먼저 측정해야 한다.

깨끗한 실행
전달·스키마·해시·메타데이터 모두 천장 수준

불안정한 측정
동결된 기준 대비 큰 격차로 게이트 실패

기기 우선 규율
사다리·설계 규칙·보고 체크리스트 제공

모든 결과는 공유 서빙 인프라에서 외부 관측된 행동에 한정 — 모델 내부와 공급자 서비스 품질에 대한 평가가 아닙니다.
