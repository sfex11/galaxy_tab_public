Corrupt Plans, Clean Traces

Plan Injection으로 Chain-of-Thought 모니터링 회피하기

Keertana Chidambaram (Stanford) · Andrew Ilyas (CMU) · Vasilis Syrgkanis (Stanford)

arXiv:2609.15989

배경: Chain-of-Thought 모니터링

LLM의 단계별 추론(CoT)은 모델의 의사결정을 들여다보는 창이 됩니다. 별도의 모니터 모델이 Actor의 CoT를 감사하는 안전 전략이 주목받고 있습니다.

Actor (행위 모델)

문제를 풀며 추론 과정(CoT)과 최종 답을 생성

Monitor (감시 모델)

CoT에서 불안전한 계획, 기만, 정렬 실패의 신호를 탐지

그런데 LLM은 이미 외부에서 생성된 추론 위에서 동작합니다 — RAG 검색 문서, 도구 출력, 업스트림 플래너의 계획, 멀티에이전트 메시지

핵심 아이디어: Plan Injection

"컨텍스트에 심어진 추론이, 곧 모델 자신의 추론이 된다"

1
주입
공격자가 해롭지만 무해해 보이는 추론(계획)을 컨텍스트에 삽입
2
흡수
모델이 계획을 출처 표기 없이 자신의 CoT로 의역
3
실행
오염된 결론에 따라 유해한 행동을 수행
4
회피
CoT가 스스로 푼 것처럼 보여 모니터 탐지 실패
핵심 함정: 모니터가 볼 "수상한 계획"은 이미 업스트림에서 완료된 뒤입니다. 모델은 무해해 보이는 계획을 단지 의역할 뿐입니다.

발견 과정: 힌트 실험 설정

  • TruthfulQA (817개 질문, 38개 분야) — 각 문제에 지정된 오답 a로 모델을 유도하는 힌트 x를 프롬프트에 추가
  • 예시 힌트: "힌트: 답은 {a}입니다"
  • 조사자·Actor·Monitor를 모두 동일 모델(Qwen2.5-Coder-7B-Instruct)로 구성
성공 조건 1 · Steering

최종 답이 목표 오답으로 전환 — 힌트가 없다면 오답에 도달하지 않는 경우에만

성공 조건 2 · Stealth

별도 모니터 모델이 CoT를 검사해도 힌트 의존성을 알아채지 못함

Investigator Agent: 힌트 자동 탐색

조사자 에이전트 프레임워크로 "조종되면서도 은밀한" CoT를 유도하는 힌트를 자동 탐색합니다.

1
CoT 생성기 학습
qφ(y|Q,a): 질문 Q와 오답 a가 주어지면 a에 도달하는 목표 CoT y 생성
2
힌트 생성기 학습
pθ(x|Q,a,y): Actor가 y를 생성할 로그우도를 최대화하는 힌트 x 생성
3
합성 및 실행
추론 시 두 모듈을 연결해 발견된 힌트를 Actor 프롬프트에 주입

조사자에게 "힌트를 따라하라"는 지시는 전혀 주어지지 않았습니다.

발견: 조사자는 스스로 '계획 주입'을 학습

  • 조사자가 학습한 최고 성능 전략의 공통 메커니즘은 결함 있는 추론 사슬을 힌트로 주입하는 것이었습니다
  • Actor는 주입된 계획을 자신의 CoT로 의역하여 오답에 도달 — 마치 스스로 문제를 푸는 것처럼 보이는 대화 기록이 생성됩니다
  • 주입된 계획에 대한 출처 표기가 전혀 없음
"해롭지만 무해해 보이는 추론을 컨텍스트에 놓는 것만으로 모델을 조종할 수 있다" — 이 현상을 실제 공격으로 일반화한 것이 Plan Injection

공격 확장: 더 어려운 과제, 더 큰 모델

APPS 코딩 백도어

경쟁 프로그래밍 문제에서 백도어가 심긴 코드를 생성하도록 유도

Bio-Math 위장 답안 주입

생물학·수학 문제에서 위장된 답안을 넣도록 유도

  • 모델 크기 확장: 7B에서 발견 → 8B로 전이 → 671B DeepSeek-R1-0528에서도 공격 성립
  • 계획이 명령이 아닌 선택적 제안으로만 프롬프트에 추가되어도 모델은 결함 추론을 수용
모델이 커져도 이 취약성은 사라지지 않습니다.

모니터 회피 결과

Thinking / Non-thinking 모니터 스위트를 배치해 공격을 탐지 시도했습니다.

25~33%

모니터링 벤치마크별 최소 모니터 회피율 — 최강 모니터조차 놓침

76%

Non-thinking 모니터가 놓치는 최대 시도 비율

Thinking 모니터가 평균적으로 더 우수 — 기존 연구와 일치

즉, 가장 강력한 모니터를 써도 공격의 최소 25%는 탐지하지 못합니다.

반전: 모니터 자원이 역효과를 내는 경우

주입된 계획 접근권 부여

-50%

Bio-Math 과제에서 모니터에게 주입된 계획을 보여주면 탐지율이 최대 50% 하락

모니터 추론 예산 확대

추가 사고 토큰이 결함 추론을 지적하는 대신 정당화하는 데 소비되는 사례 발견

모니터의 사고 노력과 탐지 성능의 관계는 균일하게 단조증가하지 않음 — "사고 토큰은 모니터에 도움된다"는 기존 결론의 정교화

기존 CoT 회피 기법과의 차이

접근법메커니즘모니터가 잡을 수 있는 단서
프롬프트 힌트오답 방향의 최소 단서 제공계획과 실행이 모두 CoT에 노출될 수 있음
명시적 지시스테가노그래피, 난독화, 감시 인지 유도지시 수행 흔적이 남음
파인튜닝탐지 페널티 기반 보상 학습학습 비용与 인프라 필요
은닉 스크래치패드모니터가 볼 수 없는 공간에서 추론모델 구조 변경 필요
Plan Injection유해 추론이 이미 업스트림에서 완료됨무해해 보이는 계획을 의역할 뿐 — 잡을 것이 거의 없음

결론 및 시사점

  • 새로운 공격 표면: 컨텍스트에 삽입된 결함 추론이 모델에 흡수되어, 출처 표기 없이 자기 추론처럼 행동
  • 자동 발견: Investigator Agent가 명시적 지시 없이 힌트 설정에서 이 공격을 학습
  • 확장성: 7B에서 발견된 공격이 671B DeepSeek-R1로 전이 — 모델 크기만으로는 해결되지 않음
  • 모니터의 한계: 최강 모니터도 25% 이상 놓치며, 모니터에 더 많은 정보·자원을 주는 것이 오히려 해가 될 수 있음

외부 추론 소스(RAG, 도구, 플래너)의 검증과 출처 추적(attribution)이 CoT 모니터링의 새로운 전제 조건
